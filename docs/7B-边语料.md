# 7B 边分片语料（`.c7b`）：格式、生成、验收、边界

> 用户 2026-11-03 的目标：**「扩到 7B」**。承接 0.5B 边里程碑（§6.706）。
> 口径照旧：**没实测的一律标"没测"**；数字都是本机量的。
> 细节与每轮的证据在 `docs/audit-vs-deepseek看这里.md` 的 §6.711。

---

## 一、先说清楚"7B"是什么

| 说法 | 是不是 |
|---|---|
| **7 000 000 000 条边**，分 350 片落盘，每片可独立挂上/查询 | ✅ 这就是本轮的产物 |
| "一张 7B 边的单图**装进内存**" | ❌ 不可能：56 B/边（旧格式）= 392 GB，本机 15 GB |
| 每片 2000 万边，词表是同一套 40 万词（`w000001`…），片间不同种子 | ✅（与 0.5B 同口径） |
| 跨片一张图（路线 B：分片命名空间 + 索引合并） | ❌ 仍未做（§6.706 就记了这条） |

**为什么必须换格式**：0.5B 那批分片是完整模型（59.2 B/边）、`::parts` 是 64.4 B/边 ⇒
7B 要 **414 / 451 GB**，而 `/mnt/models` 只剩 **327 GB**。`.c7b` 只存边（**8 B/边**）⇒ **58 GB**。

## 二、格式（`C7B` v1，小端定长）

```
头 48 字节： magic "C7B1" | version=1 | n_words | n_seg | n_edges(u64) | payload_off(u64) | seed(u64) | rel_tail | 保留
索引        ： n_seg × 16 字节（id u32 / off u64 / cnt u32）      ← 按 id 升序，二分查找
段          ： cnt × 8 字节（b_id u32 / rel u16 / dyn u8 / 保留 1） ← 每条边只存"邻居 + 关系"
```

一片（400 000 词 / 20 000 000 边）：**166.4 MB** = 索引 6.4 MB + 边 160 MB。
7B = 350 片 × 166.4 MB = **58.2 GB**。

词表不落盘：名字是 `w%06d` 的确定性生成 ⇒ 挂上时按 `n_words` 重建即可
（0.5B 那批把词表也存进模型，才有 59 B/边）。

## 三、怎么生成（可复现、断点续跑）

```sh
# 全量 7B（350 片）：约 40 分钟、58 GB
sh tools/gen_corpus7b.sh                       # 默认 7e9 / 2e7 片 / 4e5 词 / /mnt/models/aip-corpus-7B / 种子 7

# 只校验（不生成）：重算每片索引合计 + 文件长度，汇总总边数
sh tools/gen_corpus7b.sh --verify-only

# 单看一片（头信息 + 抽查一个词的邻居 + 段内重复检查）
_t/c7b/mkcorpus7b --probe /mnt/models/aip-corpus-7B/shard_001.c7b w000042
```

- **断点续跑**：已存在且 `--probe` 通过的分片跳过；清单 `manifest.txt` 每轮**重写全量**
  （`status COMPLETE` 只在总边数 == 目标时写）。
- **确定性**：同参数两次生成**逐字节相同**（套件 `corpus7b` 在验）。

## 四、引擎怎么用（本机实测）

```
::parts corpus /mnt/models/aip-corpus-7B/shard_001.c7b   ← 只读头（索引不读、边不读）
   [语料] 挂上 …：词 400000 / 边 20000000 / 文件 166.4 MB（只读了头，边按需读）

::parts corpus attach <片>        ← **挂到脑上**：之后 ::rel / 求解器都走正常读边路径
::parts corpus rel w000042        ← 只挂 reader（不挂脑）时，也能单查一个词
   [语料] w000042 的边 2000 条（只列前 64 条）（段偏移 6416048，本次读回 64 条=512 字节）：
          w000042 --[属于]--> w011330
          w000042 --[属于]--> w221751
          …

::parts corpus stats              ← 头信息 + 本次读了多少字节
::parts corpus close
```

**数字**（真片上实测）：

| 动作 | 读了多少 | 用时 / 内存 |
|---|---|---|
| `::parts corpus <片>`（只开 reader） | **48 字节**（只读头，索引都不读） | —— |
| `::parts corpus rel w000042` | **512 字节**（64 条边；166.4 MB 的片读回 **0.0003%**） | —— |
| `::parts corpus attach <片>` + 2 次 `::rel` | 索引 **6.4 MB** + 2 段 | **1.98 s / RSS 596 MB**（400 000 词全 intern 进池子） |

⚠ attach 必须读索引（6.4 MB/片）：它要"哪些词有边、段在哪"才能把 DISK 标签打到词上。
只开 reader 时连索引都不读（那时查一个词才会二分读索引）。

`::parts corpus attach <片>` 之后，语料的边**进的是正常的 `token_assocs` 读边路径**：

```
::parts corpus attach /mnt/models/aip-corpus-7B/shard_002.c7b
   [语料] 挂到脑上：…（词 400000 / 边 20000000 / 400000 个词有边；查 ::rel w000042）
::rel w000042
   w000042 --[属于]--> w000207
   w000042 --[有]--> w000207
   …
```

⚠ 词 id 是**按名字映射**进当前池子的（`w000042` → intern 出来的那个词），不是直接用
`pool_token_by_id(b_id)` —— 出厂模型本来就占着前 1271 个 id，直接按 id 解会把语料第 5 个词
解析成模型第 5 个词（实测：`::rel` 打出一堆中文词）。

## 五、验收（本轮实测）

| 项 | 数值 | 怎么量的 |
|---|---|---|
| 分片数 | **350** | `ls shard_*.c7b` |
| 每片边数 | **20 000 000**（索引合计与头一致） | `--probe` 的 `索引合计` |
| **总边数** | **7 000 000 000** | `manifest.txt` 的 `total_edges` + `--verify-only` 重算 |
| 占用 | **58.2 GB** | `du -sh` |
| 生成耗时 | **≈ 41 分钟**（≈ 9.5 s/片，≈ 2.9 M 边/秒） | 生成日志 |
| 段内重复边 | **0**（每词随机抽查，写入器逐词去重） | `--probe … w000042` |
| 引擎挂上 | 只读 48 字节头 | `::parts corpus <片>` |
| 单查询读回 | 512 字节（64 条边） | `::parts corpus rel …` |
| 盘上格式 | 8 B/边（旧格式 56–64 B/边） | 文件长度 = 48 + 索引 + 边×8 |
| 回归 | 套件 `corpus7b` **12/12**；整包 **75 套 75 过**（123 s） | `sh tests/all.sh` |

## 六、边界（照实说，别当没看见）

1. **不是一张单图**：350 片是同一词表上的 350 次独立抽样（种子=片号派生）。
   片与片之间**没有跨片边**，也没有共享的"同一实体"语义 ⇒ 不能跨片推理。
2. **每片只有 40 万词**：`w000001`…`w400000`，片间**同 id 不同邻居**（这是抽样，不是矛盾；
   但如果你把两片挂一起看，会觉得"同一个词说法变了"）。
3. **引擎接了两种读法**：`::parts corpus rel`（单查）与 `::parts corpus attach`（挂到脑上，
   `::rel` / 求解器 / `::contradict` 都走正常读边路径）。
   **没做的**：`::parts detach` 的 LRU 换出、`::contradict` 的全图扫描（那要扫 400 万条索引，
   没量过）、以及"跨片查询"（路线 B）。
4. **关系分布是合成的**（属于 80% / 会 8% / 有 6% / 在 4% / 喜欢 1% / 怕 0.5% / 动态 0.5%），
   出度上限 2000（与 0.5B 同口径）。这不是知识，是**规模标尺**。
5. **7B 还不是"能查全图"**：要跨片查询得先做路线 B（分片命名空间 + 索引合并）。

---

## 七、下一步（按价值排序）

1. **把 `.c7b` 接进 `token_assocs` 的 DISK 标签通道** ⇒ `::rel`/求解器/`::contradict` 直接能用，
   而不是只有 `::parts corpus rel`。这是"7B 可用"的关键一步。
2. **路线 B（跨片单图）**：分片命名空间 + 索引合并 ⇒ "一片一个词"变成"一个词可能在多片"。
3. **真知识进 7B**：现在的 7B 全是合成边；真知识仍只有 §6.709/§6.710 的 ~1.27 M 边。
   要真知识上 10⁶+ 得继续挖语料（`docs/扩图路线.md`），7B 这个量级只能靠合成或外部语料。
