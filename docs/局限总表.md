## 一、能力边界（做得到什么、做不到什么）

### 1. 语料与知识（用户点过：**核心瓶颈不在代码，在语料**）

- **边是纯共现，没有关系类型**：边只有 `role/topic/pattern` 三个位置性标签；`frames.txt` 里
  0 处关系标签。→ audit §一.❌1
- **token 稀疏**：出厂模型 ~1200 token / ~41000 边，平均每词边数仍少，"泡出来的"语义要靠人看。
- **语料格式 bug 的残留**：`X Y Z 连接` 只建 `Y→Z` —— 训练路径已用 `token_observe_names`
  绕过，但 **`::asm` 直接跑解释器时 bug 还在**（实测）。→ audit §一.⚠️记忆行
- **语义精度会松**：关系词表**手写**、闭合世界假设、谓语只认清单里那十来个（另有动态谓语）、
  embedding 撑不起关系类比（关系是显式规则推的，不是向量算的）。→ audit §6.12
- **动态关系只支持肯定，不支持否定**。→ `ai.h:554`
- **关系别名只对"分词器不切开的词"有效**：多字词必须先是词表 token（`喜爱`→`喜`+`爱` ⇒
  别名永远看不到）。现在只有 `拥有` 是真可达的，其余等它们进词表。→ `rel.h:158`
- 训练/巩固是**训练期内联**的（睡眠/抽象在训练时做），短对话看不见睡眠/漂移/叙事的效果。→ audit §一.✅9

### 2. 语言与理解

- **对话触发仍是关键词表**：能认说法，不是"懂话"（`条件/塞/搭/词儿` 能认，其余听不懂）。→ §B.1
- **分词器会切开多字词**（`喜爱`→`喜`+`爱`）：别名表、触发表、词表查询都会因此"看不见"某个词。→ §C 陷阱
- **合写否定的残余**：`不会/不喜欢/不是` 已统一（§6.69），但 **`猫 不能 飞 吗` / `不敢` 仍掉
  降级答复** —— 情态动词不是关系词的否定，要单开一张同义/情态表（不塞进 `neg` 字段）。→ §6.69 局限
- **`subs_not[]` 语言层没有原语**（`grep subs_not token_lang.h` = 0）；类别继承靠
  `ai_form_abstractions`。→ §一.⚠️3
- **VSA 原语能跑，但语料里没有 VSA 结构** ⇒ 等于摆设；**`ai_analogy` 从没被调用过**。→ §一.⚠️4、§二.❌2
- **语言层的覆盖只到 `::asm` 一条路**：`展开/检索` 之后栈深不确定就不查操作数（校验器宁可漏）。→ 顶块 5.③

### 3. 推理

- **只有关系推理走"链是一等公民"那条路**；推测置信度是**拍的**；不支持反事实（反事实后来有了假设世界，
  但"如果…会怎样"的推理仍窄）。→ §6.13
- **完备性靠手写**：独占公理最初是手写的，后来改成"量出来的"（§33.1），但**仍不是"没写就算假"**——
  开放/闭合世界开关是**人的选择**，不是模型判断。→ §6.15、§33.1
- **前提成立永远是图内判据**（提到过 / 够得着 / 有据），不是"世界真相"。→ §B.5
- **D4 提的前提是统计模式**（语料上给 `你—[前提]→我→说（95%）` 这类），语义要人看。→ §B.6
- **结构类比只在思维层的「借最近邻」里生效**，求解器内部仍只用规则。→ 四件 doc 130
- **机制路的链长/链底可信度**（§6.67 已接全）但两处是近似：经由中间词的链长是**算术**（子链+1），
  借最近邻的 `cred` 是**邻居边的可信度**（不是知识链的底）。→ §6.67 局限
- **静态知识 0 条时只能靠语料**：语料里没有的结论推不出（设计使然，不是缺陷）。

### 4. 思维循环

- **机制只有内建五条**（问前提/换问法/缺前提/借最近邻/经由中间词），**顺序即优先级**。→ `docs/thinking.md` 十一.1
- **N3 回溯**：一轮最多退 2 次；回溯深度**只有 1 层**（退回这一支的起点，没有分支树）；
  "换一条"**只有改问反面一种**；触发面只有"前提刚被判不成立"。→ §6.65 局限
- **N1 思考对象**：只进**内存**、一轮一个、**不参与决策**；`::cot` 没接它。→ §6.61 局限
- **N4 空闲思考**：不会主动说话（回复仍是"……"）、只够得着 `Think.open` 那批问题、
  会推高思维自己的元认知计数。→ §6.63 局限
- **N2 轮中草稿**：auto 模式下当轮发送会清掉草稿（既有行为）；两个开关都开时发出去的**是草稿全文**。→ §6.64 局限
- **缓存不参与自由联想**（走边那套按 role 取边，缓存不在其中）。→ `docs/thinking.md` 322
- **未解问题的文本被截断**（`think_ask_name` 的预算），恢复出来的是截断后的问句，解析不出的跳过。→ `think.h:699`

### 5. 他者 / 视角

- **他者模型只有一层表**：没有多视角证据合并/冲突裁决 —— ⚠ **部分过时**：§6.45 已做"多层合并 + 四态判定"
  （同类别并进滑动窗、待验≠否定）；**剩下的**是"上位说法只算相关、不算依据"与"每人只留最新一版极性"。→ §B.3、§6.68
- **"他说的"档在可信度里是摆设**：他的信念走别的路（`OtherModel.bel[]`），不参与我的后验。→ §B.8
- **③ 复数主语进回答路径**：只认**句首**复数主语（固定表：大家/他们/她们/别人/旁人/大伙/众人/其他人）；
  **时间维度不做**（谁先说的、谁改口了看不出来）；答复里"我自己的知识"只查**直接边**。→ §6.68 局限
- **同义改写对不上**（"他说的按 (A,关系,B) 精确匹配"）—— ⚠ 部分过时：§6.45 加了"同类/蕴含"判据；
  剩下的见上一条。→ 五个局限 4

### 6. 时间

- **时间只有区间**（首次/最近 + `[时刻:]` 标记）：没有"同时 / 先后不明 / 因果时序"的判据。→ §B.4
- **`::order` 读得出图里的顺序了**（§6.66），但 `next_in_time` 是**一条线**（无分支、无"同时"），
  跨一跳的标记边（A—[关系:之后]→X→B）读不出来。→ §6.66 局限
- 他者答复里**没有时间维度**（用户明说"时间维度不做"）。→ §6.68

### 7. 情绪与内生状态

- **情绪耦合表共线**：真矩阵是 舒适×不适 r=−0.99、舒适×唤醒 −0.94、不适×唤醒 +0.95、舒适×疲劳 −0.82
  ⇒ **四个状态量其实只有一个自由度**（都是"我最近猜得准不准"的函数）。用户裁定**情绪不进内核**
  ⇒ 留在层里当已知局限；后来加了两个**派生**维度（`好奇`=图里的缺口感、`亲近`=信任×互动）。→ §A.5、`drive.h:50`
- **内部动力学手写**（疲劳 +0.001、舒适=预测准确率线性）；`setpoint` 只用于 drive bias。→ §B.7
- 元认知/内生状态**只在非帧、非检索的输入上显形**（被帧或检索接管时不涨）。→ §一.✅5/6 的注解

### 8. 记忆与持久化

- **推论档后验偏乐观**：`n_cached` 语义变窄 + `n_retracted` **重载恢复不了**（撤掉的东西图里没痕迹）
  —— 这是"格式不动"的代价，注释里写明。→ §A.6、`model_io.h:427`
- **临时 token 不存盘**（设计）：草稿区随进程走。**过程记号是普通 Token + 边（role/记号都序列化）**，
  所以结构**跨会话**（`::load` 之后 `::proc` 看得见、`::proc run` 跑得动，§6.71 已证）；
  但"执行结果"不进存盘（轨迹是内存里的 `Derivation`）。→ §6.70、§6.71、记事本 doc 172
- **存档格式不动**是纪律（现 v10）⇒ 任何新能力都得挤进既有字节（role/topic/pattern 是常被借用的地方）。

### 9. 写入与安全（内核）

- **老写入者还没全搬到队列上**：感知共现、内部对话、想象、`ai_learn_causal`、`ai_learn_expression`、
  信用分配等仍**直写**（现在是"有账 + 可路由"：`ai->writes[]` 记账，`route_writes` 打开时知识类写入走受审通道）。→ §B.2、`microkernel.md` 局限 1、`ai.h:3810`
- **路由只覆盖关系事实一类**（感知共现刻意直写，`::safe` 写明理由）。→ §B.2
- **写入闸门判别力窄**：实测重要度落在 0.587–0.725，阈值 0.65/0.70 只切掉 24%/4.2%；
  `imp` 公式里 `Δ²D/Δ²T` 是拿"惊讶/不累"**替代**的（不是同一个东西）。→ §A.7
- **过程记号**：①② 落地（§6.70）、**③ 写引擎落地**（§6.71：`::proc run` 逐步核对 + 受审执行 +
  断点）。剩下的：**v1 判据只到"现在过得去"**（词在 + 前提成立 + 行为跑得成）——
  **"这一步做不做得了"不判**；步骤是**扁平的**（没对象/条件）⇒ 逐条 `der_verify` 独立重推**还没接**
  （留给 ⑤）；行为步骤**不能带参数**（不猜）；调用只跑 `[过程:…]` 子过程；回边只认步号、迭代 ≤2、
  一次跑 ≤64 步；顺序只认 `[步骤:N]`（改号不重排）；`加回边 <动作词>` 会和那一步共用一条边；
  根上有一条"挂靠边"；`::proc` 一次最多列 256 条边。→ §6.70、§6.71 局限
- **④ 干跑的假定只到"前提成立"这一种**（记的是 `(动作, 需要, 前提)`）："假定某个**对象**存在/
  某个**条件**为真"要等 ⑤（步骤带对象/条件时才有三要素可假定）；假定**不进图、也不进推理**；
  干跑**不执行行为** ⇒ 不会有真实副作用、也不会发现"执行到一半才炸"；
  **假设层只有 4 层**（主过程 + 3 层调用，到顶就明说"假定没地方放"，不假装假定过）；
  按步回退只在"这一步失败"时触发（步子成功时假定留给后面的步用，整轮跑完一起 pop）；
  干跑的"核对"只是 `hypo_find` 复核（假设还在不在层里），**不是**"这一步在世界上成立"。→ §6.72 局限
- **⑤ 分支/循环/异常**：**一条边一个记号**是硬约束 ⇒ 条件不能和步骤同挂一条边（用回边记号绕过）、
  `[异常]`/`[否则]` 各只能有一条（v1 只跑第一条）；**条件判据 = 前提判据**（没有独立求值能力，
  数值比较那类"真条件"要先有求值层）；**异常不按类型分派**（类型只是标签、只跑一次）；
  **循环只有 while 形态**（回边+条件+迭代上限 2，没有 for/break）；**分支没有 if-elif 优先级**
  （多条条件边逐条各自判）。→ §6.73 局限
- ~~过程不跨会话~~ **已修**：①② 的结构/role/记号本来就在存盘里，③ 的引擎让第二个会话
  `::load` 之后 `::proc` 看得见、`::proc run` 跑得动（§6.71 证据）。→ 原 §6.70 局限
- **`ai_new` / `ai_load_file` 的历史常量默认值两份**（后加开关已集中到 `ai_switches_init`，
  历史那批待合并）。→ §A.9
- 自修改**不能改自己的底线**（安全内核的阈值写死在一侧）——这是刻意的，不是局限。

### 10. 代码 / 动作 / 外部世界

- **代码闭环是降级版**：只会两类修法（补声明/补头文件一类）、**不生成代码**、最多改**一次**、
  编译命令固定、产物落在 `_t/work/`。→ `code.h:21`
- **没有通用动作接口**：「我做了什么 → 世界变了」这条因果链**不存在**，系统不会主动调外部程序
  （`action.h` 是受审的白名单执行，不是通用工具调用）。→ §二.❌7
- **过程的"执行"只到"核对 + 受审执行"**（③ 已落地，§6.71）：能判"现在过得去/哪儿断"，能真执行
  `min_args==0` 的 Token 行为；但**对外部世界产生效果**（行动/工具调用）仍没有通用接口
  ⇒ "计划 → 真的改变世界"之间还断着（和"没有通用动作接口"同源）。→ §6.71、§二.❌7

### 11. 对话与输出

- **帧/检索接管之后，后面那一段（元认知/想象/内部对话/叙事/漂移）走不到**：
  实测长时间非帧输入下 `想象=1 内部对话=20`，而 **`叙事=0`**（要 500 轮且路径没被接管）。→ §二.⚠️4/6
- **`::notepad on` 会替掉流水线措辞**（已改成"待验"式措辞）；**`manual` 模式默认关**（默认 auto = 行为不变）。→ 五个局限 2、记事本 doc 170
- **输出侧补丁的边界**：缓冲**不持久化**（`::save` 不存草稿）；`改`/`改发言` **只认单 token**
  （CLI 参数按空格切，替换串含空格传不进去；C 层/语言层没这个限制）；
  "想清楚再改口"**还不会**结合"刚刚那句降级答复到底行不行"。→ 记事本 doc 170

### 12. 工具与看护（harness 自己）

- **成对开关无法全枚举**（缓解：`SUITES="…" SKIP_BASE=1 ONLY=…`，≈1 分钟）。→ §A.11
- **"写进 `switches_ab.sh` ≠ 跑过"**：`AIP_WGATE=1` 这一档三个月没人跑，C 级测试里 12+1 项
  一直假红（§6.67 当场抓到）。→ §6.67
- **C 级测试必须自己钉默认档**：`ai_new()` 会读环境变量 ⇒ 反向测量时"默认关"的断言会假红；
  规矩是测试自己 `tnew()`（钉 `write_gate_off`/`route_writes`）或按 env 分叉。→ §6.67
- **`selfcheck.sh` 只覆盖三类机械可判的坑**（管道吃退出码 / 没兜住的 grep 赋值 / 脚本与清单对不上）；
  **"永不红的断言"仍靠人** —— 它的真实形态是"grep 命中了**帮助文本**而不是痕"（本会话踩到 4 次）。→ §6.66
- **整包时间**：并行 32 套 + 冒烟**实测 ≈ 46 s**（套件相位 20~29 s；audit §C 记的是 ≈70 s ——
  机器不同，两个数都对；串行仍 ~6 分钟）⇒ 纪律是"迭代跑单套、整包只在批次收尾跑"。
- **探针/编译门**已修（26 探针 `-Werror` + 4 个跑出结论进第 0 步），但"探针改了 API 忘了改"
  这类错误只能靠这道门拦，别再绕过它。→ §A.1

## 二、设计取舍（**不是缺陷**，是拍过板的选择；写在这里免得被当成 bug 反复"修"）

| # | 取舍 | 为什么 |
|---|---|---|
| 1 | **只有观测进图** | AI 自己想出来的东西要过闸门/沉淀通道（缓存档），不许当事实写 |
| 2 | **结构改动只走 `micro_step()`** | 自修改与自修改系统共用"提议→审查→记账→应用→审计"，没有特权后门 |
| 3 | **存档格式不动**（现 v10） | 旧模型能读、不用重训；代价见 §一.8（`n_retracted` 等） |
| 4 | **临时草稿不存盘** | 名字前缀是唯一判据 ⇒ 跳过存盘才是格式安全的 |
| 5 | **报告文字可以随能力改写** | A/B 里说"行为逐字节一致"指的是行为/图/痕迹；`::safe`、元认知行这类**报告**允许改写（每次都在审计里记明） |
| 6 | **情绪不进内核** | 用户裁定；耦合表共线 ⇒ 留在层里 |
| 7 | **记忆/日记/搜索补丁：暂缓** | 原口径"不做"（用户原话），2026-10-10 改成"先不急"；真要做只在**补丁层**（挂载式、默认不挂） |
| 8 | **明确不做**：拆预测簇、分页/懒加载、4B/27B 存储改造 | 顶块「二、已拍板」 |
| 9 | **他者答复不带时间维度** | 用户明说"时间维度不做" |
| 10 | **过程记号走五步**（①表示 ②记号 ③引擎 ④Hypo 栈 ⑤分支循环） | §6.56 定序；**①②③ 已落地**（§6.70/§6.71），④⑤ 未做 —— 步骤扁平（无对象/条件）是当前的设计边界 |

## 四、已知陷阱（写代码时避坑；照抄 audit §C + 本会话新增）

| 陷阱 | 症状 | 规矩 |
|---|---|---|
| **原语层按"下标"引用 `TOKEN_OPS[]`** | 新行为插在表中间 ⇒ `IPOP_COLLECT_TEMP` 指到别的行为上（`[原语:回收临时]` 变成建过程） | **新行为一律追加到表尾**；看护把 `IPOP_*` **每一条**都钉住（§6.70） |
| **dash 双引号里的反引号** | 被当命令替换 ⇒ 语法错/消息被吃掉 | 说明文字用「」不用 `` ` ``（本会话踩 4 次） |
| **断言 grep 到自己的帮助文本** | 假绿（`思考对象`/`轮中打草稿`/`退回分支起点换一条` 都踩过） | 判据挑**只可能来自痕**的字符串 |
| **C 级测试假设默认档** | 反向测量假红 | 测试自己钉开关（`tnew()`）或按 env 分叉 |
| 分词器会切开多字词 | `喜爱`→`喜`+`爱`，别名/触发表看不到 | 多字词要先是词表 token；用连写匹配 |
| `ai_load_file` 不调用 `ai_new` | 新开关在读盘路径是 0 | 开关集中 `ai_switches_init()`，两条路都调 |
| `-Werror=format-truncation` | 小缓冲收长名字编译失败 | 有界手写拷贝，别 `snprintf("%s")` |
| CLI 的 `cmd` **已去掉 `::`** | 参数偏移算错 → 命令静默无效 | 按 `cmd[命令名长度]` 判空格（`::proc` 踩过：写成 6 拿不到参数） |
| 内核意图是 **const** | 想改 `m->main` 编译不过 | 用局部变量（如 `Token *Mn`） |
| **"拆直连"会拆结构** | 给过程的某一步挂前提时，`加前提` 顺手把步骤边拆了（过程少一步） | 结构边要进 `micro_edge_removable` 的"不可拆"那一侧（§6.71）|
| **一条边只能挂一个记号** | 条件挂步骤动作 ⇒ 覆盖步骤边；挂 `[步骤:N]` ⇒ 和回边撞车（§6.73 两次实测） | 要同时表达两件事就把第二件写进**记号名**（`[回边:条件词]`），别另挂一条边 |
| 同一件事**两处判据** | 主循环放行的步，回边重跑时按另一套判据判成断点 | 抽成一个判据函数，两处都调（§6.71）|
| `char[4][40]` 不能当 `char**` | SEGV | 建 `char *argv[4]` 真数组 |
| UTF-8 **字节位置**当字符位置 | 插/删把汉字劈开 | 用 `note_utf8_off` 这类字符级偏移 |
| `gcc ... \| head` | **错误被吞**，旧二进制照跑 | 先看退出码；第 0 步的探针门别绕过 |
| 清 `_t/` 里的活动日志 | 正在跑的整轮白跑 | 跑之前先确认没人写 |
| `env "$A B"` 对成对开关 | 只当一条赋值 | 用 `env $A $B`（不引用） |
| 循环里跑被测脚本 | stdin 被吃光，只跑第一个 | `< /dev/null` |
| 反复跑整包 | 一轮几分钟变几小时 | 迭代跑单套；整包只在收尾 |
| 两个 `all.sh` 跑重叠 | 共用 `_t/par`：抢任务、互删沙箱 | `_t/par/.lock` 并发锁（撞上 exit 3）|
| **被回收的跑法留下死锁** | `... &` 起的整包随命令退出被收走，锁留在那儿 ⇒ 后面每次都被"另有一个在跑"挡住（提示是骗人的） | 锁里记 pid，`kill -0` 判死锁自动清（§6.71 顺带修的）|
