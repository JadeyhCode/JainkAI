## 〇、先读这一节（30 秒看懂这份文档）

**这是什么项目**：一个用 C 写的"AI 内核"实验 —— 记忆是**图**（词＝节点、关系＝边），
推理是**图上求解 + 验证**，思考是**逐步在图上走**，写入走一条"提议 → 审查 → 记账 → 应用"的
受审通道。所有能力都有回归看护（`tests/`）；所有"还没做到"的地方都**照实写下来**，就是本文。

**这份文档怎么用**（三种读法）：
- **只想快速了解"它现在行不行"**：读下面的「只读十条」。
- **读某条时卡在术语上**：查「〇之二、术语与代号表」（每个词一句话白话）。
- **想挑一件活干**：看「〇之三、解法速览」（按"能不能现在做"分三档）。
- **想自己确认一条**：看「五、怎么自己验证一条局限」（可直接粘的命令，含"改了什么看哪一节"）。

**这份文档的立场**：**不吹**。每条局限都写清"现在到什么程度、卡在哪、想复现看哪一节"。
已经修掉的**不删**，划掉并注明改到哪一节 —— 因为"这条还在不在"本身就是信息。

### 只读十条（如果只读十条，就读这十条）

1. **最大的瓶颈是语料，不是代码**：图上的边是"一起出现过"的共现，**没有语义类型**；
   语料里没出现的结论，它推不出来（§一.1）。
2. **它"听懂"靠关键词表，不是理解**：「条件/塞/搭/词儿」这类说法能认，
   别的话就掉到"我不太懂"（§一.2）。
3. **思维一轮最多退 2 次、深度 1 层**（回溯只有"改问反面"一种换法；§一.4）。
4. **他者视角只有一张表**：每人只留**最新一版**极性，"他上个月说 A、这个月说 ¬A"看不出时间（§一.5）。
5. **时间只有区间**：首次/最近 + `[时刻:]` 标记；没有"同时/先后不明/因果时序"的判据（§一.6）。
6. **情绪四个状态量其实只有一个自由度**（都是"我最近猜得准不准"的函数），用户裁定不进内核（§一.7）。
7. **不是所有写入都过安全内核**：感知共现、内部对话、想象等仍**直写**（只有账 + 可选路由，§一.9）。
8. **它不会写代码**：代码闭环只会两类修法、最多改一次、不生成代码（§一.10）。
9. **帧/检索接管之后，元认知/想象/叙事那一段走不到**（实测 `叙事=0`；§一.11）。
10. **看护也有洞**：`selfcheck` 只覆盖三类机械可判的坑，"永不红的断言"仍靠人（§一.12）。

## 〇之一、别误会（三条最常见的误解）

| 你可能会以为 | 其实是 |
|---|---|
| "它是个聊天机器人/大模型" | 不是。它是**一个 C 写的图 + 求解器 + 验证器**：回答是"在图里找到一条链"的结果，没有神经网络生成（embedding 只用来算相似度） |
| "它有记忆库，会把对话存起来检索" | 不是。它存的是**图**（词与关系 + 命中次数 + 角色），没有"会话记录/向量库"；对话里说的东西只能通过"学成边"留下来 |
| "它自己能想明白并改自己" | 只能**在受审通道里**改（提议 → 审查 → 记账 → 应用 → 审计），而且**不是所有写入都走这条路**（见「一、能力边界」第 9 节）；"想明白"= 在图上走 + 独立复核，复核不过就报缺口 |

**还有一条**：这份文档里"**局限**"不等于"bug" —— 很多是**取舍**（「二、设计取舍」那一节列了 10 条），
写进来是为了让人知道"为什么现在是这样"，不是催人去改。

| **干跑（dry）** | 过程执行的一种模式：**不真做**（行为不执行）、不成立的前提**假定成立**（记进假设层），跑完把假设层清干净 | `::proc dry on` + `::proc run X` |

## 一、能力边界（做得到什么、做不到什么）

### 1. 语料与知识（用户点过：**核心瓶颈不在代码，在语料**）

> **白话**：它脑子里那张图是靠"读语料"长出来的。语料里没写过的事，它推不出来；
> 语料里写过的，它也只记住了"这些词常一起出现"，没记住"它们是什么关系"。

- **边是纯共现，没有关系类型**：边只有 `role/topic/pattern` 三个位置性标签；`frames.txt` 里
  0 处关系标签。→ audit §一.❌1
  - **解法**：关系位现在是「清单 + 掩码」。要让**边自带类型**有两条路：① 生成语料时给行打关系标签（`relations.txt` 已有几百条，语料行没有）② 把关系槽换成可学习的一格（动边布局 ⇒ **要拍板 + 重训**）。**先量**：语料里有多少行标得出关系。

### 2. 语言与理解

> **白话**：它是靠**认说法**（关键词表 + 词法规则）来听懂你的话的，不是靠理解句子。
> 你的说法不在表里，它就回"我不太懂"——这类洞下面逐条列着。

- **对话触发仍是关键词表**：能认说法，不是"懂话"（`条件/塞/搭/词儿` 能认，其余听不懂）。
  **§6.86 起有一条通往求解器的路**：开放式关系问句（`A R 什么` / `谁 R B`）能走求解器

- **分词器会切开多字词**（`喜爱`→`喜`+`爱`）：别名表、触发表、词表查询都会因此"看不见"某个词。
  **§6.84 量清楚了**：分词器本来就是**池内最长匹配**（探针 18/27 整词），切开的词**全是池里没有的**
  ⇒ 缺口在**词表覆盖**；现在有数据入口 `lexicon.txt`（+ `lexicon.example.txt`）。
  **剩下的**：同句里的新词仍会被切开（词表要事先写好）；词表是平表（无词性/权重）。→ §C 陷阱、§6.84
  - **解法**：① 词表补词（最稳）② 分词器加「已知词优先/最长匹配」（`tokenize` 一处）③ 短期兜底：匹配时认**前缀**（过程记号已经这么做）。
- ~~合写否定的残余：`不能/没法` 掉降级答复~~ **已修**（§6.74③）：`REL_MODALS[]` 情态说法表

  别的情态（未必/恐怕/免得）没进表。→ §6.74 局限
- ~~`subs_not[]` 语言层没有原语~~ **结案**（§6.78 核查：v10 删掉语境字段后机制已退役，

### 3. 推理

> **白话**：推理是"在图上找一条链，再拿验证器独立复核一遍"。链找得到就答，找不到就说不知道；
> 但它只会在**已经写进图的关系**上推，不会自己发明关系。

- **只有关系推理走"链是一等公民"那条路**；推测置信度是**拍的**；不支持反事实（反事实后来有了假设世界，
  但"如果…会怎样"的推理仍窄）。→ §6.13
  - **解法**：把「链」推广到别的判定（前提/时间/他者）：每一条都要一个 `Derivation` 构造器，**一次一条**地做。
- **完备性靠手写**：独占公理最初是手写的，后来改成"量出来的"（§33.1），但**仍不是"没写就算假"**——
  开放/闭合世界开关是**人的选择**，不是模型判断。→ §6.15、§33.1
  - **解法**：把「独占」从「量出来的统计」再往前一步：按宾语分布自动判单值/多值（`::stats` 的关系独占表已经是这个），阈值可以量、有看护。
- **假设下的结论**：~~被当垃圾丢掉~~ **§6.118 起沉淀成条件缓存**（`A —[前提]→ P`，P = **整栈假设指纹**；
  栈一撤自动失效；默认关 `::hypo cache on`）。~~仍缺：升格~~ **已做**（§6.119：撤了假设 + 无条件推得出（含"用户后来教了"）⇒ 摘掉前提、升格为普通推论；

  - **解法**：加「句法位置/顺序」判据（D4 现在只用同轮共现）；或把 `::op 加前提` 的人工复核做成半自动（入口已经有了）。

  ⇒ 所有靠猜的推导都过不了 `der_verify`）；`rel_guess` 同时放宽（不再硬性要求 emb；同上位兄弟算硬证据）。
  **仍缺**：CLI 答复层的联想走不到出口（思维层已能推出并标"类比猜的"）——下一步定位答复那一层。
  原话（§6.113 那次的记录）：~~只在思维层的「借最近邻」里~~ **§6.113 起也在求解器里**（同类互推给"标了 guessed 的"

  - **解法**：把求解器里「规则不行时」的分支接上类比兜底（一处分支 + A/B；会影响置信度，要量）。

### 7. 情绪与内生状态

> **白话**：舒适/唤醒/疲劳/不适这四个量是手写公式算出来的，而且实测**高度共线**

  ⇒ 留在层里当已知局限；后来加了两个**派生**维度（`好奇`=图里的缺口感、`亲近`=信任×互动）。→ §A.5、`drive.h:50`
  - **解法**：① 继续加**独立来源**的维度（已在做：好奇=图缺口、亲近=信任×互动）② 把耦合矩阵对角化、只留主成分（省字段、行为不变）。
- **内部动力学手写**（疲劳 +0.001、舒适=预测准确率线性）；`setpoint` 只用于 drive bias。→ §B.7
  - **解法**：把常量变成「可被反馈校准」的参数（学习率调小 + 默认关 + A/B；底线仍写死）。
- 元认知/内生状态**只在非帧、非检索的输入上显形**（被帧或检索接管时不涨）。→ §一.✅5/6 的注解

### 8. 记忆与持久化

> **白话**：记的东西能存盘再读回来（格式 v10），但**存盘格式不许动**是铁律 ——
> 所以有些数（比如"撤回过多少条缓存"）重载后恢复不了，下面写清楚了。

- **推论档后验偏乐观**：`n_cached` 语义变窄；~~`n_retracted` 重载恢复不了~~ **已修**（§6.78：
  撤销时留 `[撤销:A|R|B]` 标记，`ai_recount_evidence` **从图里数回来**——旧档那些仍恢复不了）。→ §A.6
  - **解法**：让「撤销」在图上留痕：撤销时写一条 `[撤销:…]` 标记节点 ⇒ `n_retracted` 能从图里数回来，**零格式改动**（`[修正:…]` 已有先例）。
- **临时 token 不存盘**（设计）：草稿区随进程走（`[草稿:…]` 是持久的那一半，§6.103）。
  **§6.110 起存档 = v11**：N1 思考对象**摘要**也存盘（结论/缺口/复没复核；推导链仍不存）。**过程记号是普通 Token + 边（role/记号都序列化）**，
  所以结构**跨会话**（`::load` 之后 `::proc` 看得见、`::proc run` 跑得动，§6.71 已证）；
  但"执行结果"不进存盘（轨迹是内存里的 `Derivation`）。→ §6.70、§6.71、记事本 doc 172
  - **解法**：要存就借「标记节点」落到图上（`[草稿:…]` 那套），而不是加格式字段。
- **存档格式不动**是纪律（现 v10）⇒ 任何新能力都得挤进既有字节（role/topic/pattern 是常被借用的地方）。
  - **解法**：新能力优先借 `role/topic/pattern` 的余量（`ASSOC_ROLE_*` 还剩 250 个值）；真要加字段 ⇒ 用户拍板 + 版本号 + 迁移。

### 9. 写入与安全（内核）

> **白话**：任何"改自己脑子"的动作都要走同一条受审通道（提议→审查→记账→应用→审计）。
> 但**不是所有写入都搬过来了**：感知共现、内部对话等仍直写，只有账；这条是当前最大的安全缺口。

- **老写入者还没全搬到队列上**：~~内部对话、想象~~ **已修**（§6.77：两类自撰写入接上
  `ai_write_assoc`，`route_writes` 打开时受审）；**仍直写**的是感知共现（观测）、睡眠/衰减、
  自模型锚点、时间线链（结构/协议骨架）。→ §B.2、§6.77、`microkernel.md` 局限 1
  - **解法**：① 感知共现 = **观测**，不该受审（保持直写）② 睡眠/衰减是派生量，可以从图重算 ⇒ 不写最省 ③ 自模型/时间线是**结构**，要单独一条「结构写入」通道（不是知识闸门）。
- **路由只覆盖关系事实一类**（感知共现刻意直写，`::safe` 写明理由）。→ §B.2
  - **解法**：已扩到 `ai_write_assoc`（K6）+ 自撰写入（§6.77）；剩下的见上一条。
- ~~写入闸门判别力窄（一个阈值切不动）~~ **部分已修**（§6.89：`::wgate tier` 分层判据 —— 硬门槛 +
  高档直放/中档要旁证/低档拦；默认关，双跑法全绿）：实测重要度落在 0.587–0.725，阈值 0.65/0.70 只切掉 24%/4.2%；
  `imp` 公式里 `Δ²D/Δ²T` 是拿"惊讶/不累"**替代**的（不是同一个东西）。→ §A.7
  - **解法**：① 把 `imp` 从「加权和」改成**分层判据**（先生词/来源硬门槛，再分数）② 用 `tests/meas_wgate_cand.sh` 重标定阈值并再量分布 ③ 已加「链长/链底」（§6.67）⇒ 再量一次判别力。
- **过程记号**：①② 落地（§6.70）、**③ 写引擎落地**（§6.71：`::proc run` 逐步核对 + 受审执行 +
  断点）。剩下的：**v1 判据只到"现在过得去"**（词在 + 前提成立 + 行为跑得成）——
  **"这一步做不做得了"不判**；步骤是**扁平的**（没对象/条件）⇒ 逐条 `der_verify` 独立重推**还没接**
  （留给 ⑤）；行为步骤**不能带参数**（不猜）；调用只跑 `[过程:…]` 子过程；回边只认步号、迭代 ≤2、
  一次跑 ≤64 步；顺序只认 `[步骤:N]`（改号不重排）；`加回边 <动作词>` 会和那一步共用一条边；
  根上有一条"挂靠边"；`::proc` 一次最多列 256 条边。→ §6.70、§6.71 局限
  - **解法**：剩下的都在「新记号」这一层：① 多条否则/异常 ⇒ 约定「每支一个不同端点」（`[否则:2]`、`[异常:类型:2]`）② 顺序只认 `[步骤:N]` ⇒ 想重排就加一个「重排」行为（走受审通道）。
- **④ 干跑的假定只到"前提成立"这一种**（记的是 `(动作, 需要, 前提)`）："假定某个**对象**存在/
  某个**条件**为真"要等 ⑤（步骤带对象/条件时才有三要素可假定）；假定**不进图、也不进推理**；
  干跑**不执行行为** ⇒ 不会有真实副作用、也不会发现"执行到一半才炸"；
  **假设层只有 4 层**（主过程 + 3 层调用，到顶就明说"假定没地方放"，不假装假定过）；
  按步回退只在"这一步失败"时触发（步子成功时假定留给后面的步用，整轮跑完一起 pop）；
  干跑的"核对"只是 `hypo_find` 复核（假设还在不在层里），**不是**"这一步在世界上成立"。→ §6.72 局限
  - **解法**：步骤带对象之后（§6.74 `加断言`），「假定某个对象存在」可以记成同类事实 ⇒ 把 `加断言` 的对象槽接进干跑的假定里（一处 + 看护）。
- **⑤ 分支/循环/异常**：**一条边一个记号**是硬约束 ⇒ 条件不能和步骤同挂一条边（用回边记号绕过）、
  `[异常]`/`[否则]` 各只能有一条（v1 只跑第一条）；**条件判据 = 前提判据**（没有独立求值能力，
  数值比较那类"真条件"要先有求值层）；**异常不按类型分派**（类型只是标签、只跑一次）；
  **循环只有 while 形态**（回边+条件+迭代上限 2，没有 for/break）；**分支没有 if-elif 优先级**
  （多条条件边逐条各自判）。→ §6.73 局限
  - **解法**：① 条件/否则/异常各只有一条 ⇒ 用「带序号的记号名」解决 ② 条件判据=前提判据 ⇒ 要真条件得先有求值层 ③ 循环只有 while ⇒ for/计数循环可以加「回边次数上限」参数（现在是常量 2）。
- ~~过程不跨会话~~ **已修**：①② 的结构/role/记号本来就在存盘里，③ 的引擎让第二个会话
  `::load` 之后 `::proc` 看得见、`::proc run` 跑得动（§6.71 证据）。→ 原 §6.70 局限
- **`ai_new` / `ai_load_file` 的历史常量默认值两份**（后加开关已集中到 `ai_switches_init`，
  历史那批待合并）。→ §A.9
  - **解法**：把历史那批也搬进 `ai_switches_init()`（机械改动 + 逐字节 A/B）。
- 自修改**不能改自己的底线**（安全内核的阈值写死在一侧）——这是刻意的，不是局限。

### 10. 代码 / 动作 / 外部世界

> **白话**：它能**跑**外面写好的程序、看报错、按规则改一两处（受审、有白名单、有超时），
> 但它**不会自己写代码**，也没有通用的"调工具"接口。

- **代码闭环是降级版**（**§6.96 起有"生成"了**：`::proc gen <过程>` 把过程翻译成原语程序 +
  干跑校验 +（可选）受审执行；仍然只翻译**原语**不生成 C，循环不翻译）：~~只会两类修法~~（§6.97 起**三类**：补分号/补 `#include`/补声明）、~~不生成代码~~（§6.96 起能生成**原语**程序）、~~最多改一次~~（§6.97 起 `::code multi on` 可**最多三轮**）、
  编译命令固定、产物落在 `_t/work/`。→ `code.h:21`
  - **解法**：① 扩 `code.h` 的规则表（编译器输出 → 修法）② 允许改 N 次（默认关 + A/B）③「生成代码」要先让语言层能**生成**（远）。
- ~~没有通用动作接口~~ **部分已修**（§6.82：`[执行:动作词 参数…]` 动作 token + `::op 加执行` +
  过程执行槽 ⇒ 过程步骤能**真的调**白名单动作，rc/理由进痕与账）。**剩下**：动作的**输出**
  还没被当成观测写回图（`g_act.last_out` → 观测，下一步）；参数不解释引号/转义；
  动作失败就是断点（不重试/不回滚，交给 ⑤ 的异常支）。原文：「我做了什么 → 世界变了」这条
  因果链**不存在**，系统不会主动调外部程序
  （`action.h` 是受审的白名单执行，不是通用工具调用）。→ §二.❌7
  - **解法**：现成件已经够拼：`action.h` 是受审的白名单执行 ⇒ 把它做成「动作 token」（走 `::op` 表），过程步骤就能调它（受审 + 有账）。
- **过程的"执行"只到"核对 + 受审执行"**（③ 已落地，§6.71；§6.82 加了动作执行槽）：能判"现在过得去/哪儿断"，能真执行
  `min_args==0` 的 Token 行为；但**对外部世界产生效果**（行动/工具调用）仍没有通用接口
  ⇒ "计划 → 真的改变世界"之间还断着（和"没有通用动作接口"同源）。→ §6.71、§二.❌7
  - **解法**：步骤加一个「**执行槽**」指向白名单动作（`加断言` 已经有对象槽，照它的样子加一格）⇒ 执行就从「核对」走到「真的调动作」。

### 11. 对话与输出

> **白话**：回答有几条通路（帧/检索/联想/推理），谁先接管谁说话。
> 一旦被"帧/检索"接管，后面那一段（元认知、想象、叙事…）就跑不到了 —— 这就是下面几条的由来。

- **帧/检索接管之后，后面那一段（元认知/想象/内部对话/叙事/漂移）走不到**：
  实测长时间非帧输入下 `想象=1 内部对话=20`，而 **`叙事=0`**（要 500 轮且路径没被接管）。→ §二.⚠️4/6
  - **解法**：把元认知/想象/内部对话/叙事那几段改成**轮末无条件跑一次**（一处结构调整 + A/B；代价是每轮多花时间）。
- **`::notepad on` 会替掉流水线措辞**（已改成"待验"式措辞）；**`manual` 模式默认关**（默认 auto = 行为不变）。→ 五个局限 2、记事本 doc 170
  - **解法**：措辞已改（「待验」式）；`manual` 默认值是**取舍**，要改就拍板（默认 auto = 行为不变）。
- **输出侧补丁的边界**：缓冲**不持久化**（`::save` 不存草稿）；`改`/`改发言` **只认单 token**
  （CLI 参数按空格切，替换串含空格传不进去；C 层/语言层没这个限制）；
  "想清楚再改口"**还不会**结合"刚刚那句降级答复到底行不行"。→ 记事本 doc 170
  - **解法**：① 持久化：走 `[草稿:…]` 标记节点（已有）② 多 token 替换：CLI 参数上限已从 4 提到 9（§6.74），再加「引号参数」就能传带空格的串。

### 12. 工具与看护（harness 自己）

> **白话**：测试/看护本身也会骗人（比如"命令的退出码被管道吃掉""断言其实永远不会红"）。
> 这一节记的是**看护自己的洞**，以及已经修掉的那几个。

- **成对开关无法全枚举**（缓解：`SUITES="…" SKIP_BASE=1 ONLY=…`，≈1 分钟）。→ §A.11
  - **解法**：`switches_ab.sh` 生成**组合抽样**（随机 N 组，各跑一次整包）——纯脚本层面可行。
- **"写进 `switches_ab.sh` ≠ 跑过"**：`AIP_WGATE=1` 这一档三个月没人跑，C 级测试里 12+1 项
  一直假红（§6.67 当场抓到）。→ §6.67
  - **解法**：给开关表加「最近一次跑过的时间戳」，整包收尾时检查；或每次整包**随机挑一组**开关跑（把「没人跑」变成不可能）。
- **C 级测试必须自己钉默认档**：`ai_new()` 会读环境变量 ⇒ 反向测量时"默认关"的断言会假红；
  规矩是测试自己 `tnew()`（钉 `write_gate_off`/`route_writes`）或按 env 分叉。→ §6.67
  - **解法**：提供一个统一的测试构造器（`tnew()` 已在 delibtest 里这么做）⇒ 把「钉默认档」收成一处，新测试默认就安全。
- **`selfcheck.sh` 覆盖四类机械可判的坑**（清单/管道退出码/没兜住的 grep/**断言撞帮助文本**，§6.79）（管道吃退出码 / 没兜住的 grep 赋值 / 脚本与清单对不上）；
  **"永不红的断言"仍靠人** —— 它的真实形态是"grep 命中了**帮助文本**而不是痕"（本会话踩到 4 次）。→ §6.66
  - **解法**：可做：先跑一次 `::help` 把**所有帮助文本**抓下来，再检查每条断言的字符串是否出现在帮助里 ⇒「断言 grep 到帮助文本」这类假绿就能机械抓（本会话踩了 8 次）。
- **整包时间**：并行 32 套 + 冒烟**实测 ≈ 46 s**（套件相位 20~29 s；audit §C 记的是 ≈70 s ——
  机器不同，两个数都对；串行仍 ~6 分钟）⇒ 纪律是"迭代跑单套、整包只在批次收尾跑"。
  - **解法**：已并行；再快就按改动面选套件（`SUITES=` / `ONLY=`），或把「只跑受影响套件」做成一张映射表。
- **探针/编译门**已修（26 探针 `-Werror` + 4 个跑出结论进第 0 步），但"探针改了 API 忘了改"
  这类错误只能靠这道门拦，别再绕过它。→ §A.1
  - **解法**：保持第 0 步**不许绕过**（它是唯一拦住「探针改了 API 忘了改」的门）。

## 五、怎么自己验证一条局限（命令可直接粘）

> 这份文档里的每一条都**能自己验**，不用信我。下面按"想验什么"给命令（都在仓库根跑）。

**先编一个（约 20 秒）**
```sh
gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror -o build_aip main.c -lm
```

**验一条"对话能力"的局限**（例如第 2 条：触发只认关键词表）
```sh
printf '::load model.bin\n::notepad off\n把这个词加进去\n::quit\n' | ./build_aip
printf '::load model.bin\n::notepad off\n帮我把这个词加进去\n::quit\n' | ./build_aip   # 换个说法：多半"听不懂"
```

**验"图里有什么"**（例如第 1 条：边只是共现、没有语义类型）
```sh
printf '::load model.bin\n::edges 猫\n::quit\n' | ./build_aip | head -20
```
看到的是"→ 某某   hits=N 角色=X 动作=Y 来源=共现" —— `来源=共现` 就是"没有语义类型"那句话的证据。

**验某个能力开关（默认关）开着与关着的差别**
```sh
printf '::load model.bin\n::proc\n::quit\n' | ./build_aip            # 关着：给提示
AIP_PROCRUN=1 printf '::load model.bin\n::op 建过程 试\n::op 加步骤 试 烧水\n::proc run 试\n::quit\n' | ./build_aip
```
（开关清单在 `deepseek看这里.txt` 顶块「四、当前状态」；`::help` 里也有对应的 `::xxx on|off`。）

**验"某条局限还在不在"**（看护是怎么钉的）
```sh
sh tests/tokenop.sh        # 过程记号/执行/对话入口那一套（约 10 秒）
sh tests/relations.sh      # 关系层：合写否定、情态说法
sh tests/thinking.sh       # 思维循环：回溯/空闲/思考对象
```
每条断言的**原话**就在 `tests/*.sh` 里（`grep -n '那条断言的中文' tests/*.sh`）。

**看"当时是怎么量的"**（探针，不是断言）
```sh
sh tests/probes_build.sh   # 把 26 个探针编一遍（量闸门分布、前提有据度…）
```

**跑整包（≈46 秒，32 套 + 冒烟 + 自检）**
```sh
sh tests/all.sh
```

**看某一轮到底改了什么**（每条局限的出处）
```sh
grep -n "### 6.74" docs/audit-vs-deepseek看这里.md     # 换成你要找的编号
git log --oneline | head -20                            # 提交信息里通常也写了"这一轮干了什么/局限"
```

**如果哪条你验出来"其实没这个局限"或"比写的还严重"**：把它记进本文对应条目的"白话"那一行，
并注明日期 + 你用的命令 —— 这份文档的价值就在"如实"，不在"好看"。
