# 行为模块完善计划（为"语言模块下沉到图与语料"铺路）

> 用户的路线（原话）：**「完善逻辑和图里的行为模块，完善到一定程度以后可以把语言模块下沉到图和语料里」**。
> 这份文档记：现状、缺口、顺序、验收标准。**每做完一项就在下面的表里打勾并写 §6.x 编号。**

## 1. 现状（代码里已经有的"行为"）

| 层 | 在哪 | 能表达什么 |
|---|---|---|
| 符号节点**行为表** | `micro.h` `TOKEN_OPS[]` | 加前提/加反前提/前提接线/中间插词/回收临时/调用补丁/建过程/加步骤/加调用/加回边/加条件/加否则/加执行/加断言/加异常 |
| **过程执行引擎** | `agent.h` `proc_exec`/`proc_run` | 按步号跑、条件分支、否则支、异常支、步骤上限、调用、回边（while）、干跑/实跑、执行栈与假设层 |
| **判据** | `ai_premise_holds` + 求值层 `ai_eval_cmp` | 三档：注意窗口里 / 图上够得着 / 够得着且有据；数值比较（默认关） |
| **受审通道** | `mod_propose` → 安全内核 | 预算/底线/审计；`::op` 与系统自动修改**同一条路** |

## 2. 缺口（语言模块下沉需要、现在还没有的）

| 编号 | 缺口 | 为什么语言下沉需要它 | 状态 |
|---|---|---|---|
| B1 | **条件组合**（与/或/非） | 语言里的"如果 X 且 Y ""除非 X"都是合取/否定；单原子不够 | ✅ §6.507 |
| B2 | **条件引用同一步的断言结果** | "若 猫 属于 动物 则…"需要把 `加断言` 的结论喂给条件 | ✅ §6.508 |
| B3 | **过程参数/绑定** | 问句里的实体要传进过程（`[执行:查 猫]` 现在只能写死） | ✅ §6.509 |
| B4 | **答复模板也是行为** | 现在答复在 `[reply]`/形状里；要让行为能"拼一句答复"（同一受审通道） | ⬜ |
| B5 | **语言规则以数据形式进图** | 问句识别/外壳剥离现在是代码 + `[shape]`；目标是**同一张行为表能表达"匹配—改写—答复"** | ⬜ |

## 3. 顺序与验收

1. **B1（已做）**：`A&B`/`A|B`/`!A`，原子判据不变，判不了**不静默当成立**。
   验收：`tests/tokenop.sh` 四项（与/或/判不了/恒真恒假），45 套件全绿，blind4 448 不变。
2. **B2**：条件可以引用"本过程内某一步断言的结果"。验收：新开一节 tokenop 用例 + 干跑可复现。
3. **B3**：过程参数绑定（`[参数:a]` 占位，跑时按调用实参替换）。验收：一条过程被两个不同实参调用，结果不同。
4. **B4/B5**：把"语言模块"的某一小块（先挑**外壳剥离**）改写成行为 + 数据，A/B 对照证明**逐字节等价或更好**。

## 4. 纪律（沿用本仓库既有规矩）

- **不改默认行为**：新能力先默认关（或只在显式路径生效），再用"反向测量"打开跑一遍；
- **证不出正例就不留在树上**：每项必须有"改动前写"的验收用例；
- **量尺优先**：任何改动若让 blind4/pert/blind5 掉，一律回退；
- **行为进表**：新增一种行为 = 表里加一行 + 写展开函数（表尾追加，`IPOP_*` 按下标引用）。
