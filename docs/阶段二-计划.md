# 阶段二：把六个目标落成可执行的步骤（**计划书，不是实现**）

> 状态：**只出计划，不写代码、不扩图**。
> ⚠ 本文里带「（计划）」字样的命令**都还不存在**（`prove`/`paper`/`lang`/`pred`/`dump`）——
> 写在这里是"将来要长这样"，不是"现在就能用"（`tests/selfcheck.sh ⑧` 专门盯着"文档引用不存在的命令"）。阶段三等第三阶段收尾之后才开工。
> 依据：本仓库现有能力（`rel.h`/`derive.h`/`code.h`/`action.h`/`agent.h`/`parts.h`/数据层），
> 每条"现有地基"都指明文件；"缺什么"没有夸大。
> 你的六个目标（原话）：① 图足够大时支持**复杂逻辑**；② 现场**搜并读论文**；③ 现场**学一门新语言**；
> ④ **不随随便便就信**论文和用户说的话；⑤ 会写**复杂逻辑代码**；⑥ 会根据**已有条件证明新东西**。
> 全部建立在"**图足够大**"这个理论前提上。所以本计划的第一步不是写功能，而是**把"图足够大"变成可测量的门禁**。

## 0. 约束与前提（先钉死，免得后面打架）

| 约束 | 含义 | 影响 |
|---|---|---|
| **不扩图** | 不加新的存储结构（不换数据库、不加大向量、不批量灌语料） | 所有能力只能用**现有的 token + 边 + 数据文件**（`patterns.txt`/`frames.txt`/`relations.txt`）编码 |
| 图"足够大"是**前提**，不是本轮任务 | 现在不训练、不灌数据 | 计划里每个能力都给**双档判据**：小图能验证"逻辑对"、大图才验证"撑得住" |
| 外部世界只能走**受审通道** | `action.h` 白名单现在是 `echo/cat/wc/gcc/grep/head/tail/ls`，**没有网络** | "搜论文"必须走**新增白名单 + 配额 + 沙箱**，且单独一轮做（WP4） |
| 一句话原则不变 | "**说得进、问得出、说得清、改得动**" | 每个 WP 的判据都要覆盖这四条，不能只测"能跑" |

**不扩图的边界（写死，避免偷换概念）**：
1. 不新增 `AI` 里的大数组（除非 ≤1KB 且登记在案）；
2. 不改 `model_io.h` 的**主结构**（允许像 v15 那样在尾部加**可选段**，但要能读旧档）；
3. 不引入第三方库（PDF/HTTP 都用系统命令或自己写小解析，否则"单头文件"这条线就断了）；
4. 不做"批量语料灌图"——那是**第三阶段**（图扩张）的事，本轮明确不做。

## 3. 落实计划：8 个工作包（WP）+ 5 个里程碑（M）

> 每个 WP 都写：**做什么 → 最小实现路线 → 判据（可跑的命令/套件） → 依赖 → 轮次估计 → 风险**。
> 轮次估计按"一个 autonomus round = 一次提交"的口径，含写代码+套件+审计+文档。

### WP0（M1 前置）：把"图足够大"变成**可测门禁**

- **做什么**：定义三档规模 + 每档的硬指标，写成 `tests/scale.sh` 与 `docs/规模门槛.md`：
  | 档 | token 数 | 边数 | 规则条数 | 单次 `prove`（计划）深度 5 的时限 | 常驻内存 |
  |---|---|---|---|---|---|
  | S（小，现役） | 1.2k | 4.1 万 | 18 | 50 ms | 60 MB |
  | M（中） | 5 万 | 200 万 | 500 | 100 ms | 600 MB |
  | L（大） | 50 万 | 2000 万 | 5000 | 300 ms | 4 GB |
  （**数字待你拍板**，见第 7 节问题 4。）
- **怎么造"大"**：**不灌语料**——用 **合成图生成器** `tools/mkbig.c`（造 token + 规则 + 随机事实，
  不写语义），只用于压测/索引验证，**不进 model.bin**、不进 git 的历史资产。
- **判据**：`sh tests/scale.sh S/M` 打出实测表格；M 档下 `prove`（计划）、`::contradict`、`::rel X` 都有时限内的结果；
  超时/超内存要**明确报错**，不许静默降级。
- **依赖**：无。**轮次**：1–2。**风险**：合成图不能代表真实分布（写进局限）。

### WP1（M1）：谓词化 —— 把三元图变成"谓词 + 参数"（不扩图）

- **做什么**：用**现有节点与边**编码多元谓词，例如 `敌人(A,B)`：
  - 谓词节点 `[谓词:敌人]`（沿用 `[原语:]`/`[过程:]` 的内部命名空间约定）；
  - 参数节点 `[参数:0]`、`[参数:1]`（或用 `role` 字段标序，`AssocEntry` 已有 `role/topic/pattern` 字节）；
  - 一条谓词实例 = `[谓词:敌人] --[参数:0]--> A`、`--[参数:1]--> B`（**复用现有的边**）。
- **最小实现路线**：① 写 `pred.h`（纯函数：`pred_make(ai, name, args[], n)`、`pred_read(ai, node, …)`）；
  ② 用 `::op` 的原语通道落地（受审），**不许直写**；③ `pred` 命令列出/查验；
  ④ 与现有三元关系**互操作**：`A 属于 B` 可以看作 `属于(A,B)` 的一元化特例。
- **判据**：`tools/predprobe.c` ≥20 项（造/读/参数序/同名不同元数/存盘重开不丢/与 `::rel` 互不污染）；
  整包不红；`asan`/`tsan` 干净。
- **依赖**：无。**轮次**：2–3。**风险**：`[参数:N]` 会被当成普通词 → 必须在 `micro_internal_ns()` 里登记；
  命名空间一多，"内部节点"的可读性下降（要用 `dump`（计划）工具兜住）。

### WP2（M1）：规则即数据 + 前向/后向链（复杂逻辑的核心）

- **做什么**：
  1. **规则节点** `[规则:R<id>]`，形状用现成机制：
     `前提 = [规则] --[前提:i]--> 谓词节点`、`结论 = [规则] --[结论]--> 谓词节点`，
     变量用 `[变量:x]` 占位（`role` 标记）；
  2. **前向链**：一次扫描把所有能触发的规则跑完（预算：规则数 × 事实数上限，超了**明说截断**）；
  3. **后向链**：`prove <目标>`（计划） 从目标反查规则，深度 ≤ `REL_MAX_DEPTH`（现成常量），失败返回**缺口清单**；
  4. **与现有 R0–R10 并存**：R1/R2 的语义**写成数据规则**（`trans/inherit` 保留为快捷方式，行为不变）。
- **最小实现路线**：先只做**正向（Horn）**：`body` 全为肯定、无函数符号、无等式；变量用**线性模式**（每个变量在 body 至少出现一次）。
  这条限制要在计划里写死（见第 6 节"不做"）。
- **判据**：新套件 `tests/logic.sh`：
  - 经典题 15 条（三段论、传递闭包、父子-祖孙、传递+例外、独占有矛盾、缺前提）**全部给可复核证明**；
  - `prove`（计划）输出**证明链**（每步 rule 号 + 依据），验证器独立复核 100% 通过；
  - **反例**：结论不成立时，明确说"推不出"，并列出"缺哪条前提/哪条规则"；
  - A/B：现有 448/470、215/275 等**不许掉**（规则只增不减要挡住）。
- **依赖**：WP0（预算/规模）、WP1（谓词）。**轮次**：4–6。**风险**：**组合爆炸**——必须有预算与"截断要报告"，
  否则大图一开就卡死；另外要防"自己推出来的东西又被当事实用"（`ASSOC_ROLE_DERIVED` 已有区分，得延伸）。

### WP3（M1）：证明对象与入口（C15/C16）

- **做法**：把 `Proof` 扩展成**可序列化**的证明（步骤 + 规则 + 变量绑定），加：
  - `prove <A R B>`（三元）/ `prove <谓词(参数…)>`（多元）——**命令名待定**，见第 7 节问题 3；
  - `prove --why`（计划）打印每步依据（`proof_text` 已有，扩成多行）；
  - `::contradict` 复用同一套证明器做**反证**：假设 `¬目标`，推出矛盾 ⇒ 目标成立（只有规则集是"确定"时才允许）。
- **判据**：`proveprobe` ≥30 项：证明成立/不成立/未知三态；反证只在"规则可确定"时给结论；证明可**存盘/重开复核**。
- **轮次**：2。**风险**：反证在开放世界**不成立**（现在项目坚持"未知不说假"），必须**显式开关**（比如 `prove closed on`，命名待定）。

### WP4（M2）：来源分级 + `[待证]` 状态机（**"不轻信"的地基**）

- **做什么**：
  1. **来源类别**（进 `AssocEntry` 的 `topic` 或新的一字节 role 子类，不能扩结构）：`用户` / `论文` / `语料` / `自推`；
  2. **可信度**（0–100）：用户教 = 80，论文（未验）= 40，语料 = 60，自推 = 30；`::trust` 从"开关"升级为**阈值**（`::trust set 60`）；
  3. **状态机**：外部来源的断言先记成 **`[待证]`**（不是事实）→ 需满足其一才升格：用户确认 / 与现有知识**交叉验证**（≥2 独立来源）/ 被规则推出来；
  4. **回答纪律**：引用 `[待证]` 时必须说"这是 XX 说的、我还没验证"；`::contradict` 把"待证 vs 事实"单列一栏。
- **判据**：新套件 `tests/trust.sh` ≥20 项：待证不入事实层；升格三条路径各 3 例；降级/撤销；跨会话（v15 存档）保住来源。
- **轮次**：3–4。**风险**：`topic` 那个字节已被语义占用（`::hypo`/话题），要么复用 `role` 的高 4 位，要么在**待证 token** 的名字里编码（`[待证:论文:…]`）——**先做后者**，不动字段。

### WP5（M3）：搜论文 & 读论文（受审、离线优先）

- **做什么**：
  1. **取文**：给 `action.h` 加两条**受审命令**：`curl`（仅 HTTPS、主机白名单、单次 ≤2 MB）和
     `pdftotext`（若系统有；没有就**跳过并明说**）。两者都要**超时 + 配额（每轮 ≤1 次）+ 审计账**；
  2. **离线优先**：仓库内 `papers/` 目录放**几篇小样本**（自造/公开许可），默认只读本地；
  3. **抽取**：把文本切成句子 → 找**断言句式**（"X 属于 Y"、"X 导致 Y"、带数字的结论）→ 用 **WP1 谓词**表示 →
  4. **落地**：全部进 `[待证]`（WP4），并带 `[论文:标题/页码]`；
  5. **用户交互**：`paper read <文件>`（离线）/ `paper fetch <url>`（联网，默认关）——**均为计划中命令**→ 输出"抽到 N 条断言，M 条待证"。
- **判据**：`paperprobe`：3 篇小样本 → 抽出的断言**不编**（原文可对照）；进待证；交叉验证升格 1 条；
  **离线不可用时明确报错**（不假装读过）。
- **轮次**：3–4。**风险**：**抽取质量**是最弱一环（模板只能覆盖少数句式）——计划里把它定位成"**辅助**：抽出候选，用户确认"，
  绝不号称"读懂了论文"。

### WP6（M4）：现场学一门新语言（语言包 = 数据 + 少样本归纳）

- **做什么**：
  1. **语言包**：`lang/<code>/` 三件套（`patterns.txt`/`frames.txt`/`relations.txt`）+ `meta.txt`（词序：SVO/SOV、疑问标记…）；
  2. **装载**：`lang load en` → 换数据层（**不动图**）；`lang list/current`；
  3. **归纳（现场学）**：给 20–40 句**带中文对译**的例句 → 用现有分词器 + 对齐信号（`::ascii` 已有 ASCII 词法）
     归纳：① 高频词表（词↔译义的候选对齐）；② 词序（主/谓/宾位置）；③ 关系词候选（与 `relations.txt` 的中文关系对齐）；
  4. **落成语言包**：归纳结果**写成 `lang/<code>/` 的文件**（人可读、可改），再 `lang load`（计划） 生效。
- **判据**：`langprobe`：两门小语言（一门 SVO 人造、一门 SOV 人造，各 30 例句）→ 归纳后的问答准确率门槛（≥70%）；
  **不给语言包时**要明确说"我不懂这种语言"，不许乱编。
- **轮次**：4–5。**风险**：真自然语言（英/日）**远超**30 例句的归纳能力 —— 计划里只承诺"**人造小语 + 英/日的**极小子集**"，
  并明确"这不是通用翻译机"。

### WP7（M5）：会写复杂逻辑代码（测试驱动 + 多文件 + 预算）

- **做什么**（在 `code.h` 已有"写→编→取错→改一次→再编"上叠）：
  1. **测试驱动**：`::code test <dir>`：先编译并**运行**测试（`gcc` 编出的可执行也算受审命令，要在白名单里加"跑自己编的程序"——**只允许 `_t/work/` 里的产物**）；
  2. **多文件**：`_t/work/proj/` 支持 `*.h/*.c`+`Makefile`（`make` 要进白名单，或用 `gcc` 拼）；
  3. **规格→骨架→实现**：给"输入/输出/约束"的三段规格，生成**骨架**（函数签名+空体+`TODO`），再逐函数填；
     每次只改**一处**并编译+跑测试（预算：≤N 轮，超了停下报告）；
  4. **回滚**：每步先存快照（`git` 不进白名单，就用文件副本），失败回到上个绿点。
- **判据**：`codeprobe`：① 给规格+3 个测试，能跑到全绿；② 故意给错规格，能停在"测试不过"并说明；
  ③ 多文件工程能编过；④ 预算耗尽要报告，不无限重试。
- **轮次**：4–5。**风险**：**这是六个目标里最容易"看起来行、其实靠人兜"的**——必须用"测试全绿"当唯一判据，
  不接受"编过了"。

### WP8（贯穿）：长链验收 —— "论文→断言→待证→证明→代码"

- 一段剧本：读一篇小样本论文 → 抽 3 条断言（待证）→ 用户确认 1 条 → 规则推出新结论（WP2）
  → 用结论写一个 20 行的小程序并通过测试（WP7）→ 全程可 `::src` 追溯来源。
- **判据**：`e2e_paper.sh`（新）≥15 项；任一步失败要**说清断在哪**。

## 6. 不做清单（明确的"不"）

1. **不扩图**：不加向量库、不做批量语料训练、不做分布式（那是第三阶段/另一个项目）；
2. **不做全量自然语言理解**（翻译机/语义解析）：只做"少样本、带对译、可人工修正"的语言包；
3. **不做自动化定理证明器**（不实现归结/DPLL/合一的全套）：只做**Horn 规则 + 线性模式 + 有界深度**；
4. **不做"自动读懂论文"**：只做"抽候选断言 + 待证 + 人确认"；
5. **不做网络爬虫**：`curl` 只在白名单主机、单次单请求、明确配额；
6. **不做代码生成器**：只做"规格→骨架→按测试修"，不承诺"从零写出程序"；
7. **不做"论文说的就信"**：所有外部断言默认 `[待证]`（G4 就是这条的机制）。

## 7. 需要你拍板的问题（这四条会改计划，请先定）

1. **联网吗？** `paper fetch` 要不要真联网（`curl` 进白名单 + 主机白名单）？还是**只做离线论文包**（更安全、可复现）？
2. **"新语言"指什么？** ①人造小语言（SVO/SOV 各一门，30 例句）②英语极小集（100 词 + 3 种句式）③日语（SOV，助词）？
   —— 这决定 WP6 的判据和轮次。
3. **证明要多"强"？** 只要 **Horn + 单调**（可解释、可复核、开销小），还是也要**非单调**（例外/缺省推理，例如"鸟会飞，企鹅是鸟但不会飞"）？
   非单调要多 2–3 轮，且会改变 `::contradict` 的语义。
4. **"图足够大"定哪一档？** M（5 万 token / 200 万边 / 500 规则 / 100 ms）还是 L（50 万 / 2000 万 / 5000 / 300 ms）？
   —— 这决定 WP0 的压测机器与内存上限，也决定 `parts` 局部加载要不要重做。
