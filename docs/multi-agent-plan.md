# 多智能体 + 局部加载：路线（用户 2026-10-24 的目标）

> 目标原话：
> 「做到打开多个智能体，每个智能体只维护自己的修改，并且可以暂时只加载一部分图，
>   至于怎么实现，就是指针不是 8 字节对齐吗，不是 0 就是在磁盘或其他地方」

这句话拆成三件**可分别验收**的事：

| 腿 | 要什么 | 目前状态 |
|---|---|---|
| **A 多智能体共存** | 一个进程能开多个 `AI`，互不串台（图、记账、开关） | ✅ 第一刀（§6.564）：两个 `ai_new()` 共存 + 探针钉住隔离 |
| **B 只维护自己的修改** | 每个智能体一本"我改了什么"的账，不是全局共享 | ✅ 第一刀（§6.564）：`AIModLog` 在 `AI` 里、有界环形、记 id 不记指针 |
| **C 只加载一部分图** | 图可以部分在内存、部分在磁盘/别处，按需取 | 🚧 地基就绪（§6.564 的 `ptrtag.h`）；加载器改造未开始 |

---

## 1. 指针标签（C 的地基，已落地）

`ptrtag.h`：`malloc` 至少 8 字节对齐 ⇒ 低 3 位恒 0，塞"东西在哪儿"：

| tag | 含义 | 现在谁用 |
|---|---|---|
| 0 `AIP_PTR_RAM` | 内存里 | 全部旧代码（**默认值 0 ⇒ 接进来零行为变化**）|
| 1 `AIP_PTR_DISK` | 在磁盘（某个区段文件），用时才读 | 未用（下一轮接 `Token.assocs`）|
| 2 `AIP_PTR_ELSEWHERE` | 在别处（别的池 / 压缩块 / 父进程），不是本进程堆 | 未用 |
| 3..7 | 保留 | — |

**三条纪律**（写进 `ptrtag.h` 注释，探针里也钉住）：
1. 只有 8 字节对齐的指针才能打标签（`aip_ptr_taggable`），非对齐时断言而不是悄悄丢位；
2. **读指针前必须 `aip_ptr_strip`**，直接解引用会崩；
3. tag=0 必须与"没打标签"逐字节等价（`aip_ptr_untagged_identity` 有机器检查）。

## 2. C 腿：局部加载怎么接（三轮）

**先说清"不能打在哪些字段上"** —— 这是本轮读代码得出的结论，不是猜：

| 字段 | 能否打标签 | 为什么 |
|---|---|---|
| `Token.assocs` | ✅ 可以 | 本来就是 `malloc` 出来的数组，指针只被"读边"的代码用；有 12 个文件在直接访问（`token.h` 49 处、`ai.h` 49 处…）⇒ **必须先收成一个访问器**，否则无从下手 |
| `Token.name` | ❌ 不行 | 参与 `strcmp`/`strstr` 的地方太多，且存档会写它（存档写的是字符串，不是指针）|
| `Token.emb` | ⚠ 暂不 | 现算的（不进存档），但遍历时直接 `memcmp`，先不动 |
| `TokenPool.tokens[i]` | ❌ 不行 | 数组本体；"某些节点不在内存"要另用一层池级索引 |

**第 1 步（收口）✅ 已完成（§6.565）**：所有 `->assocs` 直接访问收进
`token_assocs()`（可写 / 将来在这里触发按需加载）/ `token_assocs_ro()`（只读视图）——
**171 处搬运，行为零变化**（`probematrix` 28 行 diff 为空）。剩下的直接访问只在
`token.h`（分配）与 `model_io.h`（存盘/读盘/校验）这两个**存储层**，由 `tests/assocaudit.sh` 常驻看守
（新代码一律不许直接摸 `->assocs`）。

**第 2 步（打标签 + 段文件）✅ 已跑通（§6.566）**：`parts.h` 提供
`aip_parts_save / aip_parts_open / aip_parts_attach / aip_parts_detach`：
每个有边的词一段；`detach` 把边 free 掉、指针打 `AIP_PTR_DISK`；`token_assocs()` 碰到标签就按需读回。
探针 `tools/partprobe.c`（第 48 套）证明**只读了一部分**：`n_loads < 被卸下的词数`、`n_bytes > 0`。

**原计划（细节）**：
- 存档旁生成 `*.edges.<k>` 段文件（每 N 个节点的边一段），主文件只留"段索引"（谁在哪一段、什么偏移）。
- 加载时可以只读主文件 + 需要的段；没读的节点 `Token.assocs` 存 `tag=1 + 段偏移`。
- 访问器 `token_assocs(t)`：`tag==0` 直接返回；`tag==1` 触发 `part_load(t)`（读段、挂回、改 tag）；
  `tag==2`（别处/已回收）走 LRU 或拒绝并上报。
- 验收：新增的 **part 命令**（尚未实现）打印"已加载段数 / 总段数 / 触发读取次数"；`probematrix` diff 必须为空（同一份数据）。

**第 3 步（按需回收）✅ 跑通（§6.567）**：`aip_parts_evict(ai, keep, &skipped)` 把**干净**的段换回磁盘
（`token_assocs_set_disk`），`aip_parts_stats` 给四个验收数字（loads/bytes/resident/evicted）。
真实图实测（`model.bin`，1199 词/41216 边）：段文件 **1059 段 / 2.5 MB**，问 50 个词只读回
**50 段 / 483008 字节 = 18.19%**。判脏是**启发式**（只看条数），改了内容不加条数的段不会被换出。

**原计划（细节）**：内存上限到了就把冷段的边写回段文件并改 tag=2，配 LRU 计数；
验收用"小上限 + 大图"跑同一批问句，答对率不变、part 命令显示真的换出了。

## 3. B 腿：修改账下一刀

现在记的是**关系写**（`AIMOD_REL`）**与删**（`AIMOD_REL_DEL` / `AIMOD_ASSOC_DEL`，§6.568），
并出了 **`::mods`** 命令（只看本脑）。后面：
- 记"删/改"（`MOD_REMOVE_ASSOC`、改口重写）——同样是知识变更，必须进账；
- 账里加 `pool->serial`（跨 agent 身份，见 `token.h` 的 `serial` 注释：光比指针会串味）；
- 新增 **mods 命令**（尚未实现）：看自己的账；再加 `mods diff <另一个 agent>`（两本账的差集）——
  这是"合并/回放"的前提，也是**多智能体协作**最小可用的形态。
