# 多智能体 + 局部加载：路线（用户 2026-10-24 的目标）

> 目标原话：
> 「做到打开多个智能体，每个智能体只维护自己的修改，并且可以暂时只加载一部分图，
>   至于怎么实现，就是指针不是 8 字节对齐吗，不是 0 就是在磁盘或其他地方」

这句话拆成三件**可分别验收**的事：

| 腿 | 要什么 | 目前状态 |
|---|---|---|
| **A 多智能体共存** | 一个进程能开多个 `AI`，互不串台（图、记账、开关） | ✅ §6.564 探针 + §6.571–§6.578 命令面（new/list/use/drop/save/mods/diff；上限 4 个，各持整份图）|
| **B 只维护自己的修改** | 每个智能体一本"我改了什么"的账，不是全局共享 | ✅ §6.564 账 + §6.568 记删 + §6.572 `brain diff` + §6.573/§6.574 delta/流水 |
| **C 只加载一部分图** | 图可以部分在内存、部分在磁盘/别处，按需取 | ✅ §6.566–§6.576（段文件/按需读回/LRU/verify；单问读回 ≈11%）|

---

## 1. 指针标签（C 的地基，已落地）

`ptrtag.h`：`malloc` 至少 8 字节对齐 ⇒ 低 3 位恒 0，塞"东西在哪儿"：

| tag | 含义 | 现在谁用 |
|---|---|---|
| 0 `AIP_PTR_RAM` | 内存里 | 全部旧代码（**默认值 0 ⇒ 接进来零行为变化**）|
| 1 `AIP_PTR_DISK` | 在磁盘（某个区段文件），用时才读 | 未用（下一轮接 `Token.assocs`）|
| 2 `AIP_PTR_ELSEWHERE` | 在别处（别的池 / 压缩块 / 父进程），不是本进程堆 | 未用 |
| 3..7 | 保留 | — |

**三条纪律**（写进 `ptrtag.h` 注释，探针里也钉住）：
1. 只有 8 字节对齐的指针才能打标签（`aip_ptr_taggable`），非对齐时断言而不是悄悄丢位；
2. **读指针前必须 `aip_ptr_strip`**，直接解引用会崩；
3. tag=0 必须与"没打标签"逐字节等价（`aip_ptr_untagged_identity` 有机器检查）。

## 2. C 腿：局部加载怎么接（三轮）

**先说清"不能打在哪些字段上"** —— 这是本轮读代码得出的结论，不是猜：

| 字段 | 能否打标签 | 为什么 |
|---|---|---|
| `Token.assocs` | ✅ 可以 | 本来就是 `malloc` 出来的数组，指针只被"读边"的代码用；有 12 个文件在直接访问（`token.h` 49 处、`ai.h` 49 处…）⇒ **必须先收成一个访问器**，否则无从下手 |
| `Token.name` | ❌ 不行 | 参与 `strcmp`/`strstr` 的地方太多，且存档会写它（存档写的是字符串，不是指针）|
| `Token.emb` | ⚠ 暂不 | 现算的（不进存档），但遍历时直接 `memcmp`，先不动 |
| `TokenPool.tokens[i]` | ❌ 不行 | 数组本体；"某些节点不在内存"要另用一层池级索引 |

**第 1 步（收口）✅ 已完成（§6.565）**：所有 `->assocs` 直接访问收进
`token_assocs()`（可写 / 将来在这里触发按需加载）/ `token_assocs_ro()`（只读视图）——
**171 处搬运，行为零变化**（`probematrix` 28 行 diff 为空）。剩下的直接访问只在
`token.h`（分配）与 `model_io.h`（存盘/读盘/校验）这两个**存储层**，由 `tests/assocaudit.sh` 常驻看守
（新代码一律不许直接摸 `->assocs`）。

**第 2 步（打标签 + 段文件）✅ 已跑通（§6.566）**：`parts.h` 提供
`aip_parts_save / aip_parts_open / aip_parts_attach / aip_parts_detach`：
每个有边的词一段；`detach` 把边 free 掉、指针打 `AIP_PTR_DISK`；`token_assocs()` 碰到标签就按需读回。
探针 `tools/partprobe.c`（第 48 套）证明**只读了一部分**：`n_loads < 被卸下的词数`、`n_bytes > 0`。

**原计划（细节）**：
- 存档旁生成 `*.edges.<k>` 段文件（每 N 个节点的边一段），主文件只留"段索引"（谁在哪一段、什么偏移）。
- 加载时可以只读主文件 + 需要的段；没读的节点 `Token.assocs` 存 `tag=1 + 段偏移`。
- 访问器 `token_assocs(t)`：`tag==0` 直接返回；`tag==1` 触发 `part_load(t)`（读段、挂回、改 tag）；
  `tag==2`（别处/已回收）走 LRU 或拒绝并上报。
- 验收：新增的 **part 命令**（尚未实现）打印"已加载段数 / 总段数 / 触发读取次数"；`probematrix` diff 必须为空（同一份数据）。

**第 3 步（按需回收）✅ 跑通（§6.567；§6.575 改成真 LRU）**：`aip_parts_evict(ai, keep, &skipped)` 把**干净**的段换回磁盘
（`token_assocs_set_disk`），`aip_parts_stats` 给四个验收数字（loads/bytes/resident/evicted）。
**读放大（§6.570）**：一次问答从"必然读回全图 1265 段/2.8MB"压到 **29~34 段（≈11%）**——
逐条抓的是"谁在摸全图"（思考播种、因果学习、结构扫描、巩固、GC、因果边查询），
其中 GC 在部分加载时**整轮跳过**（宁可不删，不能删错）。**命令面（§6.569）**：`::parts save|attach|detach|stats|evict` 五个子命令，一条问答实测
只读 **33 段 / 318KB（≈11%）**——这中间还修掉了 `aip_shell_refresh` "扫每条边找外壳标记"
把全图拉回来的问题。段文件 **1059 段 / 2.5 MB**，问 50 个词只读回
**50 段 / 483008 字节 = 18.19%**。判脏是**启发式**（只看条数），改了内容不加条数的段不会被换出。

**原计划（细节）**：内存上限到了就把冷段的边写回段文件并改 tag=2，配 LRU 计数；
验收用"小上限 + 大图"跑同一批问句，答对率不变、part 命令显示真的换出了。

## 2.5 共享 base + 自己的 delta（§6.573 已做"边级"，词级还没做）

- 写：`::parts delta <f>` 只写 `edges_dirty` 的段（base 一字节不动）。
- 读：`::parts attach <base> [delta]` / `::parts overlay <f>`，同一个词的段以 delta 为准。
- **边界**：delta 按 `Token.id` 存 ⇒ 只对同一个 base 池有效；**新造的词不在 delta 里**（词级 delta 未做）。
  实测 base 2.85MB / delta 0.43MB（15%）：一次学习会连带弄脏公共节点。

## 2.6 词级流水（§6.574 存 / §6.580 照抄）：`journal` / `replay`

- 写：只写 `edges_dirty` 的关系边，按名字（文本、可读可手改）。
- 读（**§6.580 改了语义**）：`replay` 不再走 `agent_step`，而是**照抄**写进图（确定性迁移），
  并**先判冲突**。三条规则（实现在 `xbrain.h`，探针 `tools/xbrain.c`）：
  1. **本地优先**：本地已有同一条 → 不动；有相反极性 / 独占关系已有别的值 → **默认不写**并记账上屏；
  2. **`force`**：极性冲突**真覆盖**；独占冲突**并列写入不撤回**（`属于` 有嵌套，删旧知识比留两条更糟）；
  3. **`check`**：干跑，只报"会新增/会冲突/会建几个词"，一个词都不建、一条账都不记。
- 为什么不再"重学"：学习路径会拒绝/撤回（§6.574 实测 `蛇 属于 植物`），迁移结果依赖于目标脑当时的状态；
  而且被拒的那些**没有痕迹**。照抄 + 冲突可见把"谁的规则优先"变成一条**显式**的规则：
  **本地知识优先，外来事实要覆盖必须用 `force`**。
- 结论：能带、可复现、冲突可见；**不保证**两脑自动一致（那本来也不是靠"抄"能解决的）。

## 2.7 池级共享（下一轮，先把结构约束写清）

用户要的"池级共享"卡在一个结构事实上：**边的两端存的是 `Token*`**（`AssocEntry.main/action`），
所以两个脑要各自修改、就必须各有各的 `Token` 对象；一旦各有各的 `Token`，边里的指针全得重写
⇒ 边数组（出厂图 41216 条边的绝大部分内存）**没法直接共享**。

| 可共享 | 不可共享（要复制） | 结论 |
|---|---|---|
| `Token.assocs` 里的 `emb`（1024 维 int8，≈1.2MB/脑，**不含指针**） | 边数组（含 `Token*`） | 共享"不带指针的大块" |
| `name` 字符串（不可变） | `Token` 结构本身（字段每轮都在变） | |
| 段文件（磁盘）：两个脑接同一份 base | 已读回内存的段 | 磁盘层共享 + 按需加载 |

能落地的两条（下一步做）：
1. **`::brain fork N`**：新脑由序列化读回（现有 `::brain save`/`new <模型>` 已经能做"独立一份"），
   然后把 **emb 数组 / name** 改成引用计数共享（写前复制：`ai_embed_build` 之前整脑复制一次）；
2. **`::brain new parts <base> [delta]`**：新脑**接同一份 base 段文件**，内存里只装问到的段（≈11% 的边），
   真正共享的是"磁盘上的 base"。
- 两个都要**量出来**：3~4 个脑的总分配字节数 / RSS，与"各持整份图"对比。
- 明确**不做**的：把 `AssocEntry` 改成存 id（那是"真共享"的前提，但是一次全仓重构，不在这一轮）。
