## 一、「给 Token 加上行为」= **行为也是一张表**

一个 Token 可以**命令图改变自己**：接线、按语境接线、在两者之间插一个中转 Token、回收草稿。
这些是**操作（机制）**，不是知识 —— 所以它们写成一张表，和 `CMDS[]` / `AI_RELS[]` / `REL_RULES[]` 一个路子：

```c
typedef struct {
    const char *name;      /* 行为名（::op 后面写它） */
    const char *shape;     /* 人看的参数形状 */
    const char *help;      /* 一句话说明 */
    size_t      min_args, max_args;
    int (*expand)(AI *ai, char *const *args, size_t n, ModQueue *q, char *note, size_t cap);
} TokenOp;
```

三条边界写死在这个接口里（和设计原则一致）：

1. **展开函数只产出 `ModIntent`，不碰图** —— 结构改动照旧只有 `micro_step()` 一个入口，
   每条意图都要过**安全内核**（预算、底线、审计）。所以「Token 有行为」**不等于**「Token 能绕过审查」。
2. **参数形状进表**：个数不对就拒绝，帮助由表生成（`::op` 打的就是这张表）。
3. **新增一种行为 = 表里加一行 + 写它那个展开函数**（不碰循环、不碰安全内核）。

手动入口是 `::op`（和 `::mod try` 同类：**调试/手动**入口，不是系统自己提的修改）。

## 二、三条行为（用户点名的那三条）

| 行为 | 语义 | 落地成什么 |
|---|---|---|
| `::op 加前提 <A> <B> [前提名]` | 给 A 与 B 之间加一个**前提 token** P：`A —[前提]→ P → B`（P 缺省 `[临:前提]`），拆掉直连 | `MOD_INSERT_BETWEEN` + `MOD_FLAG_MARK_PREMISE` |
| `::op 前提接线 <A> <前提P> <目标Y>` | 让 A 经前提 P 也能到 Y（确保 `A —[前提]→ P`，并加 `P→Y`）—— 原来「按语境接线」的能力，**选择判据换成了图里的前提链接** | `MOD_ADD_ASSOC` + `MOD_SET_ACTION` |
| `::op 中间插词 <A> <B> [中转名]` | 在 A 与 B 之间插一个 Token：**A→N→B**，并**拆掉 A—B 的直连**（语义就是用户补的那句：*不要直接联想到，经过这个 token 中转*）。不写名字时 N 是**临时 Token** `[临:中转]` | `MOD_INSERT_BETWEEN`（一条复合意图，见下） |
| `::op 回收临时` | 回收**没人引用**的草稿 Token | `MOD_REMOVE_TOKEN` |

实测（真模型）：

```
你 > ::asm [原语:对象] 猫 [原语:对象] 吃 [原语:前关联] 饿 [原语:连接]
[原语 加前提] 猫 —[前提]→ 吃 → 饿（已提出）；应用 1 条
  → 吃   hits=…  **前提**（吃 是这两个词之间的前提 token）
你 > ::premise 猫 饿
[猫 与 饿 之间的前提 token：1 个]   吃

你 > ::mod try 加边 猫 月亮
你 > ::op 中间插词 猫 月亮
[行为 中间插词] 猫 —[临:中转]→ 月亮（已提出）；应用 1 条
  → [临:中转]  hits=1            ← 直连没了，改走中转
  → 月亮       hits=1            ← 中转连到 B
```

**为什么插词必须是「一条复合意图」**：它一次做三件事（造 N、加 A→N、加 N→B、外加拆 A—B）。
拆成四条意图的话，「拆直连」会在 N 还没建好时就执行。所以它是 `MOD_INSERT_BETWEEN`
（新增的一个 `ModType`），审查/记账/应用/审计都在原有那一条路径上。

**直连拆不拆由安全内核裁决**，不是在展开函数里写死：判据只有一份
（`micro_edge_removable()`）——观测到的关系边是**知识**，铁律 2 不许剪；
推出来沉淀的缓存可以。实测：

```
你 > ::op 中间插词 猫 鱼          ← 「猫 吃 鱼」是观测关系边
  → 鱼           hits=…            ← 知识不拆（留着）
  → [临:中转]    hits=1            ← 但中转照样接上（联想改走中转）
```

## 三、临时 Token：**草稿纸**

`[临:…]` 是与 `[新概念:` / `[自问:` 并列的**内核自有命名空间**（"注册一行"那种）：

| 性质 | 实现 |
|---|---|
| 能参与边 | 安全内核区分两件事：`micro_endpoint_reserved()`（能不能当**端点**）放行内核自有命名空间；`micro_token_reserved()`（算不算**内容**）仍然跳过它们 —— 统计/邻居重叠/共现固化不被草稿污染 |
| **不存盘** | 存盘时跳过临时 Token **以及指向它的边**（`mio_edge_saved()`）。名字前缀是唯一判据 ⇒ **不动存档格式** |
| 可回收 | `MOD_REMOVE_TOKEN`：只许 `[临:` 且**必须没人引用**（自己没边、也没有任何 Token 指向它）。回收是**软删**（标 `is_garbage`、清空边表），和 `ai_gc` 一样 —— 物理搬走会让池里的指针全悬空 |
| 不当内容 | 带 `[` 的节点不参与走边（`ai_edge_walkable`）⇒ 草稿永远不会被说出来 |

一条**刻意的局限**（照实说）：临时中转**不存盘**，所以存读之后「A 经 N 到 B」这条中转路径会消失
（直连那次拆除是存下来的）。要持久的中转就给它起个**真名字**：
`::op 中间插词 猫 月亮 食物`。这是草稿纸的定义使然，不是 bug。

## 四、修正的记忆 / 来源监控

上一轮的「观测改口语义」把**当前**的极性修对了，但**变更的历史**没有留下来 ——
系统答得出「猫 没有 毛」，却说不出「这件事改过口」。这一轮补上：

* 改口时（`agent_learn_relation`）经受审通道落一个标记节点
  **`[修正:猫_不_有_毛]`**（格式：`[修正:<主语>_<不?>_<关系>_<宾语>]`），并连回主语；
* **幂等**：同一件事改口多次只有一个标记（`MOD_ADD_TOKEN` 同名 intern），
  两个**不同方向**的修正各留一个（`猫_有_毛` / `猫_不_有_毛`）；
* **它是留痕，不是知识**：带命名空间标记、不进关系表、不参与走边 —— 旧极性不会因为它复活；
* **它是持久的**：普通 Token，随图存盘（`::revise` 里看得到；换进程还在）。

```
你 > 猫 有 毛
AI > 记下 了 ： 猫 有 毛
你 > 猫 没有 毛
AI > 改 过来 了 ： 猫 没有 毛（你 先前 说 的 是 反 的）
你 > ::revise
  本次会话改口 1 次；关掉之后同一段对话会报「互相矛盾的依据」。
  修正的记忆（[修正:…] 标记节点，改口时经受审通道落下）：
    [修正:猫_不_有_毛]  ←  猫
```

这补上的是「来源监控」里缺的那一半：**谁说的**这一档已经由观测/缓存/假设/他人/类比分开了
（见 `docs/人思考的原理-采用与不采用.md`），**改过口**这一档原来没有，现在有了标记节点。

## 四点五、为什么是**临时 Token**，不是给行为再加一台 **Token 栈**

用户点过这个选择（「你是选择加上 token 栈还是临时 token」→「我认为临时 token 更好」）。
记一下取舍，免得下一个改这段代码的人再纠结：

| | 临时 Token（**采用**） | Token 栈（不采用） |
|---|---|---|
| 是什么 | 图里的**草稿节点** `[临:…]`：能参与边、不存盘、可回收 | 语言层再加一台栈机，行为从栈上弹操作数（类似 `token_lang.h` 的 `Interp.stack`） |
| 操作的参数从哪来 | `::op <行为> <参数…>` 直接写；组合靠**多跑一条**（或 `::asm` 造语境边） | 先 push 一串 token，再让行为 pop |
| 好处 | 操作数就是**图里的东西**（跟别的边同构）：可以查、可以看、可以被别的规则引用；草稿不落盘这条语义已经和存档、走边、统计都对齐了 | 组合写法更短，能写成程序（`[原语:…] 猫 … 插词`） |
| 代价 | 组合要写两条命令；没有"把行为当程序跑"的语法 | **多一台要维护的机器**：栈的生命周期、错误恢复、和 `Interp` 的关系、和 micro 队列的边界，全是新的失败面 |
| 为什么不要它 | 现有需求（接线/插词/回收）不需要"弹栈式组合"；真正需要组合时，**图本身就是组合**（中转节点把两跳串起来） | 加栈是把「组合」从图搬进语言层 —— 而设计原则是**行为留给图** |

一句话：**草稿纸放在纸上（图里），不要为了草稿纸再造一台印刷机。**
如果哪天真的需要"把一串行为写成程序"，正确的第一步是复用**已有的** `Interp` 栈机
（它已经在跑原语、切分、语料），把行为注册成原语 —— 而不是新造一台。这件事**没做**，
写在这里当下一步（见第七节）。

## 四点六、把行为写进**语言层**：复用已有的原语栈机

按上面的选择（要组合就复用**已有的** `Interp`，不新造栈），这一轮把三种行为注册成了**原语**：

```
[原语:对象] A [原语:对象] B [原语:插词]        在 A、B 之间插一个**临时 Token**（经它中转、拆直连）
[原语:对象] A [原语:对象] B [原语:插词为] <名字>  同上，但中转 Token 用这个名字（要持久就用它）
[原语:对象] A [原语:对象] P [原语:对象] Y [原语:前提接线]   让 A 经前提 P 也能到 Y
[原语:前关联] P + [原语:连接] A B                        建 A —[前提]→ P → B（语境的替代）
[原语:回收临时]                                 回收没人引用的草稿
```

实测（真模型）：

```
你 > ::asm [原语:对象] 猫 [原语:对象] 月亮 [原语:插词]
[原语 中间插词] 猫 —[临:中转]→ 月亮（已提出）；应用 1 条
你 > ::asm [原语:对象] 猫 [原语:对象] 桌子 [原语:插词为] 家具
[原语 中间插词] 猫 —家具→ 桌子（已提出）；应用 1 条
你 > ::asm [原语:对象] 猫 [原语:对象] 吃 [原语:前关联] 饿 [原语:连接]
[原语 加前提] 猫 —[前提]→ 吃 → 饿（已提出）；应用 1 条
```

**分层是这一节的要点**（也是"不新造栈"之外更重要的收获）：

| 层 | 它知道什么 | 它**不**做什么 |
|---|---|---|
| `token_lang.h`（语言层 / 栈机） | 原语表、栈、操作数怎么弹 | **不碰图**：没有 AI、也不认识 `micro.h`；它只把「行为编号 + 操作数」交给宿主 |
| `main.c`（宿主） | 编号 → `TOKEN_OPS[op].name`（名字仍只写在表里一处） | 不解释原语语义 |
| `micro.h`（安全内核） | 审查 / 记账 / 应用 / 审计 | 不关心请求是 `::op` 还是原语来的 |

所以「用原语写法」和「用 `::op` 写法」**走的是同一条落地路径**，区别只在谁把操作数组装起来。
没有宿主（`token_run_names` 旧入口）时，这些原语**什么也不做** —— 语言层永远不会自己改结构
（这条由 `tools/optest.c` 钉住：跑一遍原语，图的边数一条不变）。

**顺带清掉的是三处重复**（本来以为只有两处，清的过程中逮到第三处）：

| 第几处 | 在哪 | 现在 |
|---|---|---|
| ① | `prim_kind()` 的 32 个 `if (strcmp)` 长链 | 一张 `PRIMS[] = {name, kind}` |
| ② | `pool_init_prims()` 里手抄的名字清单 | 改读同一张表（它是个工具函数：一次全 intern；生产路径是**按需** intern —— `[原语:x]` 一出现就进池子） |
| ③ | `cmd_prims()`（`::prims` 命令）里**又**手抄了一份 —— 加原语时它不会跟着变，症状是 `::prims` **漏列**新原语（老式的"文档骗人"） | 由表生成；`tests/tokenop.sh` 断言「表 N 条 / 列 N 条」且 5 条新入口都在 |

`tools/dupcheck.c` 查名字不重复、kind 不落空、intern 得进池子（24 项）。
教训和当年命令表那次一样：**以为只有两份，往往还有第三份** —— 清重复要按"同一份清单"的
**语义**去找（这里是"所有原语名字"），不是按文件或函数去找。

「编号 ↔ 行为名」这条跨层契约由 `tools/optest.c` 钉着（`IPOP_PREMISE_CONNECT → 加前提`、`IPOP_PREMISE_TIE → 前提接线` …）：
**改了 `TOKEN_OPS[]` 的顺序，测试当场变红**，不会静默错位。

## 五、顺手查出来的两个真洞（都属于「机制在、行为不在」）

改这一段时按「判机制在不在要看可观测量」去量，逮到两个：

| 洞 | 症状 | 根因 | 修法 |
|---|---|---|---|
| **每步新建边预算从来没扣过** | `max_new_edges_step` 形同虚设：一步里能无限建边（只有队列上限兜着） | `safety_charge()` 排在 `micro_apply_one()` **之后**，而它靠 `!micro_has_edge()` 判「这条边是不是新的」—— 应用完那条边已经在图上，判断永远为假 | 记账挪到**应用之前**（预算是「这一步允许多少」），应用失败用 `safety_refund()` 退回 |
| **带语境的边在辅助函数里等于不存在** | `n_subs>0` 的边加权加不上、预算不算、反事实削不到 | `micro_edge_index()` / `micro_has_edge()` / `ai_weaken_edge()` 都要求 `n_subs==0`；调用方却拿它们做「边存在吗/加权」 | 新增 `micro_edge_index_ctx()` / `micro_has_edge_ctx()` 并让调用方按语境走；反事实那处上一轮已修 |

证据（跨代码版本逐字节比较，不是"看起来没变"）：

```
slot0（训练后存盘，4738521 字节）        改前 == 改后   ← 「没有草稿时过滤恒等」+ 格式没动
规范状态 dump（::pooldump+::derivedump，2783 行） 改前 == 改后   ← 预算修复没有改变既有行为
```

## 七、局限与下一步（照实说）

1. **只有三条行为 + 回收**：表是"注册一行"的，但内容还少（够用户点名的三条）。
   比如「把一条边的语境换掉」「把一个 Token 的所有边改挂到另一个 Token 上」都还没有。
2. **行为只能手动触发**：`::op` 是入口；**对话触发没做**（「把猫和鱼之间加一个词」这种自然语言
   到行为的映射，需要切词+意图识别，属于另一层）。
   **已经注册成原语**（见第四点六节），所以 `::asm`/语料能写行为；
   但**对话触发**仍然没有（下一步）。
3. **临时中转不参与生成**（`[临:` 不可走边），也**不存盘** —— 它现在的用处是
   "让两个词不直连 + 结构上留一个中转点"，不是"生成时绕一下"。要后者就得给它真名字。
4. **语境接线只按 `subs` 匹配**：不支持多语境组合、不支持否定语境（`subs_not`）。
5. **来源监控只记「改过口」**：还没记「谁说的」（多说话人场景下，同一件事两个人说法不同时，
   现在只会互相改口 —— 那是下一个要分的事）。
