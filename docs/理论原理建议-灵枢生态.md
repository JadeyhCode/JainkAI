智能论 3.4 把「记忆系统」拆成四个能力：主动读写、记忆压缩、记忆推理、选择性遗忘。你的图内核已经覆盖：

| 智能论能力 | JainkAI 现状 | 判定 |
|---|---|---|
| 主动读写 | 陈述当场学进图；:: 元命令读写 | 已有 |
| 记忆压缩 | 巩固/衰减/漂移采样（按轮全量扫） | 有机制，无层级 |
| 记忆推理 | 图上求解 + 多跳 + 类比 + 反事实 | 已有 |
| 选择性遗忘 | 缓存可撤销；观测不许删 | 有，但边界可被绕过（审计发现） |

**你已经把骨架搭对了。缺的是纪律的物质基础——这也是本次审计反复出现的主题。**

## 二、六条建议

### 建议一：来源可溯的核心判据（补 der_verify 的独立性看护）

灵枢 provenance 模块有一条硬判据：**声称已验证 ⇒ 验证方法非空 且 验证引用非空**——不可复现的验证等于没验证。

你的 der_verify 声称「拿图重推一遍」做独立复核。审计没读 derive.h，无法确认它是否复用推导时的同一状态——**如果复用，就是自己验证自己**，独立复核名存实亡。

**落点**：给 der_verify 加一条看护断言——验证用的状态结构必须是推导状态的深拷贝（或至少是只读视图）。加一条测试：故意在推导里放一条错误中间结论，验证 der_verify 能推翻它。
**代价**：一次深拷贝的性能开销；边界情况（推导中途的假设层）需要想清楚拷贝什么。

### 建议二：审计落盘（「可审计」承诺的物质基础）

你宣称「每次自改都留痕——::safe 随时可查」。但 SafetyKernel.audit 只有 48 条环形缓冲、活在进程内存里、::safe reset 可清零。

**落点**：格式 v10 加一个可选段（审计日志，带版本号，旧文件没有就跳过）。每次受审通道应用/拒绝时追加一条。文件大小可控：审计条目定长或按月分文件。
**代价**：格式 v10 → v11（或 v10 的可选扩展段）；加载兼容旧文件（你已经做过多次版本迁移，这不是新课题）。

### 建议三：写入闸门 + 一扇门原则

你的待做清单里已有写入分级闸门（imp 评分丢弃低价值快照）。审计发现的两条旁路让这条更有紧迫性：

- micro_remind 直写图（不过审查）
- 内部前缀（[撤销:]等）只查名字不查来源

**落点**：
1. 所有建 Token/建边的路径收敛到一个入口函数（一扇门）——入口里做：受审通道检查 + imp 评分 + 审计记录
2. source 字段（提议里已有，24 字节）在审查时校验：内部前缀只许内核自己提（source == KERNEL）
3. imp 评分可直接搬灵枢 longterm_gate 的公式：0.30·新颖 + 0.25·可信 + 0.15·二阶信息差 + 0.15·二阶时间差 + 0.15·提及；低于阈值进缓存（可撤销），高于阈值才进观测
**代价**：重构写入路径（agent.h 里可能有直接调图原语的地方）；收益是「统一走一扇门」从承诺变成事实。

### 建议四：观测/缓存的完整性判据

micro_edge_removable 只看 role == DERIVED 决定可撤销。如果任何路径能把 role 改成 DERIVED，「观测不许删」就被绕过。

**落点**：加一条不变量看护——role 只允许在创建时设置一次，之后只读。C 里可以做：把 role 放进一个 const 修饰的结构段，或提供唯一 setter 并在 setter 里断言旧值是 0（未设置）。
**代价**：极低（一条断言 + 检查现有 setter）。

### 建议五：TTL 租约（你的对照文档里已经写了怎么落）

灵枢的 stable 不是终态而是带 TTL 的租约：(t-t_verified) ≥ TTL 或 conf·e^(−γ·age) < 0.3 → 降级为 weak。**降级只作用于状态，不作用于记录**。

你的唯一时间核已经落地（ai_recency_weight）——租约只差一步：给关系边加一个 last_verified 时刻，查询时按租约判据降级。
**代价**：格式 v10 里关系边的字节区是否有空位（你对照文档里评估过——[时刻:] 链可以代替，或接受不持久化）。

### 建议六：层级压缩（图版本的归并固化）

billion-context-dsh（另一个我们审计过的项目）做了三层压缩：原始消息 → 摘要 → 更精炼摘要 → 最精炼，每层记录从哪些块蒸馏来的。

你的图可以做类似的事：**对已巩固的子图再做一次抽象**——把「一组共现边」蒸馏成一条「主题边」（带指向成员的溯源链）。你的巩固/衰减机制已经是单层的了；层级化之后，长会话的记忆不会无限膨胀，而细节仍可沿溯源链找回。
**代价**：中——需要设计蒸馏的触发条件与溯源链的存法。建议放在审计落盘与一扇门之后做。

## 三、优先级

| # | 建议 | 代价 | 收益 |
|---|---|---|---|
| 1 | 审计落盘（建议二） | 低-中 | 让「可审计」从措辞变成事实；也是排查 P0/P1 类问题的证据基础 |
| 2 | 一扇门 + source 校验（建议三） | 中 | 封死两条旁路；写入闸门顺路落地 |
| 3 | der_verify 独立性看护（建议一） | 低 | 补「独立复核」的可信度 |
| 4 | role 不变量（建议四） | 极低 | 一条断言的事 |
| 5 | TTL 租约（建议五） | 低 | 你的对照文档已评估过路径 |
| 6 | 层级压缩（建议六） | 中 | 长会话记忆不膨胀 |
