# 思维循环（deliberation）—— 「有思维的行为」那一层

> 微内核（`micro.h`）解决的是「**改**得有规矩」：Token 和关联在运行时被系统自身修改，
> 但只经一条受审的通道。这一层解决的是「**想**得有过程」：
> 它不是一次性把四种策略排队试一遍，而是**有议程的循环** ——
> 立目标、取一个、够不着就拆成子目标压回去、追到有结论或追不动为止，
> 并且**写明为什么停**。
>
> 新增 `think.h`（1070 行，单头文件）。依赖：`token.h` 的图、`rel.h` 的求解器、
> `derive.h` 的验证器、`micro.h` 的意图队列。**存档格式没动**（思维状态不进模型）。
>
> 默认值（都是**量出来的**，见第二节与第十节）：
> **每轮都想 = 开**、**想的结果可以改脑 = 开**（只经意图队列）、
> **让思维接管输出 = 开**（只接管两种既有流水线给不出的情况：知识自相矛盾、
> 跨轮想通）。`::thinkout off` 是逃生口。
> 默认值翻过来之前先做了 A/B（`tests/thinkout_ab.sh`）：第一次量出 5 套回归变红，
> 查出思维层自己的三个真 bug，修完之后 7/7 行为套全绿 —— 这才敢翻。

---

## 一、它和既有「思维链」（COT）不是一回事

这是最容易混的地方，必须说清楚：

| | `ChainOfThought`（原有） | `Think`（这一层） |
|---|---|---|
| 是什么 | **一轮输出过程**的记录 | 一段**有议程的循环** |
| 形状 | 读入→骨架→校验→降级→成句（四种策略咬合） | 立目标→取目标→挑手段→够不着就拆→再取→收束 |
| 回答的问题 | 「这一步在干什么、成没成」 | 「它在追什么、追到哪、为什么停下来」 |
| 跨轮 | 一轮一清 | **未解问题跨轮活着**（想不通就挂起来接着想） |
| 能不能失败 | 每步有 ok 标志 | 有**八种停止原因**，且「推不出来」是合法结果 |

一句话：COT 是**过程的记录**，Think 是**追一个目标的过程**。

## 二、循环长什么样

```
读入 ──▶ 立目标（关系问题 / 关系陈述 / 没有要弄清的事）
          │
          ▼
   ┌──────────────── 议程（去重表 + 队列）────────────────┐
   │  取一个目标：                                       │
   │    查     图里/假设覆盖层里直接有吗                  │
   │    推     交给求解器（传递/继承/逆/缺前提）          │
   │           再用**验证器独立复核**，gaps>0 不算结论     │
   │    试反方向  正方向推不出来时，答案常常在对面         │
   │    类比   借最近邻的意见（**是猜的，必须标出来**）    │
   │    问缺什么前提（「会」推不出来时）                  │
   │    够不着 ▶ **拆成子目标压回议程**（这一步才叫循环）  │
   │            拆什么**不在这层写死**：关系表的声明 +   │
   │            图给出的候选（见 2.1）                    │
   └─────────────────────────────────────────────────────┘
          │
          ▼
   反省（证据强度 vs 把握）──▶ 收束（写明停因）
```

### 2.1 拆什么，是从架构里长出来的

按项目的设计原则（`docs/设计原则-涌现与脑区.md`）：
**机制可以新写，知识必须涌现**。所以这一层不知道「只有『会』才有前提」这种知识，
它只读表和图：

| 子目标 | 谁决定它存在 |
|---|---|
| 换问法 | **机制**（规则 R7/R8/R9 只在问否定时开火），与具体关系无关 |
| 缺哪条前提 | 关系表：`rd->prereq`（这一位是这一轮从 `rid == REL_CAN` 搬进表的） |
| 借最近邻 | **表示层在不在**（`emb` 有值才有这条路） |
| 经由某个中间词 | 关系表：`rd->trans` / `rd->inherit` + **图给出的候选**（`rel_next_cands`，含假设覆盖层） |
| 问前提 | **图里**这个词有前提链接（`[前提]` 标记，见 `docs/语境退役-前提token.md`）—— 只报告"前提成不成立"，不结结论 |

「经由中间词」不是把求解器重写一遍：每一跳都是一次**独立**求解，
所以串起来的深度不受求解器单次调用的深度上限约束 —— 新增能力来自机制的组合。

实测痕迹：

```
 5. 分解   ✓  够不着就拆
    够不着 → 拆出 4 个子目标压回议程（换问法 缺前提 借最近邻 经由动物 ）
```

末尾那个「经由动物」不是代码里写的，是图给的。

### 2.2 机制注册表：**新增一条手段 = 注册一行**

上面那张表里的「谁决定它存在」如果靠一排 `if` 实现，新增一条手段就得改循环 ——
那就又变成规则引擎了。所以这一层现在是一张**注册表**：

```c
struct ThinkMech {
    const char *name;                                   /* 显示名（打在痕迹上） */
    ThinkGoalKind kind;                                 /* 它产出/处理哪种目标 */
    const char *needs;                                  /* 人看的：它依赖什么 */
    int (*applicable)(AI *, const ThinkGoal *);          /* 现在能用吗 —— 只读表/图/表示层 */
    int (*expand)(AI *, Think *, const ThinkGoal *);     /* 压子目标（NULL = 默认压一个） */
    int (*process)(AI *, Think *, const ThinkGoal *,     /* 处理一个这种目标：
                      int *cls, char *note, size_t);       返回**正关系的真值** */
};
```

三条边界写死在这个接口里：

1. **机制怎么干活**写在回调里 —— 新写代码，正当（这是「区域」的结构）；
2. **机制什么时候能用**写在 `applicable()` 里，而它**只读关系表 / 图 / 表示层** ——
   知识从这里被读出来，不许写进控制流；
3. **调度按注册表下标**（`ThinkGoal.mech`），不按 `kind` ——
   外部机制用 `TG_EXT` 就行，不必去抢内核的枚举值。

好处是**扩展点是真的**：`tools/delibtest.c` 里在运行时注册了一条内核根本没有的机制
（`试上位类`），循环、分解、调度**一行都没改**，而它确实答出了核心答不了的问题：

```
前置条件：核心的直接查够不着（父子关系是**结构**，不是图里的边）
结论是**新注册的机制**给的（成立）
痕上能看到这条机制自己写的话（说明它真的被调用了）
```

三个让它是「循环」而不是「并列」的地方：

1. **议程**：目标是数据，被压进队列、按序取出；同一件事有**去重表**，不会重复想。
2. **分解**：够不着不是直接放弃，而是拆出子目标（试反方向 / 类比 / 问缺什么前提）压回去。
3. **停滞检测**：连续几步既没结论也没拆出新目标 → 判「原地打转」，停下并记账。

实测（`::delib`，`猫 会 唱歌 吗`）：

```
 1. 读入   ✓  读入
 2. 立目标 ✓  立目标（关系问题）
 3. 查      ✗  直接查图            直接查不到 `猫 会 唱歌`
 4. 推      ✗  交给求解器          求解器给不出依据
 5. 分解   ✓  够不着就拆            拆出 3 个子目标压回议程（试反方向/类比/缺前提）
 6. 推      ✓  交给求解器 + 验证器复核   猫 -[会·缺前提]-> 唱歌
 7. 反省   ✓  反方向才是答案        正方向推不出来，但「猫 不 会」推得出来
 8. 查矛盾 ✓  查反方向              反方向推不出来（好，那就不矛盾）
 9. 反省   ✓  反省                  有依据（80% 把握）
```

## 三、八种停止原因（都必须写明）

「想完了」和「想不下去」如果看起来一样，这一层就没有意义。

| 停因 | 含义 |
|---|---|
| 有结论 | 有验证得住的依据（直接事实或规则推导） |
| 只有猜测（标明是猜的） | 只有类比推测，把握 45 |
| 推不出来 | 求解器给不出依据，链上有缺口 |
| 正反都能推出来（矛盾） | 两条依据互相打架 → **不下断言** |
| 没有要弄清的事 | 这句不是关系问题（普通陈述句） |
| 步数预算用完 | 想到上限就停，**不硬凑结论** |
| 原地打转 | 连续几步没有推进 |
| 思维循环关着 | `::thinkrun off` |

## 四、三条铁律（都有测试钉着）

1. **想出来的不等于真的**。结论必须过 `der_verify`，链上有缺口（`gaps > 0`）就不下结论 ——
   这是 `derive.h` 早就立的规矩，思维层只是照办。
2. **思维不把猜出来的东西写进图**。假设、推测、传递出来的结论都只留在**痕**上；
   只有**观测**（用户说的、外部补丁给的）才配进图。
   测试里是硬断言：做一次成功推导，前后图里的关系边数**一变不变**。
3. **想不通是合法结果**，而且要**挂起来**（跨轮接着想），不是忘掉。

## 五、思维怎么改脑（只有两种提议）

思维改脑走的是 `micro.h` 那条受审通道（提议 → 安全内核审查 → 安全点应用），
而且只提两类：

| 提议 | 名称 | 依据 |
|---|---|---|
| 登记未解问题 | `[自问:…]` 节点，接回触发它的词 | 「这个问题我想不通」这件事本身 |
| 固化连结 | 两个词的邻居高度重叠（共同邻居 ≥ `D1+2`、Jaccard ≥ 30%）、图里却还没有边 | **图内已有证据**，不是「一起出现过」 |

审计里看得到来源：

```
::mod
   应用 1（新边 0 新Token 1 打关系 0 强化 0 删边 0）  被拒 0
   最近应用：
     - 加Token [自问:猫_会_跳舞_吗]→猫 [思维:自问]
```

**改不了脑的时候（`::safe off`、被冻结、`::thinklearn off`）思维照样想，只是不落地** ——
痕上会写一句「自修改被冻结或关着：想法留在痕上」。

## 六、跨轮：未解问题

| 阶段 | 做法 |
|---|---|
| 挂 | 想不通的**问句**（陈述句不挂）→ 进 `Think.open`；最多 16 个，满了就拦住并记账 |
| 试 | 每轮收尾（`think_settle`）拿**这一轮新学到的知识**重试，最多 4 个/轮 |
| 通 | 想通了 → 记着「等下要说一句」；**不写图**（想通 ≠ 观测） |
| 老 | 试够 `stall_limit`（3）次就停止再试；放够 600 tick 就过期 |
| 说 | 打开 `::thinkout` 之后，**追加**在正常回答后面 |

实测（同一会话）：

```
你 > 猫 会 跳舞 吗
AI > 猫 应该 会 跳舞            ← 输出流水线照常（帧层）
你 > ::pending
[未解问题] 还挂着 1 个（跨轮会拿新知识再试）： - 猫 会 跳舞 吗  试过 1 次
你 > 猫 会 跳舞
AI > 记下 了 ： 猫 会 跳舞       ← 关系层现场学
你 > ::pending
[未解问题] 没有挂着的（累计挂过 1，想通 1，过期 0）
你 > ::delib
  …  14. 登记   ✓  跨轮想通
你 > 你好                       （::thinkout on）
AI > 你 好 我 一直 在 等 你 说 话（你 上次 问 的 猫 会 跳舞 吗，现在 我 知道 了 ： 猫 会 跳舞）
```

那句补充是**追加**而不是替换：跨轮想通是一条补充，不该把用户这一轮问的东西挤掉。

## 六点五、推理沉淀：**想通的东西要留下来**

在这之前，「学」只有两条路：**听到的**（用户陈述 → 关系边）和**共现出来的**（语料/对话）。
推论用完就丢 —— 同一件事问一百遍，它就从头推一百遍，什么也没积累。
这既不省力，也不像「懂」：**懂包含「记得自己想过什么」**。

所以第三条路：**推理沉淀**。

| 什么会被沉淀 | 什么不会 |
|---|---|
| 现场用**健全规则**（传递/继承/对称/逆/缺前提）推出来的结论 | 独占/闭合世界推出来的（那是**非单调默认**，本来就可能被推翻） |
| 推的时候**不是**在假设世界里 | 假设世界里的（`DER_HYP` 不进图） |
| 不是类比猜的 | 类比推测（`DER_GUESS`） |
| 验证器 `gaps == 0` | 链上有缺口的 |

落地方式：边照旧建，但 `role` 标成 **`ASSOC_ROLE_DERIVED`**。
这个字节**本来就在存档格式里**（role 从 v4 起就序列化），所以
**格式没动、不用重训** —— 旧模型里没有这个值，新模型里它照样读得回来。

```
你 > 猫 有 毛 吗
AI > 对 ， 猫 -[属于·继承]-> 动物 ； 动物 -[有]-> 毛      ← 现场推
    ::mod → 沉淀 猫 rel2 毛（沉淀） [思维:沉淀]            ← 经意图队列落地
    ::rel 猫 → 猫 --[有]--> 毛（推出来的，可撤）            ← 标着来源
你 > 猫 有 毛 吗
AI > 对 ， 猫 -[有·记]-> 毛                                ← 直接用缓存
    ::delib → 依据强度：推导缓存（以前想通并记住的）
```

**撤销有两条路，走的是两种完全不同的原因**：

| 触发 | 怎么做 | 为什么 |
|---|---|---|
| **观测**与缓存相反 | `token_tag_rel/nrel` 里把这条边上的缓存**整条撤掉**，再落观测 | 具体压过一般：**观测是事实，缓存是笔记**。同一条边上不混两种来源（混了之后「这是推出来的吗」答不清，撤销时会误删观测） |
| **现场推理**算出反面 | `think_finish` 当场翻转结论 → 收尾时提 `MOD_REMOVE_ASSOC` 撤销缓存 | 缓存不是独立依据，是**记忆**；记忆和现算的冲突，听现算的 |

安全内核里那条硬底线**没有松**：观测到的关系边**依旧不许删**；
只有 `role == ASSOC_ROLE_DERIVED` 的缓存可撤。

还有一条推理规则这一轮才补上（**具体优先于一般**，见 `rel.h`）：
同一对词上若有一条**观测到的**边说的是正相反的事，那么**传递/继承不再外推** ——
不是「两边都成立、报个矛盾」，而是「这条一般规则在这个具体例子上被推翻了」。
没有它，用户教的修正永远留不下来（每轮都报自相矛盾）。
边界有四条，每条都是被回归逼出来的：只挡外推（不挡独占/闭合世界/缺前提）、
只判 `depth==0`（例外不传播）、**假设世界里不挡**（覆盖层本来就压过图）、
只认非缓存边（缓存该被推翻并撤销，不是挡住推理）。

实测（`tests/consolidate.sh`，18 项）：

```
① 推导 → 沉淀（::rel 标「推出来的，可撤」；::mod 里来源是「思维:沉淀」）
② 复用（链上是 ·记，依据强度=推导缓存）
③ 观测压过缓存（那条边不再是缓存，回答跟着观测走，且**不报矛盾**）
④ 现场推理推翻（当场改口「我原先记的是反的」+ ::mod 里「删边 … [思维:撤销缓存]」）
⑤ 两条继承路径真打架 → 老实报「互相矛盾的依据」
⑥ 存盘重载后仍是「推出来的」（不冒充观测）
⑦ ::thinkcache off 之后不再沉淀（想还是照想）
```

### 6.5.1 缓存跟着前提走（依据是**现算**的，不存依赖表）

一条缓存过期，最常见的原因不是「有人推翻它」，而是**它的前提没了**：
`动物 有 毛` 被撤/被改口之后，`猫 有 毛`（靠继承推出来记住的）就不该再算数。

实现上**没有依赖表、也不动存档格式**：依据就是「**把它排除在外，还推得出来吗**」。

```
rel_solve_ignoring_caches(ai, a, rid, b, want)   ← 把缓存全当不存在，再推一遍
```

两道闸，缺一不可：

| 闸 | 在哪 | 作用 |
|---|---|---|
| **实时闸** | 求解器 R0 + 候选枚举（`rel_next_cands`） | 查到/路过一条缓存时先复核依据；没依据就当它不存在 —— 任何消费者（关系层/思维层/帧层）自动正确 |
| **收尾扫描** | `think_settle`（`think_revalidate_caches`） | 扫一遍图上所有缓存，把没依据的**提出来撤销**（`[思维:前提没了]`），免得它老挂在图上每次都要复核 |

实测（`tests/consolidate.sh` 第八节、`delibtest` 第⑫节）：

```
猫 有 毛 吗 → 沉淀（依据：猫属于动物 + 动物有毛）
动物 没有 毛 → 前提被改口
  · 求解器当场不再拿那条缓存当数（实时闸）→ 这一轮答「推不出来」
  · ::delib → 前提没了 1 条      ::mod → 删边 删 猫→毛 [思维:前提没了]
  · ::rel 猫 → 那条缓存已经不在图上了
依据回来（动物 有 毛 重新成立）→ 照样能推、能重新沉淀（不是永久拉黑）
```

还有一条同源的原则：**统计只看观测**。独占/多值那些性质是从数据里**量**出来的
（`rel_excl_build`），所以它扫边时必须跳过缓存 —— 不然自己推出来的结论会回头
强化推出它的那条规则（自我印证），而缓存本来就是随时会撤的东西。

一个刻意的保守：**缓存不许互为依据**。复核时把所有缓存都当不存在，
所以一条缓存的依据只能是**观测 + 规则**。这样「A 依赖 B、B 依赖 C」那种链不会出现，
也就不用写传播算法 —— 捷径不许嵌套。
代价照实说：多跳结论如果中间那一跳本身也是缓存，它就不会被沉淀（保守，但不会错）。

**局限照实说**：
* 还没有逐条可信度衰减（只有 hits 那套）；
* 依据复核是**现算**的，缓存多的模型每轮会多几次求解（实测可忽略，缓存本来就少）；
* 缓存**不参与自由联想**（走边那套按 role 取边，缓存不在其中）——
  这是有意的：联想是关于原始共现的，缓存是**推理用**的；
* 缓存也没有「依据变弱就降级」这一档：要么有依据、要么撤。

## 六点六、观测改口语义：**后说的替换先说的**

「用户先说『猫 有 毛』、后说『猫 没有 毛』」这件事以前**没有定语义**：两句话都落成观测，
同一条边（同一对词、同一条关系）上两个极性并存 → 每次提问都报
「关于 猫 有 毛 这件事，我这儿有互相矛盾的依据」。听起来像系统自己的知识有毛病，
其实只是**它没改口** —— 用户教的修正留不下来。

现在定成一句话：

> **同一对词、同一条关系上，后落的那条观测替掉先落的对立极性。**

实测（`model.bin`，默认开关）：

```
你 > 猫 有 毛
AI > 记下 了 ： 猫 有 毛
你 > 猫 没有 毛
AI > 改 过来 了 ： 猫 没有 毛（你 先前 说 的 是 反 的）
你 > 猫 有 毛 吗
AI > 不 对 ， 猫 -[不 有]-> 毛
你 > ::revise
[改口语义 = 开（默认）]（后说的观测替掉同一条边上先说的对立极性）
  本次会话改口 1 次；关掉之后同一段对话会报「互相矛盾的依据」。
```

五条边界，每条都有回归钉着：

| 边界 | 做法 | 为什么 |
|---|---|---|
| 只改极性，**不删边** | 那条 `AssocEntry` 还在，清掉的只是对立的那个极性位 | 「关系边不许删」那条铁律没松（安全内核也只允许删缓存） |
| 只管**同一对词、同一条关系** | 不同宾语的多值事实各自并存（`猫 有 毛` 与 `猫 有 尾巴`） | 改的是「同一件事的说法」，不是整条关系 |
| 「观测压过缓存」**不算**改口 | 缓存那一半照旧整条清掉，确认话仍是「记下了」 | 那是「具体压过一般」，不是用户改主意 —— 两套语义不能混 |
| **基准知识不许盖掉存盘观测** | `relations.txt` 装载时，若存盘里已有观测说了反话 → 这一行跳过 | 模型文件是**更晚**的状态（用户教过、存过盘），基准知识每次启动重读；不让路的话「重启一次就把用户教的忘了」 |
| **话要说清楚** | 改口时回「改 过来 了 ： …（你 先前 说 的 是 反 的）」，`::stats` 里也记「改口 N 次」 | 用户得知道自己的修正生效了，不然只能靠猜 |

`::revise on|off` 是开关（默认 on）。它不是逃生口，是 **A/B 的对照组**：
`tests/revision.sh` 同一段对话跑两遍，量出 **开 → 矛盾 0 次 / 关 → 矛盾 2 次**，
并逐条钉住上面五条边界（含「改口存盘重载之后不会被 relations.txt 改回去」、19 项）。
C 级看护在 `tools/delibtest.c` 第十三节（17 项）。

顺带一处**一致性**：他者信念表（`OtherModel.bel[]`）本来就是这个语义 ——
同一个「他」对同一件事再说一遍，是**替换**那一格的极性（`other_believe_add`），
而不是记两条。所以这一轮其实是把**主图**对齐到信念表早就有的做法上。

**一个仍然存在的边界（照实说）**：并存状态不再可能由「用户说两句话」产生，
但**旧模型里可能已经带着它**（这一轮之前存的盘），读进来仍然会报「知识自相矛盾」；
`::revise off` 也是同一个状态。所以那条代码路径没删，只是不再是常态 ——
`tools/delibtest.c` 第三节现在显式关掉改口来构造它。

## 七、矛盾检测：单轮输出流水线给不出的一个行为

```
你 > 猫 会 唱歌            ← 教它一条和「缺前提」推理相反的事
AI > 记下 了 ： 猫 会 唱歌
你 > 猫 会 唱歌 吗
你 > ::delib
       这一轮：没有结论（把握 0%）  停止原因：正反都能推出来（矛盾）
       结论投影：关于 猫 会 唱歌 这件事，我这儿有互相矛盾的依据
       依据：图里直接有 `猫 会 唱歌`
       另一条依据：猫 -[会·缺前提]-> 唱歌
       元认知：… 发现矛盾 1 次 …
```

要点：**正反都过验证器**时，正确的行为不是「挑一条说」，而是不下断言、把矛盾说出来。
理由留在链上（一条是直接事实，一条是缺前提推理），元认知也会留下
`[提醒:知识自相矛盾]`。

打开 `::thinkout` 时这一句会**替换**整句回答 —— 这时候说一句正常回答等于把矛盾盖住。

### 10.1 A/B 是怎么把默认值翻过来的（这一步才是关键）

「让思维接管输出」当时是默认关的，理由写的是「先测量再决定」。真的去量了：

```
第一次：AIP_THINKOUT=1 sh tests/thinkout_ab.sh
  关系/推导 不变；hypothesis / logic4 / exclusivity / hypo_frames / thinking → 变红
```

查下来**不是输出变差，是思维层自己有三个真 bug**（都在这一层，不在既有代码里）：

| # | bug | 症状 | 修法 |
|---|---|---|---|
| ① | `rel_solve` 的 `pf.status` 被当成「问法的答案」 | 问「猫 属于 植物 吗」，独占推出的**否定**（那本来就是答案）被当成「反面也成立」→ 判成矛盾 | `status` 是**正关系的真值**（+1 真 / -1 假）；加 `think_answer_of(truth, want_neg)` 换算 |
| ② | 没分证据强度 | 独占/闭合世界（非单调默认）与**假设**推出来的东西，被拿去和事实并列判「矛盾」 | `think_evidence_class`：观测事实4 > 规则3 > 独占/闭合世界2 > 假设1 > 类比0；**两边都不弱于规则**才算矛盾 |
| ③ | 只查到直接否定就下结论 | 图里有 `猫 不会 飞`，但假设「猫 属于 鸟」+`鸟 会飞` 能推出肯定 → 被短路成「不成立」 | 只查到否定时**不下结论**，交给求解器；求解器也推不出来，才经「试反方向」把它当答案 |

```
第二次：AIP_THINKOUT=1 sh tests/thinkout_ab.sh
  relations / derivation / hypothesis / logic4 / exclusivity / hypo_frames / cot → 全绿
  → 默认才敢改成「接管输出 = 开」
```

这个脚本留着：**以后再动默认值，先跑它**。反面（默认关）也能量：
`AIP_THINKOUT=0 sh tests/all.sh`。

「默认每轮都想、结果可改脑」而 **21 套既有回归一条没变**：
原因是思维的产物只走意图队列（受预算与底线约束），
而接管输出默认关着 —— 它没有去动那条被钉住的输出基线。

## 十一、局限照实说

1. **机制是可注册的，内建五条**：问前提 / 换问法 / 缺前提 / 借最近邻 / 经由中间词
   （**顺序即优先级**：「问前提」排第一 —— 它只是图读 + 焦点查询，而且解释
   "为什么这条连结现在不能用"；排在后面会被停滞检测吃掉，实测踩过）。
   另外四条见 `docs/语境退役-前提token.md` 第五节（前提是闸门，不是路障）。
   `applicable()` 谓词仍是手写的（四个），**但它们只读表和图** ——
   这是接口要求，不是巧合。彻底版是让机制自己声明依赖、由内核去满足；
   四条机制上还不值当。
2. **类比受表示质量限制**：仓库既有的结论是 `emb` 撑不起细粒度分类与关系类比，
   所以猜出来的把握只能给 45，而且必须标明是猜的。
3. **未解问题不进存档**（会话内）：换一次进程就没了。想通之后落地的只有那个 `[自问:…]` 节点。
4. **接管输出只做两件事**（矛盾替换、跨轮想通追加），别的一律不碰。
   它现在**默认开着**（A/B 量过），但能力面很窄：思维想通的关系问题
   仍然由原来的关系层去说，思维只在「两条依据打架」和「旧问题想通了」时插话。
5. **没有规划**：只有「追一个关系目标」，没有多步行动序列、没有目标层级、
   没有「想多久才划算」的元决策（步数预算是常数，不是算出来的）。
6. **证据强度只做了粗分级**（4/3/2/1/0：事实/规则/非单调默认/假设/类比，取链上最弱一步）。
   它够用来避免「假设 vs 事实」被误判成矛盾，但**没有逐条知识的可信度权重**，
   所以两条都是「事实」级时，仍然不会说「我更信哪一条」，只会说「它们打架」。
   （同一对词上的两条**观测**现在由改口语义收拢成一个极性，见六点六；
   剩下能撞出「两条都是事实」的，只有旧模型里遗留的并存位或 `::revise off`。）
7. **不改脑那一半依旧是绕过审查的**：`ai_learn_pair` / `ai_inner_dialogue` /
   `ai_imagine` / 关系层现场学知识这些既有写入者仍然直接改图
   （见 `docs/microkernel.md` 局限 1）。思维层只是**新增**了一条受审通道。

## 十二、下一步（按性价比）

1. **给「经由中间词」加深**：现在每步最多经由两个中间词、只拆一层（防爆炸）。
   真正的搜索要能把子目标再展开（`depth` 放开 + 去重表更细），
   并且要知道什么时候该停 —— 这需要一次专门的测量。
   **这一轮先量了才决定不做**：`REL_MAX_DEPTH = 5`，而现成的知识里没有超过 5 跳的链
   （`属于` 最长 3~4 跳，而且它同时是**独占**关系 —— 传递会被「具体优先于一般」挡住），

   （C 级可做，CLI 要现教 6 跳以上）。收益/风险比不如这一轮做的两件事，故暂缓，

2. **让思维结论驱动更多输出**（现在只接管两种）：做法还是同一条路 ——

3. **证据强度做成逐条的**（现在是 5 档粗分级）：给知识一个可信度（观测 > 推导 > 类比、
   按命中次数/来源/时间衰减），矛盾时才有资格说「我更信哪一条」。
4. ~~**未解问题持久化**~~ **已做（不用动格式）**：思维层挂问题时本来就会经安全内核落一个
