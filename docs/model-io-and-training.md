# model.bin：完整快照存盘 / 读盘 + 批量训练

> **给三天后的人（一句话）**：存档格式（现在 v10）、每个字段的来历、训练语料格式（`X Y Z 连接` 那些原语行）、巩固/睡眠/抽象怎么内联在训练里。
> **格式不许动**是这个项目的铁律，所以"想加能力要挤进现有字节"的取舍都记在这里。
> **代码**：`model_io.h`、`token.h`；**看护**：`tests/model_roundtrip.sh`、`tests/frames.sh`。


本次改动解决了 `deepseek看这里.txt` 的诉求：**训练它、存成 `model.bin`、并补上加载
`model.bin` 的能力**。同时把「睡眠」从「等空闲才走」改成「训练期内联推进」。

## 一、怎么用

```bash
# 看一眼命令
./build_aip --help

# 训练 → 直接落 model.bin（批量模式，训练期内联做巩固/抽象/睡眠回放）
./build_aip seed_full.txt --batch --interval 200 --save model.bin

# 训练后直接进对话（不带 --save 也行，进去后 ::save）
./build_aip seed_full.txt --batch

# 有 model.bin 时，不带参数启动就会自动加载它
./build_aip

# 指定别的模型文件
./build_aip --model some.bin
```

对话里的元命令（`::x` 和 `:x` 都认）：

| 命令 | 作用 |
|---|---|
| `::help` | 帮助 |
| `::stats` | 符号节点 / 边 / 状态 / 全部计数器 |
| `::save [文件]` | 存完整快照（默认 `model.bin`） |
| `::load [文件]` | 读完整快照，替换当前脑 |
| `::fingerprint` | 打印内存态指纹（存读无损验证用） |
| `::train <文件>` | 继续灌图（只走学习，不做周期巩固） |
| `::batch <文件> [N]` | 批量训练：每 N 行内联做巩固/抽象/睡眠回放（默认 200） |
| `::gen <词>` | 从某个词生成一句话 |
| `::think <文本>` | 看每个词的感知子图 / 缺失感 |
| `::asm <原语序列>` | 语言层直接执行原语 |
| `::edges <词>` | 列某个符号节点的全部边（hits / seq / 状态 / 语境 / 否定 / 动作） |
| `::tokens [N]` | 关联最多的前 N 个符号节点 |
| `::prims` | 列全部原语 |
| `::gc` | 手动跑一遍遗忘 |
| `::quit` | 退出（**不自动存盘**，要存就显式 `::save`） |

> `::quit` 故意不再自动存盘：以前它会把当前脑覆盖到 `model.bin`，写脚本/跑测试时
> 会悄悄污染别人的模型。

## 二、为什么不能直接用原来的 `token_pool_dump`

`token.h` 里那份序列化只写「符号图」，读回来会丢：

- `Token` 的 `birth_tick` / `last_touch_tick` / `mem_state` / `is_garbage` / `next_in_time` / `perspective_of`
- `AssocEntry` 的 `birth_tick` / `last_touch_tick` / `mem_state`
- `TokenPool` 的 `current_tick` 和视角栈
- 整个 AI 层：`rng` / 内生状态 / 元认知 / 校准 / 表达自举 / 时间线 / 他者模型 / 焦点环 /
  `trace` / `last_output` / `last_skipped` / 各种计数器

所以新建了 `model_io.h`：**完整 AI 快照**，自描述小端格式，不依赖结构体 padding。

### 格式（`MODEL_MAGIC = "AIMD"`，`MODEL_VERSION = 1`）

```
[FileHeader 24B]  magic, version, VSA_DIM, n_tok, n_assoc, perspective_depth
[TokenRec × n]    按 id 0..n-1 顺序，每个 Token 一条（长度可变）
                  id, name, hv?, hv_prev?, misses, recent_misses,
                  parent_id, next_in_time_id, perspective_of_id,
                  is_category, is_garbage, mem_state, birth_tick, last_touch_tick,
                  assoc_count, 然后 assoc_count 条边
[边]              n_subs + subs ids, n_not + not ids, main_id, action_id,
                  hits, seq, mem_state, birth_tick, last_touch_tick
[PoolLayer]       current_tick, n_entries
[AILayer]         rng, gc_rng, turns, n_learned, energy/decay/cutoff/max_gen/…,
                  gc/uncertain/setpoint 配置, inner, meta, 九个核心 Token id,
                  焦点环, trace, last_output, last_skipped, last_path,
                  expr_root[7], timeline[32], others[8], 全部行为参数与计数器
```

`cap`（数组容量）**不存**：它是分配细节，读盘时按 `token_add_assoc_ex` 的
「起步 4、`count==cap` 时翻倍」规则还原，这样加载后的内存态与训练出来的内存态
**连指纹都逐位一致**。

## 三、这次揪出来并修掉的 5 个真 bug

写快照 + 往返回归的过程中，把原来的几处硬伤一起暴露并修掉了：

1. **边目标写成了指针**（`model_io.h`）
   `ai_snapshot` 里 `e->main` / `e->action` 直接按指针宽度写出了原始指针值，而不是
   `id`。符号节点 id 0 是「我」，于是所有指向「我」的边在文件里变成 0，读回来
   `main` 成了 NULL —— 表现为 `说 → 我` 的边凭空消失。

2. **单遍解析在指针还没建齐时就去解析**（`ai_load_file`）
   边可以引用文件里更靠后的符号节点（id 0 的「我」经常比引用它的符号节点先出现）。
   第一遍就解析会拿到 NULL 并误判成「文件损坏」。改成**两遍**：第一遍只建符号节点
   骨架 + 跳过边，第二遍（池里 0..n-1 齐了）再把裸 id 换成 `Token*`。

3. **`cap` 与分配大小不一致**（`ai_load_file`）
   只 `calloc(count)` 个元素，却把 `cap` 报成「严格大于 count 的 2 的幂」。
   下一次追加就写到分配区外面 —— ASan 报的是 `assocs` 数组堆越界。
   修法：**按 `cap` 分配**，并按同一条增长规则还原 `cap`。

4. **`ai_new()` 的临时池变成悬垂引用**（`ai_load_file`）
   原来先 `ai_new()` 再整体换池，而 `ai_new()` 已经把**旧池的符号节点** 写进表达池的边
   （`ai_init_expr_pools`）。换池后那些边指向已 `free` 的内存，几轮之后必炸。
   修法：读盘路径不再调 `ai_new()`，只 `calloc` 一个空 AI 骨架，所有符号节点都从快照
   池里长出来。

5. **`n_candidates` 被重复施加偏置**（`ai_load_file`）
   它是**基准值**，每轮由 `ai_exploration_bias` 在它基础上乘 bias。原来读盘时又把
   bias 算了一遍塞回去，基准从 3 变成 4，加载后的候选数和原地训练不一致 →
   对话轨迹分叉。

修完之后：**存 → 读 → 再存，两次 `model.bin` 字节完全一致；加载后跑同一段对话，
回复逐行一致，最终状态也逐字节一致。**

## 四、睡眠改成训练期内联

原来这三件事挂在交互循环的「空闲睡眠」上（`agent_step` 每 `sleep_every` 轮才
`ai_sleep_begin` 一次、每次只走一小步），**纯烧语料时永远不触发** —— 训练出来的图
就是很稀疏的初始态。

现在 `--batch` / `::batch` 按语料行数确定性推进，每 N 行内联做一轮：

1. **启发式巩固**：每个符号节点的边按 `hits` 重排，再整体 `* decay_factor`；
2. **抽象形成**：Jaccard ≥ 70% 的两个符号节点归到一个自动类别（`[抽象N]`）下；
3. **睡眠回放**：把这一段 `trace` 按 `0.9 / 0.1 / 深度 6` 再扩散一遍（等价 `ai_sleep()`，
   但不等空闲、不分帧）；
4. **遗忘**：按 `gc_interval` 周期跑 `ai_gc`。

运行时的交互式睡眠**仍然保留**（`agent_step` 里那段没删），只是训练不再依赖它。

实测（`seed_full.txt`，8088 行，`--interval 200`）：

```
[批量训练: 8059 行；睡眠回放 40 次，抽象 56 个]
[统计] Token=844  边=7176  已学=63885  抽象=56  睡眠=40
```

对照：不内联巩固的话是 `Token=784 边=2068`（每符号节点平均 2.6 条边），
现在是 **平均 8.5 条边**，图明显稠密了，生成也不再两三个词就断。

另外顺手修了一个生成瑕疵：`[表达:*]` 那套前缀脚手架（`应该/大概/可能/…`）
原来会被当成内容词再吐一遍，输出就成了「大概，猫人知道地上来了再见」这种带前缀
残留的句子。现在 `ai_pick_next_ex` 会把表达池符号节点排除在候选之外。

## 六、诚实的边界

- **否定语境 `subs_not[]`**：引擎和文件格式都支持（`token_add_assoc_not`，
  `entry_matches` 会检查），但 `token_lang.h` 的**语言层没有任何原语能构造它** ——
  只有 C API 和手写 `model.bin` 能建。要"一个功能不少"就得给语言层加个原语
  （比如 `[原语:除非]`），这属于新增功能，本次没做，留给你定。
- **关系标签**：边仍然是纯共现/带语境，没有 `猫 --[属于]--> 动物` 这种类型化标签。
- **`[原语:认为]` / 视角栈**：机制在，但当前语料只在 `pat_perspective` 里用了少量，
  生成时也没启用视角栈。
- **生成质量**：目前是 3–6 个词的短语，通顺度受限于语料本身（共现 + 模板）。
  把 `generated.txt`（5177 行纯共现）并进来会有可感知的提升，但语料本身的
  「是/像/做/所以」这类高频虚词会主导游走。
- **`token_pool_dump`/`token_pool_load`（`token.h` 里那对老函数）仍然只做符号图**，
  没有 tick/mem_state。本次没有删它们，`model.bin` 走的是 `model_io.h` 的新路径。

## 七、让它「能对话」：做了哪些事，到什么程度

### 7.1 之前为什么只会复读

原来的答非所问不是模型小，是**切词错位**：

- 语料里写的是 `[原语:对象] 猫 [原语:对象] 动物 [原语:连接]`，按空白切；
- `ai_tokenize`（用户输入走的路径）把 CJK **按字**切，`什么` → `什` + `么`；
- 于是「语料里的 `什么`」和「输入切出来的 `什`/`么`」是两个不同的符号节点，
  从输入尾词出发根本走不到学过的回复上。

修法：`ai_tokenize` 改成**词汇感知的最长匹配**，并加了一张固定词表 `AI_LEXICON`
（什么 / 因为 / 我们 / 喜欢 …）。语料构建和用户输入走同一条切词路径。
另外 `[原语:对象]`、`[对话:结束]` 这类方括号标记在切词时**整体成一个符号节点**。

### 7.2 新增对话语料

`traindialog.c` 生成 `dialog.txt`（1185 行），覆盖：

打招呼 / 自我介绍 / 提问（是什么·为什么·怎么·在哪·是谁·什么时候）/
索取请求 / 道谢道歉道别 / 情绪表达 / 喜好 / 因果解释 / 能力与记忆 /
附和否定追问 / 开放陈述 / 多轮小对话 / 问句尾词→回复首词的桥。

行格式统一是 `[原语:对象] <输入> [对话:结束] [原语:对象] <回复> [对话:结束]`。
用 `[对话:结束]`（不是 `[原语:分割]` / `[原语:连接]`）是因为后两个是**解释器原语**：
`PK_SPLIT` 清栈、`PK_CONNECT` 静默弹栈，标记本身不落图，学不到「回复到这里结束」。

一条命令复现：

```bash
sh tests/train_model.sh          # 生成语料 + 合并 + 批量训练 → model.bin
```

### 7.3 生成端的三处改动

1. **跨过边界**：`[原语:分割]` 是「输入/回复」的分界，游走时**放行但不输出**；
   原来它权重最高却是个死胡同，导致每条回复都被截断。
2. **收句**：走到 `[对话:结束]` 就结束 —— 句长来自学到的边界，不是猜步数。
3. **防环**：撞到已经走过的词就收句（共现图里有 `反义`/`什么` 这类小环，
   进去就会反复念同一个词）。

另外 `ai_edge_weight` 加了封顶（hits 实测能到 1e4 量级，线性权重会让游走
退化成「总走同一条边」）。

### 7.4 现在实际能到什么程度（诚实评估）

**能用**：

| 输入 | 回复 | 评价 |
|---|---|---|
| `你好` | `你好` | 对 |
| `谢谢` | `谢谢` | 对（礼貌应答的最短形式） |
| `再见` | `谢谢 对不起` | 部分对 |
| `我很难过` | `难过 …` | 情绪词接住了 |

**还是不行**：多词回复会漂。比如 `你好` 可能得到
`你好 请 你 说 话 坏 事 我们 为什么` —— 首词对，后面在图上漫游散了。

根因不在管线，在**表示**：这是一张共现图 + 加权随机游走的生成器，
不是序列模型。回复的「内部词序」和随便什么共现边同等存储，
一旦从回复首词走第二步，就可能被别处的高频边带走。
要真正通顺，得往「按语境约束的序列生成」走（比如把边按语境切分、
或给回复段单独的转移权重），那属于模型结构的改动，不是调参能解决的。

### 7.5 已验证

```bash
sh tests/model_roundtrip.sh _corpus.txt   # 存读无损 + 行为等价（含合并语料）
sh tests/features.sh                      # 十项能力 20/20
sh tests/train_model.sh                   # 从零复现 model.bin
```

**过程中为了让它可复现，又修掉一个真 bug**：`ai_form_abstractions` 每次最多建
3 个类别，所以「训练中途调用几次」会决定最终抽象数（同一份语料实测 55 vs 67），
训练路径和读盘路径的调用次数不同 → 加载后行为分叉。改成**训练收尾跑一次到不动点**
（`stabilize_abstractions`），两条路径才落到同一个集合。

## 八、按建议动手：给关联边加「角色」标签

第七节说的下一步是「给关联边加语境/位置标签」。这一步已经做了。

### 8.1 设计

`AssocEntry` 多了一个 `role` 字节：

| 值 | 含义 |
|---|---|
| `ASSOC_ROLE_NONE` (0) | 通用共现，没标过 |
| `ASSOC_ROLE_INPUT` (1) | 学自「输入段」内部（预留） |
| `ASSOC_ROLE_REPLY` (2) | 学自「回复段」内部，或「输入尾词 → 回复首词」 |

语料里每一行是 `[原语:对象] 输入 [对话:结束] [原语:对象] 回复 [对话:结束]`，
`reinforce_reply_slots` 会把：

1. **段内转移**（回复段里所有相邻 / 跳一个词的组合，窗口与
   `token_observe_names(window=3)` 一致 → 拿到的和观察到的是同一批边）；
2. **跨段主干**「输入尾词 → 回复首词」；
3. **收句**「回复最后一词 → `[对话:结束]`」

统统标成 `ASSOC_ROLE_REPLY` 并加权。

生成时有一个**角色寄存器**：从输入尾词出发时寄存器是 NONE，
一旦跨过输入/回复边界就锁死 REPLY，之后每一步只在回复角色的边里走。

### 8.2 选边的三层优先级

`ai_pick_next_role()` 按这个顺序挑，某一层有货就用它：

1. **目标角色 + 内容词** —— 回复内部的真实转移；
2. **通用角色 + 内容词** —— 目标角色没边时的兜底；
3. **边界标记**（`[对话:结束]` / `[原语:分割]`）—— 只能兜底。

第 3 层单独隔开是必须的：否则「吗 → `[对话:结束]`」会被当成一次正常续接，
句子刚开头就收了（实测过这个 bug）。

### 8.3 顺带修掉的三个真 bug

1. **`role` 字段没初始化**：`token_add_assoc_ex` 是新边唯一的创建点，加字段后
   忘了赋值，`::edges` 打出过 `角色=118` / `125` 这种栈上脏值。
2. **死胡同**：语料里 **320 行**的末尾都是 `[原语:分割]`，它**没有任何出边**。
   游走踩进去就断句。加了 `ai_can_continue_from()`：没有可用出边的词不算出路。
3. **自环**：`你好 → 你好` 这种 hits=0 的自环会被选中，走一步就撞环检测 → 截断。
   自环现在直接排除。

另外把 **hits==0 的边**挡在抽签之外：那些是「建了但从没在任何语料上下文里强化过」
的残留（解释器建的原语边等），带着权重 1 参与抽签只会带偏。

### 8.4 效果（诚实）

**明显变好的**：回复的**开头**现在基本是对的 —— 因为角色机制保证了第一步一定落在
「输入尾词 → 回复首词」这条主干上：

| 输入 | 回复 |
|---|---|
| `你好` | `你好 吗 我 从 家` |
| `谢谢你` | `你 在` |
| `再见` | `再见 谢谢 你 慢 下来` |
| `我很难过` | `难过 陪 慢 就 安静` |

**还是不行**：从第二个词往后开始漂。首词对、后面接不上，读起来像「说了一半」。

根因这次是**数据密度**，不是机制：角色子图虽然隔离干净了，但每个回复内部词的
角色出边平均只有几个，走两步就开始挑到不太相关的转移。要真正通顺，需要：

- 回复语料再扩一个量级（同一话题的回复互相之间也要连起来），
- 以及给「回复长度」本身建模（现在 `max_gen` 是写死的 4）。

机制这一层我认为已经到位了；剩下的是喂数据的事。

### 8.5 model.bin 格式升到 v2

`AssocEntry` 多一个字节，所以 `MODEL_VERSION` 从 1 升到 2。
**v1 老文件仍然能读**：loader 接受 `mver == 1 || mver == 2`，v1 的边缺 role 就按
`ASSOC_ROLE_NONE` 补上。两份回归在 v2 下都通过：

```bash
sh tests/model_roundtrip.sh _corpus.txt   # 存读无损 + 行为等价
sh tests/features.sh                      # 十项能力 20/20
```

## 九、继续扩语料之后（本轮）

第八节说剩下的瓶颈是「回复语料密度」。这一轮就扩了，并且又挖出四个真 bug。

### 9.1 扩了什么

`traindialog.c` 加了 `pat_topics()` 和 `pat_continuations()`：

- **14 个话题**（心情 / 在做什么 / 喜欢什么 / 害怕什么 / 想我吗 / 难过 / 开心 /
  你是谁 / 会忘我吗 / 累吗 / 能帮我吗 / 记得我吗 / 在想什么 / 我走了），
  每个话题 3 种问法 × 10~13 条自然回复；
- **同话题回复互为输入**——这是关键：让同一批词互相成边，
  而不是只把「问法 → 回复」连起来；
- **接话短句**：常见开头词 × 常见尾巴的笛卡尔积。

`dialog.txt`: 1185 行 → **3616 行**；合并语料 14421 → 16852 行。

### 9.2 又挖出四个真 bug

1. **`Topic` 数组开小了**（`r[14]` 装 10~13 条），编译器报 `excess elements`，
   超出的回复被静默丢弃。改成 `r[20]`。
2. **观察窗口是 3**，所以能打的角色边本来就不多——打角色用的窗口必须和
   `token_observe_names` 一致，两个都提到 **5**。
3. **词表太窄导致切词碎裂**：`满足` 被切成 `平`+`满`+`足`、`之前` 切成 `之`+`前`、
   `属于` 切成 `属`+`于`，`之前` 甚至不在表里。这些碎字成了角色子图里的噪声节点。
   改成**从语料里自动抽取全部多字 CJK 词**喂给词表（442 个词）。
4. **词表被我自己搞丢过一次**：重写词表块的正则匹配到的是「已经被替换过的」块，
   结果把原来 178 个基础功能词（你好 / 谢谢 / 再见 / 开心 / 知道…）全删了，
   于是这些词又退回单字切分。改成「语料词 ∪ 基础功能词」取并集重建。

### 9.3 效果

| | 第八节 | 本轮 |
|---|---|---|
| 合并语料 | 14421 行 | 16852 行 |
| 内容符号节点 | 757 | 884 |
| 平均角色出边 | 11.60 | 12.19 |
| 有 ≥3 条角色出边的词 | 337 | 376 |

回复开头明显更准了：

| 输入 | 回复 |
|---|---|
| `你好` | `你好 我在` |
| `我很难过` | `很难过 我 慢 休息` |
| `今天过得怎么样` | `怎么样 我 都 放松` |
| `你 在 做 什么` | `什么 海 软 是 你 因为 女人` |

**还是漂**。诚实说：扩语料让「开头」从 1 个词准变成 2~3 个词准，
但没有改变性质——从第三个词往后还是随机游走。

### 9.4 我的判断

机制这一层（角色隔离 + 三层优先级 + 死胡同/自环过滤）已经到位，
再往上不是「喂更多语料」能解决的：

- **要通顺，需要的是「按话题/意图约束解码」**，也就是先判断用户在问哪一类，
  再只在那一个话题的回复集合里生成。现在的角色标记是全局的一张子图，
  跨话题的边仍然互相竞争。
- 具体落地方式：给角色再加一维**话题 id**（`AssocEntry` 再多一个字节就够），
  生成时先用输入词投票选出话题，然后只在该话题的角色边里走。
  这是同一套机制的延伸，不是重写。

我没有继续做这一步——它需要先决定「话题」从哪来（语料里显式标注，
还是靠聚类自动形成），这是设计选择，想听你的意见。

```bash
sh tests/model_roundtrip.sh _corpus.txt    # 存读无损 + 行为等价 ✅
sh tests/features.sh                       # 十项能力 20/20 ✅
```

## 十、话题约束解码（选 A：语料显式标注）

第九节给的方案是「角色再加一维话题 id」。这一步做完了，而且是**语料显式标注**。

### 10.1 设计

`AssocEntry` 再加一个 `topic` 字节（`MODEL_VERSION` → 3）：

| 值 | 含义 |
|---|---|
| 0 | 无话题（`seed_full` / `generated` 那些通用共现语料） |
| 1..14 | 语料里 `[话题:N]` 块内学到的转移 |

生成流程：

1. **投票**：`ai_detect_topic()` 拿输入词去每个话题的词表里数命中数（词表在训练时由
   `[话题:N]` 块内的词自动累积），票数最高的话题胜出；
2. **锁定**：话题锁进 `ai->cur_topic`，整个生成过程只在**该话题**或**无话题**的边里走
   （`ai_pick_next_topic()`），跨话题的边一律排除；
3. **兜底**：如果本话题的边走不通，才放宽到无话题/其它话题的边（否则会饿死）。

话题表本身也要持久化，所以 `model.bin` v3 的 AI 层尾部多了一段
「每个话题的词 id 列表」。v1/v2 老文件仍能读（缺 topic 按无话题补）。

### 10.2 又挖出两个真 bug

1. **话题表没进快照**：我先把 `ai_topic_vote()` 接上了，但忘了写进
   `ai_snapshot`/`ai_load_file`。训练完内存里是对的，一存一读就全没了 ——
   表现是「训练时 ::topics 有 14 个话题，读了 model.bin 就一个都没有」。
2. **`strncmp` 判定死活不成立**：`[话题:N]` 的解析我写成
   `strncmp(line, "[话题:", 10)`。实测这行**字节完全正确**（`5b e8 af 9d e9 a2 98 3a`）、
   同一个比较在调试块里返回正确值，但函数里的判定始终失败（字节数到底该是 9 还是 10
   对不上）。改成**就地、用显式转义字节、长度 7 比 `话题:`**，一次就通了。
   教训：这种「字面量长度」的坑，别再靠数数，直接比可验证的字节序列。

### 10.3 效果：这是目前提升最大的一步

话题锁定之后，回复**全句都留在同一个语义域里**了：

| 输入 | 回复 |
|---|---|
| `你 能 帮 我 吗` | `吗 当然 帮 好` |
| `你 会 忘 了 我 吗` | `吗 想 我 最 住 东西` |
| `我 很 开心` | `开心 今天 什么 没 做 很 安静` |
| `你 在 做 什么` | `什么 没 放松 我 里 安静 今天` |
| `今天过得怎么样` | `怎么样 今天 来 平常 的 一天 我` |
| `我 要 走 了` | `了 再见 回来 我 走 时候 安静` |
| `你 是 谁` | `谁 有 时候 难过 我` |

对比第九节（话题未锁）：

```
你 在 做 什么   → 什么 海 软 是 你 因为 女人      ← 跨话题漂
今天过得怎么样   → 怎么样 我 整理 学 雨 空气 慢   ← 跨话题漂
```

现在这两句都落在「心情/日常」这个话题的词里（放松、安静、今天、平常、一天），
不再乱入「海/女人/雨/空气」。**这是从「词组级」到「主题级」的质变。**

仍然不完美：句子内部还是随机游走的产物，会出现
`吗 想 我 最 住 东西` 这种半通顺的搭配 —— 但它至少**在说同一件事**。
要再往上就是给话题内部也建一句一句的模板约束（相当于让回复长度/句式也带标签），
那是同一个思路的继续。

## 十一、句尾模式标签（本轮）

第十节末尾说「再往上就是给话题内部也加句式/长度标签」。这轮做了长度那一半。

### 11.1 设计

`AssocEntry` 再加一个 `pattern` 字节（`MODEL_VERSION` → 4）：

| 值 | 含义 |
|---|---|
| `NONE` | 没标 |
| `TAIL0` (1) | 这个词**本身就是句尾** |
| `TAIL1` (2) | 它后面**还有 1 个词**就结束 |
| `TAIL2P` (3) | 它后面还有 ≥2 个词 |

打标在语料构建时算：某一段（一段 = 一条完整的话）有 `plen` 个内容词，
第 `a` 个词的 `rest = plen-1-a`，按 `rest` 取值。生成时寄存器
`pat_from_cur` 记住「当前这个词在语料里离句尾还有多远」，到 `TAIL1` 就收尾。

为什么需要它：光靠「走到 `[对话:结束]`」判断收句是不够的 ——
那条边经常选不中，句子就会顺着共现边一直漂下去，这是之前
`吗 想 我 最 住 东西` 这类「越走越远」的直接原因。

### 11.2 坑

`ai_pick_next_role` / `ai_pick_next_topic` 得把「选中那条边的 pattern」
带出来，为此把角色选边拆成了 `_pat` 变体（原来只有一个返回值）。
拆的时候把包装函数放在了被包装函数**前面**，直接编译不过 —— 顺序又调了一次。

### 11.3 效果

| 输入 | 第十节（无 pattern） | 本轮 |
|---|---|---|
| `你 能 帮 我 吗` | `吗 当然 帮 好` | `吗 当然 帮 一 来` |
| `我 很 开心` | `开心 今天 什么 没 做 很 安静` | `开心 今天 里 安静 我 不错` |
| `你 在 做 什么` | `什么 没 放松 我 里 安静 今天` | `什么 做 放松 我 整` |
| `今天过得怎么样` | `怎么样 今天 来 平常 的 一天 我` | `怎么样 我 里 很 满足` |
| `你 是 谁` | `谁 有 时候 难过 我` | `谁 这样 时候 靠 我` |

句子**变短了**（少了尾部乱飘），而且开始出现真正的短语搭配：
`很 满足`、`不错`、`当然 帮`。

**但性质没变**：一条边携带的 pattern 是**它在某个语境里**的标签。
同一个词在不同回复里位置不同，它的出边就会带着互相矛盾的 pattern；
游走挑中哪条就按哪条收尾，所以仍会出现 `帮 一 来` 这种接不上的三词尾。

### 11.4 我的判断（就此打住）

到这里，机制层面能做的我认为已经做完了，一共四维标签：
**role（是不是回复段）→ topic（哪个话题）→ position（离句尾多远）**。
结果也确实从「答非所问」推进到「同一话题、长度可控、开头正确」。

再要提升，本质上需要**按整句记忆检索**（把语料里的整句当成候选，
用输入去匹配、直接吐一整句），而不是继续拆标签 —— 那是另一种模型，
不是这张共现图的调参范围。我不再往上加了，除非你明确要换那个方向。

```bash

sh tests/model_roundtrip.sh _corpus.txt    # 存读无损 + 行为等价 ✅
sh tests/features.sh                       # 十项能力 20/20 ✅
```

## 十二、换方向：整句检索（本轮）

第十一节末尾我说「再要提升本质上需要按整句记忆检索」。你点了这个方向，做完了。
**这是整条线上第一次让回复真正像人话。**

### 12.1 核心变化

之前所有努力（role / topic / pattern）都是在**改进逐词游走的约束**。
逐词游走的根本问题没变过：它只能用「边的局部权重」决定下一个词，走到第三个词就开始漂。

整句检索换的是另一件事：

> 把语料里的整句当成候选，用输入去匹配，匹配上就**把那一整句原样吐出来**。

这是「记忆复述」，不是「生成」。

### 12.2 数据结构

```c
#define AI_MAX_SENT 24
typedef struct {
    Token  *in[AI_MAX_SENT];  size_t in_n;   /* 输入句 */
    Token  *out[AI_MAX_SENT]; size_t out_n;  /* 回复句 */
    uint8_t topic;
} AISentPair;
```

语料是「`[原语:对象]` 输入段 `[对话:结束]` `[原语:对象]` 回复段 `[对话:结束]`」的线性结构，
所以**相邻两段天然就是「输入 → 回复」**。构建时把它们存进 `ai->pairs[]`，
`MODEL_VERSION` → 5，整句库进快照（AI 层尾部）。

### 12.3 匹配

`ai_sent_lookup()`：对库里每一条算 **Dice 相似度**
`2 * |交集| / (|输入| + |库里输入|)`（比 Jaccard 对短句更宽容），
命中话题的候选 +25 分，并列时用 rng 蓄水池抽样避免每次同一句。

阈值按话题置信度分档：

- 话题解析出来了 → `sc >= 60` 就用检索；
- **话题没解析出来 → 要求 `sc >= 85`**，否则退回逐词生成。

最后这条是必须的：话题没定的时候，检索分基本是噪声，
实测会挑出「你好 → 小孩 弱 反义」这种从 seed 片段里配出来的垃圾对。

### 12.4 本轮踩的坑（4 个）

1. **`in_seg` 在标记处理之前取值** —— 我用 `int cur_is_obj = in_seg;` 判断「这一段是不是对象段」，
   但 `in_seg` 要到循环体后面处理 `[原语:对象]` 时才置位，所以它**永远是上一段的值**。
   改成单独跟踪 `seg_is_obj`（段开始时清、遇到对象标记时置位）。
2. **`prev_closed` 只在 `cur_is_obj` 分支里赋值** —— 那个分支对普通段落根本不进，
   于是配对条件永远不成立，整句库恒为 0。
3. **写序与读序不一致** —— 写的时候是「话题表 → 整句库」，读的时候我先读了整句库，
   整个 AI 层流位移，读出来 `npair=0`。交换读写顺序后正常。
4. **`[对话:结束]` 的 `seg_closed` 判定时机** —— 冲刷发生在处理标记之前，
   等到底下再置位就晚了。

**最后我放弃继续纠缠布尔标记，改用「话题标注」作为唯一仲裁**：
`cur_topic != ASSOC_TOPIC_NONE` 才收进检索库。
话题块本来就是生成器里写死的「一问一答」，边界天然正确；
seed_full / generated 没有话题标注，直接不参与。这一下就收敛了。

### 12.5 效果 —— 质变

| 输入 | 回复 |
|---|---|
| `你好` | `你好 我 在` |
| `谢谢你` | `别 客气 有 事 你 说` |
| `我很难过` | `很难过 我 舒服` |
| `我 很 开心` | `今天 对 我 来 说 是 平常 的 一天` |
| `你 会 忘 了 我 吗` | `我 会 想 起来 的 只要 你 来 找 我` |
| `你 在 做 什么` | `我 在 看 书` |
| `今天过得怎么样` | `我 今天 心 里 很 安静` |
| `你 喜欢 什么` | `我 喜欢 陪 你 说 话` |
| `你 记得 我 吗` | `忘 了 别 的 也 会 记得 你` |
| `你 累 吗` | `我 累 的 时候 就 想 想 你 说 的 话` |
| `你 在 想 什么` | `我 没 想 什么 就 在 等 你` |
| `我 要 走 了` | `我 会 想 你 的` |
| `你 能 帮 我 吗` | `我 帮 你 我们 一起 想 办法` |
| `你 害怕 什么` | `我 怕 我 答 不 上 你 的 问题` |
| `你 会 想 我 吗` | `我 把 你 放 在 我 最 记得 住 的 地方` |

**这些是完整、通顺、切题的句子。** 对比第十一节（逐词游走）：

```
你 会 忘 了 我 吗 → 吗 想 我 最 住 东西
你 在 做 什么   → 什么 没 放松 我 满足
```

逐词游走那一层**仍在**，作为检索落空时的兜底（比如 `对不起` 这种没被
话题覆盖的输入，会得到 `对不起 谢谢 你 东西 我` —— 不完美，但不崩、不空）。

### 12.6 现在的边界

- **只覆盖被话题块写到的输入**。14+4 个话题之外的说法匹配不到，会退回逐词游走。
- **回复是语料里的原句**，不会自己组合出新句子 —— 这是「检索」的固有性质。
  想让它说出语料里没有的话，得回到生成侧（那是另一个方向）。
- 要扩覆盖面，**最快的办法是往 `traindialog.c` 的话题表里加条目**（我在本轮末尾
  补了「你好 / 谢谢 / 对不起 / 你还好吗」四个话题块）。

```bash
./build_aip    →  ::pairs 看检索库   ::topics 看话题表
```

## 十三、扩话题覆盖（本轮）

## 十四、换匹配器（本轮）

第十三节末尾说串话题的根因是「Dice 只看整词重叠」，得换匹配信号。这轮换了。

### 14.1 旧匹配器的病灶

`ai_sent_score` 原来是纯 Dice：`2 * |交集| / (|输入| + |库里输入|)`。

「你 能 帮 我 个 忙 吗」和「你 会 想 我 吗」共享 `你/我/吗`，
Dice 分数接近 → 话题投票选歪 → 整句串过去。
实测就是 `你能帮我个忙吗 → 我 会 想 你 想 到 你 回来`。

### 14.2 新匹配器：三路信号

```
sc = (cov * 55 + bg * 30 + dice * 15) / 100          // 0..100
```

| 信号 | 权重 | 作用 |
|---|---|---|
| **IDF 加权重合 `cov`** | 55 | 主信号。`你/我/吗` 这类高频词权重被压到 ~1，
`帮/想/抱` 这类只在少数话题出现的词权重到 2~4 |
| **字符 bigram `bg`** | 30 | 抓「换个说法问同一件事」：`你平常做什么` vs `你平时做什么`
词重叠只有一半，字符几乎全同 |
| **词级 Dice `dice`** | 15 | 短句兜底（「你好」这种没什么可加权的） |

**IDF 从整句库现算**：`df` = 该词出现在多少条「输入句」里，
`idf = 1 + ln((N+1)/(df+1))`，只在回复里出现的词（df=0）直接给 2.5。
不进快照，训练收尾和读盘收尾各重建一次。

### 14.3 效果：三个串话题案例全修

| 输入 | 旧（纯 Dice） | 新（IDF+bigram） |
|---|---|---|
| `你能帮我个忙吗` | `我 会 想 你 想 到 你 回来` ✗ | `当然 我 愿意 帮 你` ✓ |
| `我想抱抱你` | `没 关系 啦` ✗ | `你 想 我 的 时候 就 来 找 我` ✓ |
| `你会想我吗` | — | `我 想 你 的 时候 就 把 记 忆 再 走 一 遍` ✓ |

覆盖率：

| 探针集 | 第十三节 | 本轮 |
|---|---|---|
| 手写日常改述（50 条） | 86% | **100%** |
| 语料全部问法（306 条） | 100% | **100%** |
| 话题表原始问法（104 条） | 98.1% | 98.1% |

### 14.4 踩的坑

1. **前向声明的位置** —— 新签名带 `AI *`，而 `AI` 类型在 `ai.h` 后面才定义，
   把声明放文件开头直接编译不过。最后把「整句票」从 `ai_detect_topic` 里
   拆出来，放到 `ai_sent_score` **之后**定义（词表票留在前面，
   两票同场竞争的逻辑合并进后者）。
2. **`ai_char_bigram_score` 段错误** —— 原来靠「相邻字符指针相减」算 UTF-8 字符长度，
   越界时会读到垃圾长度，`memcmp` 直接踩空。改成**字符指针 + 长度双数组**，
   并在切字符时就不越过字符串结尾。
3. **词表与语料切法冲突**（上一轮遗留）—— 词表里的 `做什么` 让
   「你平常做什么」切成 3 个词、语料是 4 个词，Dice 只有 58 卡在阈值下。
   删掉该词表项后两边对齐。

### 14.5 现在的边界

- **匹配器已经够准**：50 条日常改述全部命中，且三条历史串话题案例全修。
- **回复仍是语料里的原句**。这是检索的固有性质 —— 想让它说出语料里没有的话，
  得回生成侧，那是另一个方向。
- **没覆盖的说法会退回逐词游走**（`::pairs` 里没相似的输入）。
  扩覆盖面还是加话题块最直接。

### 15.2 揪出的真 bug：两轮投票的尺度混用

补完之后测「你会支持我吗」，检索出来的是 `我 会 想 你`（想念话题）。

`ai_detect_topic` 的结构是：先按**词表**投票（得分 = 命中词数，2~4 分），
再按**整句相似度**投票，然后让整句票去翻盘。但两个比分**尺度完全不同**：

- 词表票：命中 4 个常用词 = 4 分；
- 整句票：把该话题下**所有**对的相似度**累加** = 5598 分（「想念」是大话题）。

于是「支持」话题（小，49 分）被「想念」话题（大，5598 分）压死。
修法是两处：

1. **每个话题取「库里最像那一条」的分数，而不是累加** ——
   累加奖励的是话题规模，取最大值才是「这个输入属于哪个话题」；
2. **整句票从零开始重比**，不拿自己的累加值去和词表票的命中数比。

修完：`你会支持我吗` → 话题 48，`我 一 直 支 持 你`（sc=103）。

这个 bug 从第十二节引入整句检索时就存在，只是之前大话题恰好都是正确答案，
一直没暴露。

## 十六、拒答能力（本轮）—— 不是「回生成侧」，是更该先修的东西

你问「回生成侧？」。我先实测了**检索落空时到底退化成什么**，结论和预期不一样：

```
地球为什么是圆的   → 我 想 让 你 开心
1加1等于几       → 先 喝 口 水 我 在 这 里
明天会下雨吗      → 下雨 的 时候 适 合 待 在 家里
```

**它不会说「我不知道」。** 任何输入都被硬塞一个最像的句子 ——
没覆盖的知识问题就变成瞎编。这比「不会造句」严重得多，而且**不是生成侧的锅**：
那些差输出全部来自检索强行应答（串话题那类已经在第十四节修掉了）。
所以这轮没回生成侧，先把「诚实」这件事做掉。

### 16.1 加了一个拒答门

```
接受一条检索结果要过四关：
  ① 总分 sc 够（话题命中 60，未命中 85）
  ② 输入覆盖率 cov ≥ 55
  ③ 不是「陈述句但 cov < 25」（那种硬答没意义）
  ④ 长度比 ≥ 0.45（|输入词数| / |命中输入句词数|，小除大）
任一关不过：**如果输入像问题就拒答**（轮换 6 种说法：「这个我不太懂」/
「我还学过这个」/「这个问我答不上」…）；是陈述句则退回逐词游走。
```

### 16.2 为什么要第四关（长度比）

第三关的 `cov` 单独用会被骗：实测「1加1等于几」（4 个词）`cov=55`，
其实是拿一个 `几` 去撞了一条长句。而真正该对应的记忆，输入句长度不会差太远：

- `你今天怎么样`(6 词) vs `我 今天 过得 很 充实`(7 词) → 0.86，过；
- `1加1等于几`(4 词) vs 8 词长句 → 0.5，不过。

### 16.3 一个必须说清楚的发现：**阈值分不开这两类**

我把四套对话探针（831 条，正样本）和一套知识问题探针（15 条，负样本）
的 `cov` 分布都量了出来：

| cov 阈值 | 对话保留 | 知识误答 |
|---|---|---|
| 45 | 99.4% | 12/15 |
| 50 | 99.2% | 12/15 |
| **55** | **98.4%** | **10/15** |
| 60 | 98.2% | 6/15 |
| 65 | 97.8% | 5/15 |

**即使把阈值提到 65，仍然有 1/3 的知识问题被误答，而对话质量已经掉了 2 个点。**
结论很明确：`cov` 这个信号**本质上分不开**「闲聊」和「问事实」——
因为两者用的都是同一批词。要真正分开需要语义层面（判断这是不是一个
需要外部知识的事实问题），不是调阈值能解决的。

所以我把阈值定在 **55**（折中点），并接受这个限制。

### 16.4 效果

```
【知识问题（该拒答）】
  地球为什么是圆的   → 这个我 不 太 懂          ✓
  什么是量子力学     → 我 还 没 学 过 这个       ✓
  1加1等于几       → 我 不 知道 你 能 告诉 我 吗  ✓
  明天会下雨吗      → 外面 有 云 但 我 觉得 很 好   ✗ 仍误答
  北京今天冷吗      → 我 今天 过 得 很 充实      ✗ 仍误答

【对话（该正常答）】
  你好呀           → 早上 好 今天 也 要 好 好 的   ✓
  我该怎么办        → 没 有 完全 对 的 选择 但 有 你 想 要 的 ✓
  我想哭           → 抱 一 下 你 虽然 我 抱 不 到   ✓
  我压力好大        → 先 停 一 下 深 呼 吸        ✓
  我没人说话        → 不 是 没 人 懂 是 还 没 遇 到  ✓
  你会支持我吗      → 你 比 你 以 为 的 强         ✓
```

**从「任何输入都硬答」变成「明显答不上来就诚实说不知道」。**
这是本轮最实在的收益 —— 正常交流里，会说「我不知道」比会编重要。

### 16.5 关于「回生成侧」的诚实回答

## 十七、上了生成侧：模板合成。**结论是触发太少，不够用**

你说「上生成侧」，我做了。诚实汇报：**机制建起来了、能量出效果，但在真实的新输入上触发率太低（1/13），不足以称为「会造句」。**

### 17.1 做法：同位槽类 + 模板替换

不是修随机游走（它天生会漂），而是**模板合成**：

1. **同位槽类** `ai_slots_build()`：从整句库里归纳「占据相同句法位置」的词。
   签名 = 紧邻左邻 + 紧邻右邻 + 是否句尾。于是
   `我 喜欢 猫` / `我 喜欢 狗` 里的 猫/狗 归一类（左邻都是 喜欢、右邻都是句尾），
   而 `猫 吃 鱼` 里的 猫 是另一类。
2. **模板替换** `ai_synthesize()`：找一条最像的语料记忆，如果输入和它的差别是
   「干净的 n↔n 同位词替换」，就把回复里对应的词也换掉 ——
   于是产出一句**语料里没有、但骨架是学来的**句子。

### 17.2 触发条件（试了三轮才定下来）

| 规则 | 合成命中 | 结果质量 |
|---|---|---|
| 任意同位词都可替换 | 34/50 | **差**：「我 不 走 对 放心」「不 用 我 歉」 |
| 干净的一换一（各自恰好 1 个未匹配） | 2/50 | 好，但几乎不触发 |
| n↔n 一一对应 + 长度相近 + 每个未匹配词同位 | 1/13（真新输入） | 好 |

中间走了两次弯路，都记在这里：
- **槽位签名用左右各 4 个邻居** → 1 万多个签名塞进 128 个类，几乎每类一个成员，
  「同位」永不成立（1/50）。改成只用**紧邻**邻居才对。
- **只在位置对齐处找差异** → 长度不同时对齐没意义，永远找不到（0/10）。

### 17.3 为什么触发率上不去

看 debug 就清楚了。对真新输入「你害怕水吗」，匹配到的最像模板**就是**
`你 害怕 水 吗`（语料里已有）—— 两边未匹配词都是 0，**没有槽位可换**，跳过。

因为 `traindialog.c` 里每个话题都写了 3~5 种问法，这些问法已经覆盖了
用户绝大多数自然的措辞；剩下真正没覆盖的说法，往往连最像的模板也不构成
「只差一个词」的关系，所以合成不触发。

**这是本质限制，不是调参问题**：模板合成要求「骨架已被学到、只差槽位」，
而我们的语料已经把那层骨架覆盖掉了。

### 17.4 能触发的例子（证明机制是活的）

```
新输入: 你最怕什么   → 我 怕 学 会 一 件 新 事情
        （语料里没有「你最怕什么」这一对；它拿「你 害怕 什么 → 我 怕 …」
          做了 什么↔最 的槽位替换）
```

### 17.5 我的判断：这条路在当前架构下收益很低

- **检索侧已经是强项**：四个探针集 98~100%，回复通顺切题，还会诚实拒答。
- **生成侧要真正产出新句子**，需要的是「按语境约束的序列生成 + 模板/槽位的
  组合式表达」，也就是要把回复表示成**结构**（谁-做什么-对谁），
  再按结构组合 —— 那是换表示，不是在这张共现图上加机制。
- 我**没有**继续往那儿推，因为那等于重写认知层，风险和工程量都和前面几轮
  不是一个量级；而且当前版本已经能「正常交流」。

**所以我把模板合成就保留在这里**（代码在、能触发、有统计 `ai->n_synth`），
但**没有让它在正常对话里抢答** —— 只在满足严格条件时才用，避免产出病句。

## 十八、评估「把回复表示成结构再组合」—— 先算，再决定

你问这条路怎么样。我没直接写代码，先**量了语料里到底有没有帧和槽位结构**，
因为这条路成不成，完全取决于语料能不能被归纳成「帧 + 槽位」。

### 18.1 什么是「结构再组合」

把回复从**扁平词序列**改写成**带槽位的帧**：

```
现在的表示：  「我 喜欢 猫」        （一串词）
结构表示：    帧[我 喜欢 {喜欢物}]  槽位{喜欢物} = {猫, 狗, 花, 音乐, …}
```

匹配到「你 喜欢 {X} 吗」就答「我 喜欢 {X}」，`{X}` 从槽位类里取 ——
于是能说出语料里没出现过的具体组合，而句子永远是合法帧。

### 18.2 实测：我们的语料**没有**这个结构

我写了 `tools/structprobe.py` 直接分析 54 个话题块（543 条回复）：

| 检查项 | 结果 |
|---|---|
| 同话题内 **问法变体**的长度一致性 | 188 对里只有 **60 对（32%）** 长度相同 |
| 同话题内 **回复池**能被单个粗帧覆盖的比例 | 中位数约 **20%**（最高 75%，最低 10%） |
| 天然槽位规模 | 419 个左邻词，平均每个后面可接 4.0 个词 |

举实际例子最清楚。同一个话题的三种问法：

```
你在做什么      你 现在 忙 吗      你 有 空 吗
```

**它们不共享任何帧** —— 长度、词序、用词全都不同，是三个独立说法。
回复池也一样，10 条回复能被同一个「首词+长度」帧覆盖的通常只有 2 条。

为什么？因为 `traindialog.c` 是我**手写**的自然说法集合，写的时候追求的是
「像人话、覆盖多种说法」，**天然就是长尾、无模板的**。
结构表示要求的是相反的语料：同一帧的多个实例。

### 18.3 所以这条路要付的代价

不是「加个机制」，而是三层一起动：

1. **语料要重写**成结构化的（每个话题一个帧 + 明确的槽位取值），
   否则归纳不出帧 —— 这一条是硬前提，现有 543 条回复基本作废；
2. **模型要加结构层**：帧表 + 槽位类 + 「输入对齐到帧」的匹配器；
3. **回复要改成从结构渲染**，`AISentPair` / 检索 / 合成那套要换表示。

工作量 ≈ 前面所有轮次的总和，而**收益不确定**：结构化之后回复会变「工整」，
但也可能变**呆板**（同一帧反复套），未必比现在像人话。

### 18.4 我的建议（三选一）

| 选项 | 做什么 | 代价 | 我的判断 |
|---|---|---|---|
| **A. 停在这里** | 保持现状：检索为主 + 拒答 + 严格条件下的模板合成 | 0 | **推荐**。四个探针集 98~100%，通顺切题，会诚实说不知道 |
| **B. 小范围试点** | 只挑 3~5 个高频话题，手写结构化语料，量一下「结构化后的回复是否更像人话」 | 中（约 1 轮） | 想验证收益就先做这个，**不要一上来重写全部** |
| **C. 全面结构化** | 重写语料 + 加结构层 + 换表示 | 大 | 收益不确定，风险最高 |

我倾向 **A**，如果你对「会自己造句」有明确需求，就先走 **B** 拿数据说话。

**你定，我照做。**

## 十九、C 方案：全面结构化（本轮完成）

按你的选择走了 C：**把回复表示成「帧 + 槽位」再组合**。这是这条线上第一次让系统
**说出语料里根本没写过的句子**，而且骨架合法、句子通顺。

### 19.1 做了什么

新增三个文件：

| 文件 | 作用 |
|---|---|
| `trainframes.c` | 结构化帧语料生成器（10 个帧） |
| `frames.txt` | 帧语料（人类可读的行式格式） |
| `frame.h` | 结构层：帧表 + 槽位 + 匹配 + 渲染 |
| `frame_io.h` | 把帧库挂到 AI 上（读/释放/生成入口） |

**帧格式**：

```
[帧:喜欢X吗]
[问] 你 喜欢 <X> 吗
[问] 你 觉得 <X> 怎么样
[答] 我 喜欢 <X>
[答] <X> 很 好
[填:X=猫,狗,雪,月亮,...]        ← 槽位允许填充的集合
---
```

**生成流程**：输入 → 匹配问法骨架（**严格位置走法**：固定词必须逐字对上，
槽位吸收中间的词）→ 取出用户的槽位取值 → 选回复模板 → 渲染。
**输出的是新句子**，因为模板里的 `<X>` 被填成了语料里没这样配过的词。

覆盖 10 个帧：喜欢/害怕/记得/想学/知道/二选一/状态/陪伴/程度/位置。

### 19.2 效果：真的会造句了

```
你喜欢雪吗   → 我 喜欢 雪          ← 语料里没有这一对
你怕黑吗     → 我 怕 黑
你知道量子吗 → 我 知道 量子
你想学画画吗 → 我 想 学 画画
你记得月亮吗 → 我 记得 月亮
你害怕水吗   → 我 怕 水
你怕孤单吗   → 我 怕 孤单
你想学唱歌吗 → 我 想 学 唱歌
你喜欢旅行吗 → 我 喜欢 旅行
你知道数学吗 → 我 知道 数学
```

**10/10 都是语料里没有的句子**，而且都通顺。

### 19.3 过程中修掉的一串真 bug（都记下来）

1. **`strdup` 不是 C11 标准** —— 自己写 `fr_dup`。
2. **前缀长度手数错** —— `[帧:` 是 5 字节我写成 7；`[填:`/`[问] `/`[答] ` 同理。
   教训：一律用 `strlen` 或显式字节比较。
3. **`[答]` 的字节偏移错** —— '答' 紧跟在 '[' 后面占 `line[1..3]`，
   我写成从 `line[2]` 起判，读的是第 2 个字节，**永远为假**
   （于是所有回复模板都被当成问法）。
4. **哨兵字符串表示槽位** —— 用 `\x01X\x01` 当标记，结果踩了字符串长度/字节偏移的坑，
   槽位识别一直失败。**改成直接存「每个位置的槽位下标」**，一次就对了。
5. **`[填:]` 声明写在 `---` 之后** —— `---` 会清掉「当前帧」，声明直接丢。
   改成帧内输出。
6. **全局声明没接到槽位上** —— 声明进了 `fs->decl`，但槽位自己的 `n_fill` 是 0，
   白名单形同虚设。改成「帧自己的声明优先，否则用全局」。
7. **LCS 对齐太松** —— 「你 会 支持 我 吗」会撞进「你 想 学 <X> 吗」
   （你/我/吗 三个虚词恰好对上）。换成**严格位置走法**：固定词必须逐位相同。
8. **槽位取值可能是多个词** —— 「画画」是 画+画 两个符号节点，
   单符号节点存不下。改成 `FrValue{tok[], n}`。
9. **对齐强度没门槛** —— 「太阳 离 我们 多 远」被「你 会 <X> 吗」整个吞进槽位，
   产出「远 别 事 的」。加了「固定词数 / 输入词数 ≥ 1/3」。
10. **扁平合成（`ai_synthesize`）会把动词当名词填** ——
    「你会支持我吗 → 我想学支持我」。**已停用**（代码保留），
    结构化帧用「允许填充集合」把这件事做对了。

### 19.4 诚实的边界

- **帧只覆盖 10 类问法**。没落进这 10 类的输入，走回原来的检索 + 拒答路径。
- **帧的槽位是「词」级别**，没有真正的句法树（谁是主语、谁是宾语）。
  想表达「A 对 B 做了什么」这种双槽结构，需要再加帧。
- **有一个已知的残留问题**：某些长问句（如「太阳 离 我们 多 远」）会落到
  逐词游走的兜底，产出「远 别 事 的」这种碎片。单独调用帧生成器时它正确地
  拒绝了，但应用内的路径仍有别的地方接管。**这个我没修完**，据实记录。
- **扁平合成已停用**：它没有槽位语义约束，会把动词当名词填。

## 二十、修掉残留问题 + 扩帧到 16 个（本轮）

两件都做了。

### 20.1 残留问题：定位到「逐词游走兜底被误放行」

用 `PATHDBG` 打路径，一下就看清了：

```
PATHDBG 检索后 resp=无 cov=43
PATHDBG is_question=0 cov=43 frames=有
PATHDBG → 逐词游走
AI > 远 别 事 的
```

「太阳 离 我们 多 远」：

- `is_question=0` —— 它不含 吗/呢/什么/怎么/哪… 这些问句词，被判成陈述句；
- `cov=43` —— 高于 25 的门槛，于是没走拒答；
- 帧也匹配不上（正确拒绝）→ 落到**逐词游走**，游走临场拼出「远 别 事 的」。

**根因**：`cov` 是 IDF 加权的，会被「一个少见词命中」抬起来 ——
这句话里其实只有 `远` 一个词真的在命中的记忆里出现过，却算出 43。

**修法**：加一个**词命中比例** `last_token_ratio`（命中的输入句里，
有多少比例的输入词真的出现过），并把它作为游走兜底的门槛：

```
允许逐词游走 ⇔ 不是问句 且 cov ≥ 25 且 词命中比例 ≥ 50%
```

改完 `太阳离我们多远 → 这个我 不 太 懂`（正确拒答），
而正常的陈述句（「我今天去公园了」）仍然能接话。

### 20.2 扩帧：10 → 16，并加了双槽结构

新增 6 个**双槽**帧 —— 之前的帧只换一个槽位，现在能同时换主语和动作/宾语：

| 帧 | 问法 | 例 |
|---|---|---|
| `Z会X吗` | `<Z> 会 <X> 吗` / 你觉得… | `你觉得猫会游泳吗` → `我 觉得 猫 会 游泳` |
| `Z在做什么` | `<Z> 在 做 什么` | `猫在做什么` → `猫 在 看 书` |
| `Z有X吗` | `<Z> 有 <X> 吗` | `你有书吗` → `你 有 书` |
| `Z喜欢X吗` | `<Z> 喜欢 <X> 吗` | `老师喜欢花吗` → `老师 喜欢 花` |
| `Z和Y哪个好` | `<Z> 和 <Y> 哪 个 好` | （这条还没匹配上，见下） |
| `如果Z会X` | `如果 <Z> 会 <X> 就 好 了` | `如果我会画画就好了` → `如果 我 会 画画 那 真 好` |

新增三类允许填充集合：`ENT`（我/你/他/老师/学生/猫/狗…）、
`ACT`（吃/喝/看/想/学/唱/画/游泳/唱歌…）、`OBJ` 扩充（旅行/咖啡/电影/颜色/季节…）。

**双槽替换举例**（两句都是语料里没有的）：

```
你觉得猫会游泳吗 → 我 觉得 猫 会 游泳     （<Z>=猫, <X>=游泳）
```

## 二十一、补全比较帧 + 扩到 22 个帧（本轮）

### 21.1 修掉 `Z和Y哪个好` 匹配不上

两处问题：

1. **模板里写「哪 个」，切词器却把「哪个」当一个词** ——
   模板和真实输入对不上。改成写「哪个」。
2. **`frame2(..., ask, 3, ...)` 的数字是手写的** ——
   我把问法数组从 3 条加到 6 条，但那个 `3` 没改，
   于是**只输出了前 3 条**。改成 `sizeof ask / sizeof ask[0]`，
   并把所有帧的调用统一改掉，以后加问法不会再漏。

改完 `你觉得猫和狗哪个好 → 我 觉得 猫 更 好`、`猫和狗哪个好 → 我 觉得 猫 更 好`。

### 21.2 又发现一个设计点：槽位吸收长度要设上限

「你 觉得 猫 和 狗 哪个 好」里，如果放任 `<Z>` 吸收 3 个词，
它会去撞更短的模板「`<Z>` 和 `<Y>` 哪个 好」，把 `<Z>` 填成「你 觉得」——
产出「我 觉得 你 觉得 猫 更 好」。

修法：给槽位加 **`max_len`**（最多吸收几个词，默认 2）。
实体/动作这类槽位本身就只有 1~2 个词，超过就不该匹配。
同时给比较帧加了「`你 觉得 <Z> 和 <Y> 哪个 好`」这条前缀变体，
两条一起才能对得上。

## 二十二、混合模式：思考与输出分开（本轮）

第二十节说「回复改由检索/帧产出，逐词关联链事实上被门槛停用了」。
这一轮把它救回来了 —— 但不是靠放松门槛，而是**分成两条通道**。

### 22.1 设计

```
每一轮 agent_step：
  ① 内部思考：先跑一次关联链（ai_plan_and_act）
       产物 → ai->last_idea       ★ 默认不决定回复
  ② 决定输出：结构化帧 → 整句检索 → 拒答 → （可选）关联链
```

关键点：**想什么**和**说什么**解耦。
联想这个能力一直活着（每轮都在想、可以随时查看），
但它不再有权把碎片当回复吐出来。

### 22.2 新命令

| 命令 | 作用 |
|---|---|
| `::free [词]` | 自由联想：只跑关联链，打印**结果 + 走出来的路径**；不给词就看上一轮的内部联想 |
| `::walk [on\|off]` | 是否让联想**直接决定输出**（默认 off） |

### 22.3 实测

同一条输入，两个通道分开：

```
输入「你好呀」
  输出      → 嗨 我 在                   （检索/帧）
  内部联想  → 呀 开心 见 到 好 早 休息     （关联链）
```

主动联想并看路径：

```
::free 猫
  自由联想 → 猫 看 大人 好 要 什么
  路径     → 猫 看 大人 好 要 什么
```

路径必须和产物是同一条链。原先打印的是 `ai->last_path`，而它是
`ai_plan_and_act` 循环里**最后一条**候选的路径（不是被选中的那条），所以
老版本会出现「产物 `猫 看 大人 好 要 什么` / 路径 `猫 所以 天 不错 呢 不 走`」
这种对不上的怪现象。修法：新增 `ai->last_walk_path`，在候选成为 best 的那一刻
快照 `last_path`，`::free` 打印它；模型刚加载还没游走过时退回 `last_path`。
这个字段是诊断用的，不写进 `model.bin`（格式保持 v5 不变）。

开关效果：

```
::walk on   → 你喜欢雪吗 → 吗 小 很 安静     （关联链产物，碎片感明显）
::walk off  → 你喜欢雪吗 → 我 喜欢 雪         （结构化帧，通顺）
```

`ai_stats` 里加了 `帧生成=N  逐词游走=N` 两个计数，能看出两条通道各跑了多少次。

### 22.4 这样解决了什么

| 之前 | 现在 |
|---|---|
| 关联链被门槛挡死，等于停用 | **每轮都在跑**（内部思考），`::free` 随时可查 |
| 想「自由联想」只能放宽门槛，代价是碎片输出 | 想看就看、想用就 `::walk on`，**默认不影响对话质量** |
| 两条路径非此即彼 | **混合**：内部联想 + 结构化输出 |

### 22.5 验证

```bash
sh tests/model_roundtrip.sh _corpus.txt    # 存读无损 + 行为等价 ✅
sh tests/features.sh                       # 十项能力 20/20 ✅
sh tests/frames.sh                         # 帧生成 27/28 ✅
# 交互里： ::free 猫    看联想与路径
#          ::walk on    让联想直接输出
#          ::walk off   回到默认
```

## 二十三、结构化帧读关联链产物（Gate B）

上一节把「联想」和「输出」解耦了，但两件事仍然是**各干各的**：帧用
`frames.txt` 里手写的槽位白名单，关联链在后台自己走。这一节是让帧**真的去读**
关联链里的东西。

### 23.1 问题：白名单是手写的，关联链是学出来的

`fr_generate` 原本只认白名单：

```c
if (!fr_in_set(set, nset, fill[k].tok[0])) bad = 1;   /* 名单外一律拒绝 */
```

名单是 `trainframes.c` 从语料里**抽**出来的 21~49 个词，抽到就认、没抽到就退回避。
于是：

```
你 知道 老师 吗   →  名单里没有「老师」  →  不认这个帧  →  退回检索
检索给的          →  「应该，这个我 不 太 懂」（其实是拒答）
```

而图里明明有「老师」这个符号节点，也明明记着它和白名单里的词邻居很像 ——
都是「可以知道/喜欢的对象」。这份证据一直没被用上。

### 23.2 先量化：关联链里到底有没有可用的证据

写了个探针 `tools/slotprobe.c`，在真模型上量了三件事，结论是**有的能用量不了**：

| 证据 | 结果 | 能不能用 |
|---|---|---|
| 句尾模式 `TAIL1`（X 后面正好接一个词） | `喜欢→老鼠/月亮/山/海`、`吃→饭`、`怕→危险/黑/孤单` 全对 | **很准，但太稀**：只在「动词是倒数第二个词」时才成立 |
| 句尾模式 `TAIL2P` | `喜欢→安静(2690)/天(1849)/说(1894)` —— ±5 窗口串味 | ❌ 噪声太大 |
| 前一个固定词的出边（`会→支持`） | **无边**。语料里问答两段被 `[原语:…]` 切开，跨段共现几乎不存在 | ❌ 用不了 |
| **与白名单示范词的邻居重叠**（Dice） | 对 `[帧:想X吗]` 的 21 词示范集：`支持 47 / 理解 66 / 保护 66 / 告诉 42`，`照顾 16 / 昨天 29` | ✅ **用这个** |

第三个证据值得多说一句：**类要够宽才有用**。同一批词拿去比「7 个动词示范」
（唱歌/画画/游泳/写字/做饭/读书/跳舞）就塌了 —— `保护 0`、`理解 0`，因为它们和那
7 个词**一条邻居都不共享**。真正生效的 `[帧:想X吗]`/`[帧:知道X吗]` 示范集是
19~24 个**混装**词（动词+名词都有），邻居面铺得开，Dice 才有分辨率。

`stat` 模式还画了全图分布，确认阈值不是拍脑袋（`[帧:想X吗]` 的 X 示范集 21 个词）：

```
分数桶:  0-9:248  10-19:212  20-29:265  30-39:99  40-49:55
        50-59:43  60-69:14   70-79:3    80-89:22  90-99:11  100-109:12
```

（100 分档就是示范词自己。≥40 的约 160 个词，而这个槽位声明的示范词是
**21** 个 —— 过了阈值就相当于把可填词表扩了约八倍。）

阈值 40 不是拍的：`因为 55 / 很 41 / 不 59` 这些虚词的分数**比好词还高**，
所以光靠阈值分不开，必须再加 ① 号门把它们挡掉（见下）。

### 23.3 Gate B 的三重门

白名单落空时才启用，三道门全过才放行：

```c
① 候选必须是实词     —— FR_FUNC[] 挡住 因为/很/不（它们邻居天然和别人像，
                        能拿到 40~60 分，填进槽位就是病句）
② 候选必须是成形词   —— 至少两个汉字、不以 吗/呢/吧/了/的 收尾
                        （「顾」「信」这种切词碎片、「累了吗」这种碎片，
                         分布分数同样虚高）
③ 与示范集的 Dice ≥ 40
```

还有一条**跨度规则**同时修掉了（这个更容易出错）：

```c
/* 你 会 支持 我 吗 —— 模板「你 会 <X> 吗」会找上「吗」，
 * 于是 <X> 吞掉「支持 我」两个词，渲染成「我 想 学 支持 我」。
 * 槽位取值是名词/动词短语，里面不该夹着光杆代词或助词。 */
if (take > 1) { 吞进去的每个词都必须是内容词，否则本次匹配作废 }
```

### 23.4 顺带修掉的第三个坑：答案模板选择

改动 Gate B 之后，「你会支持我吗」又答成「我 想 学 支持 我」了 —— 这次不是槽位
问题，是**答案模板挑错**。挑法前后改了三版，每次都换出一个新坑：

| 挑法 | 「你 会 <X> 吗」选到 | 「你 知道 <X> 吗」选到 | 「你 在 学 <X> 吗」选到 |
|---|---|---|---|
| 只比「新实词少」 | ❌ `我 想 学 <X>`（和 `我 会 试 着` 平票，取第一条） | ✅ `我 知道 <X>` | ✅ `我 在 学 <X>` |
| 改比「共用词多」 | ✅ | ❌ `你 能 给 我 讲 讲 <X> 吗`（你/吗 两个虚词共用） | ✅ |
| 只比实词、但按出现次数 | ✅ | ✅ | ❌ `我 学 <X> 学 得 很 慢`（学 出现两次） |
| **共用不同实词多 → 新实词少 → 总新词少** | ✅ | ✅ | ✅ |

现在 `frame.h` 里那段注释把三次都记下来了，免得以后又改回去。

### 23.5 实测 A/B

`tests/framegate_ab.sh`（模型不变，只切开关，两边并排打；每条探针独立加载模型）：

```
  输入              | framegate=on            | framegate=off
* 你怕老师吗        | 我 怕 老师               | 我 怕 我 记 不 住 你
* 你知道动物吗      | 我 知道 动物             | 我 喜欢 鸟 因为 会 唱 歌
* 你知道老师吗      | 我 知道 老师             | 这个我 不 太 懂        ← 原来是拒答
* 你知道天气吗      | 我 不 知道 天气          | 这个我 不 太 懂        ← 原来是拒答
* 你喜欢安静吗      | 我 喜欢 安静             | 小 动物 让 人 放 松
  你喜欢雪吗        | 我 喜欢 雪               | 我 喜欢 雪            ← 白名单，必须一致
  你怕黑吗          | 我 怕 黑                 | 我 怕 黑
  你知道量子吗      | 我 知道 量子             | 我 知道 量子
  你在学画画吗      | 我 在 学 画画            | 我 在 学 画画
  你觉得天气怎么样  | 我 觉得 天气 很 好       | 我 觉得 天气 很 好
  你会支持我吗      | 不 管 你 选 什么 我 都 站 你 这 边 | （同左）
  你喜欢那么吗      | 我 喜欢 鸟 因为 会 唱 歌 | （同左）
```

- **Gate B 改变了 5/15 句，5 句全是改善**（原先是跑题或拒答）；
- 白名单内的句子两通道**逐字一致** —— 证明 Gate B 只在 Gate A 落空时才动手；
- `framegate=off` 时放行次数必须是 0（测试里有断言）；
- 最后两行是**反面看护**：`你会支持我吗` 不许答成「我 想 学 支持 我」（跨度规则），
  `你喜欢那么吗` 不许答成「我 喜欢 那么」（虚词表 —— 那么 的分布分数 56，
  比不少实词还高，光靠阈值分不开）。

> 为什么每条探针要单独加载模型：这个 agent 会**边聊边学**，上一条回复不同 →
> 图里多出来的边不同 → 后面几条的检索结果跟着变。不隔离的话，A/B 表里会混进
> 「对话级联」的差异，看不出到底是谁的功劳（这一版之前就混过一次）。

### 23.6 局限（据实记录，别当它能包治百病）

1. **图里没有任何证据的词救不了。** `火锅`/`火车` 这种，整词从没出现过，但
   `火` 在语料里有 174 条边 —— 于是能靠 `火` 的证据拼回整词（见第二十四节）。
   而 `北京`（`北`/`京` 各 0 条边）、`钢琴` 这种**每个部件都没证据**的，
   哪条通道都没辙：没有依据就不该硬接。
2. **语义精度会松。** 类是从邻居分布估的，所以 `你怕安静吗 → 我 不 怕 安静`
   （44 分，过了阈值）说得通但不自然；`你认识理解吗 → 我 认识 理解 你 呢`
   就是妥妥的病句。这是「扩覆盖面」的代价，不是 bug。
3. **稀疏词会被拒。** `危险` 只有 1 条出边，Dice 恒为 0，`你怕危险吗` 过不去 ——
   宁可不动也不乱放行。
4. **这不是「谁分数高用谁」。** 输入里的词是用户给的，Gate B 只回答「用户说的这个
   词，像不像这个槽位该有的词」，不做候选排序。

## 二十四、现场造词：没有就创建，然后现场关联

### 24.1 问题：切词器把没见过的词切碎了

`你吃火锅了吗` 的符号节点序列是：

```
你 / 吃 / 火 / 锅 / 了 / 吗        ← 「火锅」被按字切开
你 / 吃 / 饭 / 了 / 吗              ← 对照组：饭是认识的词
```

切词器对没见过的词只能按字切（`ai_tokenize` 的最长匹配在语料词典 + 词池里找不到
「火锅」）。于是模板 `你 吃 <X> 了 吗` 的槽位 `<X>` 拿到的是**两个单字**，帧要么
答出「我 吃 了 火 锅」（两个字中间带空格，一眼就知道是切碎的），要么被 Gate B
挡掉（单字 火 过不了「至少两个汉字」那道门）。

### 24.2 用户的这句话本身就是证据

「火锅」这个词系统没见过，可是**用户把它放在了「你 吃 `<X>` 了 吗」的 X 位上** ——
这就是一次标注：火锅是能吃的东西。加上 `火` 在图里本来就有 174 条边、和食物类
的 Dice 是 89，证据是够的。所以当场就能：

```
拼回整词 → 进池子 → 现场关联（接到该槽位全部示范词上，正反两向）
        → 记进白名单（帧的填充表在对话里长大）
```

实测效果：

```
你 吃 火锅 了 吗  →  我 吃 了 火锅          ← 一个新词，一句新话
::think 火锅      →  思考 1 个词，边=17      ← 它已经是一个整体 Token
（再问一遍）       →  我 吃 了 火锅          ← 这次走白名单，不再造
::save / ::load    →  我 吃 了 火锅          ← 重载后仍然认得出
::coin off         →  我 吃 了 火 锅          ← 关掉开关就退回按字
```

### 24.3 三道自我约束（都是拿血换的）

**① 只有「整段都是单字」才是切词产物。** 这是最要紧的一条。少了它，模板
`你 <X> 吗` 会把 `怕危险`、`知道天气` 整个吞进 X 位，再拼成新词答出去：

```
少了这条判据的实测后果：
  你 怕 危险 吗    →  我 不 怕危险            ← 把「怕+危险」拼成了「怕危险」
  你 知道 天气 吗  →  我 不 知道天气          ← 同理
加上「整段都是单字」之后：
  火/锅 都是单字 → 是切词产物 → 拼 ✓
  怕(单字)+危险(两字词) → 不是切词产物 → 不拼 ✗
  知道/天气（都是词）    → 不是切词产物 → 不拼 ✗
```

**② 至少要有一个部件的图证据够格。** `火锅` 靠 `火`（Dice 89）过关；
`北京` 的 `北`/`京` 在图里**各 0 条边**，没有任何依据，就不硬接 —— 宁可不答。

**③ 「类成员」得是真的接过线，不能靠邻居像。** 一开始我用的是普通覆盖率
（候选的出边盖住多少示范词），结果 `天气` 的出边里一大半正好是「知道X吗」的
示范词，覆盖率算下来 60%+，于是 `你知道天气吗` 被放进 X 位答「我 不 知道天气」。
改成只认**造词时接的那种角色** `ASSOC_ROLE_COINED` 之后，覆盖率就只对真的接过线
的词成立：造的时候 100%，而且 role 字节是写进模型的，**重载后仍然 100%**。

### 24.4 新增的 role 值

```c
ASSOC_ROLE_COINED = 3,   /* 现场造词时接的「类成员」边：新词 ↔ 该槽位示范词 */
```

单独一种角色换来一个**精确**判据。角色字节本来就在 v2+ 的模型格式里持久化，
所以不需要改格式版本 —— `model.bin` 仍是 v5。（代价：保存后文件会长一点，
本次实测 4466145 → 4477327 字节。）

### 24.5 局限

1. **部件全都没有图证据的词造不出来。** `北京`/`钢琴`：`北`/`京`/`钢`/`琴` 在语料里
   一次都没出现，没有可关联的对象。这不是实现偷懒，是**不该凭空接**。
2. **判不出「火锅」和「火车」。** 两个部件都是单字，`火`(89) 和 `车`(84) 对食物类
   的 Dice 都过线，所以 `你吃火车了吗` 也会答「我 吃 了 火车」。语料只有 484 个词的
   时候，靠「哪个字像食物」是分不开的 —— 系统在这里**选择相信用户的句式**。
   想要它别乱学，`::coin off`。
3. **只对「走 Gate B 才过关的多词跨度」造词。** 如果 Gate A 就认了（首词在白名单
   里），说明用户的意思可能就是那个词，不该硬拼：`你 喜欢 雪 花 吗` 里 雪/花 都
   合法，拼成「雪花」是把用户的话改了。

```bash
sh tests/all.sh         # 七套一起跑 ✅
```

## 二十五、切分是可以选的：拼接 / 拆解 / 合并 / 中转 / 新建

前面几节是**一个词一个词**地补：Gate B 放行槽位、现场造一个词。这一节改的是
更下面的一层 —— **同一句话该切成什么，本身就是一个可以搜索、可以判断的问题**，
不只是切词器的最长匹配说了算。

### 25.1 五个操作，各自的判据

| 操作 | 什么时候用 | 判据 | 结果 |
|---|---|---|---|
| **新建**（COIN） | 输入里有个图里没有的复合词 | 整段单字 + 至少一个部件有类证据 | 造符号节点 + 现场接类成员边（第二十四节） |
| **拼接**（CONCAT） | 相邻单字本来就该是一个词 | 同上（`fr_coin` 就是拼接） | 复用/新建整词 |
| **拆解**（SPLIT） | 切词器**匹配过长**，挡住了模板的固定词 | 拆开后能让某一帧匹配上 | 本次解析改用拆开的序列 |
| **合并**（MERGE） | 切词器**切得过碎**（用户空格、词典没收） | 拼出来的**必须已经是池子里的词** | 本次解析改用拼起来的序列 |
| **中转**（RELAY） | 模板写死的连接词，用户换了说法 | 在 `FR_RELAY` 同一类里（和/跟/与…） | 固定词位置容错匹配 |

「拼接」和「合并」看着像，区别在**部件**：拼接的部件是单字（切词器按字回退的产物），
合并的部件本身已经是词。`人工智能` 那个例子里切词器给的是 `人/工/智/能` 四个单字，
所以走的是合并那条（判据是「拼出来是池子里已有的词」，不是「部件是单字」）。

### 25.2 判定标准：哪种切分能让句子被理解

切分不是猜的，是**有对错的**，而能对「骨架是否合法」表态的只有结构化帧：

```c
① 主切分      —— 切词器的答案，先试它（不改变现有行为）
② 拆解候选    —— 逐个多字词试着拆开
③ 合并候选    —— 相邻 2~4 个词拼成池子里已有的词
判定 = 这一版切分能不能让 fr_generate_one 渲染出一句话
```

为什么判定要交给帧而不是检索/游走：检索只比整句相似度，切分怎么变它都差不多；
逐词游走更是不管切分对错都往前走。**只有帧会说「这个骨架我不认」。**

### 25.3 三个真实故障，三条修复

| 输入 | 之前 | 现在 | 靠什么 |
|---|---|---|---|
| `你 睡 得 好吗` | 「我 的 梦 里 都 是 今天 学 的 东西」 | **「我 睡 得 好 你 呢」** | 拆解：`好吗` 是一个词典词，挡住了模板要的 `吗`；拆成 好+吗 就中（好 进槽位、吗 落在固定词位） |
| `你 知道 人工 智能 吗` | 「这个我 不 太 懂」 | **「我 知道 人工智能」** | 合并：切词器只认词典，`人工智能` 是 `frames.txt` intern 的，被切成四个单字；拼回去才中 |
| `猫 跟 狗 哪个 好` | 「这个我 不 太 懂」 | **「我 觉得 猫 更 好」** | 中转：模板 `[帧:Z和Y哪个好]` 写死了「和」，和/跟/与 互认才接得住 |

**顺带把帧命中从 26/28 提到 27/28** —— 提上来的那一条正是 `你睡得好吗`；
`tests/frames.sh` 的阈值也跟着从 24 提到 26，让拆解这条能力有看护。

### 25.4 护栏：拆开的碎片不许塞进槽位

拆解一放开就踩了一个坑，而且是**必须先踩出来才知道要防**：

```
你 怕 老师 吗 —— 「老师」被拆成 老 + 师
模板「你 怕 <X> 吗」把 老+师 一起吞进 X
而 老 正好在恐惧类的白名单里（怕老）
→ Gate A 放行 → 答出「我 怕 老 师」
```

修法是给每个变体符号节点记一个 `origin`（它是第几个原词拆出来的），然后规定：

```
槽位取值里如果有两个 token 来自**同一个原词的拆分** → 这次匹配作废
```

对照：
- `你 睡 得 好吗` → 好 进槽位、吗 在**固定词**位 → 槽位里只有一个碎片 → 放行 ✓
- `你 怕 老师 吗` → 老+师 都在槽位里 → 同一个 origin → 作废 ✓

一句话：**拆解是为了让骨架对上，不是为了把词拆碎塞进槽位。**

### 25.5 中转：为什么不是「走路时路过不吐」

一开始想的「中转」是走路时的换乘站（经过但不输出）。写探针量了一下，
**这条路在这个模型上不成立**：

```
./build_slotprobe model.bin relay
[抽象N] 个数=49  成员总数=98  单个最多成员=2
内容 Token: 有出边=881  死胡同=160
死胡同里**挂在抽象节点下**（可经 parent 绕行）= 0（占死胡同 0%）
```

- 49 个抽象节点、每个只挂 2 个成员，能新开的 2 跳路径最多 98 条，
  对着 41022 条边可以忽略；
- 160 个死胡同**没有一个**挂在抽象节点下 —— 绕行救不回来任何一条。

所以「走路时中转」这条路**量完就放弃了**，没写进代码。真正有用的是
**匹配时的中转**：模板里的连接词可以被同类词换掉（25.1 表格那一条）。
这条有真实故障（`猫跟狗哪个好`）撑着，也看得见效果。

> 抽象节点仍然是「装饰」—— 这一节的测量是它没用起来的直接证据，
> 不是又一次「先记着、后面再说」。

### 25.6 局限

1. **拆解/合并只在主切分失败时才试。** 主切分能匹配上就直接返回，不动切分 ——
   这样现有行为零风险（`tests/frames.sh` 里那些「语料里没写过」的句子
   一个字都没变）。
2. **合并要求「拼出来是池子里的词」。** 池子里没有的组合一律不拼。好处是不会乱造；
   代价是**拼不出新词** —— 那件事归 `新建`（第二十四节）管。
3. **合并的搜索代价是 O(n×4)。** 24 词的输入最多 96 个候选变体，每个变体跑一遍
   22 帧的位置匹配；实测交互无感（`tests/segmentation.sh` 14 项断言秒级跑完）。
4. **中转词表是手写的语言知识。** 图只知道「跟」和「和」都跟猫/狗共现过，
   推不出它们能互换 —— 这不是能从这份语料里学出来的东西，所以老实写在
   `FR_RELAY` 里。

## 二十六、思维链：从「并列试四种策略」到「咬合的链」

### 26.1 之前不是链

前面所有工作的输出路径其实是这样一句话：

```c
if (walk_output) 用联想;
if (!resp && 帧匹配上) 用帧;
if (!resp && 检索够好) 用检索;
if (!resp) 拒答;
```

四个 `if` 互相**不知道对方存在**，只是按优先级排队。这叫「策略栈」，不叫思维链 ——
链的定义是**后一步读前一步的结果**。

### 26.2 现在的咬合

```
 读入 ──→ 联想 ──→ 骨架 ──→ 校验 ──→ 降级 ──→ 成句
                     │          │
                     │          └─ 失败**才**走降级；成功直接成句，降级不参与
                     └─ 认出问法骨架（槽位待验）
 检索 ────────────────────────────────────→ 只在前两步都没话说时才轮到
```

「降级」这一步**只因为「校验」失败才存在** —— 这就是链。`::cot` 打出来是这样：

```
你 > 你知道北京吗
你 > AI > 我 不 太 懂 北京
你 > ::cot
[思维链：上一轮 7 步，累计 7 步]
  1. 读入 [成]  分词 + token 代数
        └ 5 个词
  2. 联想 [成]  沿关联链想一遍
        └ 吗 喜欢
  3. 骨架 [成]  认出问法骨架
        └ 知道X吗（槽位没过校验）
  4. 校验 [没成]  校验槽位类证据
        └ 类证据不够，不能拿它当这一类的东西说
  5. 降级 [成]  降级：改说诚实答复
        └ 我 不 太 懂 北京
  6. 检索 [成]  整句检索
        └ 帧层已经给话了，sc=76 cov=55 这条只当备选
  7. 收尾 [成]  输出
        └ 我 不 太 懂 北京
```

对照「真骨架接住」的情况（`你知道量子吗`）：链上是 `骨架[成] → 校验[成] → 收尾`，
**没有降级步**。`tests/cot.sh` 就是拿这条断言看护咬合关系的（骨架 < 校验 < 降级）。

### 26.3 降级答复：把拒答变成「我听懂了但不知道」

原来的问题是：`你知道北京吗` 撞在「槽位类证据不够」上，就一路掉到拒答，
出来一句光秃秃的「这个我 不 太 懂」—— 用户根本不知道**哪一部分**没懂。

`frames.txt` 里本来就有这类答复，只是被同一道门槛一起挡掉了：

```
[降级答] 我 不 太 懂 <X>              （知道X吗）
[降级答] 我 不 太 确定 <X> 在 哪       （X在哪里）
[降级答] 我 不 确定 <Z> 会 不 会 <X>    （Z会X吗）
[降级答] 我 不 太 确定 <Z> 有 没有 <X>  （Z有X吗）
[降级答] <X> 我 不 太 知道 你 那 边 呢  （X天气如何）
```

它们的共同点：**没有对槽位取值做任何断言**。「我 不 太 懂 北京」里的「北京」纯粹是
复述用户说的词，成不成立不依赖「北京是不是这类东西」。所以这类模板可以直接用，
哪怕类证据是零。

实测：

| 输入 | 之前 | 现在 |
|---|---|---|
| `你知道北京吗` | 这个我 不 太 懂 | **我 不 太 懂 北京** |
| `你知道钢琴吗` | 别 憋 着 我 陪 你（检索跑题） | **我 不 太 懂 钢琴** |

顺带：降级时槽位里的单字碎词会拼回整词（`北 京` → `北京`），并且这个新词进池子 ——
下次 `::think 北京` 就是一个符号节点了。它**没有边**（复述不等于断言），所以不会污染游走。
`::fall off` 可以关掉整条降级路径（关掉后链上也不会有降级步）。

### 26.4 「符号神经」体检：神经那一半目前是空的

要谈「联想型符号神经 AI」，先得知道现在到底有多少是「神经」的。
写了 `./build_slotprobe model.bin neuro`，把三个数打出来：

```
① 内容 Token 的出边 35858 条：带角色 14763 (41.2%)  带话题 6496 (18.1%)  带句尾模式 8372 (23.3%)
② VSA 相似度（余弦）:
   猫    ↔ 狗        0.6%   (同是宠物)
   喜欢  ↔ 爱        0.2%   (近义)
   雪    ↔ 雨        2.7%   (同是天气)
   猫    ↔ 量子     -3.5%   (无关·对照)
   随机词对（139 对）：均值 0.2%  标准差 2.9%
③ hv 与 hv_prev 不同的 Token = 0 / 1169（0.0%）
```

三条结论，都是硬账：

1. **符号侧只做了一半。** 近六成边是**没有类型**的共现边。`role` 记的是
   「这条边学自输入段还是回复段」——那是**出处**，不是**语义**。
2. **VSA 是死的。** 语义相关的词对（猫↔狗 0.6%）和随机词对（均值 0.2%、标准差 2.9%）
   **分不开**。原因在 `token.h`：`vsa_init(t->hv, hash(t->name))` —— 超向量只是
   **名字的随机投影**，建好之后再没有被任何学习更新过。
3. **`ai_analogy` 从没被调用过。** 那个用 bind/unbind 做 `A:B :: C:?` 的函数
   （`ai.h` 里唯一像「神经计算」的东西）是死代码。另外 `hv_prev` 从来没变过，
   所以 `ai_drift_sample` 里的「漂移」恒等于 0 —— 又一个恒定指标。

一句话：**现在是一个带死掉的 VSA 附录的符号关联图**，不是符号神经混合体。

### 26.5 三层路线（按依赖顺序）

| 层 | 做什么 | 判据 / 验收 | 状态 |
|---|---|---|---|
| **L1 思维链** | 把「并列试策略」改成「咬合的链」+ 降级答复 | `tests/cot.sh`：骨架<校验<降级 的顺序断言 | ✅ 本节 |

## 二十七、L3 神经表示：把「名字的随机投影」换成「学出来的向量」

### 27.1 emb 是什么

```
emb(t) = Σ_c PPMI(t,c) · r_c      r_c = 由 c 的稳定 id 生成的 ±1 随机向量
```

外加一项反向贡献（`c` 也受「把它当上下文的词」影响），对稀疏词很关键。
PPMI 是**符号统计**（谁跟谁共现得多），`r_c` 是**分布式编码**（每个符号一个近乎
正交的高维向量），两者相乘再求和 —— 得到 1024 维稠密向量，每个维度都没有名字，
但余弦保留了 PPMI 空间的内积（随机投影的 Johnson-Lindenstrauss 性质）。
这就是「符号神经」的字面意思。

几个实现决定，都有理由：

| 决定 | 理由 |
|---|---|
| **一遍投影，不做多轮邻居聚合** | 多轮聚合会 oversmoothing：迭代几轮后所有向量趋同，相似度全都变高，等于什么都没说 |
| **emb 不写进模型文件** | 它是 (边 + hits + 稳定 id) 的确定性函数 → 训练收尾和读盘后各现算一遍。**格式仍是 v5，不用重训** |
| **单独一个 `emb` 字段，不动 `hv`** | `hv` 是给 bind/unbind 代数用的（要近乎正交的随机向量）；`emb` 是语义向量。混在一起两边都做不好 |

成本：O(E × VSA_DIM)。实测 model.bin（35858 条边）**0.4 秒**（含读盘）。

### 27.2 效果：从「等于噪声」到「分得开」

```
./build_slotprobe model.bin neuro

                hv（旧：名字的随机投影）      emb（新：PPMI 随机索引）
猫 ↔ 狗              0.6%                        62.2%
雪 ↔ 雨              2.7%                        63.8%
喜欢 ↔ 爱            0.2%                         0.2%
猫 ↔ 量子           -3.5%                         0.0%
随机词对       均值 0.2% 标准差 2.9%        均值 3.7% 标准差 17.6%
```

关键在最后两行：旧 `hv` 里「猫↔狗」和「猫↔量子」**统计上无法区分**
（0.6% vs 随机 0.2%±2.9%），所以 `ai_analogy` 从来不敢被调用。现在无关词对
**精确落在 0**、相关词对 60%+。`emb` 非零的符号节点 = 867（内容词共约 930）。

### 27.3 中途踩的坑：模板话把向量拉平了

第一版做完，`::near 猫` 的邻居是 **雨 82.9% / 椅子 80.7% / 小孩 80.6% / 女人 79.5%** ——
全是高频名词，`狗` 连前八都进不去，而且 `鱼` 与 `狗`（77.3%）比 `猫` 与 `狗`（67.2%）还高。

写了个 `ctx` 探针去看 PPMI 上下文，一下就看明白了：

```
./build_slotprobe model.bin ctx 猫 狗 雨 鱼
[猫] 出边 254 条，行和 9798（占总权重 0.258%）
  PPMI 最高的上下文: 是什么(7.75) 在哪里(7.06) 是谁(7.06) 软(5.96) 旧(4.95) 抓(4.86) ...
[狗] 出边 181 条，行和 4896（占总权重 0.129%）
  PPMI 最高的上下文: 是什么(8.45) 在哪里(7.75) 是谁(7.35) 暗(6.25) 之前(5.01) ...
[雨] 出边 243 条，行和 6017（占总权重 0.158%）
  PPMI 最高的上下文: 是什么(7.83) 声(7.20) 在哪里(7.14) 是谁(7.14) 软(5.76) ...
```

**`是什么`/`在哪里`/`是谁` 只跟名词搭配**，所以单看 PMI 比任何实词都高；可它们跟
**每一个**名词都搭配 —— 信息量为零，却把所有名词的向量拉到一起。这些是
`frames.txt` 生成的模板句留下的痕迹。

修法是数据驱动的：**df（被多少个不同词指向）超过内容词总数 15% 的上下文，
一律不当上下文用**（「近万能上下文」过滤器，不用手写停用词表）。
另外加了 embedding 的常规后处理 **all-but-the-top**（去均值 + 幂迭代去掉前 3 个主成分）。

修完：模板话从邻居里消失了，相关/无关的区分更干净，但**邻居仍然由高频名词主导**
（雨 71.4% / 小孩 66.7% / 椅子 66.3%）。

### 27.4 诚实结论：机制到位了，语义没到位 —— 这是**语料**的问题

三条硬边界，都写进 `tests/embed.sh` 当**负结果**看护：

1. **撑不起细粒度分类。** `猫` 对「食物类」（饭/面/菜/肉/鱼…）的 emb 相似度有 **55.5%**。
   拿它当槽位门槛，`猫` 就能被当成食物放行 —— 比现在的 Dice + 白名单**更差**。
   所以 **emb 绝对没有接进 Gate B**。
2. **撑不起关系类比。** `猫 : 动物 :: 狗 : ?` 最高只有 36.2%（月亮）。所以 `::analogy`
   加了 50% 门槛，**在表示不够时诚实拒答**，不报一个自信的错答案。
3. **主成分没有塌**（PC1 4.4% / PC2 3.4% / PC3 3.0%），所以问题不是「秩 1 塌陷」，
   而是**共现统计本身太同质**：484 个内容词、±5 窗口、清一色闲聊，几乎任意两个
   实词都共现过。这个用算法修不了。

一句话：**L3 的机器造好了，但它照出来的镜像还是糊的 —— 因为底片（语料）分辨率不够。**

### 27.5 L2 关系类型：卡在**数据**上，不是卡在代码上

本来打算「L3 做完顺便把 L2 也做了」，先做了一次侦察：

```
grep -oh '\[原语:[^]]*\]' _corpus.txt dialog.txt seed_full.txt | sort | uniq -c | sort -rn
 104913 [原语:对象]
  21419 [原语:连接]
   1793 [原语:请求]
   1231 [原语:好]
    520 [原语:分割]
    292 [原语:认为]
    286 [原语:坏]
      4 [原语:上]
      2 [原语:了]
```

**语料里没有任何语义关系原语** —— 没有「属于」「有」「会」「怕」这类边标签，
连 `[原语:关系]` 都不存在。所以「从语料里抽关系类型」这条路**没有原料**。

现在唯一带关系结构的东西是**帧库**（谓词 + 槽位角色，比如
`会(老师, 唱歌)`、`怕(我, 黑)`），它能当关系清单用，但：

- 要把关系落成边上的持久化字段 → **模型格式要升到 v6**；
- 要让关系真的有用，得有**可以传递的关系**（`猫 —属于→ 动物 —有→ 毛`），
  而这需要语料里有承载关系的句子 → **必须重训**（L3 不用重训，这是两者的本质差别）。

**结论：L2 的下一步是数据工作，不是代码工作。** 具体需要加的是这样一批语料行：

```
[原语:对象] 猫 [原语:关系:属于] [原语:对象] 动物 [原语:连接]
[原语:对象] 动物 [原语:关系:有] [原语:对象] 毛 [原语:连接]
[原语:对象] 猫 [原语:关系:怕] [原语:对象] 狗 [原语:连接]
```

有了这批行，关系类型才既有原料、又有传递的路径；在那之前**不动代码**是更诚实的选择
（免得又造一个像旧 VSA 那样的装饰品）。

## 二十八、L2 语义关系层：类型化关系 + 传递推理 + 对话中动态学知识

### 28.1 之前边上只有一个「出处」

`role` 记的是**这条边学自输入段还是回复段** —— 那是出处，不是语义。
所以「猫 属于 动物」和「猫 旁边出现过 动物」在图上长得一样，推理无从谈起。

这一层加上真正的语义关系：

| 关系 | id | 可传递 | 可沿「属于」继承 | 否定形式 |
|---|---|---|---|---|
| 属于 / 是 | 1 | ✅ | — | 不 属于 / 不 是 |
| 有 | 2 | — | ✅ | 没有 |
| 会 | 3 | — | ✅ | 不 会 |
| 怕 | 4 | — | — | 不 怕 |
| 喜欢 / 爱 | 5 | — | — | 不 喜欢 |
| 吃 | 6 | — | — | 不 吃 |
| 在 | 7 | — | — | 不 在 |

**推理规则只有两条**，就写在 `rel.h` 里：

```
① 传递：  猫 属于 动物，动物 属于 生物  ⟹ 猫 属于 生物
② 继承：  猫 属于 动物，动物 有 毛     ⟹ 猫 有 毛
```

就这两条，不做通用逻辑 —— 因为**这一层的目的是可解释**：每条推出来的结论都要能报出
它是怎么来的，而 `::cot` 会把路径打出来。

### 28.2 效果：语料里从没写过的问题也能答，而且带推导路径

```
你 > 猫 有 毛 吗
AI > 对 ， 猫 有 毛 （猫 → 动物 → 毛）

你 > ::cot
  1. 读入 [成]  分词 + token 代数
        └ 4 个词
  2. 联想 [成]  沿关联链想一遍
        └ 吗 喜欢 日子 我 空 说 随
  3. 推理 [成]  关系推理（多跳）
        └ 猫 → 动物 → 毛
  4. 收尾 [成]  输出
        └ 对 ， 猫 有 毛 （猫 → 动物 → 毛）
```

顺序是「先想一遍，再动确定性推理」—— 联想在前、推理在后。
（第一版把关系那两步内联在联想之前，链上就成了「推理 → 联想」，
因果顺序都乱了；后来抽成两个独立函数放回联想之后。）

`猫 有 毛` 这句话在 242176 条学习记录里**一次都没出现过** —— 它是推出来的。
这就是「有明确思维链的联想型 AI」和「检索最像的句子」的区别。

### 28.3 对话中动态获得知识

这是这一层最要紧的部分：**知识不是只有那个静态文件**。

```
你 > 猫 属于 宠物
AI > 记下 了 ： 猫 属于 宠物          ← 当场学进图里

你 > 猫 属于 宠物 吗
AI > 对 ， 猫 属于 宠物                ← 立刻能用

::save m.bin  →  ::load m.bin
你 > 猫 属于 宠物 吗
AI > 对 ， 猫 属于 宠物                ← 存盘重载后还在
```

为什么重载后还在：`rel` 字节**写进了模型**（格式从 v5 升到 **v6**，
`has_rel` 向后兼容 v1~v5）。静态的 `relations.txt` 像 `frames.txt` 一样
每次读盘装载，所以**改知识不用重训**；对话里学到的那些则在模型里。

### 28.4 三条护栏（都踩出来的）

**① 只认一个形状。** `<主语> <关系词> <宾语…> [吗]`，3~6 个词，
关系词必须在清单里，主语宾语不能是标记词，宾语里的单字必须是**实词**。

**② 解析器绝不许改图。** 这条是血换的：

```
你 吃 火锅 了 吗
  → 关系解析器看到 words[1]=吃（吃是关系词），把宾语拼成「火 锅 了」
  → pool_token_intern("火锅了")  ← 凭空造出一个垃圾 Token！
  → 之后切词器把整句切成 你/吃/火锅了/吗 → 帧再也匹配不上 → 造词反复触发
```

修法两条：宾语里的单字部件必须过虚词检查（`了` 挡掉）；**疑问句分支只查不建**
（`pool_find` 而不是 `pool_token_intern`）。**解析阶段往图里写东西是不会有好下场的。**

**③ 闭合世界的「不是」只对知识库里的实体说。**

```
猫 会 飞 吗     → 不 对 ， 猫 不 会 飞       （猫 在知识库里有关系边）
你 会 游泳 吗   → 我 会 试 着 游泳           （你 没有关系边 → 不接管，走帧）
```

没有这条护栏，`你 会 游泳 吗` 会被抢答成「你 不 会 游泳」。

### 28.5 关系可以叠加：`rel` 是位掩码

同一对词可以同时有多种关系：`老师 有 学生` 和 `老师 喜欢 学生` 都是真的。
一开始我把它存成单个 id，于是：

- 后者把前者盖掉（丢知识）；
- 存盘再读时两条事实**各自再加一次权**，hits 从 64 变 128，`emb` 跟着变，
  「读盘前后语义邻居一致」直接挂掉。

改成**位掩码**（7 种关系正好一个字节，仍不占额外空间）后两个问题一起解决：
置位幂等，且多种关系共存。为了定位这个 bug 专门写了个 `tools/rtdiff.c` ——
指纹只能告诉你「edge 维度变了」，它能告诉你是**哪一条边**。

### 28.6 顺带修好的：关系知识不能污染分布统计

加完关系边之后 `你知道动物吗` 从「我 知道 动物」退化成降级答复 ——
因为 `动物` 的出边多了几条人工知识（属于生物/有毛/有腿…），
`fr_dice` 的分母变大、分数掉到门槛以下。

修法：**Dice / 覆盖率只算共现边，跳过关系边**。Gate B 要量的是
「上下文像不像」（分布统计），别让人工知识去污染它。
实测改回来之后 framegate_ab 5/15 改善，与之前一致。

### 28.7 局限

1. **关系词表是手写的**（7 种），语料里没有关系原语，这层知识来自
   `relations.txt` 和对话中的陈述 —— 是**注入**的，不是从闲聊里学出来的。
2. **闭合世界假设**：说了「不是」其实是「知识库和学过的东西里没有」。
3. **谓语只认清单里那 7 个**。`你 想念 我 吗` 里的「想念」不在表里 → 不接管。
4. **embedding 仍然撑不起关系类比**（第二十七节）：关系是靠**显式规则**推的，
   不是靠向量运算。这两条路现在并存，还没打通。

## 二十九、推导层：链是一等公民，文字只是它的投影

### 29.1 为什么改

到第二十八节为止，推理的输出还是「边算边拼出来的一句话」。这有个要命的后果：
**流程本身知道自己推了什么，但那个东西不是一等公民** —— 它没法被单独检查、
没法被换一种说法、也没法回答「你这结论站得住吗」。

那一节还留了一个不健全的地方：推不出来时靠闭合世界假设硬答「不对」。
补了三态（真/假/未知）之后，链条的**可验证性**就成了下一个必须做的事。

### 29.2 结构

```
Derivation = 一串 DerStep + 整体真值 + 缺口数 + 是否用了推测
  DER_GOAL     目标（要回答什么）
  DER_FACT     事实（图里直接有的边，带极性）—— 验证器会独立复查
  DER_RULE     规则应用（传递/继承/对称/逆关系）
  DER_DEFAULT  默认推测（类比，非单调）
  DER_SOURCE   非逻辑来源（整句记忆/结构化帧/降级答复）—— 不做断言
  DER_GAP      缺口（这一步没有依据）
  DER_CONCLUDE 结论
```

### 29.3 验证器：**独立重推每一步**

`der_verify()` 不信任构造时写下的东西，它重新验一遍：

| 检查 | 怎么验 |
|---|---|
| 事实步 | 那条边**真的**在图里，极性也对（`rel_direct` / `rel_direct_neg`） |
| 规则步 | ① 这一跳的边存在；② 这条关系**声明**了支持该规则（不能拿「传递」套「有」） |
| 推测步 | ① 知识库里确实推不出来；② 最近邻确实够近；③ **那个最近邻确实对这件事有态度** |
| 连通性 | 相邻两环首尾相接（断链要被抓出来） |
| 结论 | 拿 `rel_solve` **重新推一遍**，推不出来就是缺口 |

`gaps > 0` 时，渲染器**绝不下断言** —— 只会说「推不出来（链上缺 N 步）」。

### 29.4 验证器自身的测试

「可以正确思考」不能靠声称。`tools/dertest.c` 故意造坏链，看验证器认不认：

```
① 伪造一个「图里不存在的事实」（狗 属于 鱼）      → 被识破，降级成缺口 ✓
② 用错误的规则（「有」不支持传递，却按传递推）    → 被识破 ✓
③ 链断掉（上一环终点 ≠ 这一环起点）              → 被识破 ✓
④ 推测却没有真凭据（依据词对这件事没态度）        → 被识破 ✓
⑤ 结论重推不出来                                → 被识破 ✓
⑥ 一条真链（猫 有 毛）                           → 放行（缺口=0）✓
⑦ 有缺口的链渲染                                → 「推不出来（链上缺 1 步）」，不下断言 ✓
```

### 29.5 语言是最后一步

同一份链，四种说法，**真值不变**：

```
$ ::style 3 ; 猫 属于 生物 吗
对 ： 猫 属于 生物  ⇐  猫 属于 动物  ∧  动物 属于 生物

$ ::style 0   →  对
$ ::style 1   →  对 ， 猫 -[属于·传递]-> 动物 ； 动物 -[属于]-> 生物
$ ::style 2   →  猫 -[属于·传递]-> 动物 ； 动物 -[属于]-> 生物
$ ::style 3   →  对 ： 猫 属于 生物  ⇐  猫 属于 动物  ∧  动物 属于 生物
```

风格 2「只给链不给结论」是刻意留的：它证明**链本身是独立于措辞存在的**，结论只是链的一个属性。

### 29.6 结构化看链

```
$ 猫 有 毛 吗
$ ::der
[推导] 有逻辑结论  真值=真  缺口=0  推测=否  把握=85
  1. 目标      猫 有 毛 ?
  2. 规则 ✓   猫 -[属于]-> 动物   （继承）
  3. 事实 ✓   动物 -[有]-> 毛
  4. 结论      真
  → 这么说（风格 结论 + 推导链）：对 ， 猫 -[属于·继承]-> 动物 ； 动物 -[有]-> 毛
```

非逻辑路径也留记录，而且**不许包装成推导结论**：

```
$ 你好呀
$ ::der
[推导] 无逻辑结论（只有来源）  真值=未定  缺口=0  推测=否  把握=0
  1. 来源      结构化帧渲染（骨架合法，非逻辑结论）
```

「检索到一句像的话」和「推导出一个结论」是两件事，混起来就是撒谎。

### 29.7 局限

1. **只有关系推理走这条路**。检索/帧/降级仍然自己拼句子，`last_der` 里只记来源。
   要做到「所有输出都是渲染出来的」，得把那些路径也改成先建链 —— 但它们的「链」
   里没有逻辑步骤，硬套反而是形式主义。
2. **推测（DER_DEFAULT）的置信度是拍的**（45）。相似度门槛 40% 是按 L3 的实测定的，
   但这个语料里「像」的区分度本来就弱（第二十七节），所以推测仍然只能当提示。
3. **没有反事实推理**。「如果 猫 会 飞」这种需要引入假设世界，现在完全不支持。

## 三十、反事实：假设世界，而且**假设绝不进图**

### 30.1 上一节自己点的空缺

第二十九节的局限第三条写着「**不支持反事实**」：「如果 猫 会 飞」需要引入假设世界。
这一节补它 —— 而且重点不在「能不能推」，在**假设的边界**。

### 30.2 做法：一个覆盖层

```
HypoFact { a, rid, b, neg }        // 假设「a 不/是 R b」
Hypo     { f[8], n }               // 放在 AI 里，**不存盘、不进图**
```

求解器查事实时**先看覆盖层再看图**：

```c
int d_pos = rel_direct(a, rid, b) || rel_direct_h(ai, a, rid, b, &hy_pos);
```

凭这一行，假设世界就成立了，而图**一个字节都没动**。传递/继承的**候选枚举**
也必须过一遍覆盖层（`rel_next_cands`），否则假设那条边根本不在图里，
图里的循环看不到它 —— 这正是「如果 猫 属于 鸟」推不出「猫 会 飞」的原因。

### 30.3 效果

**① 直接在假设下推理**（并与已知事实冲突时如实说明）：

```
你 > 如果 猫 会 飞
AI > 好 ， 就 当 猫 会 飞 —— 不过 我 知道 实际 上 不是 这样 ，下面 说 的 都 是 假设 下 的
你 > 猫 会 飞 吗
AI > 在 假设 下 ： 对 ， 猫 -[会·假设]-> 飞
```

**② 假设不覆盖无关的已知事实**（这一条很重要 —— 假设不是「把图关掉」）：

```
你 > 猫 会 游泳 吗    → 不 对 ， 猫 -[不 会]-> 游泳
你 > 猫 属于 植物 吗  → 不 对 ， 猫 -[不 属于]-> 植物
```

**③ 假设能沿规则外推**（这才是反事实推理的价值）：

```
你 > 如果 猫 属于 鸟
你 > 猫 会 飞 吗      → 在 假设 下 ： 对 ， 猫 -[属于·假设]-> 鸟 ； 鸟 -[会]-> 飞
你 > ::der
[推导] 有逻辑结论  真值=真  缺口=0
  1. 目标      猫 会 飞 ?
  2. 假设 ✓   猫 -[属于]-> 鸟   （来自假设层，不在知识库里；被继承/传递规则用上）
  3. 事实 ✓   鸟 -[会]-> 飞
  4. 结论      真
```

「猫 会 飞」在图里**从没存在过**，它是靠「假设 猫 属于 鸟」+「鸟 会 飞」+ 继承规则
推出来的。链条把哪一步是假设、哪一步是真事实分得清清楚楚。

**④ 撤回与存盘**：

```
你 > 算了           → 好 的            （撤回）
你 > 猫 会 飞 吗    → 不 对 ， 猫 -[不 会]-> 飞     （回到原本的知识）
::save → ::load → 猫 会 飞 吗 → 不 对              （假设从没写进图，自然存不出来）
```

### 30.4 三条护栏

| 护栏 | 怎么落实 |
|---|---|
| **假设不进图** | 只活在 `ai->hypo` 覆盖层里；无任何代码路径把假设 tag 进边；不参与序列化 |
| **验证器不认假假设** | `DER_HYP` 那一步必须能在**覆盖层**里核对上；核对不上就是缺口 → 不下断言 |
| **假设不绕过规则检查** | `DER_HYP` 若还标了规则，规则合法性照查（假设不能拿「传递」去套「有」） |

第三条是 `tools/dertest.c` 里那条「猜测/假设都要有真凭据」的延伸。

### 30.5 踩出来的两个 bug（同一类）

1. **假设边被当成图里的边去验**：`rel_next_cands` 里给候选打「来自假设」标记的那一行
   改漏了（`if (!dup) out[n++] = f->b;` 没写 `from_hyp[n] = 1`），
   于是「假设 猫 属于 鸟」推出来的那一步被当成图里的 RULE 步，
   验证器正确地拒绝（「这一跳的边在图里不存在」）→ 整条问答退化成帧答复。
2. **`proof_push` 漏清 `hyp` 字段**：撤回假设之后再问，数组里残留的 `hyp=1`
   让一个**真事实**步被误标成「靠假设」，验证器照样拒绝。
   和当年 `role` 字节没初始化是同一类 bug —— **每个字段都要写**。

第二条尤其值得记：它不是逻辑错，是**内存里的残值**。验证器的行为完全正确
（它拒绝了一个确实站不住的链），错在构造器给了它脏数据。

### 30.6 局限

1. **只支持单条假设**（后来的「如果」会替换掉前一条）。多假设共存是下一步。
2. **外推只走两条规则**（传递/继承）。「如果 猫 会 飞」不会推出
   「猫 不是 鸟」这类需要**完备性**的结论 —— 那是开放世界假设，现在没有。
3. **假设不参与检索/帧层**。检索与骨架答复看不到覆盖层，所以「在假设下」的
   说法只出现在关系推理这条路上。
4. **没有嵌套假设**（「如果他以为我以为…」）。多视角已经有了基础设施
   （`OtherModel` / perspective），但没接。

## 三十一、把上一节点出的四个局限解决掉

第三十节末尾列了四条局限。这一节逐条处理，并且每条都有测试看护
（`tests/logic4.sh`）。

### 31.1 局限①：只支持单条假设 → **栈式多层**

原来「如果」是**替换**，后一句把前一句冲掉。现在是一叠：

```c
HypoFrame { HypoFact f[8]; size_t n; Token *who; }   // 一层
Hypo      { HypoFrame fr[4]; size_t depth; }          // 一个栈
```

- `如果 …` → **压一层**（不再清空）
- `算了` → **弹掉最深一层**（不是一次清空），所以能一层层退出来
- 求解时**所有层都算数** —— 内层不推翻外层，那正是「他以为」的意思

```
你 > 如果 猫 属于 鸟
你 > 猫 会 飞 吗        → 在 假设 下 ： 对 ， 猫 -[属于·假设]-> 鸟 ； 鸟 -[会]-> 飞
你 > 如果 猫 属于 鱼
你 > 猫 会 游泳 吗      → 在 假设 下 ： 对 ， 猫 -[属于·假设]-> 鱼 ； 鱼 -[会]-> 游泳
你 > 猫 会 飞 吗        → 对（第 1 层还在）
```

### 31.2 局限②：缺完备性 → **独占公理** + 开放/闭合世界开关

「推不出否定」这件事原来只有一种处理：说不知道。现在分成三种情形：

| 情形 | 处理 | 例 |
|---|---|---|
| 关系是**独占的**（函数式），且已知宾语与问的宾语**互不包含** | **健全地推出否定** | `猫 属于 植物` → 不 对（猫 属于 动物，动物与植物互不包含） |
| 关系独占，但两个宾语**互相包含** | **不能否定**，说不知道 | `猫 属于 鸟` → 不知道（鸟 ⊂ 动物，「猫 是 鸟」完全可能） |
| 关系不独占 | 说不知道，并**说明为什么** | 缺口的理由写进链里 |

新增规则 **R6 独占**：`a R b1`，`R` 独占，`b1` 与 `b` 互不包含 ⟹ `a 不 R b`。
「互不包含」是安全阀 —— 少了它就会把「猫 是 鸟」这种**可能为真**的句子判成假。

还加了一个**显式开关**：

```
::world open      （默认）没写就是不知道
::world closed    没写就是假 —— 答得快，但会自信地说错
```

闭合世界下的结论链上会标成 `—[不 属于·闭合世界]—`，让人一眼看出**这条是靠假设得来的**，
不是事实。这比「默默按闭合世界算」诚实得多。

### 31.3 局限③：假设不参与后续流程 → **说清楚，而不是被悄悄接管**

检索与结构化帧看不到假设层，所以当关系推理返回「推不出来」时，
它们会**当作没有假设**地回答。实测：

```
无假设： 猫 会 唱歌 吗 → 猫 应该 会 唱歌          （帧层照常渲染）
有假设： 猫 会 唱歌 吗 → 在 假设 下 我 推不出来   （明说，不让帧层代答）
```

改法：假设开着时，关系问题**由关系层负责到底** —— 推不出来也得说明，
并且把「为什么推不出来」写进链。不让看不见假设的层替它说话。

### 31.4 局限④：没有嵌套 → **每层可以归属某个人**

`如果 他 以为 猫 会 飞` 会被解析成：压一层，`who = 他`。

```
你 > 如果 猫 属于 鸟
你 > 如果 他 以为 猫 会 飞
你 > ::hypo
[当前假设世界：2 层]
   第 1 层：
      猫 属于 鸟
   第 2 层（这一层算在「他」头上）：
      他 以为： 猫 会 飞
```

「他以为我以为…」就是再压一层、换一个 `who` —— 栈的深度就是嵌套深度。
每层归属的存在，也让「这是谁的假设」这件事变得可查。

### 31.5 踩出来的两个 bug

1. **独占推出来的那一步被做成三跳链**（`a → 理由 → b`），验证器按「相邻两环首尾
   相接」去验就崩了 —— **理由不是链的一环**。改成两跳：`a → b`（否定），
   理由由 `rule=独占` 表达，验证器另走一条路去**独立复核**这条规则的前提
   （找得到一个反例类、且与目标互不包含）。
2. **`DerStep.note[64]` 装不下中文长句**，`cot_copy` 把「否定它需要完备性……」
   截在字符中间，打出来是乱码。中文一个字 3 字节，**别按「字符数」估缓冲区**。
   放大到 224 字节，并且答复用短句、长理由留在链里。

### 31.6 剩下的局限（继续照实说）

1. **独占是手写公理**（只给「属于」「在」标了）。哪些关系真是函数式的，
   在真实世界里是有争议的 —— 这一层是**声明**出来的，不是学出来的。
2. **多层假设没有作用域回溯**：撤销只能从最深的往下弹，不能抽掉中间那层。
3. **假设仍然不进检索/帧层**：只做到了「不被它们代答」，没做到「让它们也在假设下工作」。
4. **归属只是标注**，没有真正的视角推理（「他以为」不影响他对「我」的信念）。
   `OtherModel` / perspective 那套基础设施仍然没接上逻辑层。

## 三十二、装载态必须和训练态**逐字节**一样：三个「派生层」的坑

第三十一节留下的话是「训练收尾与读盘收尾落到同一个不动点」。
`tests/model_roundtrip.sh` 的 `[3/4]` 一直是红的 —— 而且**红了很久没人查**，
因为在这之前这个测试一直在偷偷用不存在的语料训练空模型（见 32.7）。
语料路径修好之后，两个进程给出的回复立刻不一样了。这一节是把它查到根、修干净的过程。

结论先摆在这里：**派生层（idf / slots / emb）与「指针型特殊符号节点」必须满足两条不变式**，
少一条就会得到「模型文件逐字节相同、行为却不同」这种最难查的 bug。

### 32.1 为什么「词池一样」不等于「行为一样」

第一反应是比词池：`::pooldump` 把每个符号节点（id / 名字 / count / mem / 时间戳）和
**每一条边**（main / hits / seq / role / topic / pattern / rel / nrel / dyn / action /
subs / 时间戳）按 id 打出来，两条路径 **42174 行逐字节相同**。

再比 AI 结构体的原始字节，唯一的非指针差异是 `pairs_cap`（装载时按 count 精确分配、
训练时倍增，纯容量痕迹，语义无关）。也就是说：**能看见的状态全都一样**。

差异只能来自两处：

1. **派生层**（不进快照、装载时现算的那几层）；
2. **指针**（AI 结构体里存的是指针的特殊符号节点，比字节只能看出「不同」，看不出「谁是谁」）。

### 32.2 坑①：idf 的边界用了「当前词数」，于是越界读堆内存

给每个符号节点打一行 `idf` 的位模式之后，真相很直白：

```
D 1073 包含  ... idf=4.90454e-44/00000023     ← 垃圾浮点
D 1079 [抽象5] ... idf=-nan/ffffff01
```

`ai_idf_rebuild()` 按**当时的** `pool->count` 分配数组，可它的调用点在
`rel_names_intern` / `frames_load` / `stabilize_abstractions` **之前** ——
后面这几步还会造词，于是新词（实测 50 个）没有 idf。
而 `ai_idf_of()` 的边界写的是 `t->id >= ai->pool->count`（**当前**词数），
不是数组真实长度，于是越界读到堆里别的字节。

越界读出来的浮点**每次进程都不一样**（地址相关），这些值进了检索/游走的打分，
联想链就跟着变。修法两条一起上：

```c
size_t idf_n;                                     /* AI 里新增：idf 数组的真实长度 */
if (!ai || !ai->idf || !t || t->id >= ai->idf_n) return 1.0f;   /* 边界用 idf_n */
```

并把 `ai_idf_rebuild(ai)` 挪到训练收尾 / 装载收尾的**最后一步**。

### 32.3 坑②：派生层算在「还会改图的步骤」之前

修完 idf，`emb` 又跳出来了：两条路径 **810 个符号节点（1123 个里的 810 个）emb 不同**，
而 `hv`、`idf` 全都相同。

原因不是 emb 算法有随机性（`emb_randvec(id)` 只跟 id 有关、幂迭代固定初值固定轮数），
而是**它算得太早**：训练侧在 `ai_embed_build()` 之后才跑
`frames_load()`（会造词、加 `COINED` 边）和 `stabilize_abstractions()`（会造抽象词/边）。
存盘存的是**最终**的图，读盘时又按最终的图重算 emb —— 两边当然不一样。

所以顺序统一成「先改图，后算派生层」，两条路径逐字对齐：

| 步骤 | 训练收尾（`main.c`） | 装载收尾（`model_io.h`） |
|---|---|---|
| 关系词 intern + 关系知识 | `rel_names_intern` → `relations_load` → `rel_excl_build` | 同左 |
| 帧层 | `frames_load` | `frames_load` |
| 抽象跑到不动点 | `stabilize_abstractions` | ——（结果已在文件里） |
| **派生层** | `ai_embed_build` → `ai_slots_build` → `ai_idf_rebuild` | 同左 |

槽类（`ai_slots_build`）也必须往后挪：训练侧它原来算在 `relations_load` 之前，
而装载侧的图**已经带着存下来的关系边**，两边输入根本不是同一个图 —— 这一条
顺带把思维链里降级答复的语气前缀也改了（见 32.6）。

### 32.4 坑③：`split_tok` 从来没进过存盘格式

最后一个坑最阴。给游走加跟踪（`::wtrace`）之后，同一个输入 `猫`、同一个
`rng=2654435769`、同一张图，两条路径的**边权重**却差整整 4 倍：

```
训练态:  CT ... tok=好 w=1600     装载态:  CT ... tok=好 w=400
         CT ... tok=看 w=1356              CT ... tok=看 w=339
```

4 倍只有一个来源，`ai_edge_weight()` 里那一档：

```c
/* 从分隔符出发的边 = 「回复首词」，比别的续接重要得多，单独加权 */
if (ai->split_tok && e->hits && ...) w *= 4;
```

`ai->split_tok`（`[原语:分割]`）只在 `ai_new()` 里 intern 过一次，
**存盘清单里漏了它**（self / good / bad / unknowing / causal … 十个特殊符号节点都按 id 存了），
装载后它是 `NULL` → 整档 ×4 静默失效 → 每条边都只有训练态的 1/4。

它躲过了之前所有的排查，因为**词池 dump 逐字节相同** —— 图没变，权重也没写进模型，
变的是「权重怎么算」。修法是按名字找回来（和 `unknowing` 同一套路），
并在 `MODEL_IO_INVARIANTS` 里加一条硬断言：池里有 `[原语:分割]` 时指针必须指向它。

### 32.5 不变式（下次别再踩）

1. **派生层只能用「最终的图」算**，而且训练收尾与装载收尾的**顺序必须一致**。
2. **数组边界不能用「当前规模」当长度**（`idf_n` 这种显式长度字段才靠谱）。
3. **AI 里存进池内指针的字段，必须要么进存盘格式、要么在装载时按名字重建**；
   少一个的后果不是崩溃，而是「权重算错、回复不一样」。
4. 分配容量的痕迹（`cap` / `pairs_cap`）与行为无关，**测试里显式抹掉**，别当成 bug 查。

### 32.6 顺带的行为变化（照实说）

槽类算在关系层**之后**，表达层的语气跟着变了：同一句 `你知道北京吗`，
降级答复从「我 不 太 懂 北京」变成「**大概，**我 不 太 懂 北京」。
`tests/cot.sh` 原来钉的是整串相等 —— 它钉住的是**装载态与训练态不一致时的那个旧值**，
现在两边一致了（都带前缀），测试改成查包含「不 太 懂 北京」，
并写清为什么（语气前缀由派生信号决定，复述用户的话才是这条断言的要点）。

顺带一提：这次修的都是**代码**，模型格式没动（当时还是 v7），
`model.bin` / `model_full.bin` **不需要重训**（派生层不进文件，重训会得到同一张图）。
（后来加了「需要」这个核心关系，格式升到 v9 —— 见第三十三节，那是另一次改动。）

## 三十三、把「剩下的四条」接着往下做（外加一条缺前提推理）

第三十一节末尾列了四条「照实说的局限」，第三十二节收口了存读一致性。
这一节把四条逐条解决，并加上一条更要紧的：**训练数据里没有的结论也要能推出来**。

### 33.1 局限①：独占不是手写公理，是**量**出来的

原来这张表写死在 `AI_RELS` 里（只给 `属于`/`在` 标了独占），数据只过一个
「主语数 ≥5 且多宾语率 ≤20%」的门槛 —— 真实模型上**改口 0 项**，等于没量。

现在判定是**似然比模型比较**：

| 符号 | 含义 | 取值 |
|---|---|---|
| `H_多值` | 这个关系不是函数式的，每个主语独立地以 `p1` 的概率带多个宾语 | `p1` **由数据给** |
| `H_独占` | 它是函数式的，只有 `p0` 的概率出现多宾语（数据噪声） | `p0 = REL_EXCL_NOISE = 0.10` |
| 判据 | `llr = ll_multi - ll_excl`；`llr ≤ -log(10)` 判独占，`llr ≥ +log(10)` 判多值 | 赔率 10:1 才改口 |

关键是 `p1` 从哪来。第一版把所有关系合并起来算多宾语率（15.2%），结果
「在」有 17 个主语、个个只有一个宾语，赔率只有 2.7:1，**反而被判成多值** ——
因为数据集里「属于/在」本身就是函数式的，它们把基准拉低了，独占的判定被自己拖垮。
现在参照类只取**观察到了多宾语行为**的那些关系（它们才是「非独占」的样本），
`p1 = 35.6%`，`在` 的赔率升到 292:1，判独占。

判定与证据都留在明面上（`ai->rel_excl_single/multi/llr/base`），`::excl` 打全表：

```
[关系独占表] 判据=似然比（≥10:1 才改口）；参照多宾语率 35.6%（只取「观察到过多宾语」的关系当参照类）
  属于 独占  样本 43 主语（单 43 / 多 0）  似然比 1727636.1:1 支持独占  [数据印证]
  有   多值  样本 16 主语（单 10 / 多 6）  似然比 71.6:1 支持多值      [数据印证]
  会   多值  样本 10 主语（单 7 / 多 3）   似然比 4.3:1 支持多值       [证据不够→按声明]
  吃   多值  样本  8 主语（单 4 / 多 4）   似然比 42.0:1 支持多值      [数据印证]
  在   独占  样本 17 主语（单 17 / 多 0）  似然比 292.4:1 支持独占     [数据印证]
```

`AI_RELS` 里那一列只是**先验**：数据不表态时按它，数据一边倒时按数据 ——
方向可以是**推翻声明**。`tests/exclusivity.sh` 用伪造数据证明这一点：
让 `属于` 的主语个个带两个宾语 → 改口成「多值」；让 `喜欢` 的主语个个只有一个宾语 →
改口成「独占」；让 `会` 两边都有 → 老实说「证据不够→按声明」。
改口之后推理跟着变：多值的 `属于` **不许**再靠独占推出否定（健全性）。

### 33.2 局限②：假设的作用域回溯（撤**指定**那层）

「算了」只能弹最深那层。多层嵌套时经常要抽掉中间那层：

```
如果 猫 属于 鸟              ← 这条作废
如果 他 以为 猫 会 飞         ← 这条还得留着
猫 属于 鸟 不算 了            ← 抽掉第 1 层，第 2 层原样保留
```

四种说法都认：`撤回 第 2 个 假设`（序号，中文/阿拉伯数字都行）、
`撤回 关于 猫 的 假设`（哪层提到它撤哪层，从深往浅找）、
`撤回 猫 属于 鸟`、`猫 属于 鸟 不算 了`（按内容，最常用）。
新增 `hypo_layer_of_fact` / `hypo_layer_of_subject` / `hypo_frame_text`
（撤回时要说清撤掉的是哪一层，只说「撤了一层」等于没说）。找不着就如实说
「没找到那条假设」，**一层都不许乱撤**。

踩到的坑是**切词器**：`撤回` 被切成 `撤`+`回`、`关于` 切成 `关`+`于`、
`不算` 切成 `不`+`算`（和 `算了` 切成 `算`+`了` 一个道理）。
第一版只比对整词，于是三个说法全都匹配不上、静默走成「按内容」还找不着。

### 33.3 局限③：假设进检索/帧层，而不只是「不被代偿」

原来假设只做到「关系层被叫停」：关系问题关系层负责到底，可**帧层和检索层**
照样按没有假设的世界答话 —— 「如果 我 不 怕 黑」之后问「你害怕黑吗」，
帧层照样渲染出「我 怕 黑」，和自己刚说的假设正面矛盾。

现在帧/检索给出的句子先过一遍 `ai_hypo_conflicts()`：

1. **看图的边**：句子里若有一对词 `(x,y)`，图里有 `x -[r]-> y`（或否定形式），
   而看得见的假设写的是相反极性 → 冲突；
2. **看句面**：句子里同时出现 `a` 和 `b`、中间夹着这个关系的词（`怕`/`会`/`属于`…），
   极性看 `a` 与关系词之间有没有「不/没」 → 和假设相反就算冲突。
   第二路是必须的：帧的答复是模板渲染的，句中的边不一定在图里，只查图就管不住帧层。

命中冲突就**作废这句话**（检索那条另加一道「第五关」），并在思维链上记一步
`假设否决了检索/帧层的说法（和假设相反）` —— 否则看起来像系统漏答了。
没开假设时零开销（先 `hypo_visible_n`）。`tests/hypo_frames.sh` 看护四条：
没有假设时行为不变、相反时被否决且链上写明、一致时照说、假设下的关系问题仍由关系层负责。

### 33.4 局限④：归属 = 每个「他」一份**信念表**

原来 `OtherModel` 里只有 `who/trust/n_interactions` 三个字段，谁都没用 ——
「他 以为 X」只是给假设层贴个标签，轮末就没了；问「他 觉得 X 吗」其实是拿
**我的知识**答的。那不叫视角推理。

现在：

* `他 以为 猫 会 飞` / `他 说 X R Y`（**陈述**，不是「如果」）→ 存进**他名下**
  （`OtherModel.bel[]`，模型 v8 起持久化），并指出「可我知道实际上不是这样」；
* `如果 他 以为 X` 仍然是**反事实假设**（临时、不存盘）—— 两者绝不混淆，
  测试专门看护「反事实不写进他者模型」；
* 问他的想法（`他 觉得 X 吗`）时，把他名下的信念**临时铺成一层假设**（`who = 他`）
  交给原来的求解器/验证器/链式渲染 —— 他的信念和归他的假设因此走**同一条**代码路径，
  不需要为它开特例；答完立刻按 depth 原样撤回（所以外面包了一层，
  中间从哪儿 `return` 都不会漏）；
* 他没说过这个 → 老实说「我没听他说过这个」，**不许**拿我的知识冒充他的想法；
* 我不知道、但他提过 → **引用**他的话：「他 说过：猫 会 跳舞 —— 我不知道实情」；
* 看法和我的知识相反时，答复里补一句「（这是他的看法；我知道实际不是这样）」。

顺手修了一个同类 bug：`ai_identify_speaker` 原来只看「他/你/她 + 下一个词」，
于是 `他 以为 …` 给「以为」建一个他者模型、`他 说 …` 再给「说」建一个，
一次对话冒出好几个**假人**。现在后面那个词必须不像谓语（有一张小的排除表）。

`::others` 看他的信念表；`::derivedump` 的 `O` 行把它纳入存读一致性比较。

### 33.5 新的一条：缺前提 → 否定能力（规则 R9）

这是「训练数据里没有『猫 会不会唱歌』，也要能推出来」的答案。做法是加一个
**核心关系「需要」**（`REL_NEED = 9`）和一条推导规则：

```
唱歌 需要 灵活的声带      （做这件事的前提）
猫   没有 灵活的声带      （这个主语没有那个前提）
⟹ 猫 不 会 唱歌           （结论在语料里从来没出现过）
```

* **关系**：`AI_RELS` 里 `{ "需要", "不 需要", REL_NEED, … }`。
  第 9 个核心关系要 bit8，`AssocEntry.rel/nrel` 因此从 1 字节扩到 **2 字节**
  （`MODEL_VERSION` → **9**；v8 及以前在文件里仍是 1 字节，按单字节读，
  那些文件不可能有 bit8）。`REL_DYN_BASE` 跟着从 9 挪到 10（`dyn` 字节存的是
  相对值，所以旧文件不受影响）。
* **规则 R9**：`want_neg && rid == REL_CAN` 且 `rel_need_witness()` 找得到一个前提
  `P`（`Y 需要 P`，且 `X` 或它的上位 `X'` 明确「没有 P」）→ `X 不 会 Y`。
  链上只写两步（起点 → 结论），「理由」由规则号表达 —— 和独占那条一个套路。
* **验证器独立复核**（`der_verify` 的 `rule == 9`）：自己再找一遍那个前提，
  找不到就是缺口。`der_rule_name(9) = "缺前提"`，链上读作
  `猫 -[会·缺前提]-> 唱歌`。
* **只加在 `会` 上**：别的动词（吃/喜欢/怕）没有「前提」这回事，
  硬套会推出「猫 没有 声带 ⟹ 猫 不 喜欢唱歌」这种胡话。
* **前提可继承一跳**：`唱戏 属于 唱歌` + `唱歌 需要 灵活的声带` ⟹ `唱戏` 也要声带；
  `猫 属于 猫科` + `猫科 没有 P` 同理。
* **口语里的「没有」**：`猫 没有 声带` 是一个词而不是「不 有」两段，
  `rel_parse` 和 `relations_load` 都要认（只接受**正好一个宾语词**，
  多的词宁可整句不认，也不能静默丢词）。
  否定事实的答复措辞改取 `AI_RELS[].neg`，于是说「鱼 没有 声带」而不是「不 有」。

`relations.txt` 里新增的知识（这是**数据**，不是硬编码）：

```
唱歌 需要 灵活的声带
唱歌 需要 声带
猫 没有 灵活的声带
鱼 没有 声带
```

实测：`猫 会 唱歌 吗` → 「不 对 ， 猫 -[会·缺前提]-> 唱歌」（链上 `缺口=0`，验证器验过）；
`鱼 会 唱歌 吗` → 不 对（鱼没有声带）；`狗 会 唱歌 吗` → 关系层不表态（帧层照旧兜底）。
`tests/prerequisite.sh` 还证明结论**来自数据**：把「需要」那两条拿掉，就不许再推否定。

### 33.6 顺带：三个测试的探针换了位置

`猫 会 唱歌` 原来是「推不出来」的标准例子。它现在被 R9 接住了，于是：

* `tests/derivation.sh` 的「缺口 → 不下断言」改用 `猫 会 跳舞`；
* `tests/logic4.sh` 的「有假设时明说推不出来」同样改用 `猫 会 跳舞`；
* `tests/belief.sh` 的「我不知道但他提过 → 引用他的话」改用 `猫 会 跳舞`
  （我既然能推出「猫不会唱歌」，就不该去引他的话了）。

三处都在注释里写清了为什么换 —— 不是把断言改松，而是**探针要挑真的没有知识的**。

```
猫 属于 鸟 不算 了        → 撤了第 1 层，第 2 层原样保留
猫 会 唱歌 吗             → 不 对，缺前提
::excl                    → 独占判定的全部证据
::others                  → 他者模型（他的信念表）
```

### 33.8 剩下的局限（继续照实说）

1. **「需要」只支持肯定**（`唱歌 不 需要 声带` 不解析），也不出现在「缺前提」之外的规则里。
2. **前提继承只放一跳**（`Y 属于 Y'`、`X 属于 X'` 各一跳）；更深的链要显式写出来。
3. **冲突否决是句面的**：只看「同现 + 中间的关系词 + 极性」，不做语义理解 ——
   长句里可能误伤（宁可不说，也不说反话）。
4. **他者信念表不参与我的推理**：他的看法只在他的视角下算数；「他说的对不对」这件事
   目前只做了「点出分歧」，没有做「按信任度决定要不要采纳」。
5. **帧层在假设下的「补全」还没做**：现在只做到「和假设相反的话不说」，
   没做到「按假设补出该说的话」。
