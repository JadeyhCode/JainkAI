# 记事本与草稿区：把「输出」做成 AI 可编辑的文本（**作为补丁**）

> 用户的原话：
>
> > 「我打算把回答的输出设置为 AI 可以编辑的文本，AI 可以干的事情就类似**记事本**，
> > 然后 AI 可以控制**什么时候发送**，还有就是给一个**草稿区**，用来打草稿，
> > 这两个我认为应该**作为补丁**」
>
> 结论：这两个能力**不是塞进输出流水线**，而是走**补丁边界** ——
> 内核只多认三个口子（暂存 / 取输出 / 调用操作），完全不知道"记事本"是什么。
> 备份：动手前那一份在 `_backup/`（见 `docs/语境退役-前提token.md` 开头那次的同目录）。

---

## 一、内核侧只加了三条口子（通用，不给记事本特判）

`Patch` 结构多了三个可选回调（补丁想用就实现，不实现就是空转）：

| 口子 | 签名 | 内核怎么用 |
|---|---|---|
| **暂存** | `void stage(Patch*, const char *text)` | 一轮结束前，把**流水线本来要说的原文**交给补丁（补丁爱怎么改改自己的副本） |
| **取输出** | `int emit(Patch*, char *out, size_t cap)` | 问补丁"这一轮发什么"：`1` = 用我写的；`0` = 我不接管；`-1` = **明确这一轮不说话**。按注册顺序问，第一个接管的赢 |
| **调用操作** | `int op(Patch*, const char *op, char *const *args, size_t n, char *out, size_t cap)` | 内核**不解释** op 的语义，只做有界派发 + 故障隔离 |

配套：
* `patch_stage_all / patch_emit_all / patch_op_call_by_name` 三个**有界**派发器；
* 新修改意图 **`MOD_PATCH_CALL`**：AI 想用外设，走**和改图同一条受审通道**
  （审查 → 记账 → 应用 → 审计），吃**硬预算** `max_patch_calls_step`（默认 4，`::safe` 里看得见）；
* 新 Token 行为 **`::op 调用补丁 <补丁> <操作> [参数…]`** —— 行为表里加一行，语言层/CLI/AI 三条路都通。

`agent.h` 的输出段现在长这样（没挂补丁时三步全是空转，`out` 还是流水线文本）：

```c
patch_stage_all(ai, out);          /* ① 把"本来要说的话"交给补丁暂存 */
micro_patch_act(ai, out);          /* ② 动作补丁照旧只拿到 Token（日志/机械臂那类） */
int pr = patch_emit_all(ai, p, sizeof p);   /* ③ 问"这一轮发什么" */
if (pr == 1)       snprintf(out, out_cap, "%s", p);
else if (pr == -1) out[0] = 0;             /* 补丁说：这一轮不说话 */
```

## 二、记事本补丁（内置，`::patch mount 记事本`）

两个缓冲：

| 缓冲 | 谁写 | 作用 |
|---|---|---|
| **草稿区** `draft` | `写 / 插入 / 删 / 改 / 清空` | 打草稿。**不影响发言** —— 写坏了大不了清空 |
| **待发送** `outbox` | `插入发言 / 删发言 / 改发言 / 提交 / 清空发言` | 这一轮真的要说的话（`提交` 把草稿搬进来） |

两个模式：

| 模式 | 行为 |
|---|---|
| `auto`（**默认**） | 流水线本来要说的文本**原样**进待发送并发送 → **没编辑时逐字节等于**没挂补丁时的输出（挂上它不改行为） |
| `manual` | 流水线文本先扣在待发送区，AI 不显式 `发送` 就**不说话** —— 这就是"控制什么时候发送" |

操作清单（`::patch op 记事本 <操作> [参数…]`；位置按**字符**算，长度按字符算）：

```
写 <文本…>            追加到草稿
插入 <字符位> <文本…>  在草稿的字符位置插入
删 <字符位> [字符数]   删草稿的一段（不会把汉字劈成两半）
改 <旧> <新>           草稿里第一处替换（单 token，CLI 传不了带空格的旧串）
清空                  清空草稿
提交                  草稿 → 待发送
插入发言 <字符位> <文本…> / 删发言 <字符位> [字符数] / 改发言 <旧> <新>   直接编辑"要说的那句话"
清空发言              清空待发送
发送 / 不发            这一轮发不发（`manual` 下才有意义）
模式 <auto|manual>     切模式
读                    报出两个区的内容、模式、本轮发不发
```

实测（真模型）：

```
你 > ::patch mount 记事本
你 > ::patch op 记事本 模式 manual
你 > 猫
AI >                                  ← **不说话**：AI 还没决定发
你 > ::patch op 记事本 读
[补丁 记事本.读] 草稿[0字节]=(空) | 待发送[15字节]=猫 看 来 跑 | 模式=manual | 本轮发=否
你 > ::patch op 记事本 改发言 看 跑   ← 编辑"要说的那句话"
你 > ::patch op 记事本 发送
你 > 猫 有 毛 吗
AI > 猫 跑 来 跑                      ← 说出来的是**它自己改过的那句**
```

## 三、坑（都踩了）

1. **`char[4][40]` 不是 `char**`**：`MOD_PATCH_CALL` 的参数数组直接强转传给补丁，
   补丁把参数行当指针读 → 当场 SEGV（ASAN 定位到 `note_append`）。必须先落成真正的
   `char *argv[4]`。**教训**：跨边界传"字符串数组"要么带长度+指针数组，要么别转。
2. **位置不能按字节**：中文一个字 3 字节，`删 1 1` 会把「在」劈成半个字符。
   现在 `插入/删` 的位置按**字符**（UTF-8 码点）换算成字节偏移。
3. **`-Werror=format-truncation`**：补丁名(24)+操作名(48)+返回说明(160) 一起 `snprintf` 到 192 字节的
   note 里会被拦 —— 改成有界手动拼接（截断是故意的）。
4. **手动模式的暂存语义**：`stage` 不能每轮覆盖 AI 已经写好/排好的内容，也不能重置它的
   "发送"决定 —— 否则"打草稿、改满意了再发"根本跨不了轮。现在的规则是：两个区都空时才把
   流水线的话放进待发送，且不碰 `send_flag`。

## 三点五、让 **AI 自己**用它：写草稿 / 决定什么时候发送（`::notepad`）

补丁在那儿，但"什么时候该打草稿、什么时候该发送"得由**思维层**决定 —— 这才叫
"AI 可以控制什么时候发送"。落地在 `think_settle` 的**思维改脑**那一段
（和「登记连结 / 沉淀 / 撤销缓存」同一处：那里是"这一轮想完之后，我打算做点什么"），
提议照样走**受审通道**（`MOD_PATCH_CALL` → 审查 / 预算 / 审计）：

| 开关 | 这一轮有结论（成立**或**不成立） | 这一轮没结论 |
|---|---|---|
| `::notepad off`（**默认**） | 什么都不做（流水线照说） | 什么都不做 |
| `::notepad on` | 把结论写进**草稿区**并 `发送` → 说出来的是**它自己写的那句** | 什么都不做 |
| `::notepad hold` | 同 `on` | **按住不说**（`不发` → 这一轮不出声） |

前提：挂了 `记事本` 补丁才谈得上（没挂 → 机制整个空转，内核照跑）。

实测：

```
你 > ::patch mount 记事本
你 > ::notepad on
你 > 猫 会 唱歌 吗
AI > 猫 不 会 唱歌                    ← 它自己写的结论（流水线本来会说
                                        「不 对 ， 猫 -[会·缺前提]-> 唱歌」）
你 > ::notepad hold
你 > 猫 会 跳舞 吗
AI >                                  ← 没想清楚就**不说**（::delib 里看得见「按住不说」）
```

三条实现层的规矩（都是踩出来的）：

1. **输出侧的两个口子顺序要对**：`stage`（暂存流水线原文）在**安全点之前**，
   `emit`（问"这一轮发什么"）必须在**安全点之后** —— 否则思维层这一轮"要不要说、说什么"
   还没应用完，就已经问过它了（实测：`hold` 生效不了）。
2. **AI 自己写的优先**：`发送` 时若草稿非空 → 草稿顶掉流水线早先 `stage` 进来的那句
   （否则写完的结论发不出去）。
3. **`stage` 绝不覆盖 AI 自己写过的东西**：只要草稿或待发送非空、或它已经明确表过态
   （发送/不发），流水线这一轮就只是"替它起草"，不再改主意。

**A/B（按规矩先量）**：

| 跑法 | 结果 |
|---|---|
| `sh tests/all.sh`（默认关，不挂补丁） | **31 套全绿** |
| `AIP_NOTEPAD=on sh tests/all.sh`（开着但**没挂补丁**） | **31 套全绿**（机制真的挂在补丁上，不是挂在内核上） |
| `AIP_PATCH=记事本 AIP_NOTEPAD=on sh tests/all.sh` | **9 套变红**：relations / hypothesis / logic4 / belief / hypo_frames / prerequisite / consolidate / revision / tokenop |

第三行**不是 bug，是这件事的定义**：那些套钉的是**流水线的措辞**
（`猫 属于 生物` 要带规则名、链式渲染要出现），而机制一旦打开，AI 就用**自己写的句子**
（`猫  属于 生物`，草稿区里的投影）把它替掉。所以：**默认关**，
`::notepad on|hold` 显式打开 —— 和 `::thinkout`（改了默认、因为那是修 bug）、
`::premiseout`（改了默认、因为 A/B 0/8 且严格更好）不同：
**这一条按定义就要改输出，默认权留给用户。**

## 四、看护与局限

* `tools/optest.c` 第十三节（25 项）：auto 逐字节回放、草稿六种编辑、提交/改发言、
  manual 沉默与发送、**受审通道 + 预算**、故障隔离（连错 3 次自动停用）、卸载后回到流水线。
* `tests/selfmod.sh` 第七节（CLI）：挂上不改行为（与无补丁的输出**逐字节比对**）、
  草稿区、manual 沉默、编辑+发送说出的确实是改过的那句、`调用补丁` 走审计、坏补丁不拖累内核。
* 全量 31 套仍全绿；`model.bin` 不变；**格式没动**（两个缓冲是瞬态，不进存档）。

局限（照实说）：

1. **缓冲不持久化**：记事本随进程走，`::save` 不存草稿（要存就是新格式字段 —— 没做，先别假装）。
2. **`改`/`改发言` 只认单 token**：CLI 参数按空格切，替换串含空格传不进去（C 层/语言层没这个限制）。
3. ~~**AI 自己"想"到要用外设**还没有机制~~ **已做**（第三点五节：`::notepad off|on|hold`，
   思维改脑那一段提议、走受审通道）。局限是：它的"想清楚"用的是思维层自己的结论，
   **还不会**结合"刚刚那句降级答复到底行不行"来决定要不要改口。
4. **`manual` 模式默认关**：现在默认 `auto`，所以挂上补丁 = 行为不变；要它"想说先扣着"得显式切模式。
