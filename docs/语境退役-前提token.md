# 语境退役：用**前提 token + 行为 token + 临时 token** 替掉边上的「语境」字段

> **给三天后的人（一句话）**：v9→v10 删掉语境字段之后，"条件"改由**普通 token + 动作槽标记**表达（`[前提]`/`[前提不]`），
> 以及三档前提成立判据（提到过 / 够得着 / 有据）。
> **代码**：`token.h` 的 `edge_premise_*`、`ai.h` 的 `ai_premise_holds`；**看护**：`tests/prerequisite.sh`。


> 用户的决定（原话）：
>
> > 「语境我想要淘汰它，你想想可不可以用行为 token 和临时 token 替代」
> >
> > 「语境想要淘汰还要有**前提 token** 和**行为 token** 和**临时 token**，
> > 前提 token 可以被正常联想到，但是逻辑会知道前提 token 是什么」
> >
> > 「我这话有歧义，**联想本来不依赖前提，可以正常联想**，前提 token 可以被正常联想到，
> > 但是**逻辑会知道这两个之间的前提 token 是什么**，并且可以被正常处理」
>
> 结论：**可以替代，而且替代之后表示的层次更清楚** ——
> 条件从「边上的一个字段」变成「图里的一个节点 + 边上的一个标记」。
> 备份：`_backup/20261007-primop/`（动手前那一份，含 model.bin，逐字节校验过）。

## 一、先量：语境到底在干什么（改之前）

| 量什么 | 结果 |
|---|---|
| `model.bin` 里带语境（`assoc.n_subs>0`）的边 | **0 条**（41138 条边） |
| 带否定语境（`n_not>0`）的边 | **0 条** |
| 各语料（`_corpus.txt`/`seed*.txt`/`dialog.txt`/`generated.txt`）里 `[原语:前关联]` | **0 处** |
| 谁能创建它 | 只有语言层的 `[原语:前关联] X` + `[原语:连接]` 这一个句式 |
| 谁在消费它 | `entry_matches()` —— **扩散激活**（`token_activate*`，四个调用点）会按语境放行/拦截；**走边生成**（`ai_edge_walkable`）则**直接跳过**带语境的边 |

所以「语境」当时的实际角色是：**激活层的一道门**（"这个转移只在某些词在场时才走"），
而它在生成/关系/知识里都没有份。它的表达能力只有语言层一个句式在用。

## 二、替成什么：`A —[前提]→ P → B`

```
A —[前提]→ P → B
     │       │
     │       └── P 是**前提 token**：一个**普通 token**（可以是被说出来的词）
     └────────── `[前提]` 是**行为 token**（标记），挂在 A→P 这条边的**动作槽**上
```

三条性质正好对上用户的三句话：

| 用户的话 | 实现 |
|---|---|
| 「联想本来不依赖前提，可以正常联想」 | A→P→B 都是**普通边**：`ai_edge_walkable` 不认识 `[前提]`，联想照走（`tools/optest.c` 断言 A→前提 是可走边） |
| 「前提 token 可以被正常联想到」 | P 就是普通 token：有自己的边、有权重、能被 `::rel`/`::edges`/联想/关系层正常处理，**没有任何特殊对待**（它不是 `[` 标记） |
| 「逻辑会知道这两个之间的前提 token 是什么」 | `token_premise_between(A,B)` 直接答出 P（可多个）；CLI 是 `::premise A B`；`::edges` 把前提链接标成 `**前提**` |
| 「临时 token」 | 不给前提名时缺省用 `[临:前提]`（草稿：不存盘、没人引用时可回收） |

**为什么不用「把 P 塞进 token 名字」**（比如 `[前提:吃]`）：那样多前提就得拼字符串、
条件就不能被当数据查询了。前提是节点，条件才是图。

## 三、旧字段怎么办：**退役而不是删除**（格式仍 v9）

`AssocEntry.subs[]`/`subs_not[]`/`n_subs`/`n_not` 是**存档字段**（v9 就写在文件里）。
这一轮的处理：

| 做法 | 结果 |
|---|---|
| **不再有任何创建者** | 语言层的 `[原语:前关联]+[原语:连接]` 与 `::op` 全部改走前提表示；C 层测试扫一遍池子断言 `n_subs/n_not == 0` |
| **读得回来、老语义不坏** | `entry_matches()` 保留旧分支：旧模型里带语境的边照样按语境匹配（`optest` 用一条手写的旧边验证「语境在→匹配 / 不在→不匹配」） |
| **不动格式** | 字段照旧序列化（新数据恒为 0）→ **不用升 v10、不用重训**；将来要做 v10 时再物理删掉 |

这是「淘汰」的诚实版本：**语义退役了，字节留着兼容**。文档里不许说"字段已经删了"。

## 四、命令与语言层入口（都换到前提表示）

| 入口 | 语义 |
|---|---|
| `::op 加前提 <A> <B> [前提名]` | 建 `A —[前提]→ P → B`（P 缺省 `[临:前提]`），并拆掉 A—B 的直连（拆不动就保留并说明——关系边是知识） |
| `::op 前提接线 <A> <前提P> <目标Y>` | 让 A 经前提 P 也能到 Y（确保 A—[前提]→P 并加 P→Y）—— 这就是原来「按语境接线」那条能力，**选择判据从字段换成了图里的前提链接** |
| `::premise <A> <B>` | **逻辑的那句话**：答出这两个之间的前提 token 是谁（可能多个） |
| `[原语:前关联] P` + `[原语:连接] A B` | 同一件事的语言层写法 → 走「加前提」（语言层照旧**不碰图**，交宿主过安全内核） |
| `[原语:前提接线]` | 前提接线的语言层写法（弹 A、P、Y 三个操作数） |

原来的 `随语境接线` / `指定接线` / `[原语:接线]` / `[原语:指定接线]` **已删掉**（语境跟着退役），
`::prims` 的表里也随之少两条、多一条 `[原语:前提接线]`（36 条）。

实测（真模型）：

```
你 > ::op 加前提 猫 月亮
[行为 加前提] 猫 —[前提]→ [临:前提] → 月亮（已提出）；应用 1 条
你 > ::premise 猫 月亮
[猫 与 月亮 之间的前提 token：1 个]
    [临:前提]  （普通 token：联想照走、::rel/::edges 都能正常处理它）
你 > ::op 加前提 猫 月亮 食物
你 > ::edges 猫
  → 食物   hits=1  ...  **前提**（食物 是这两个词之间的前提 token）
你 > ::premise 猫 月亮
    [临:前提]
    食物
你 > ::asm [原语:对象] 猫 [原语:对象] 吃 [原语:前关联] 饿 [原语:连接]
[原语 加前提] 猫 —[前提]→ 吃 → 饿（已提出）；应用 1 条
你 > ::premise 猫 饿
    吃            ← 前提是一个**普通词**，它照常能被联想到
```

## 五、消费：**推理/思维层按前提决定用不用**（已落地）

用户的话：「**联想本来不依赖前提**，可以正常联想……但是逻辑会知道这两个之间的前提 token 是什么」
+「推理/思维层按前提决定用不用」。所以**闸门只装在逻辑这一侧**：

| 层 | 前提的角色 |
|---|---|
| 走边 / 自由联想 | **完全不看前提**：A→前提 是普通可走边（`ai_edge_walkable` 不认识 `[前提]`）—— 前提不成立也不挡回忆 |
| 求解器（`rel.h`） | **R10「经前提」**：`A —[前提]→ P`，**P 在当前注意窗口里**，且 `P R B` ⟹ `A R B`。前提不成立 → **不用**这条连结（不是"图里没有"，是"现在用不了"） |
| 验证器（`derive.h`） | 独立复核前提步（规则 10）：① 边必须是前提链接；② 前提**现在成立**。伪造的前提步 → `gaps>0` 被拒 |
| 思维层（`think.h`） | 第 5 条内建机制**「问前提」**：痕上写明「这条连结有前提：人（没成立）—— 前提没成立，按前提**不用**它」。它排在机制表**第一位**（最便宜、且解释失败原因；实测排在后面会被停滞检测吃掉） |

判据一句话：**前提 token 出现在当前注意窗口里（输入里的词会被推进焦点环）⇒ 前提成立**。
只看注意力、不看权重 —— 简单、确定、说出来也听得懂（"你刚才提到过它"）。

实测（真模型；`人 会 做饭` 是模型里已有的知识，把它当 猫 与 做饭 之间的前提）：

```
你 > ::op 加前提 猫 做饭 人
你 > 猫 会 做饭 吗                      ← 前提「人」不在语境
AI > 猫 应该 会 做饭                     （关系层没硬用那条连结）
     ::delib → 6. 问前提 ✗ 这条连结有前提：人（没成立） —— 前提没成立，按前提**不用**它

你 > 人 好                              ← 前提出现在语境里
你 > ::op 加前提 猫 做饭 人
你 > 猫 会 做饭 吗
AI > 对 ， 猫 -[前提]-> 人 ； 人 -[会]-> 做饭     ← 用上了，链上看得见前提这一跳
```

另外两个**查询/可辨识**入口（上一小节就有，这里并列保留）：
`token_premise_between()` / `::premise`（同一对词可以有多个前提）、
`::edges` 把前提链接标成 `**前提**`。

**为什么这不改变既有行为**：现成模型与语料里**一条前提链接都没有**（0 条），
所以 R10 在真实对话里永远不触发；它的行为只在显式建了前提之后才出现 ——
这也解释了为什么 31 套回归一条没变（`model_roundtrip` 仍逐字节一致）。

## 五点五、反前提（`[前提不]`）与「前提说明进答复」

上一节留下的两条局限这一轮补掉了：

### ① 反前提：`[前提不]` —— 条件是"前提 token **不在**注意窗口里"

```
A —[前提不]→ P → B      只要没人提到 P，A 就能到 B（旧 subs_not 的能力有了替代）
```

* 创建：`::op 加反前提 <A> <B> [前提名]`；语言层 `[原语:前关联不] P + [原语:连接] A B`；
* 消费：求解器 R10 按**极性**判条件（正前提要它在窗口里，反前提要它不在）；
* 验证器：规则 **11**（`前提不`）独立复核，而且**极性必须和链上写的规则对得上** ——
  把一条正前提写成规则 11 会被 `gaps>0` 拒掉；
* 链上读作 `猫 -[前提不]-> 人 -[会]-> 做饭`（和正前提的 `-[前提]->` 分得开）。

实测：

```
你 > ::op 加反前提 猫 做饭 人        （没人提到 人）
AI > 对 ， 猫 -[前提不]-> 人 ； 人 -[会]-> 做饭
你 > 人 好                            （提到了 人）
你 > 猫 会 做饭 吗
AI > 猫 应该 会 做饭（不过这件事有个前提：不 人（没成立） —— 你刚才没提到它，所以我先不用这条连结）
```

### ② 前提说明进答复：**默认开**（A/B 量过 0/8）

上一节说"痕迹只在 `::delib` 可见，还没进答复"——现在进了，走的是思维接管输出那条路
（**追加**，不替换原答）：

| 开关 | 效果 |
|---|---|
| `::premiseout on`（**默认**） | 有连结因为前提条件不成立而没用时，在回答后面追加「不过这件事有个前提：… —— 你刚才没提到它，所以我先不用这条连结」 |
| `::premiseout off` | 一个字都不加，只留在 `::delib` 的痕上 |

翻默认之前先量（`tests/premiseout_ab.sh`，把 8 套行为看护开/关各跑一遍）：
**0/8 变了** —— 现成模型与语料里一条前提链接都没有，所以这个开关对既有会话本来就是惰性的；
而探针那一侧严格更好（上面那两行对比）。和当年 `::thinkout` 翻默认的规矩一样：
**先 A/B，再翻**（反向测量：`AIP_PREMISEOUT=0 sh tests/all.sh`）。

## 五点六、前提的**生产端**：D4「条件依赖」——从反复出现的谈话里自己长出来

前面几节的入口都是**手打**（`::op 加前提`、`[原语:前关联]+[原语:连接]`）。
这不合"知识必须从图/语料/流里读出来"的原则 —— 前提是知识，不该只有手打入口。
这一轮补上生产端：微内核第 4 个内建检测器 **D4 条件依赖**。

**判据（全在流里，不新造字段、不动格式）**：

```
A 与 B 的同轮共现里，有 ≥70% 的轮次 P 也在场（且 n_triple ≥ 3、n_pair ≥ 3）
⟹ 提议 A —[前提]→ P → B（就是 `加前提` 那条意图，照样过安全内核）
```

两张**有界**表（满了淘汰计数最低的一行，不动态分配）：

| 表 | 记什么 | 为什么 |
|---|---|---|
| `(A,B) → n_pair` | A、B 同轮的次数 | **分母**。必须**独立于 P** 记 |
| `(A,B,P) → n_triple` | 三元同轮的次数 | **分子** |

> ⚠ 这类检测器最容易犯的错：分母只统计"P 在场的那些轮"，比值恒等于 100%。
> 实测踩过两次：① 短句（只有 A、B 两个词）整轮被 `n < 3` 跳过 → 分母少算一半；
> ② 检测器**拿自己刚造出来的边当依据**（它建的 `A→P` 也是"连结"）→ 级联再提一条。
> 现在的护栏：**两个词也要记分母**；只认命中 ≥2 次的"观测到的连结"才算证据
> （和"缓存不许互相为依据"是同一条纪律）。

**阈值是量出来的，不是拍的**（`tools/d4probe.c` 回放 `_corpus.txt` 两万行）：

| 门槛 | 会提几条（19888 轮） | 备注 |
|---|---|---|
| 分母≥3、比例≥70% | 18 条 | 里面混着 `4/5 = 80%`、`6/8 = 75%` 这种**小样本巧合** |
| **分母≥8、分子≥5、比例≥70%**（现在） | **~19 条**（换了一批） | 留下的都是几十上百次里稳定 ≥70% 的模式 |

**量出来的两个计数陷阱**（都已修 + 都写了反例测试）：
1. **分母必须存在三元组行里**：原来分母在另一张表，48/64 的容量在真实语料上**秒满**，
   淘汰一轮后分母被挤掉、分子还在 → 比值算出 `0%` 甚至 `171%`（分子比分母还大）。
2. **同一轮里的重复词要去重**：`你 我 你` 这种一轮里重复出现，会让分母只加一次、
   分子加两次 → 比值 `179%`、`270%`。"同轮共现"按**轮**算，不按出现次数算。

标定后的候选长这样（真语料，全部 ≤100%）：
`你 —[前提]→ 我 → 说（1133/1188 = 95%）`、`你 —[前提]→ 我 → 想（89%）`、
`你 —[前提]→ 我 → 喜欢（96%）`、`我 —[前提]→ 你 → 帮（94%）` ——
**"我"确实是这对词的前提**（这个语料里"你…说"几乎总在"我…你…"的句子里）。

实测（真模型；`::mod cond on` 打开）：

```
你 > ::mod cond on
你 > 猫 鱼 水
你 > 猫 鱼 水
你 > 猫 鱼 水
你 > ::premise 猫 鱼
[猫 与 鱼 之间的前提 token：1 个]
    前提：水  （现在成立；普通 token：联想照走、::rel/::edges 都能正常处理它）
你 > ::mod
[微内核] … 检测器：共现固化=开 条件依赖=开(提1/成1) …
```

**默认关**（`::mod cond on` 手动开；测量钩子 `AIP_D4=1`）：它会在对话里**改结构**
（建前提链接、拆直连），和"删错比不删更糟"同理 —— 先实现、先测量（`AIP_D4=1 sh tests/all.sh`
对照 `sh tests/all.sh`），再谈翻默认。统计表是**会话内**的（不进存档），装载后重新计数。

## 六、局限（照实说）

1. **前提只在推理/求解这一侧当闸门**：联想、生成、检索都不看它（刻意的，见第五节）。
2. **操作数必须是池子里已有的 token**（`::op 前提接线 甲 乙 丙` 会报「找不到词」）；只有「加前提」的名字槽会按需 intern。
3. **旧字段留着**（退役但没删）：`::pooldump`/`::edges` 对旧模型仍会打印语境；新数据永远是 0。
4. **`[原语:前关联] + [原语:断开]`** 这条旧组合是"按语境删边"，语境退役后它找不到那种边 ——
   保留（无害）但语义已经空了，没做迁移（因为没人用它）。
5. ~~**前提不带极性**~~ **已补**（见第五点五节：`[前提不]` + 规则 11）。
6. **前提说明是"追加"而不是"替换"**：如果原来的降级答复本身就不合适，这一句也救不了它 ——
   那属于输出流水线的事，不在前提这一层。
7. **反前提的语义是"没人提到"**，不是"世界上不成立"：判据仍是注意窗口（简单、确定、可解释）。
8. **D4 只从"同一轮一起出现"学前提**：更细的条件（顺序、句法位置、否定）没做；
   而且它**默认关**，统计表也是会话内的（装载后从头计数）。
