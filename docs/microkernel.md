# 微内核：安全内核 + 自修改意图队列 + 补丁边界 + 元认知

> 落地的是分享讨论（2026-10-03）里的**内核**部分：
> 「核心要足够健壮，视觉/3D 这些作为补丁后装」「动态加边、加 Token」
> 「激活时提议、安全点应用」「元认知监控补丁」「与 CPU 解耦」。
> 本文只写**已经落进代码、并且有测试看护**的部分；没做的单独列在第十一节，
> 不假装做过。
>
> 新文件 `micro.h`（1341 行，单头文件、`static inline`、零外部依赖，风格与
> `token.h`/`ai.h` 一致），在 `ai.h` 末尾包含 —— 那时 `AI` 结构已完整。
> **存档格式没有动（仍 v9）**：微内核状态用 `AI.micro` 懒分配、不进模型文件，
> 自修改**产生的 Token 和边本身**随图存盘。所以本仓库的 `model.bin` 不用重训。

---

## 一、一句话

关联机定义的第二条 —— **Token 和关联在运行时被系统自身修改** ——
现在有了一条**受审的通道**：

```
激活 / 学习 / 补丁 ──只「提议」──▶ 修改意图队列 ──▶ 安全内核审查 ──▶ 安全点应用
                                                     │拒绝                │
                                                     ▼                    ▼
                                                  审计（理由分类）    记账（预算）→ 元认知
```

在此之前，结构修改散在好几处直接调用（`token_add_assoc_unique`、`token_tag_rel`
……），没有统一的预算、审查和记录。现在有一条统一入口，
它同时是**可解释的**（`::mod` 看最近应用了什么）和**可追问的**（`::safe` 看每条
意图为什么被拒）。

## 二、为什么必须「提议 → 安全点应用」

不是洁癖，是三个具体的崩法（`token.h` 里那句「`on_visit` 内不得对当前 Token 做
`add_assoc/consolidate`」就是这个边界）：

| 在遍历里直接改结构 | 后果 |
|---|---|
| `token_add_assoc_ex` 里 `realloc(t->assocs)` | 正在用的 `AssocEntry *e` **当场失效**（悬垂指针） |
| 边变多 → `t->count` 变了 | `for (i = 0; i < reach; ++i)` 漏边或越界 |
| 新 Token 没进路径栈 | 同一轮内被重复激活，能量算错 |
| 多线程/分布式下同时改 | 需要事务或版本号（当前是单线程，先不管） |

所以：**遍历里只往队列里写「我想干什么」，遍历结束（安全点）再统一做**。
`micro_step()` 是唯一的结构修改入口，它被放在 `agent_step()` 里
「输出成句 + 时间推进」之后、「维护（巩固/GC/睡眠）」之前 —— 一处，看得见。

## 三、安全内核（`SafetyKernel`）

### 3.1 预算

| 预算 | 默认 | 说明 |
|---|---|---|
| 每步新增边 | 8 | 被拒的意图**不占预算**（否则垃圾提案会把预算吃光） |
| 每步新增 Token | 2 | 造 Token 是最贵的一类修改 |
| 单 Token 边数 | 512 | 防单点膨胀 |
| 池子总量 | 400000 | 触顶 → 冻结 |

### 3.2 九条拒绝理由（审计按它分类统计）

| 理由 | 触发条件 |
|---|---|
| 自修改总开关关着 | `::mod off` / `::safe off` |
| 已冻结 | 速率失控或总量触顶后的停止条件 |
| 本步新建边超预算 / 新建 Token 超预算 | 见上表 |
| 池子总量触顶 | `pool->count >= max_tokens_total` |
| 单 Token 边数触顶 | `t->count >= max_edges_per_token` |
| 不许改保留 Token | 目标是 `[` 开头的骨架节点（`[原语:…]`/`[时刻:N]`/`[提醒:…]`） |
| **不许删关系边** | 这条边带 `rel`/`nrel`/`dyn` —— **知识不是共现**，硬底线 |
| 父节点不许成环 | `token_is_descendant(main, target)` |
| 不许自环 / 引用了空垃圾 Token / 这一类修改被关着 | 显然 |

### 3.3 开关与停止条件

* 反向命名（`mod_off`/`new_token_off`/`remove_off`），**`calloc` 出来的就是默认值** ——
  这是本仓库踩过「骨架漏设默认值导致训练/加载两条路径分叉」之后立的规矩。
  自修改**默认开**（按你的要求），`::mod off` 关。
* 停止条件两条：**总量触顶**、**窗口内每步都把建边预算用满**（16 轮平均 ≥ 上限）。
  触发就 `freeze`，之后一律拒绝，直到 `::safe reset`。
  阈值刻意设得高于检测器上限（D1 每步最多 3 条，预算 8 条）——
  正常对话**永远碰不到**它，它拦的是「补丁狂推意图」这种失控。
* 审计环 48 条：`tick / 操作 / 对象 / 允许还是拒绝 / 理由`，`::safe` 直接打出来。

## 四、修改意图（`ModIntent`，12 种）

| 类型 | 用途 | 谁在提 |
|---|---|---|
| 加 Token | 把「未知」具体化成一个新节点，并接回触发它的上下文 | 检测器 D2、思维层（`[自问:` / `[修正:`） |
| 加边 | 共现固化 / **按语境接线**（①号 Token 行为） | 检测器 D1、补丁、`::op` |
| 打关系 | 给边打语义关系位（属于/有/会…） | 补丁（内核不猜关系） |
| 设动作 | 给边挂动作 Token（**前提**就是用 `[前提]` 挂在动作槽上：`A —[前提]→ P → B`） | 补丁、Token 行为（前提接线） |
| 设父类 / 设类别 | 类别继承结构 | 补丁 |
| 强化 / 衰减 | 参数层的自修改 | 补丁 |
| 删边 | 剪枝（默认关，见下） | 检测器 D3、思维层（撤销缓存） |
| **插词**（`MOD_INSERT_BETWEEN`） | 在 A、B 之间插一个 Token 并（可选）拆掉直连：A→N→B | **Token 行为** `::op 中间插词` |
| **回收临时**（`MOD_REMOVE_TOKEN`） | 回收没人引用的 `[临:…]` 草稿（软删） | **Token 行为** `::op 回收临时` |

队列本身有**去重**（同一类操作 + 同一对端点算一条，`micro_intent_key`）、
**容量封顶**（64 条）和**溢出记账**（`n_dropped` 不是静默丢）。
意图**不跨轮**：一步之内要么应用要么被拒。

**Token 的行为（图操作）**：除了检测器和补丁，还有一类提案者 —— `TOKEN_OPS[]` 表里的
**行为**（接线 / 按语境接线 / 插词 / 回收临时）。它们和别的提案者走**同一条**路：
展开函数只产出 `ModIntent`，逐条过安全内核。所以「Token 有行为」不等于「Token 能绕过审查」。
两个入口：`::op <行为> <参数…>`（手动）与**原语**（`[原语:加前提]`（即
`[原语:前关联]P + [原语:连接]A B`）/ `[原语:前提接线]` / `[原语:插词]` /
`[原语:插词为]` / `[原语:回收临时]`，用已有的 `Interp` 栈机组合）。
「语境」（`subs`）已退役，条件改用**前提 token**表示，见 `docs/语境退役-前提token.md`。
原语层**不碰图**：它只把「行为编号 + 操作数」交给宿主（`main.c`），由宿主过这张表 ——
详见 `docs/token行为-图操作与临时token.md` 第四点六节。

两条**记账纪律**（都在这一轮被查出来才补上的，见 `docs/人思考的原理-采用与不采用.md`）：
* `safety_charge()` 必须在 `micro_apply_one()` **之前** —— 预算是「这一步允许多少」，
  而它靠 `!micro_has_edge()` 判「是不是新边」，应用之后再判永远是假（预算形同虚设）；
  应用失败用 `safety_refund()` 退回，被**拒**的意图从不记账。
* 「边存在吗 / 加权」这类判断要区分**带语境的边**（`micro_edge_index_ctx`）和
  不带语境的（`micro_edge_index`）：`n_subs>0` 的边在前者眼里是"不存在"。

## 五、内建检测器，以及一个实测出来的结论

三个检测器，判据都是**图内量出来的**，不是拍的：

| 检测器 | 判据 | 默认 |
|---|---|---|
| D1 共现固化 | 同轮距离 ≤2 的词对、两向都无边、且**出邻居共同 ≥4 且 Jaccard ≥ 30%** | 开 |
| D2 缺口命名 | 每 100 轮最多一个：末尾词 `token_gap ≥ 0.65`、边 ≥6、名字取当轮两个实词 | 开 |
| D3 休眠剪枝 | 边老（≥2000 tick）、hits 为 0、两端都还有别的边、不是关系边 | **关** |
| D4 条件依赖 | A 与 B 同轮共现里 ≥70% 的轮次 P 也在场（分子 ≥3、分母 ≥3）；两张**有界**表；只认命中 ≥2 次的连结当证据 | **关**（会在对话里建前提链接、拆直连，先测量再谈默认；`::mod cond on`） |

D1 的判据可以实测（`tools/overlapprobe.c`，本仓库 `model.bin`）：

```
鱼 ~ 雪   邻居 64/64  共同 41  Jaccard 0.471  无语境边 0/0  会固化=会
狗 ~ 猫   邻居 64/64  共同 38  Jaccard 0.422  无语境边 1/1  会固化=会（但已有边，跳过）
吃 ~ 飞   邻居 64/64  共同 18  Jaccard 0.316  无语境边 0/0  会固化=会
鱼 ~ 狗   邻居 64/64  共同 29  Jaccard 0.293  无语境边 1/1  不会
猫 ~ 吃   邻居 64/64  共同  9  Jaccard 0.076  无语境边 1/1  不会
```

**结论要照实说：D1 在真实对话里几乎不开火。** 10 轮普通对话实测提案 0 条。
原因不是判据太严，而是**内核原有的学习路径已经把输入输出里的共现都记下来了**：

* `ai_learn_pair` —— 输入里每一对相邻词 + 回复里每一对相邻词（还有自举那一步）；
* `ai_inner_dialogue` / `ai_imagine` —— 把焦点环、想象路径上的词也接线；
* `ai_learn_causal` / `ai_learn_expression` / `ai_credit_from_feedback`；
* `agent_step` 自己的 `[时刻:N]→词`；
* 训练期的 `token_observe_names`（窗口 5）。

所以「A 和 B 同轮出现但还没有边」这种情况，基本在 D1 看到之前就被上面的路径补上了。
这有一个直接后果，也是**好事**：**默认开着自修改，21 套既有回归一条都没变**
（`tests/model_roundtrip.sh` 连存盘都是逐字节相同）。
D1 真正的用武之地是那些既有路径覆盖不到的地方（补丁注入的 Token、被跳过/过滤的词对、
将来关掉某条学习路径时），以及**它是一条受审的通道**：
预算、去重、拒绝理由、审计都在这儿，而上面那些老路径全都绕过审查。

D3 默认关的理由：删错东西比不删更糟，而「剪枝该不该做」在短会话里根本观察不出来。

**D4 条件依赖**是**前提的生产端**（`docs/语境退役-前提token.md` 第五点六节）：
从反复出现的谈话里量出「A 到 B 的连结，前提是 P」→ 提议 `A —[前提]→ P → B`（就是 `加前提` 那条意图）。
它默认关的理由和 D3 一样：会在对话里改结构。判据的两个坑都在那份文档里（分母必须独立于 P；
不许拿自己刚造的边当证据）。
`::mod prune on` 可以打开。

## 六、补丁边界（微内核的「外设」）

```c
struct Patch {
    const char *name;
    PatchKind   kind;      /* 感知 / 动作 / 两者 */
    int         enabled, mounted;
    int    (*init)(Patch *, TokenPool *, void *cfg);
    size_t (*sense)(Patch *, TokenPool *, PatchOut *out, size_t cap);   /* 外部信号→Token */
    void   (*act)(Patch *, TokenPool *, Token *const *in, size_t n);     /* Token→外部动作 */
    void   (*update)(Patch *, TokenPool *, float dt);
    int    (*propose)(Patch *, void *mq);   /* 提议结构修改；void* = ModQueue* */
    void   (*destroy)(Patch *);
    /* ---- 输出侧的三个口子（外设不只有感官，也有"发声"的一侧）---- */
    void   (*stage)(Patch *, const char *text);      /* 暂存"这一轮本来要说的原文" */
    int    (*emit)(Patch *, char *out, size_t cap);  /* 1=用我的 0=不接管 -1=**明确不说话** */
    int    (*op)(Patch *, const char *op, char *const *args, size_t n,
                 char *out, size_t cap);             /* 补丁自己的操作；内核不解释语义 */
    /* 统计：n_sense/n_out_total/n_out_last/n_act/n_propose/n_err/err_streak/last_out_tick/
     *       n_stage/n_emit/n_op/n_op_err */
};
```

三条硬规矩（对应分享里那节的「补丁边界规则」）：

1. **只交换 Token**。要改结构就 `propose`，不能自己动手 —— 提议同样过安全内核。
2. **可缺失**。`patch_sense_all` / `patch_act_all` 在没挂补丁时是空转
   （`micro_patch_sense()` 里 `if (mk->patches.n == 0) return 0;`）——「核心不依赖补丁」
   不是口号，是这行代码。
3. **可失败**。`sense` 返回 `(size_t)-1` 记一次错，**连续 3 次自动停用** +
   留下 `[提醒:补丁异常已停用:<名字>]`；一个坏补丁不影响别的补丁，也不影响内核。

还有两条实现层的安全：

* 补丁越界写（说写了 100 条、实际只给 1 条）**按容量截断**，不信任补丁；
* 两个补丁对同一个 Token 一个说「有」一个说「没有」→ 元认知提
  `[提醒:补丁信号冲突:<名字>]`（`PatchOut.neg` 就是给这个用的）。

**本仓库不预置任何硬件补丁**：视觉、3D、听觉、运动这些是外设，装不装与内核无关。
内建的有两个，各证明边界的一侧：

```
::patch mount 自省
::patch
  自省    类型=感知 状态=启用 感知=2 输出=5(最近2) 动作=0 提议=0 出错=0
```

* **`自省`**（感知侧）：把**内核自己的状态**（疲劳高/把握低/知道感低/没有他者）变成 Token ——
  证明「外部信号 → Token」这条口子真的能用，且不依赖任何外部设备；
* **`记事本`**（输出侧，见 `docs/记事本与草稿区-输出补丁.md`）：把**回答**变成 AI 可编辑的文本 +
  一块草稿区 + "什么时候发送"的决定权。它走的是上面三个新口子
  （`stage`/`emit`/`op`），内核**完全不知道"记事本"是什么**。
  没编辑、`auto` 模式时输出与不挂补丁**逐字节相同** —— 所以挂上它不改行为。

**AI 想用外设，也走受审通道**：新意图 `MOD_PATCH_CALL`（第 12 种）把"调用补丁的操作"
送进同一条「审查 → 记账 → 应用 → 审计」的路，吃硬预算 `max_patch_calls_step`（默认 4）。
Token 行为那边对应一行：`::op 调用补丁 <补丁> <操作> [参数…]`。

## 七、元认知：监控自修改，并且自己踩刹车

`micro_metacog()` 每步看三件事：

| 看什么 | 判据 | 动作 |
|---|---|---|
| 速率 | 最近 16 轮平均应用数 ≥ 建边预算 | **冻结** + `[提醒:自修改过热]` |
| 拒绝率 | 窗口内拒绝 ≥32 且 > 应用数×4 | **关小提案**（关掉最吵的检测器 10 步）+ `[提醒:提案多被否]` |
| 补丁健康 | 感知补丁连续 40 轮无输出 | `[提醒:补丁沉默:<名字>]` |

关小**有期限**：`propose_off` 倒数到 0 就恢复；冻结靠 `::safe reset` 解。
元认知不是一次踩死，这一点是刻意的 —— 否则一次误判就永久失去能力。

提醒本身也写进图（`我 → [提醒:…]`），所以它是可被检索、可被后续推理用到的东西，
不只是一行日志。

## 八、命令与开关

| 命令 | 作用 |
|---|---|
| `::mod` | 微内核状态：开关 / 提了多少 / 应用多少 / 被拒多少 / 最近应用 / 提醒 |
| `::mod on\|off` | 自修改总开关（默认 on） |
| `::mod coact\|gap\|prune [on\|off]` | 单个检测器开关 |
| `::mod try 加边\|加Token\|打关系\|删边\|强化 …` | **手动提一条意图**（调试入口） |
| `::op` | Token 的行为（图操作）清单：接线 / 按语境接线 / 插词 / 回收临时 |
| `::op <行为> <参数…>` | **手动跑一条行为**（同样只产出意图 → 过安全内核；见 `docs/token行为-图操作与临时token.md`） |
| `::safe` | 预算 / 开关 / 拒绝理由分布 / 最近审计 |
| `::safe on\|off` | 安全内核总闸（默认 on） |
| `::safe newtoken\|remove [on\|off]` | 允许造新 Token / 允许删边（默认都允许） |
| `::safe freeze on\|off` / `::safe reset` | 手动冻结 / 解冻并清本步预算 |
| `::patch` / `::patch mount\|unmount\|on\|off <名字>` / `::patch list` | 补丁注册表与热插拔 |
| `::stats` | 多一行微内核摘要（自修改开关、轮数、意图/应用/被拒、补丁数、提醒数） |

**`::op` / `::mod try` 都不是自修改。** 按定义，自修改必须是系统运行中**自己**产生的修改；
手动试是从外面施加的，和 `::asm` / `::learn` 同级 ——
它的用处是让「这条边会被放行、还是被哪条底线拦住」变成可验证的事
（被拒的理由会出现在 `::safe` 的审计里）。

## 十、和「与 CPU 解耦」的关系（做到哪一层）

分享里把解耦分成四层：架构 / 执行 / 内存 / 认知。目前的诚实结论：

* **架构层（可移植）**：已经是纯 C，无 intrinsics、无平台调用 —— 这层本来就有。
* **逻辑层**（数据与算法分开）：微内核把「谁想改」和「怎么改」分开了
  （`ModIntent` 是纯数据，`micro_apply_one` 是唯一执行者），
  这是执行层解耦的前置条件。
* **执行层（显式栈、原子、事件化）**：**没做**。激活仍是递归 + 全局路径栈。
* **内存层（索引化、连续存储）**：**没做**。`AssocEntry` 还是指针 + `realloc`。
* **认知层（CPU 只是补丁之一、Token 总线）**：**没做**，而且补丁目前是**进程内**的
  （`PatchRegistry` 是一个数组，没有跨进程总线）。

所以别把现在这个叫「解耦完成」—— 它是**把结构修改收成一条通道**，
而这条通道正是「将来把修改搬到别的执行体上」所需要的形状（意图是可序列化的）。

## 十一、局限照实说

1. **既有结构写入者还没搬到队列上**。`ai_learn_pair`、`ai_inner_dialogue`、
   `ai_imagine`、`ai_learn_causal`、`ai_learn_expression`、`ai_credit_from_feedback`、
   抽象形成（造 `[抽象N]`）、`agent_step` 的 `[时刻:N]→词`、
   关系层的现场学知识（`agent_learn_relation`）—— 这些**直接改图，不过安全内核**。
   现在只有微内核这一条通道受审。搬过去是下一步最该做的事（见第十二节）。
2. **D1 实测几乎不开火**（10 轮 0 提案），原因见第五节。它现在是「守规矩的通道」
   而不是「新能力」。
3. **D2 极其保守**：每 100 轮最多一个，且要求 `token_gap ≥ 0.65`。
   短会话里看不到它。
4. **D3 默认关**，因为「该不该剪」在短会话里观察不出来。
5. **补丁是进程内的**：没有总线、没有跨进程/跨设备，也没有真正的热插拔（不重启进程）。
6. **微内核状态不进存档**：补丁挂载表、预算、审计都是运行时的；
   进存档的只有自修改**产生**的 Token 和边。这让格式不用动、不用重训，
   代价是「上次装了哪些补丁」不记得。
7. **元认知的阈值是手写的**（16 轮窗口、×4、40 轮沉默），不是学出来的策略。
8. **安全内核的底线也是手写的**，没有价值学习；「不许删关系边」这类是硬编码而非学得的偏好。
9. **闭环没闭**：动作接口（补丁 `act`）有了形状，但仓库里没有真正的执行者
   （不调外部程序、不写世界文件），所以「我做了什么 → 世界变了 → 我看见了」
   这条因果环仍是缺的。

## 十二、下一步（按性价比排序）

1. **把既有写入者搬到意图队列上**（局限 1）。这是让自修改**真的**统一受审的一步，
   也能让 D1 有机会开火（当 `ai_learn_pair` 不再抢先建边时）。
   风险：会改变行为基线，需要重跑 21 套回归并重新校准阈值。
2. **索引化 + 显式栈**（第十节执行/内存层）：`AssocEntryHw`（下标代替指针）、
   `token_activate` 的显式工作队列版本。好处是可并行、可固化到固定容量；
   做法是先把递归版和显式栈版**跑出逐字节相同的访问序列**，再切换。
3. **补丁总线**：把 `PatchRegistry` 的 `sense/act` 换成消息（进程间/跨语言），
   让「视觉补丁跑在另一个进程」成为可能。这一步之后 `token.h` 才真的只是协议定义。
4. **D1 换判据**：从「邻居重叠」换成「重复证据」（同一对词在多轮里反复共现）——
   更像 Hebbian，但需要持久计数器，也就是**要动存档格式**（升版本 + 重训）。
   在有第 1 条之前不建议做。
5. **价值学习**（局限 8）：把「底线」从手写常量变成可被反馈校准的偏好，
   但**安全内核本身必须留在写死的那一侧** —— 自修改系统不该能改自己的底线。
