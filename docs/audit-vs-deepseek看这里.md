### 0.2 由此定下的工程目标（可检验）
1. **表示层**：淘汰"语境"→ 改用 **行为 token + 临时 token + 前提 token**；前提是**普通 token**
   （联想照走、`::rel`/`::edges` 正常处理），只有**逻辑**知道它是前提。
2. **推理层**：**前提是闸门、不是路障**（R10：前提不成立就不用那条连结；回忆/联想照走）。
3. **输出层**：回答是 **AI 可编辑的文本** = 记事本补丁（草稿区 + 它自己决定何时发送）。
4. **生长方式**：内核**自修改**（提议 → 安全审查 → 队列 → 应用 → 记账 → 审计）。
5. **情绪不进内核**：情绪耦合表在层（`affect.h`），内核只看到三个普通数字。
6. **白箱纪律**：可溯源、条件显式、确定性优先；**同一份清单只许有一处**。

### 0.3 判定标准（每条改动都要过）
- **只有观测进图**；推论只做缓存（`ASSOC_ROLE_DERIVED`）；结构改动只走 `micro_step()`。
- **确定性**：`tests/model_roundtrip.sh` 字节一致；**存档格式 v9 不许动**。
- **行为改变三步**：先实现（默认关）→ **A/B 量** → 绿了才翻默认，并同步看护与文档。
- 报告固定五段：**做了什么 / 证据 / 踩的坑 / 局限照实说 / 下一步**。

## 六、专项：token 关联链还在不在、还用不用

**链还在，但回复已经不靠它了。**

### 6.1 链本身完好

```
Token=1169  边=41022            （平均 35 边/Token）
::edges 猫  →  在/天/树/每/吃/鱼 …   hits 从 24 到 425
::asm [原语:对象] 猫 [原语:对象] 吃 [原语:对象] 鱼 [原语:连接] [原语:激活]
      → 猫 的边里出现 吃(hits=72)、鱼(hits=24)
```

### 6.2 但回复路径已经绕开它

给 `ai_stats` 加了两个计数（`帧生成` / `逐词游走`），实测：

| 输入类型 | 帧生成 | 逐词游走 | 实际走的路径 |
|---|---|---|---|
| 常规对话（50 条探针） | 6 | **0** | 基本上全是**整句检索** |
| 安慰/支持类（50 条探针） | 1 | **0** | 同上 |
| 帧能命中的输入 | 3 | 0 | 结构化帧 |
| 没覆盖的陈述句（「苹果香蕉橘子」） | 0 | **0** | 拒答（词命中比例 20% < 50%） |

**「逐词游走」在这 100 条探针里一次都没被用到。**

原因是我自己加的那道门槛：

```
允许逐词游走 ⇔ 不是问句 且 cov ≥ 25 且 词命中比例 ≥ 50%
```

门槛是为了修「太阳离我们多远 → 远 别 事 的」那个 bug —— 游走临场编句子
经常产碎片，所以我把它的入口收得很紧。代价就是**这条链事实上被停用了**。

### 6.3 这条链现在还有什么用

- **建图**：训练时 `token_observe_names` 观察遍 + 巩固/衰减/抽象，
  41022 条边和 49 个抽象类别都是它建的 —— 这部分**一直在用**；
- **边的权重**：检索的 IDF 和相似度、帧的填充集合，都建立在这张图上；
- **`::edges` / `::tokens` / `::think`** 还能查；
- **`::asm` 里的 `[原语:激活]`** 还能跑扩散激活。

**不再用的是「用它来生成回复」这个用途。** 回复改由「整句检索 + 结构化帧」产出，
质量高得多（对比：游走会出「远 别 事 的」，检索出「我 害怕 时间 过 得 太 快」）。

### 6.4 这是个设计取舍，不是 bug

- 想要「像人话」→ 检索/帧赢；
- 想要「沿关联链自由联想」→ 只有游走能做，但它现在被门槛挡着。

### 6.5 已实现：混合模式（思考与输出分开）

采纳了「第 2 条路」—— **把自由联想做成内部思考，与输出解耦**：

```
每一轮：
  ① 先跑一次关联链（ai_plan_and_act）→ 结果存进 ai->last_idea
     ★ 这是「内部思考」，默认**不决定回复**
  ② 再按 结构化帧 → 整句检索 → 拒答 的顺序决定实际输出
```

实测（同一句话，两个通道是分开的）：

```
输入「你好呀」
  输出      → 嗨 我 在                    （来自检索/帧）
  内部联想  → 呀 开心 见 到 好 早 休息      （来自关联链）
```

**新增两个元命令**：

| 命令 | 作用 |
|---|---|
| `::free [词]` | 自由联想：只跑关联链并打印结果 + 路径；不给词就看上一轮的内部联想 |
| `::walk [on\|off]` | 是否让联想**直接决定输出**（默认 off） |
| `::think <文本>` | 看每个词的感知子图大小（原有） |

实测开关：

```
::walk on   → 你喜欢雪吗  → 吗 小 很 安静     （关联链产物，碎片感）
::walk off  → 你喜欢雪吗  → 我 喜欢 雪         （结构化帧，通顺）
```

**这样两件事同时成立**：

- 「沿关联链自由联想」这个能力**一直活着**（每轮都在想，`::free` 随时可查）；
- 正常对话的输出质量**不受它影响**（默认走检索/帧）。

`ai_stats` 里也多了两个计数，能看出两条通道各跑了多少次：
`帧生成=N  逐词游走=N`。

**顺手修掉的一个诊断 bug**：`::free` 原先打印的是 `ai->last_path`，而它是候选循环里
最后一条候选的路径，不是被选中那条 —— 所以会出现「产物 `猫 看 大人 好 要 什么`
/ 路径 `猫 所以 天 不错 呢 不 走`」这种对不上的显示。现在新增
`ai->last_walk_path`，在候选成为 best 时快照，`::free` 打印它；两者已逐字一致。
该字段纯诊断、不进 `model.bin`，格式仍是 v5。

### 6.6 结构化帧读关联链产物（Gate B）

原始文档没写这一条，是**这次补的**：让结构化帧不再只认手写白名单，
名单落空时改看关联链里的分布证据。

| 之前 | 现在 |
|---|---|
| 槽位取值必须在 `frames.txt` 手写名单里，名单外一律拒绝 | 落空时走 Gate B：实词 + 成形词 + **与示范集的邻居重叠 ≥40** 才放行 |
| `你知道老师吗` → 退回检索 → 「应该，这个我 不 太 懂」（拒答） | → **「我 知道 老师」** |
| `你喜欢安静吗` → 检索 → 「我 喜欢 狗 很 热 情」（跑题） | → **「我 喜欢 安静」** |
| `你会支持我吗` → 「我 想 学 支持 我」（槽位吞掉代词） | → 跨度规则挡住，回落检索，不再出病句 |

实测（`tests/framegate_ab.sh`，只切 `::framegate on|off`，每条探针独立加载模型）：
**改变 5/15 句，5 句全是改善**；白名单内的句子两通道逐字一致；关掉开关时放行次数为 0。

局限也照实说：部件在图里一条边都没有的词（`北京`/`钢琴`）救不了；语义精度会松
（`你认识理解吗` → 「我 认识 理解 你 呢」是病句）；稀疏词（`危险` 只有 1 条出边）
会被拒。详见 `docs/model-io-and-training.md` 第二十三节。

新增开关与计数：`::framegate on|off`、`::stats` 里的 `帧生成=N (关联链放行M 现场造词K)`。

### 6.7 现场造词（没有就创建，然后现场关联）

原始文档也没写这一条，是这一轮补的：用户说了个**语料里没有的复合词**，
系统当场把它造成一个 Token 并接进图里。

| 之前 | 现在 |
|---|---|
| `你 吃 火锅 了 吗` → 切词器按字切成 火+锅 → 槽位变成两个单字 | → 拼回一个 Token「火锅」 |
| 回复要么是「我 吃 了 火 锅」，要么干脆不认 | → **「我 吃 了 火锅」** |
| 新词是死词，图里没有它的位置 | → **现场关联**：接到该槽位全部示范词上（正反两向，标 `ASSOC_ROLE_COINED`），并记进白名单 |

现场关联的证据不是凭空来的 —— 是**用户把「火锅」放在了「你 吃 `<X>` 了 吗」的 X 位上**，
加上 `火` 在图里那 174 条边。所以判据卡得很死：

```
拼回整词的前提：整段都是**单字**（那才是切词器按字切的指纹）
  你 吃 火锅 了 吗 → 火/锅 都是单字 → 拼 ✓
  你 怕 危险 吗    → 怕(单字) + 危险(两字词) → 不拼 ✗
  你 知道 天气 吗  → 知道/天气 都是词        → 不拼 ✗
至少要有一个部件的图证据够格（Dice ≥40 或类成员覆盖率 ≥60%）
  火锅 → 火 对食物类 Dice=89 ✓
  北京 → 北/京 各 0 条边 ✗（没有依据就不硬接）
```

实测（`tests/coining.sh`，13 项断言全过）：造出 → 只造一次（第二次走白名单）→
**存档重载后仍认得出**（靠 `ASSOC_ROLE_COINED` 这条持久化的角色字节）→
`::coin off` 可关 → `怕危险`/`知道天气`/`北京` 都不许造。

### 6.8 切分可选：拼接 / 拆解 / 合并 / 中转

原始文档同样没写。**切词器的最长匹配只是「一版切分」，不是唯一答案** ——
哪一版对，看它能不能被结构层理解。

| 操作 | 判据 | 实测效果 |

| 中转 | 模板固定词与输入词在 `FR_RELAY` 同一类 | `猫跟狗哪个好`：「这个我 不 太 懂」→ **「我 觉得 猫 更 好」** |

一条护栏值得单记：拆解会把 `老师` 拆成 `老+师`，模板把两个碎片一起吞进槽位时
会答出「我 怕 老 师」（`老` 正好在恐惧类白名单里）。修法是给变体 token 记
`origin`，**同一个原词拆出来的碎片不许落在同一个槽位**。

**「走路时中转」量完放弃了**：`./build_slotprobe model.bin relay` 显示 49 个抽象节点
每个只挂 2 个成员、160 个死胡同里 **0 个**挂在抽象节点下 —— 绕行救不回任何一条。
所以抽象节点至今仍是「装饰」，这是它没被用起来的直接证据。

实测（`tests/segmentation.sh`，14 项断言全过）：拆解/合并/中转各自可关
（`::seg off` / `::relay off`），主切分能中的句子一个字都没变。
详见 `docs/model-io-and-training.md` 第二十五节。


### 6.9 思维链 + 「符号神经」体检

**思维链**：之前那条输出路径是「四个 if 并列排队」（联想 / 帧 / 检索 / 拒答），
互相不知道对方存在。现在改成咬合的链，`::cot` 可以逐step 看：

```
读入 → 联想 → 骨架 → 校验 → 降级 → 成句      （检索只在前两步都没话说时才轮到）
```

「降级」只因为「校验」失败才存在 —— 这才是链。`tests/cot.sh` 断言
`骨架 < 校验 < 降级` 的顺序，以及「真骨架接住时不该有降级步」。

**降级答复**把拒答变成了有用的话：

| 输入 | 之前 | 现在 |
|---|---|---|
| `你知道北京吗` | 这个我 不 太 懂 | **我 不 太 懂 北京** |
| `你知道钢琴吗` | 别 憋 着 我 陪 你（跑题） | **我 不 太 懂 钢琴** |

**「符号神经」体检**（`./build_slotprobe model.bin neuro`）—— 三个硬数字：

```
内容 Token 出边 35858 条：带角色 41.2%  带话题 18.1%  带句尾模式 23.3%
VSA：猫↔狗 0.6%  喜欢↔爱 0.2%  雪↔雨 2.7%  猫↔量子 -3.5%
     随机词对 139 对：均值 0.2%  标准差 2.9%      ← 分不开
hv 与 hv_prev 不同的 Token = 0 / 1169（0.0%）
```

- **符号侧只做了一半**：近六成边没有类型；`role` 是「出处」不是「语义」。
- **VSA 是死的**：超向量只是名字的随机投影（`vsa_init(hv, hash(name))`），
  建好后从没被学习更新过 —— 所以语义相关词对与随机词对**统计上无法区分**。
- **`ai_analogy` 从没被调用**；`hv_prev` 从没变过，`ai_drift_sample` 的「漂移」恒为 0。

结论（写入交付文档 26.4）：现在是**一个带死掉的 VSA 附录的符号关联图**，
不是符号神经混合体。补齐顺序 L1 思维链（本节已做）→ L2 关系类型 → L3 神经表示，
详见 `docs/model-io-and-training.md` 第二十六节 26.5。

### 6.10 L3 神经表示：emb 造出来了（含它的三条边界）

`hv` 是「名字的随机投影」（`vsa_init(hash(name))`），建好后从没被学习更新过。
现在多了一份**学出来的**表示：

```
emb(t) = Σ_c PPMI(t,c) · r_c        （1024 维 int8，随机索引投影）
```

| | hv（旧） | emb（新） |
|---|---|---|
| 猫 ↔ 狗 | 0.6% | **62.2%** |
| 雪 ↔ 雨 | 2.7% | **63.8%** |
| 猫 ↔ 量子 | -3.5% | **0.0%** |
| 随机词对 | 0.2% ± 2.9% | 3.7% ± 17.6% |

旧 hv 里「相关」和「无关」**统计上分不开**，所以 `ai_analogy` 一直是死代码；
现在无关词对精确落在 0，`ai_analogy` 改成在 emb 空间做向量算术并被 `::analogy` 调用。

**中途的关键发现**（`ctx` 探针量出来的）：猫/狗/雨/鱼 的 PPMI 最高上下文全是
`是什么`/`在哪里`/`是谁` 这些**模板话** —— 它们只跟名词搭配，所以 PMI 很高，
但跟每个名词都搭配，信息量为零，把所有名词的向量拉平了。修法是数据驱动的
**df 过滤器**（被 >15% 的内容词指向的上下文不当上下文用）+ all-but-the-top 后处理。

**三条边界（照实说，并写进 tests/embed.sh 当负结果看护）**：
1. `猫` 对「食物类」的 emb 相似度有 **55.5%** → **不能当槽位门槛**，所以没接进 Gate B；
2. `猫:动物::狗:?` 最高只有 36.2% → `::analogy` 加了 50% 门槛，**表示不够时诚实拒答**；
3. 主成分没塌（PC1 4.4%），问题在**语料**：484 词、±5 窗口、清一色闲聊，共现统计太同质。

### 6.11 L2 关系类型：卡在数据上

侦察结果：语料里的原语只有 `对象/连接/请求/认为/好/坏/分割/上/了` ——
**没有任何语义关系原语**，没有「属于/有/会」这类边标签。所以抽关系**没有原料**。

唯一带关系结构的是帧库（谓词 + 槽位角色），但要落地需要两件事：
**模型格式升 v6**（关系字段要持久化）+ **重训**（要有能传递的关系句）。
L3 不用重训，这是两者的本质差别。

详见 `docs/model-io-and-training.md` 第二十七节（含 27.5 给出的语料行样例）。

### 6.12 L2 语义关系层（含对话中动态学知识）

边上原来只有 `role`（**出处**：学自输入段还是回复段），没有**语义**。
现在加了 7 种类型化关系（属于/有/会/怕/喜欢/吃/在）与两条推理规则：

```
① 传递：猫 属于 动物，动物 属于 生物 ⟹ 猫 属于 生物
② 继承：猫 属于 动物，动物 有 毛    ⟹ 猫 有 毛
```

实测（`tests/relations.sh`，15 项断言全过）：

```
猫 有 毛 吗   → 对 ， 猫 有 毛 （猫 → 动物 → 毛）    ← 语料里从没写过这句，是推出来的
猫 属于 生物 吗 → 对 ， 猫 属于 生物 （猫 → 动物 → 生物）
鸟 会 飞 吗   → 对 ， 鸟 会 飞                       ← 直接事实
猫 会 飞 吗   → 不 对 ， 猫 不 会 飞                 ← 闭合世界，只对知识库实体说
你 会 游泳 吗 → 我 会 试 着 游泳                     ← 没被关系层抢答
```

**对话中动态获得知识**（本轮新增的能力）：

```
猫 属于 宠物     → 记下 了 ： 猫 属于 宠物    ← 当场学进图
猫 属于 宠物 吗  → 对 ， 猫 属于 宠物          ← 立刻能用
存盘 → 重载       → 对 ， 猫 属于 宠物          ← rel 位掩码写进模型（格式 v6）
```

模型格式 **v5 → v6**（边增加 rel 字节，向后兼容 v1~v5）。
静态知识在 `relations.txt`（像 frames.txt 一样每次读盘装载，**改知识不用重训**）；
对话里学的那些在模型文件里。

三个踩出来的坑，都写进文档了：**解析器绝不能改图**（曾把「火锅了」造成垃圾 Token，
让切词器和帧全乱）；**rel 必须是位掩码**（一条边可以同时有多种关系，
存单个 id 会丢知识并导致存读后 hits 翻倍 —— 为此写了 `tools/rtdiff.c` 定位）；
**Dice 要跳过关系边**（否则人工知识会稀释分布统计，`你知道动物吗` 当场退化）。

局限照实说：关系词表手写、闭合世界假设、谓语只认清单里那 7 个、
embedding 仍撑不起关系类比（关系是显式规则推的，不是向量算的）。
详见 `docs/model-io-and-training.md` 第二十八节。

### 6.13 推导层：链是一等公民（文字是投影）

第二十八节的推理输出「边算边拼句子」，链条本身不是一等公民；而且推不出来时靠
闭合世界假设硬答「不对」。这一节把两件事一起解决：

**① 链结构化**：`Derivation` = 目标 → 事实/规则/推测 → 结论，每步带类型、用了哪条规则、
真值、验证标记。`::der` 按步摊开看。

**② 验证器独立重推每一步**：事实步查边是否真的存在（极性也对）；规则步查这一跳的边 +
这条关系是否声明支持该规则；推测步查「知识库里确实没有 + 最近邻够近 + **最近邻确实
对这件事有态度**」；再加链的连通性；最后拿 `rel_solve` 把结论重推一遍。
**`gaps>0` 就不许下断言**，只会说「推不出来（链上缺 N 步）」。

**③ 验证器自身的测试**（`tools/dertest.c`）：伪造事实、非法规则、断链、假依据、
重推不出来的结论 —— 五种坏链**全被识破**，真链放行。这一条是对「可以正确思考」的
直接检验，不是声称。

**④ 语言是最后一步**：同一份链四种说法，真值不变 ——
```
::style 0 → 对
::style 1 → 对 ， 猫 -[属于·传递]-> 动物 ； 动物 -[属于]-> 生物
::style 2 → 猫 -[属于·传递]-> 动物 ； 动物 -[属于]-> 生物     ← 只给链，不给结论
::style 3 → 对 ： 猫 属于 生物  ⇐  猫 属于 动物  ∧  动物 属于 生物
```

**⑤ 非逻辑路径不许伪装成推导**：检索/帧/降级在 `last_der` 里只记「来源」，
`has_claim=0`，真值不参与任何判断 —— 「检索到一句像的话」不等于「推出了结论」。

局限照实说：只有关系推理走这条路；推测置信度是拍的；不支持反事实。
详见 `docs/model-io-and-training.md` 第二十九节。

### 6.14 反事实：假设世界（假设绝不进图）

第二十九节点出的空缺（不支持反事实）补上了。

```
你 > 如果 猫 属于 鸟
AI > 好 ， 就 当 猫 属于 鸟
你 > 猫 会 飞 吗
AI > 在 假设 下 ： 对 ， 猫 -[属于·假设]-> 鸟 ； 鸟 -[会]-> 飞
你 > ::der
  2. 假设 ✓   猫 -[属于]-> 鸟   （来自假设层，不在知识库里；被继承/传递规则用上）
  3. 事实 ✓   鸟 -[会]-> 飞
```

「猫 会 飞」在图里从没存在过 —— 它是「假设 猫 属于 鸟」+「鸟 会 飞」+ 继承规则推出来的。

**实现要害**：假设只活在 `ai->hypo` 覆盖层，求解器查事实时先看覆盖层再看图；
`rel_next_cands`（传递/继承的候选枚举）也要过一遍覆盖层，否则假设边不在图里、
图里的循环看不见它。**没有任何代码路径把假设 tag 进边，它也不参与序列化。**

**三条护栏**：假设不进图（撤回/存盘都带不出来，`tests/hypothesis.sh` 硬断言）；
验证器只在覆盖层能核对上时才认 `DER_HYP`，核对不上就是缺口、不下断言；
假设不能绕过规则合法性检查。

**踩出来的两个同类 bug**（都是「字段/标记没写」而不是逻辑错）：
① `rel_next_cands` 漏写「来自假设」标记 → 假设边被当成图里的边去验，验证器
**正确地**拒绝，于是整条问答退化成帧答复；② `proof_push` 漏清 `hyp` → 撤回后
数组里的残值把**真事实**步误标成「靠假设」，验证器又照样拒绝。
和当年 `role` 字节没初始化同一类：**每个字段都要写**。

局限：只支持单条假设、外推只走两条规则、假设不参与检索/帧层、没有嵌套假设。
详见 `docs/model-io-and-training.md` 第三十节。

### 6.15 四条局限的解决（一个有测试的清单）

第三十节点出的四条局限，逐条处理，`tests/logic4.sh` 看护。

| 局限 | 解决 | 关键点 |
|---|---|---|
| ① 只支持单条假设 | **栈式多层**：`如果` 压一层、`算了` 弹一层、求解时所有层都算数 | 内层不推翻外层（那正是「他以为」的意思） |
| ② 缺完备性推不出否定 | **独占公理 R6** + `::world open\|closed` 开关 | `猫 属于 植物`→否定（动物与植物互不包含）；`猫 属于 鸟`→**仍是不知道**（鸟⊂动物，可能为真）。健全性靠「互不包含」这个安全阀 |
| ③ 假设不参与后续流程 | 假设开着时关系问题**由关系层负责到底**，推不出来也明说 | `猫 会 唱歌 吗`：无假设→「猫 应该 会 唱歌」（帧层）；有假设→「在假设下我推不出来」 |
| ④ 没有嵌套 | 每层带 `who`，`如果 他 以为 猫 会 飞` 把该层算在「他」头上 | 栈深度=嵌套深度；`::hypo` 列出每层归属 |

闭合世界下的结论在链上标成 `—[不 属于·闭合世界]—`，一眼看出**这是靠假设得来的**，
不是事实 —— 比默默按闭合世界算诚实。

两个 bug：**独占的理由不是链的一环**（做成三跳链会被验证器按连通性判死，
改成两跳 + 验证器独立复核规则前提）；**`DerStep.note[64]` 装不下中文长句**，
截在字符中间出乱码（中文一字 3 字节，别按字符数估缓冲区）。

剩余局限照实说：独占公理是手写的、撤销只能从最深的弹、假设仍不进检索/帧层、
归属只是标注（没有真正的视角推理）。详见 `docs/model-io-and-training.md` 第三十一节。

### 6.16 「装载 = 训练」：三个派生层的坑（存读一致性收口）

`tests/model_roundtrip.sh` 的「加载后对话 vs 原地训练对话」长期是红的。
修好它顺带挖出**三个**独立 bug，共同特征是「模型文件逐字节相同，行为却不同」：

| 坑 | 症状 | 根因 | 修法 |
|---|---|---|---|
| ① idf 边界 | 最后 50 个词 idf 是 `-nan` / `-1.7e38` 这种垃圾浮点，联想链每次不一样 | `ai_idf_rebuild` 按当时 `pool->count` 分配，却排在 `rel_names_intern`/`frames_load`/`stabilize` **之前**；`ai_idf_of` 又拿「当前词数」当边界 → 越界读堆 | 新增 `idf_n` 记数组真实长度，边界改用它；`ai_idf_rebuild` 挪到最后一步 |
| ② emb 算早了 | 1123 个 Token 里 **810 个** emb 不同（hv/idf 全同、词池逐字节相同） | 训练侧 `ai_embed_build` 排在 `frames_load`/`stabilize_abstractions`（会造词加边）之前；存盘存的是**最终**图，读盘按最终图重算 | 两条收尾统一成「先改图，后算派生层」：`rel_* → frames_load → stabilize → emb → slots → idf` |
| ③ `split_tok` 没进格式 | 同一张图、同一个 `rng`，**每条边权重都差 4 倍** | `[原语:分割]` 指针只在 `ai_new()` intern 过，存盘清单漏了它（另外十个特殊 Token 都存了）→ 装载后为 NULL → `ai_edge_weight` 里「回复首词 ×4」整档静默失效 | 装载时按名字找回来（同 `unknowing`），并加 `MODEL_IO_INVARIANTS` 硬断言 |

坑③躲过所有排查的原因值得记下来：**词池 dump 逐字节相同** —— 图没变、权重也没写进模型，
变的是「权重怎么算」。它是靠新加的游走跟踪 `::wtrace`（打出每次选边的候选权重）才露头的；
跨进程比状态靠 `::pooldump` / `::derivedump`（一律按 id / 名字打，不按指针）。

不变式（写进 32.5）：派生层只能用**最终的图**算、两条路径顺序一致；数组边界别用
「当前规模」；AI 里指向池内的指针必须要么进格式、要么装载时按名字重建。

顺带的行为变化：槽类现在算在关系层之后，表达层语气跟着变 ——
`你知道北京吗` 的降级答复成了「大概，我 不 太 懂 北京」。
`tests/cot.sh` 原来钉整串，钉的是**两边不一致时的旧值**，改成查包含「不 太 懂 北京」并注明原因。

`tests/model_roundtrip.sh` 因此从四段扩成五段：多了一段「规范状态 dump 逐行一致」
（11369 行），并把 `frames.txt` / `relations.txt` 复制进工作目录，帧层与关系层才真的被覆盖。

模型格式**没动**（仍 v7），`model.bin` 不用重训。详见第三十二节。

### 6.17 四条局限接着做 + 缺前提推理（训练数据里没有的结论）

第三十一节列的四条局限逐条落地，另加一条更要紧的推理能力。**十九套回归全绿**。

| 局限 | 现在的做法 | 关键点 |
|---|---|---|
| ① 独占像手写公理 | **似然比模型比较**：`H_多值` vs `H_独占`，先验 `p1` 由**参照类**给（只取观察到过多宾语的关系），赔率 10:1 才改口；证据全在 `::excl` | 第一版把函数式关系也算进基准，`在`（17 个主语全单宾语）反被判成多值；参照类换掉后 292:1 判独占 |
| ② 撤销只能从最深弹 | 认四种说法：`撤回 第 2 个 假设` / `撤回 关于 猫 的 假设` / `撤回 猫 属于 鸟` / `猫 属于 鸟 不算 了` —— 抽掉指定那层，其余顺序不变 | 坑在切词器：`撤回`→`撤`+`回`、`关于`→`关`+`于`、`不算`→`不`+`算` |
| ③ 假设不进检索/帧层 | `ai_hypo_conflicts`：**图的边** + **句面**（同现 a…关系词…b + 极性）两路检测；命中就作废帧/检索那句话，链上记「假设否决」 | 只查图管不住帧层（模板渲染的句子里不一定有边），第二路是必须的 |
| ④ 归属只是标注 | 每个「他」一份**信念表**（`OtherModel.bel[]`，模型 v8 起持久化）；他说的存他名下、反事实仍是临时假设；问他就查他的，没说过就说「我没听他说过」；我不知道但他说过就**引用** | 顺手修掉 `ai_identify_speaker` 把「以为」「说」当人名建假人的 bug |

**新增：缺前提 → 否定能力（规则 R9）** —— 训练数据里没有「猫 会不会唱歌」，照样推得出来：

```
唱歌 需要 灵活的声带      猫 没有 灵活的声带      ⟹  猫 不 会 唱歌
```

为此加了第 9 个核心关系「需要」（`REL_NEED = 9`），`AssocEntry.rel/nrel` 因此从
1 字节扩到 2 字节，**模型格式升到 v9**（v8 及以前按 1 字节读，照样能装）。
规则由求解器给出、由**验证器独立复核**（`rule == 9`），链上读作
`猫 -[会·缺前提]-> 唱歌`；只加在「会」上（别的动词没有前提这回事），
前提可继承一跳（`唱戏 属于 唱歌` ⟹ 唱戏也要声带）。

`tests/prerequisite.sh` 特意证明它**靠数据**：把「需要」那两条知识拿掉，
就不许再推否定 —— 不是写死「猫不会唱歌」。

顺带：`猫 会 唱歌` 原来是「推不出来」的标准探针，现在被 R9 接住了，
于是 `derivation.sh` / `logic4.sh` / `belief.sh` 三处把探针换成 `猫 会 跳舞`
（不是把断言改松，是探针要挑真的没有知识的）。

新增五套回归：`exclusivity` / `hypo_scope` / `hypo_frames` / `belief` / `prerequisite`
（共十九套）。修复的都是**代码**，`model.bin` 不用重训（关系知识每次装载时从
`relations.txt` 现读，本仓库的 `model.bin` 里其实不存关系位 —— 它靠这个机制工作）。
详见第三十三节。

### 6.18 微内核：自修改收成一条受审的通道（安全内核 / 意图队列 / 补丁边界 / 元认知）

分享讨论（2026-10-03）里那轮「微内核 + 补丁 + CPU 解耦 + 动态加边加 Token」
的**内核**部分落地了，新增 `micro.h`（1341 行）。**只做内核，不预置视觉/3D 之类的
外设补丁**；存档格式**没动（仍 v9）**，`model.bin` 不用重训。

一件一件对着看：

| 分享里的说法 | 现在的做法 | 证据 |
|---|---|---|
| 「激活时提议，安全点应用」 | 遍历里只 `mod_propose`，`micro_step()` 在 `agent_step` 收尾处统一「审查→应用→记账→审计」 | `tools/microtest.c` 70 项 |
| 「动态加边、加 Token」 | 9 种 `ModIntent`；D1 共现固化 / D2 缺口命名两个检测器**默认开** | `::mod` 能看到每条应用 |
| 「hits++ 是参数层，加边是结构层」 | 参数层照旧；结构层走队列，有去重、预算、审计 | 同上 |
| 「安全内核：目标/价值/停止条件」 | 九条拒绝理由（含**不许删关系边**这条硬底线）+ 四条预算 + 冻结与解冻 | `::safe` 打理由分布与审计 |
| 「补丁只交换 Token，不改结构」 | `sense/act/update/propose/destroy`；要改结构只能 `propose`，照样过审查 | 补丁提议 → 边真的建出来 |
| 「补丁可失败，不拖累内核」 | 连续 3 次出错自动停用 + `[提醒:补丁异常已停用:…]`；越界输出按容量截断 | `microtest` 有反例 |
| 「元认知监控补丁」 | 沉默（40 轮无输出）/ 冲突（同一 Token 相反信号）/ 出错三类提醒 | 同上 |
| 「与 CPU 解耦」 | **只做了逻辑层**（意图是纯数据，唯一执行者）；执行层/内存层没做 | 见 `docs/microkernel.md` 第十节 |

**一个实测结论值得单独记**：`D1 共现固化`默认开着，但在真实对话里**几乎不开火**
（10 轮 0 提案）。不是判据太严，而是内核原有的学习路径（`ai_learn_pair` /
`ai_inner_dialogue` / `ai_imagine` / `ai_learn_causal` / 自举那一步 / 训练期的
`token_observe_names`）已经把输入输出里的共现都记下来了。
直接后果是：**默认开着自修改，原来 19 套回归一条都没变**
（`model_roundtrip` 连存盘都逐字节相同）。所以这条通道现在的作用是
**「受审」而不是「新能力」** —— 上面那些老写入者全都绕过审查，搬到队列上是下一步。

新增看护：`tools/microtest.c`（70 项 C 级）+ `tests/selfmod.sh`（33 项 CLI 级），
`tests/all.sh` 从 19 套变 21 套。新命令 `::mod` / `::safe` / `::patch`
（`::mod try …` 是**手动调试入口**，不是自修改 —— 自修改必须是系统自己提的）。
详见 `docs/microkernel.md`。

### 6.19 思维循环：从「一次性策略链」到「有议程的循环」

微内核解决的是「改得有规矩」，这一层解决的是「**想得有过程**」。新增 `think.h`（1070 行）。

| 之前 | 现在 |
|---|---|
| 输出路径是四种策略排队（联想/帧/检索/拒答），互相不知道对方存在 | 先**想**一遍：立目标 → 取一个 → 查/推/试反方向/类比/问缺什么前提 → 够不着就**拆子目标压回议程** |
| 「想不通」和「想完了」看不出区别 | 八种**停止原因**必须写明（有结论 / 只有猜测 / 推不出来 / 矛盾 / 没有要弄清的事 / 超预算 / 原地打转 / 关着） |
| 一轮结束就忘了 | 想不通的**问句跨轮活着**：每轮收尾拿新知识重试，想通了还记着「等下要说一句」 |
| 没有「知识自相矛盾」这回事 | 正反都过验证器 → **不下断言**，把两条依据都摆出来 |
| 思维（如果有）不受任何约束 | 思维改脑只能**提议**（`[自问:…]` 节点、有图内证据的连结），经安全内核审查才落地 |

实测三条（`::delib`）：

```
猫 会 唱歌 吗   → 3. 查 ✗ → 4. 推 ✗ → 5. 分解 ✓（拆 3 个子目标）
                  → 6. 推 ✓ 猫 -[会·缺前提]-> 唱歌 → 7. 反省「反方向才是答案」→ 有结论
猫 会 唱歌      → 教进去之后再问 → 正反都过验证器 →「我这儿有互相矛盾的依据」，不下断言
猫 会 跳舞 吗   → 推不出来 → 挂成未解问题 + [自问:…] 节点经队列落地；
                  教会它之后 ::pending 归零 → 打开 ::thinkout 才在回复末尾补一句
```

顺带修掉一个既有的显示缺口：`rel_via_name()` 没有 `case 9`，
于是 `proof_text` 把 R9（缺前提）渲染成 `-[会·?]->`；`derive.h` 的
`der_rule_name()` 里本来就有「缺前提」，两边现在一致了。

**默认值不是拍的，是量出来的**：接管输出先按**默认关**做（既有 21 套全绿），
再用 A/B（`tests/thinkout_ab.sh`）打开量一遍 —— 8 套里 5 套变红。
查下来不是输出变差，而是思维层自己的三个 bug：`rel_solve` 的 status 被当成
「问法的答案」（它其实是**正关系的真值**）、没分证据强度（拿独占/闭合世界/假设
去和事实并列判矛盾）、只查到直接否定就下结论（规则或假设能推翻它）。
三个都修完之后 **7/7 行为套全绿**，接管输出这才改成**默认开**
（`::thinkout off` 是逃生口）。A/B 脚本留在仓库里：以后再动默认值先跑它。

### 6.20 设计原则落地：该涌现的涌现，该新写的才新写

用户给了一条项目级原则：**没有单独脑区的东西应该从现有架构里涌现；
有单独脑区的才新写代码；对当前内核不重要的先放一放**。
写成了 `docs/设计原则-涌现与脑区.md`（含判据、逐层审计、暂缓清单、检查表），
并立刻按它改了两处「本该涌现却写死了」的地方：

| 之前（写死） | 现在（声明/涌现） |
|---|---|
| `rel.h` 求解器里 `rid == REL_CAN` 决定有没有前提推理 | 关系表多一列 `prereq`：`{ "会", …, 0, 1 }`；求解器读 `rd->prereq`（**知识进表，控制流退出**） |
| `think.h` 的分解写死「试反方向/类比/缺前提」 | 子目标由**表**（`trans`/`inherit`/`prereq`）+ **图**（`rel_next_cands` 给的中间词）+ **机制存在性**（`emb` 在不在）生成；新增关系或给关系加性质 = **改表** |

实测痕迹里那句「拆出 4 个子目标压回议程（换问法 缺前提 借最近邻 **经由动物** ）」
里，最后一项是**图给的**，不是代码写的。
「经由中间词」还补了求解器做不到的一件事：每一跳独立求解，
所以串起来的深度不受单次调用的深度上限约束。

顺带记一个坑：`RelDef` 加字段时，**字段顺序必须和表的列序一致** ——
把 `prereq` 插在 `excl` 前面而表里按「…独占、前提」写，不报错，
只让值悄悄串位（`prerequisite.sh` 当场变红）。顺序错是静默错误。

暂缓清单（按原则第三条，先不动）：视觉/3D/听觉/运动补丁、Token 总线、
CPU 解耦的执行层/内存层、未解问题持久化、逐条知识可信度。
理由与「已经有什么」都写在原则文档第五节。

### 6.21 推理沉淀：第三条学习路径（想出来的也要留下来）

「学」以前只有两条路：**听到的**（用户陈述）和**共现出来的**（语料/对话）。
推论用完就丢 —— 同一件事问一百遍就从头推一百遍，什么都不积累。
这一轮补上第三条：**推理沉淀**（`docs/thinking.md` 第六点五节）。

| 环节 | 做法 |
|---|---|
| 沉淀什么 | **现场**用**健全规则**推出来、验证器 `gaps==0`、非假设非类比的结论 |
| 怎么落地 | 边照旧建，`role` 标成 `ASSOC_ROLE_DERIVED` —— 这个字节**本来就在存档格式里**，所以**格式没动、不用重训** |
| 怎么复用 | 求解器 R0 直接查到，链上读作 `猫 -[有·记]-> 毛`，证据强度「推导缓存」 |
| 观测推翻 | `token_tag_rel/nrel` 里把这条边的缓存**整条撤掉**再落观测（同一条边不混两种来源） |
| 推理推翻 | `think_finish` 当场翻转 + 收尾提 `MOD_REMOVE_ASSOC`；**安全内核只允许删缓存，观测到的关系边依旧不许删** |
| 具体优先于一般 | `rel.h`：同一对词上有观测到的反面边时，**传递/继承不再外推**（四条边界：只挡外推、只 depth==0、假设世界不挡、只认非缓存边） |

实测（`tests/consolidate.sh`，18 项）：

```
猫 有 毛 吗   → 对 ， 猫 -[属于·继承]-> 动物 ； 动物 -[有]-> 毛     ::mod 里 沉淀 … [思维:沉淀]
猫 有 毛 吗   → 对 ， 猫 -[有·记]-> 毛                            依据强度：推导缓存
猫 没有 毛    → 那条边不再是缓存；再问 → 不 对 ， 猫 -[不 有]-> 毛   （观测赢，且不报矛盾）
宠物 没有 毛  → 现场推理推翻缓存：当场改口「我原先记的是反的」+ 删边 … [思维:撤销缓存]
两条继承路径真打架 → 老实报「互相矛盾的依据」（不硬选一边）
```

一路上被回归挡回来的三处（都记进代码注释了）：
① 特异性检查放太靠前，把**独占/缺前提**这些该开火的规则也挡了（答案没错，但依据链
从 `·独占` 变成直接事实，`logic4` 钉的就是这个）；
② 忘了**假设世界**：覆盖层本来就压过图，挡住外推就出现「如果 猫 属于 鸟」推不出「猫 会 飞」；
③ 缓存被删时要让**那一轮就改口**，否则用户先听到旧答案、下一轮才听到修正。

### 6.22 缓存跟着前提走 + 清两处「滥用硬编码」

**① 缓存跟着前提走**（`docs/thinking.md` 6.5.1 节）。
缓存过期最常见的原因不是「被推翻」，而是**前提没了**：`动物 有 毛` 被撤之后，
靠继承推出来记住的 `猫 有 毛` 就不该算数。
实现上**不存依赖表、不动存档格式**：依据 = 「把缓存排除在外，还推得出来吗」（现算）。

两道闸：**实时闸**（求解器 R0 + 候选枚举：查到/路过缓存先复核，没依据当它不存在）
+ **收尾扫描**（`think_settle` 扫一遍，把没依据的提出来撤销，来源写 `思维:前提没了`）。
刻意保守：**缓存不许互为依据**（复核时所有缓存都当不存在），
所以「A 依赖 B 依赖 C」那种链不会出现，也就不用写传播算法。

```
猫 有 毛 吗 → 沉淀；动物 没有 毛 → 前提改口
  · 求解器当场不再拿那条缓存当数 → ::delib 前提没了 1 条
  · ::mod 删边 删 猫→毛 [思维:前提没了]；::rel 猫 那条缓存已经不在图上
  · 依据回来之后照样能推、能重新沉淀（不是永久拉黑）
```

顺带修掉一处**自我印证**：`rel_excl_build`（从数据里量「独占/多值」）原来会把
缓存边也当数据数进去 —— 自己推出来的结论回头强化推出它的那条规则。
现在它跳过 `ASSOC_ROLE_DERIVED`：**统计只看观测**。

改这个功能时测试逮到一个真漏洞：实时闸一开始只装在求解器里，
而思维层**自己扫边**的那条路（`think_step_lookup`）绕过了它 —— 于是缓存还能被当答案用。
补上之后 98/98 通过。

**② 清两处「滥用硬编码」**：

| 之前 | 现在 |
|---|---|
| 推导规则的**名字**（`derive.h` 一个 switch）与**非单调性**（`think.h` 另一个 switch）分家，加规则改两处 | 一张 `REL_RULES[] = {id, name, ev}`；名字与证据强度都是表的一列，`THINK_EV_*` 直接别名 `DER_EV_*`（一处定义） |

重复的表最危险的不是啰嗦，是**行为分叉**（同一句话在一条路径上算问句、另一条上不算）。

### 6.24 观测改口语义 + 又把三处「同一份清单两处写」清掉

这一轮两件事，都是**先量后改**，`.bin` 格式没动，`model.bin` 不用重训。

**① 观测改口语义：后说的替换先说的**（`docs/thinking.md` 六点六）

修的是已知局限里那条「观测改口语义未定」：用户先说「猫 有 毛」、后说「猫 没有 毛」，
两句话都落成观测 → 同一条边上两个极性**并存** → 以后每次提问都报
「我这儿有互相矛盾的依据」，用户教的修正永远留不下来。

| 环节 | 做法 |
|---|---|
| 落观测（`token_tag_rel/nrel`） | 把**同一条边上对立极性**的旧观测改掉（只清极性位，**不删边** —— 铁律没松） |
| 说话（`agent_learn_relation`） | 改口时回「改 过来 了 ： …（你 先前 说 的 是 反 的）」，`::stats` 记「改口 N 次」 |
| 装载边界（`relations_load`） | 存盘里已有**观测**说了反话 → 这一行基准知识**跳过**。否则每次启动重读 `relations.txt` 会把用户教的改回去（「重启就忘」） |
| 开关 | `::revise on\|off`（默认 on）；off 是 **A/B 对照组**，回到旧语义 |

**先量再改**：写了个一次性探针数「同一对词、同一关系上正负极性并存」的边 ——
**现成的 `model.bin` 里 0 条**（167 条关系边）。所以这条改动在装载语义上是**空转**的
（既有 25 套回归一条不变），价值全在「以后用户改口时」；这也正是它必须配 A/B 的原因：
`tests/revision.sh` 同一段对话跑两遍，量出 **开 → 矛盾 0 次 / 关 → 矛盾 2 次**，
五条边界（不删边 / 只管同一对词 / 缓存路径不算改口 / 装载不让路 / 话要说清楚）逐条钉住。

**踩到的两个坑**（都记在代码注释里）：
1. `tools/delibtest.c` 第三节原来靠「tag 一次正、再 tag 一次负」构造「图里正反都有」，
   改口语义一上，这个状态**构造不出来了**（那条边被替换）→ 5 项当场变红。
   处理办法不是把断言改松，而是**把状态显式化**：那一节显式 `g_obs_revise = 0`
   （等价 `::revise off`，也等价旧模型里遗留的并存位），矛盾检测的代码路径保留；
   「改口本身」另开第十三节（17 项）看护。**同名两义要分开测，不能互相顶替。**
2. 第一版只顾着「后说的替换先说的」，忽略了一个更要紧的顺序：模型文件是**更晚**的
   状态，`relations.txt` 是每次启动重读的基准知识。不加装载闸门的话，
   用户改口一次、存盘、重启 → 基准知识把他教的改回去了 —— 比不改口更糟。
   闸门只认**观测**（缓存不算），所以「观测压过缓存」那条语义没被影响。

**② 三处「同一份清单两处写」**（`docs/设计原则-涌现与脑区.md` 四点五）

| 之前 | 现在 |
|---|---|
| `frame.h`：语气/结构助词在**虚词表**（Gate B ①号门）和 `fr_wellformed` 的**词尾表**各写一份 | 一张 `FR_PARTICLES[]`，两处都查它；虚词表里删掉重复项（`已经`/`正在` 各写了两遍） |

合并词表有个必须记住的边界，`tools/dupcheck.c` 专门钉住它：

### 6.25 反糟粕：**因果要协变、反例要算数**（人的原理要带上它的约束）

用户又给了两句：**「越接近人思考的原理越好」+「但是不要把糟粕学来了」**。
先写成判据文档 `docs/人思考的原理-采用与不采用.md`（采用表 ↔ 不采用表，
每行都指得出代码与回归），**然后按它去量内核**，当场挖出两个真洞。**29 套回归全绿**。

**判据（三关）**：功能关（在人身上真干活，说得清适应问题）→
落地关（落在已有层，不写新知识）→ **护栏关（这条原理的约束是什么）**。
第三关是这个仓库反复踩出来的两类坏味道：

| 坏味道 | 症状 | 实例 |
|---|---|---|
| **机制在、行为不在** | 计数器在涨，图/行为一点没变 | `ai_learn_counterfactual` 调 `ai_weaken_edge`，后者要求 `n_subs==0`；因果边带 `[因果]` 语境（`n_subs==1`）→ **永远匹配不上**：`反事实=` 每次 +1，边没动 |
| **机制在、约束不在** | 学来的是偏误 | `ai_learn_causal` 只看时序相邻：一次巧合就建一条活跃边，**出现一百次和出现一次没区别**（post hoc 迷信） |

**这一轮修的**（探针输出，改前 → 改后）：

```
一次巧合之后：  hits=0 mem=活跃          →  hits=1 mem=暂时（会淡、可被反例雪藏）
重复 4 次之后： hits=0 mem=活跃（没变）  →  hits=4 mem=升格（协变才升格，且有上限 CAP）
反事实之后：    hits=0 mem=活跃（没变）  →  hits=0 mem=暂时；再来一个反例 → mem=雪藏
```

三条**护栏**保证「见得多」不会把它变成知识（`tools/biastest.c` 逐条钉住）：
① 永远带 `[因果]` 语境标记 → 知识查询（`rel_direct_*` 要求 `n_subs==0`）认不出它；
② 永远不参与走边（`ai_edge_walkable` 挡掉带语境的边）；
③ 升格只写 `hits`/`mem_state`（**参数层**），不建边、不改结构。
参数进 `ai.h` 的参数区：`AI_CAUSAL_MIN_HITS` / `AI_CAUSAL_HITS_CAP`。

**顺带修的一处「报表骗人」**：`反事实=` 以前不管削没削到都 +1，现在只在**真的削弱**时 +1
（`biastest` 专门测「削不到时不计数」）。判「机制在不在」一律看**可观测量**，不看计数器。

**反糟粕清单里本来就在的那些护栏**（这一轮只是把它们钉成回归，不是新写）：
不虚构（`gaps>0` 不下断言 + 拒答池 + 三态"不知道"）、不自我印证（缓存不许互为依据 +
统计只看观测）、近因即真理（改口只改极性位、边不删）、锚定/从众（他者信念表独立）、
过度泛化（独占要似然比 + 样本量）、空想当真（想象只挂 `[想象]` 标记、内心排练只动注意力）、
情绪放大（惊讶只削弱那条预测边、几何衰减）。

实测入口留在仓库里：`tools/causalprobe.c`（`./build_causalprobe` 直接打出
「一次=暂时 / 协变=升格 / 反复有上限 / 反例到雪藏 / 见得多也不是知识」五个时刻，
改这条语义之前先跑它 —— **判机制在不在看边的 hits 与状态，不看计数器**）。

新增看护：`tools/biastest.c`（**35 项** C 级）+ `tests/biases.sh`（**10 项** CLI 级），
`tests/all.sh` 从 27 套变 **29 套**。`model.bin` 没动（md5 不变），
`sh tests/thinkout_ab.sh` 仍然 **0/8**。

**缺口照实说**（写进新文档第五节）：**修正的记忆**（改口后旧说法不留痕，做它可能动格式）、
结构映射式类比（表示层不够）、情绪真正参与决策、时间/顺序推理、未解问题持久化。

### 6.26 Token 的行为（图操作）+ 临时 Token + 修正的记忆 / 来源监控

用户：「应该给 token 加上行为……并且加上临时 token」+「在这两个 token 之间加一个 token
的意思是**不要直接联想到**，插入一个 token 经过此 token 中转」+「顺便继续修正的记忆 / 来源监控」。
新增 `docs/token行为-图操作与临时token.md`（能力 + 实测 + 局限）。**格式没动（仍 v9）**，
`model.bin` 不变，`tests/all.sh` 从 29 套变 **31 套**。

**① 行为 = 一张表**（`micro.h` 的 `TOKEN_OPS[]`）：`{名字, 参数形状, 说明, 参数个数, 展开函数}`。
展开函数**只产出 `ModIntent`、不碰图** —— 结构改动照旧只有 `micro_step()` 一个入口，
每条都过安全内核。新增一种行为 = 表里加一行 + 写一个展开函数。手动入口 `::op`
（和 `::mod try` 同类：调试/手动，不是系统自己提的）。三条行为正是用户点名的：

| 行为 | 语义 | 落地 |
|---|---|---|
| `::op 随语境接线 <X> <Y>` | 给**带语境 X 的连接**接上 Y（语境一起带过去） | `MOD_ADD_ASSOC`（带语境） |
| `::op 指定接线 <S> <X> <Y>` | 同上，只在**指定主语**上找（「带**指定** token 的连接」） | 同上 |
| `::op 中间插词 <A> <B> [N]` | 在 A、B 之间插一个 Token 并**拆掉直连**（经 N 中转），N 缺省是临时 Token | **新** `MOD_INSERT_BETWEEN`（复合意图） |
| `::op 回收临时` | 回收没人引用的草稿 | **新** `MOD_REMOVE_TOKEN` |

「插词」为什么必须是一条**复合**意图：它一次做三件事（造 N、A→N、N→B，外加拆 A—B），
拆成四条的话「拆直连」会在 N 还没建好时执行。**直连拆不拆由安全内核裁决**（判据只有一份
`micro_edge_removable()`）：观测关系边是知识、铁律 2 不许剪，缓存可以 —— 拆不动就保留并说明，
中转照样接上。

**② 临时 Token（草稿纸）**：`[临:…]` 是与 `[新概念:` / `[自问:` 并列的内核自有命名空间。
这一轮把**两件事分开**了（原来混成一个 `micro_token_reserved`）：
`micro_endpoint_reserved()`（能不能当**端点**）放行内核自有命名空间；
`micro_token_reserved()`（算不算**内容**）仍然跳过它们，统计/共现固化不被草稿污染。
**不存盘**：存盘跳过临时 Token **及指向它的边**（`mio_edge_saved()`），名字前缀是唯一判据 ⇒ 不动格式。
**可回收**：只许 `[临:` 且没人引用；回收是**软删**（和 `ai_gc` 一样），物理搬走会让池里的指针悬空。

**③ 修正的记忆 / 来源监控**：改口时经受审通道落一个 `[修正:猫_不_有_毛]` 标记并连回主语 ——
**幂等**（同名 intern，同一条修正改口多次只有一个标记）、**不是知识**（不进关系表、不走边、
旧极性不复活）、**持久**（普通 Token，随图存盘）。`::revise` 列得出。补的是来源监控里缺的那一档：
观测/缓存/假设/他人/类比早就分开了，**「改过口」**原来没记。

**④ 顺手查出来的两个真洞**（都属于「机制在、行为不在」，见 `docs/人思考的原理-采用与不采用.md`）：

| 洞 | 症状 | 根因 |
|---|---|---|
| 每步新建边**预算从来没扣过** | `max_new_edges_step` 形同虚设，一步能无限建边 | `safety_charge()` 排在 `micro_apply_one()` **之后**，却靠 `!micro_has_edge()` 判「是不是新边」—— 应用完那条边已在图上，判断永远为假 |
| **带语境的边**在辅助函数里等于不存在 | `n_subs>0` 的边加权加不上、预算不算 | `micro_edge_index()`/`micro_has_edge()` 都要求 `n_subs==0`，调用方却拿它们做「边存在吗/加权」 |

修法：记账挪到**应用之前** + 应用失败 `safety_refund()`；新增 `micro_edge_index_ctx()`/
`micro_has_edge_ctx()` 让调用方按语境走（反事实那处上一轮已修）。

**跨代码版本逐字节证据**（不是"看起来没变"）：
`slot0`（训练后存盘 4738521 字节）改前 == 改后；规范状态 dump（2783 行）改前 == 改后 ——
既证明「没有草稿时存盘过滤恒等、格式没动」，也证明「预算修复没有改变既有行为」。

新增看护：`tools/optest.c`（**48 项** C 级）+ `tests/tokenop.sh`（**20 项** CLI 级）。
`sh tests/thinkout_ab.sh` 仍然 **0/8**。

**一个设计取舍（用户拍的）**：行为不另造 **Token 栈**，用**临时 Token** ——
栈机式组合会把「组合」从图搬进语言层，而设计原则是「行为留给图」；
真要把一串行为写成程序时，第一步应是复用**已有的** `Interp` 栈机（把行为注册成原语），

### 6.27 Token 行为的**语言层组合**：注册进已有的原语栈机（不新造栈）

### 6.29 **前提当闸门**：推理/思维层按前提决定用不用（R10 + 验证器 + 问前提机制）

用户接着要的是「推理/思维层按前提决定用不用」。**31 套全绿**，`model.bin` 不变，格式不动。

**闸门只装在逻辑这一侧**（用户明确说过「联想本来不依赖前提」）：

| 层 | 前提的角色 |
|---|---|
| 走边/自由联想 | **完全不看前提**：A→前提 是普通可走边（`ai_edge_walkable` 不认识 `[前提]`） |
| 求解器 `rel.h` | **R10「经前提」**：`A —[前提]→ P`，**P 在当前注意窗口里**，且 `P R B` ⟹ `A R B`；前提不成立就**不用**这条连结 |
| 验证器 `derive.h` | 规则 10 独立复核：边必须是前提链接 + 前提现在成立；伪造的前提步 `gaps>0` 被拒 |
| 思维层 `think.h` | 第 5 条内建机制**「问前提」**：痕上写明「有前提：人（没成立）—— 前提没成立，按前提不用它」 |

```
你 > 人 好                         （前提进语境）
你 > 猫 会 做饭 吗
```

**两个踩到的坑**：
① 新机制一开始注册在表**最后**，结果「4 个子目标 + 停滞上限 3」把它的那一步吃了 ——

**顺序也是机制表的一列**，不是随便排的。
② `der_from_proof` / 两个链渲染器原来只认 via 0~9，`via==10` 会渲染成 `?·前提` ——

### 6.32 输出做成「AI 可编辑的文本 + 草稿区 + 自己决定何时发送」，**并且作为补丁**

用户的决定：「把回答的输出设置为 AI 可以编辑的文本……类似**记事本**，AI 可以控制**什么时候发送**，
还有一个**草稿区**……这两个我认为应该**作为补丁**」。

**没有往输出流水线里塞特判**，而是给补丁边界补上**输出侧的三个口子**（内核不认识"记事本"）：

| 口子 | 作用 |
|---|---|
| `stage(Patch*, const char *text)` | 一轮结束前把**流水线本来要说的原文**交给补丁暂存 |
| `emit(Patch*, char *out, cap)` | 问"这一轮发什么"：`1` 用我的 / `0` 不接管 / `-1` **明确不说话**（注册顺序，第一个接管的赢） |
| `op(Patch*, op, args, n, out, cap)` | 补丁自己的操作入口；内核只做**有界派发 + 故障隔离** |

AI 想用外设也走**受审通道**：新意图 `MOD_PATCH_CALL`（第 12 种，吃硬预算 `max_patch_calls_step`=4、
进审计/日志），Token 行为对应一行 `::op 调用补丁 <补丁> <操作> [参数…]`；
人工/测试入口 `::patch op <补丁> <操作> [参数…]`。

内建 `记事本` 补丁：两个缓冲（**草稿区** / **待发送**）、两种模式
（`auto` 默认：没编辑时输出**逐字节等于**无补丁；`manual`：不显式 `发送` 就**不说话**）、
14 个操作（写/插入/删/改/清空/提交/清空发言/插入发言/删发言/改发言/发送/不发/模式/读）。

实测：

```
你 > ::patch mount 记事本
你 > ::patch op 记事本 模式 manual
你 > 猫
AI >                                   ← 不说话：它还没决定发
你 > ::patch op 记事本 改发言 看 跑     ← 编辑"要说的那句话"
你 > ::patch op 记事本 发送
你 > 猫 有 毛 吗
AI > 猫 跑 来 跑                        ← 说出来的是它自己改过的那句
```

**A/B（这条最关键）**：`AIP_PATCH=记事本 sh tests/all.sh` → **全部回归通过** ——
挂上这个输出侧外设、auto 模式下**31 套行为一个字都没变**（"机制在，行为不动"）。
反过来说明：它只在 AI **真的动手编辑/扣着不发**时才改变行为，而那两件事都是显式动作。

**踩到的坑**（写进 `docs/记事本与草稿区-输出补丁.md`）：
① `char[4][40]` 强转成 `char**` → 补丁把参数行当指针读，**ASAN 当场定位到 SEGV**（必须先落 `char *argv[]`）；
② 位置按字节会把汉字劈成两半 → 改成按**字符**（UTF-8 码点）换算；
③ `-Werror=format-truncation`：补丁名+操作名+返回说明一起格式化会超 note 容量 → 有界手动拼接；
④ manual 的 `stage` 不能每轮覆盖 AI 已写的内容、也不能重置它的"发送"决定，否则跨轮打草稿不成立。

看护：`tools/optest.c` 113 → **137 项**（第十三节 25 项）、`tests/selfmod.sh` 33 → **44 项**
（第七节：挂上不改行为**逐字节比对**、草稿区、manual 沉默、编辑+发送、受审通道、坏补丁不拖累内核）。
**31 套全绿**（不挂 / `AIP_PATCH=记事本` 两种跑法都绿），`model.bin` 不变，**格式没动**。

**局限照实说**：两个缓冲**不持久化**（`::save` 不存草稿）；`改/改发言` 只认单 token（CLI 按空格切参数）；
"AI 自己想到该打草稿/该发送"还没有机制（它能走受审通道调用，但决策权在机制那一层 —— 那一步会改输出，先 A/B）。

### 6.34 让 **AI 自己**用记事本：写草稿 / 决定什么时候发送（用户点的 A）

|---|---|---|


**踩到三个坑**（都进文档了）：
① **输出侧两个口子的顺序**：`stage` 在安全点之前、`emit` 必须挪到**安全点之后** ——

③ **`stage` 绝不覆盖 AI 写过的东西**，也不许在它明确表态（发送/不发）之后再改主意。

**A/B（按规矩先量，三档）**：

#### 三、踩的坑（都是这一轮真踩的）
1. **我自己的测量脚本踩了本项目登记过的坑**：`sed | while read` 循环里跑被测套件，套件读 stdin

   整包那次虽然仍报 30/30 绿，但过程已被污染、不可信。修法：(a) 加 `_t/par/.lock` 并发锁（同上第 8 条），
   (b) 自己守纪律：启动整包前先确认没有别的跑法在跑（看 `_t/par/.lock` 或日志是否还在长）。
   顺带说明：直接跑单套（`sh tests/features.sh`）与整包**不再互相干扰** —— 单套写仓库 `_t/<名>/`，
   整包写各自沙箱里的 `_t/<名>/`，两条路不重叠。
6. 编辑纪律：**跑着脚本时别改它**（`sh` 是边读边执行的，正在跑的 `all.sh` 被改会读到半个文件）——

### 6.43 本轮：#2 写入闸门加"候选证据项" + 阈值在**候选总体**上重新标定（**已完成**）

#### 一、做了什么
1. **先量，量出两件事**（上一轮已记）：① 现值公式里 trust/惊讶/不累是"整个 AI 一个值"，
   0.35 的权重只贡献常数偏移；② 更要命的是**候选自己的证据在 `think_finish` 那一步被丢掉了**。

2. **把候选证据接进评分**（`ThinkCand` / `AiWriteCtx`）：

### 6.46 本轮：#5 情绪动力学**多独立维度**（**已完成**）

#### 一、做了什么
1. **先把量测修对**（这一步比加维度更重要）：`tools/affectprobe.c` 原来算"舒适×唤醒"相关是
   **先把两个序列各自排序再算** —— 排序把"同一轮的搭配"打散了，算出来的不是配对相关
   （旧值 r=0.91 就是这么来的）。改成按轮配对存值 + 真 Pearson，并打**两张矩阵**：
   原值（含共同漂移）与**一阶差分 Δ**（去掉漂移，看"机制上是不是一回事"）。
   真数是：**舒适×不适 r=−0.99、舒适×唤醒 −0.94、不适×唤醒 +0.95** —— 四个状态量
   **其实只有一个自由度**（都是"我最近猜得准不准"的函数）。
2. **加两个"派生"维度**（`affect.h`，**不新增存档字段**：都从已有状态现算，重载后一致）：
   · `好奇` = **当前注意环**里"薄词"（边数 < 3）的占比 —— 来自**图**，不来自预测准确率；
   · `亲近` = 他者模型的 **信任 × 互动** 归一 —— 来自**社交**（没人 = 0）。
3. **按实测分布写区间**（这一层的规矩：区间是量出来的）：`好奇 ≥0.20 → 思考步数 +2`、
   `亲近 ≥0.30 → 激活阈值 −0.01`（对话场景命中 12.5% / 67.5%）。
4. 顶部那段"量出来的三件事"同步改正（原来写的 0.91 是错算法量出来的）。
5. 新增探针输入 `tools/probes_affect_dialog.txt`（40 行对话：社交句 + 缺口语 + 提问），
   让"社交/缺口感"这两个维度有地方动 —— 光靠语料回放量不出它们。

#### 二、证据（两种场景，都是本机实测）
（1）**语料回放**（`_corpus.txt` 100 行）一阶差分 Δ：

| | 舒适 | 唤醒 | 疲劳 | 不适 | 好奇 | 亲近 |
|---|---|---|---|---|---|---|
| 舒适 | 1.00 | | | | | |
| 唤醒 | **−0.94** | 1.00 | | | | |
| 疲劳 | −0.13 | 0.08 | 1.00 | | | |
| 不适 | **−0.97** | **0.92** | 0.12 | 1.00 | | |
| 好奇 | −0.13 | 0.07 | 0.07 | 0.14 | 1.00 | |
| 亲近 | −0.19 | 0.17 | 0.02 | 0.19 | 0.17 | 1.00 |

（2）**对话场景**（`tools/probes_affect_dialog.txt` 40 行）一阶差分 Δ：

| | 舒适 | 唤醒 | 疲劳 | 不适 | 好奇 | 亲近 |
|---|---|---|---|---|---|---|
| 唤醒 | **−0.99** | | | | | |
| 不适 | **−0.74** | **0.77** | | | | |
| 好奇 | −0.01 | 0.01 | 0.12 | 0.14 | 1.00 | |
| 亲近 | −0.11 | 0.05 | 0.11 | −0.10 | 0.00 | 1.00 |

　→ 结论：**预测簇（舒适/唤醒/不适）是一个维度；疲劳、好奇、亲近各是独立的轴**
　（新加的两轴 |Δr| ≤ 0.19，对话里 ≤ 0.14）。原值矩阵里它们看着高相关，是因为**整段回放里
　所有量都在随时间漂移** —— 所以"独立性"必须看 Δ，这条经验写进了探针输出里。

（3）**整包两跑法全绿**（`tests/all.sh`）：默认（情绪层关着）**30/30**（38 s）、
　`AIP_AFFECT=1`（层开着、新维度生效）**30/30**（37 s）——这一层默认关，所以"翻默认"这件事
　不适用；A/B 要证明的是"开着也不破坏既有回归"。（探针门照旧：`affectprobe` 也在 `-Werror` 里。）

（4）**命中率**（区间不能永不触发，也不能永远触发）：对话场景里
　`好奇` 12.5%（注意环出现薄词时才触发）、`亲近` 67.5%（有几个熟人在场）；
　语料回放里 `好奇` 0%（训练语料没有缺口）、`亲近` 0%（没有社交）——**语义正确**。

#### 三、踩的坑
1. **探针的相关算法是错的**（排序后算 r）→ 结论位（"两行其实在说同一件事"）判的方向对、
   数值不对；修对之后发现共线**比登记的更严重**（0.91 → −0.99）。

   当驱动量毫无用处。改成只看**注意环**（这一轮谈到的词）才逐轮变化。
3. **探针忘了重编**：改了 `affect.h` 之后跑旧二进制，输出"好奇 0.00"看着像没生效 ——

   "按分位定阈值"必须留一位余量，或者干脆看实测取值集合。

#### 四、局限照实说
- **状态量本身没加**（舒适/唤醒/疲劳/不适 是存档 v9 的一部分，动不得）：本轮加的是**层内派生**维度。

- 派生维度依赖"注意环"和"他者模型"这两个**会随场景不同而存在或为空**的东西：

  但意味着这两行只在对话场景里有效。

### 6.47 本轮：#6 第 0 步提速（探针并行/按需）——**先量，发现前提是错的**（**已完成**）

#### 一、做了什么

   → **跳过编译**（**断言部分照跑**）。要强制重编：删 `.hash`（或整个 `_t/probes`）。

     （`MICRO_RUN_TOKEN_PREFIX`，与 `[草稿:…]`/`[自问:…]` 同一套约定），**不建关系边、不进关系表**。
   - `action_refuse()`：**每一次拒绝都留理由**（`last_reason`）；账：跑/成功/非零/超时/拒/写（+写失败）。
2. **把"受审写入"的唯一一份实现抽出来**：`micro.h` 的 `micro_drain_queue()` ——
   `micro_step`（每轮）与 `action_observe`（一次动作一小步）都走它，
   于是"审查 → 记账 → 应用 → 审计"的口径不会因为入口不同而分叉。
   一次动作会 `safety_step_begin()` 重开这一步的预算（否则第一条标记就用光"一步最多造几个 Token"）。
3. **CLI**：`::act`（状态面板：白名单 + 边界 + 账 + 最近一次 + 输出 + 落图）、
   `::act on|off`、`::act run <命令…>`、`::act write <相对路径> <文本…>`、`::act out`、`::act timeout <ms>`。
4. **看护 `tests/action.sh`（第 31 套，已进 `tests/suites.txt`）盯七件事**：
   默认关（不执行 + 留理由）/ 白名单拒 `rm` / 三次越界拒（读的绝对路径、读的 `..`、写越界）
   / **没有 shell**（`; | &` 原样进 argv）/ 超时被杀（FIFO 上 `cat` 卡住 → SIGKILL，rc=-9）
   / 输出变观测且**不是知识**（`::rel` 里没有它）/ 审计账对得上（六个计数一一对应）。
   反向测量（`AIP_ACT=1`）时"默认关"那两条断言**自动跳过**，并断言"这次真的跑了 + 账跟着变"；
   `tests/switches_ab.sh` 的开关表加了 `act:AIP_ACT=1` 一行。
5. **`_DEFAULT_SOURCE` 放在 `ai.h` 顶部**（一处生效）：`action.h` 要用
   `fork/exec/poll/kill/clock_gettime`，而特性测试宏**必须在第一个 libc 头之前**定义
   （本项目 `-std=c11` 是严格 ISO 模式），而 `ai.h` 是所有 TU 的第一个头。

#### 二、证据

| 事 | 数 |
|---|---|
| 新套件 | `tests/action.sh` **22 项全过**（默认跑法）/ 21 项（`AIP_ACT=1` 反向跑法） |
| 真闭环 | `::act write hello.c int main(void){return 0;}` → `::act run cat hello.c` 读回来 → `::act run gcc -c hello.c` 出 `hello.o`（**写 → 跑 → 看结果**第一次真的走通） |
| 拒绝有理由 | `rm`（白名单）/ `/etc/passwd`（绝对路径）/ `../../etc/passwd`（`..`）/ 写 `../越界.c`、`/tmp/越界.c`（越界）—— 五条都打出了理由，且越界文件**真的没被写出来** |
| 超时 | FIFO 上 `cat` 卡住 → `超过 300 ms 没结束 → SIGKILL`，rc = -9（`::act timeout 300` 覆盖） |

#### 三、踩的坑（**都是这一轮真踩的**）

1. **`argv` 没写 NULL 结尾** → `execvp` 顺着栈上的垃圾读，**每条命令都 rc=127**。
   症状很像"命令不存在"，其实是拆分函数少了一行 `argv[argc] = NULL`。
2. **账对不上（测试抓到的）**：写文件那条路顺手 `n_ok++`，而 `n_ok` 是"跑"的分档 →
   `跑 6 = 成功 5 + 非零 1 + 超时 1` 这种自相矛盾的账。修法：写文件单独一对计数
   （`n_write` / `n_write_failed`），跑的分档只统计跑。
3. **每步 Token 预算把标记吃了**：`action_observe` 直接调 `micro_drain_queue` 而不开新的一步，
   于是 `step_new_tokens` 从不重置 —— 第一条标记之后全被安全内核按预算拒掉
   （表现：账上"观测标记 1 个"而实际跑了三条命令）。修法：`safety_step_begin(ai)`。
4. **特性测试宏的位置**：`-std=c11` 下 `kill`/`clock_gettime` 没有声明；
   `_DEFAULT_SOURCE` 必须写在**第一个 libc 头之前**（放 `action.h` 里已经太晚）。
5. **`-Werror=format-truncation`**：理由缓冲 192 字节里塞 304 字节的路径 → 有界手写拷贝
   （这个坑项目里踩过好几次，注释里又记了一遍）。
6. **命令表的第 3 列是参数档**：写 `0`（`CARG_NONE`）→ `::act` **不收参数**，
   每条命令都回"[act 不收参数 —— 用法：::act]"。要 `1`（`CARG_OPT`）。

#### 四、局限照实说

- **账是进程级的**（层里的 static，不随 AI 实例走、不进存档）：一次会话一份账，够用但不算干净。
- **只做了通道**：命令是**人/CLI 发起**的；"AI 自己决定写文件、自己编译、自己看错误再改"是下一件（§6.49 第 4 步）。
- **读也关在工作区里**（参数不许绝对路径/`..`）：安全，但"读一眼系统头文件来学语法"这类事**做不了** ——
  真需要时得再开一个受审的口（并且要单独 A/B）。
- **不做引号/转义**（没有 shell 的代价）：`echo "a b"` 会拆成三个参数、引号原样留在输出里（看护里正是这么钉的）。
  AI 要写带空格的文本，走 `::act write <路径> <文本…>`（文本按整行取）。
- **`sed -i` 能改工作区里的文件**（cwd 在那儿、路径不许越界）——这是设计选择，不是漏。
- **不联网**：白名单里没有网络工具；但这条是"没放进去"，不是"拦住了"（`echo` 一个 URL 当然可以）。

### 6.53 本轮（接着 6.51）：**"写-跑-看错-改"的机械闭环**（`code.h`，降级版）

§6.52 说的"下一件"就是它。用户 2026-10-07 的线 A 目标里排第 4 的缺口。

#### 一、做了什么

1. **新层 `code.h`**（和 `action.h` 同一层，在内核之外）：一轮闭环 = 
   **写文件 → 跑编译器 → 看第一条错误 → 按一张规则表改一次 → 再跑一次**。
   - 读源文件（`_t/work/` 里，上限 16 KB）→ 用 `action_run()` 跑
     `gcc -std=c11 -Wall -Werror=implicit-function-declaration -o <源文件>.out <源文件>`；
   - 从编译器输出里挑**第一条 error**（连位置串 `文件:行:列` 一起取出来）；
   - 按**修法表**认规则，改**内存里的源文本**，再用 `action_write_file()` 写回去，再编一次。
2. **修法表（一行一条，只有两类）**：
   | 错误特征 | 改什么 | 为什么 |
   |---|---|---|
   | `expected … ;`（且不是 "end of input"） | 补分号 | gcc 报的是"缺分号之后的第一处" → 分号补在**上一行末尾** |
   | `implicit declaration of function` | 补 `#include` | 按函数名补头：printf/puts→stdio.h；str…/mem…→string.h；malloc/free/exit→stdlib.h |
   认不出的错误 → **停在原地并说明**（"没有已知的机械修法"），**不猜**。
3. **闭环进了代理循环**：`AIP_CODE=<相对路径>` 时，`agent_step` 在安全点之后**自己**走一遍
   （一个进程只走一次），并把痕打出来；`::code try <相对路径>` 是 CLI 的同一个入口；
   `::code` 看痕（编译几次 / 首次 rc / 最终 rc / 第一条错误 / 改了哪一行 / 产物）。
4. **观测标记**：每轮闭环落一个 `[代码:<最终rc>]` 标记（新增 `MICRO_CODE_TOKEN_PREFIX`，
   和 `[运行:rc]` 共用 `action_observe_mark()` **同一处**落标记的实现）——**不是知识**。
5. **`::act write` 支持 `\n` `\t` `\\` 转义**：一条命令就是一行输入，不支持转义的话
   **多行源码根本写不进去**（这一轮真踩到：源码被拆成了好几条命令）。
6. **看护**：`tests/action.sh` 加了第 ⑧ 节（6 项）：补分号闭环 / 改在文件本身 /
   补 include 闭环 / 认不出就**停** / 认不出只编一次 / **代理循环自己走了一遍**。

#### 二、证据

```
[写代码闭环] 缺分号.c：编译 2 次，首次 rc=1 → 最终 rc=0
  第一条错误：缺分号.c:3:5：expected ‘,’ or ‘;’ before ‘return’
  改了什么：按规则在**上一行**末尾补了一个 `;`（第 2 行） —— 再编**过了**
[写代码闭环] 缺头文件.c：编译 2 次，首次 rc=1 → 最终 rc=0
  第一条错误：缺头文件.c:1:25：implicit declaration of function ‘puts’ [-Werror=implicit-function-declaration]
  改了什么：按规则补了 `#include <stdio.h>` —— 再编**过了**
[写代码闭环] 改不动.c：编译 1 次，首次 rc=1 → 最终 rc=1
  改了什么：没有已知的机械修法（降级版只认两类错）—— 停在原地，不猜
[代理循环自己走了一遍写代码闭环：AIP_CODE=闭环.c]     ← 一句话（一轮对话）就跑完闭环
```
- `tests/action.sh` **28 项全过**（正向）/ 反向测量 `AIP_ACT=1` 也全过。
- 文件真的被改了（`cat _t/work/缺分号.c` → `int x = 1;`），产物真的出来了（`.out`）。

#### 三、踩的坑

1. **认错形状就会瞎改**：`expected declaration or statement at end of input` 也含 `expected`，
   第一版规则把它当成"缺分号"，去第 1 行末尾补 `;` —— 幸好"末尾是 `{` 就不补"那条护栏拦住了。
   现在规则①要求**真的在说分号**且不是 `end of input`。**认错比不认更糟**，所以两条都写进了代码注释。
2. **`::act write` 写不了多行**（见上）；顺带把 CLI 的转义写在注释里说明"这是 CLI 的语法，不是层的语义"。
3. **代理循环跑过了但日志是空的**：`code_auto_step` 只更新 `g_code`、不打痕 ——
   "机制在、行为在、证据不在"。现在它自己把痕打出来。
4. **`-Werror=format-truncation` 又来一次**（5 处）：小缓冲收长路径/长理由 →
   加了有界的 `code_cat()`（项目里这是第 N 次记这条坑了）。
5. **`str*/mem*` 写进 `/* */` 注释** → `*/` 提前结束注释，一片编译错误。

#### 四、局限照实说

- **它不会写代码**：源文件是外面写好的（`::act write` / 记事本草稿 / 人给的），
  这一层只做"改一处已知形状的错"。
- **只会两类修法、最多改一次**：`CODE_MAX_FIX = 1`；改完还错就报出来（不无限重试）。
- **只认第一条 error**：gcc 一次可能报很多条，第一批修法只针对第一条（够用来演示闭环，
  离"能自己修一个真项目"差得远）。
- **编译命令固定**（`-std=c11 -Wall -Werror=implicit-function-declaration`），
  产物一律 `<源文件>.out`；不支持别的构建系统。
- 它的痕**不进存档**（`CodeRun` 是层里的 static，和 `action.h` 的账一样是进程级）。

#### 五、下一步

`deepseek看这里.txt` 开头那份唯一清单的第 5 条：
**原语语言加解析器/校验器** → 再接**词法层 ASCII 逐字保留** → 再落**第 32 套看护**（代码任务回归）。
（闭环已经是现成的"便宜目标语言"跑道：写 → 跑 → 看错 → 改。）

### 6.57 实测："过程"今天能表达多少（先量再造，§6.56 第 1 条的判据）

做法：**不写任何新代码**，拿现有二进制在 `_t/proc/` 里试着表示一个小过程
（"词法分析 → 语法分析 → 语义检查"，带一个输入和一个顺序），然后看图上出来什么、逻辑层答得出什么。

命令（可复现）：
```
::asm [原语:对象] 词法分析 [原语:对象] 语法分析 [原语:前关联] 输入 [原语:连接]
::edges 词法分析
::asm [原语:对象] 词法分析 [原语:对象] 语法分析 [原语:对象] 语义检查 [原语:时间链]
::order 词法分析 语义检查
```

**图上真的出来了什么**
```
[原语 加前提] 词法分析 —[前提]→ 语法分析 → 输入（已提出）；应用 1 条
[词法分析] 有 2 条边：
  → 语法分析     hits=1 seq=0 **前提**（语法分析 是这两个词之间的前提 token）  来源=共现
  → [关系:之后]  hits=0 seq=1 来源=共现
```

**结论（一分为二，都是实测的）**
1. ✅ **步骤/条件能表达**：`A —[前提]→ P → B` 这套（动作槽标记）就是"这一步的前提/上游"，而且它
   已经被逻辑层认（`::premise` 查得到）。**顺序边也在图上**（`[关系:之后]` + `next_in_time`）。
2. ❌ **顺序读不出来**：`::order 词法分析 语义检查` 答的是
   「首次见到 tick=0 / 最近一次 tick=0 → **同一轮里出现的（先后看不出来）**」——
   因为 `::order` 只看**首次见到的 tick**，不认 `next_in_time` / `[关系:之后]` 那条边。
   也就是说：**结构写进去了，查询层没接上**。这是"机制在、读不出来"的那类缺口，和 §6.49 记过的
   「辅助函数默认无边」是同一个病。
3. ❌ **过程边与共现边分不开**：`[原语:对象] tokenize [原语:对象] input [原语:连接]` 出来的是一条
   **普通共现边**，与「猫 吃 鱼」在图上**形状完全一样** —— 这正是 §6.56 第 5 条那个"四选一"的真问题。

**所以下一步最划算的一刀**（不动格式、不动数据模型）：
把**已有的顺序结构接进查询层** —— `::order`（以及任何问先后的地方）先看
`next_in_time` 与 `[关系:之前]/[关系:之后]` 边，没有再退回 tick 比较。
这是"把已经写进图的东西读出来"，不是新语义；做它之前先量：现在有多少条 `[关系:之后]` 边
（出厂模型里）—— 如果一条都没有，那这条查询路径只对"现场用 `[原语:时间链]` 建过顺序"的会话有效，
也要照实写进局限。

**补量（出厂模型 `model.bin`，用 `tools/mdump.c` 数）**：带标记的边**一条都没有** ——
`main=[关系:之后]` 0 条、`act=[前提]` 0 条、`act=[前提不]` 0 条、`act=[因果]` 0 条。
也就是说：**标记那套东西全是"现场长出来的"**（`::asm`、D4、因果协变），出厂模型里没有。
所以上面第 2 条那个查询层补丁，收益只在"现场建过顺序/前提的会话"里 —— 照实写进局限，别夸大。

### 6.60 ⑤ 原语语言：干跑校验器 + ASCII 代码词法 + 第 32 套（**本轮做完**）

#### 一、做了什么

1. **栈效应表（`token_lang.h` 的 `PRIMS[]`，一行一条）** —— 名字、kind、`need/pop/push/flags`
   全在一张表里（原语名以前就只有这一份；现在**栈效应**也只写这儿）。
   口径按 §6.58 的纪律：**按 `interp_exec_prim` 的真实行为抄，不按名字猜** ——
   `分割`=清空整栈、`包裹/嵌套/捆绑`=整栈折成一个（`stmt_start` 恒 0 的后果）**明写在注释和 `::prims` 的输出里**。
   `interp_step` 那个"吃下一个词"的 kind 清单也收进表里（`PF_ARG`，`prim_eats_arg()`），不再另抄一份。
   途中发现并修掉一个**假错误源**：`[原语:对象]` 要的是**下一个词**，不是"栈上 1 个操作数"——
   一开始 `need` 填 1，于是 `[原语:对象] 猫 [原语:连接]` 被误报"操作数不够"（认错比不认更糟的真例）。
   现在 `need` 只算栈上操作数，`PF_ARG` 单独查"后面还有没有词"。
2. **`token_check_program()` 干跑校验**（同一头文件）—— 六条判据：
   未知原语名 / 括号不配对 / 操作数不够 / 如果-结束不配对 / 空程序 / 参数缺失。
   三条硬规矩：**干跑不 intern**（错名字不会被当场造成 Token —— 那正是"错字被静默吞掉"的机制本身）；
   **只按真实行为判**；**不确定就不判**（`展开/检索` 推几个看数据 ⇒ 从那一步起栈深不确定，
   后面的操作数检查跳过**并记账**，结果里明写"跳过 N 次"）。
   块配对用一层小栈（上限 16 层），`否则`/`结束` 没有对应的 `如果` 也各算一条。
3. **`::asm check on|off`**（不给参数看状态；默认关，`AIP_ASMCHECK=1`；`ai->asm_check_on` 进 `ai_switches_init`）。
   开着时 `::asm <序列>` 先干跑：**没过就不执行**（图一个字都不动，日志里连 `[执行了 N 个 token]` 都没有）；
   过了照旧执行。关着时**与今天逐字节相同**（实测：错名字照旧被 intern，Token 数 +1）。
4. **`lex.h`：ASCII 代码词法**（线 A ③）—— 标识符 `[A-Za-z_][A-Za-z0-9_]*`、数字 `[0-9]+(\.[0-9]+)?`、
   **标点逐字符**一个 token、**空白归一**（token 里不能有空格是硬边界）。
   **往返判据只写一处**（`lex_roundtrip()`，测试只调它）：
   ① **逐字保留**：token 首尾相接 == 源文本去掉空白后的字节串（一个字节不许丢/改/多）；
   ② **幂等**：canonical（token 间恰好一个空格）再词法一遍，canonical 逐字节相同。
   另有 `lex_balance()`（`()[]{}` 配对）与 `::lex <文本>`（看一眼：词表 + 两条判据 + 括号 + canonical）。
   `::ascii on|off`（默认关，`AIP_ASCII=1`）把这一层接进**代码通道**：开着时 `::code try` 读进来的源码
   先过一遍逐字保留判据，痕里多一行「词法：ASCII 逐字保留 ✓/✗（原因）」；关着时 `::code` 输出逐字节同今天。
5. **第 32 套 `tests/asmcheck.sh`（39 项）** + 进 `tests/suites.txt`；`tests/switches_ab.sh` 的开关表

#### 三、踩的坑（都可复现）

1. **dash 里双引号串里的反引号是命令替换**：`ok "… `if (x { }` …"` 让 `(x { }` 变成"未闭合的子 shell"，
   `sh -n` 直接语法错（bash 反而放过）。本套的说明里已把这类反引号全改成「」。
   顺带：同一类写法在别处会让消息**静默少一截**（命令替换跑出空串），比语法错更难查。
2. `Token=` 这个 grep 会撞上 `已删Token=0`：统计行要按 `^\[统计\] Token=` 取（第一次量到 `Token 0 → 1198` 就是这么来的）。
3. `[执行了 2 个 token]` 那条断言会跟后面"check off 之后真的执行一次"撞车 ——
   被拒的那个程序和执行的那个程序**词数必须不同**（现在 2 词被拒、3 词执行）。
4. `::asm` 是 `CARG_REQ`：`::asm`（不给参数）在派发层就被拦，**空程序只能从"纯空白序列"进**
   （`::asm <TAB>`）—— 这一条只有走到 `cmd_asm` 里才成立，测试已按这个口径钉住。
5. `-Werror=format-truncation` 又拦了一次：往 128 字节的消息里塞两个原语名 + 两个 `%zu` ⇒ 把 `TOKEN_CHECK_MSG_CAP` 提到 192。
6. `-Wextra` 的 `-Wmissing-field-initializers`：给 `CodeRun` 加了 `lex[]` 就得把静态初始化列表补齐。

#### 四、局限（照实说）

- **校验只接在 `::asm` 这一条路上**：语料行（`learn_primitive_line`）与 `::code` 的源码都没走它 ——
  要在别处用，调 `token_check_program()` 就行，**但今天没接**。
- **"不确定就跳过"是宁漏不假错**：`展开`/`检索` 之后的操作数检查一律跳过（记账）；
  块配对只看层数，**不看**"同一个块里重复 `否则`"这类形状错误。
- **词法不做字符串与注释**：`"`、`//`、块注释符号都按普通标点逐字符切。
  逐字保留不受影响（字节一个不少），但**括号配对会被字符串/注释里的括号骗到**（这一点写在 `lex.h` 头注释里）。
- **token→文本还原不了空白**（token 里不能有空格是硬边界）⇒「逐字保留」的口径是
  **非空白字节一个不改**；canonical 是**给人看的标准形态**，不是原样还原。`::code` 真正写文件时写的是原始 `src`，
  词法层只是**检查**"我写出去的字节有没有被词法改动"。
- **`::ascii on` 不改"怎么切词"**：代码通道依旧"原样写文件、原样交给 gcc"。真正的
  "用这套词法去**生成**代码"还没做（那是后面的事，别把今天这层说成"它会写代码"）。
- 非 ASCII 字节按"一字节一个词"（`::lex` 会把非 ASCII 数出来提醒）；`LEX_MAX_TOK=1024`，超了只测前 1024 个并明说"没测"。
- `::asm check` 的输入语法仍是**按空白切词**（`[原语:对象] 猫` 中间不能有空格）；
  "括号不配对"因此只能在**一个词里**判（`[原语:好`），真正跨词的结构配对属于 ASCII 词法那一层（`lex_balance`）。

### 6.61 N1：一轮思考产出**对象**（`[思考:N]`，内存）+ 复核器（**本轮做完**）

顶块第 6 条的第一件（§6.54 的 N1 / §6.55 的 K1）。缺口原文：思考层只有
`ThinkStep.trace[]`（**轮末清空、不进图、不可复用**），于是"这是我刚才那一次的思考"说不出口。
处理决定（§6.55 K1，已拍板）：**只进内存 + `::delib` 白箱呈现；复核器必须在；不动存档。**

#### 一、做了什么

1. **对象类型 `ThinkObj`**（`think.h`，`Think` 的一个字段）：
   `have / seq（[思考:N] 的 N）/ tick / have_goal / goal（主目标）/ der（`Derivation`）/
   verified / gaps / guessed / n_trace / stop / concl / chain`。
   步骤**直接用 derive.h 那套 `Derivation`/`DerStep`**，不新造格式 ——
   渲染也复用现成的 `der_dump()`（`[推导] … 缺口=N` + 逐步 ✓/✗），
   所以 `::thinkobj` / `::delib` 打出来的就是 `::der` 那套模样。
2. **产出点（三条路，都只在开关开着时走）**：
   · **直接查图**（`think_step_lookup` 命中）→ `FACT + CONCLUDE`；从**假设层**查到的那条记成
     `DER_HYP`（复核器去覆盖层核对，不是查图 —— 假设不进图这条铁律不破）；
   · **交给求解器**（`think_step_derive` 过了验证器那条链）→ `der_from_proof` 的 RULE/FACT 链；
   · **类比**（`think_step_analogy`）→ `DER_DEFAULT`（`guessed` 跟着对象走）。
   收的规则：**缺口更少的才顶替**（同样少 = 先到先得），所以主目标的链不会被后来拆出来的子目标挤掉。
3. **定稿 + 复核**（`think_obj_finish`，在 `think_run` 的每个出口调用）：

   把缺口数记在对象上。没有任何链的一轮也定稿，但对象里会留一条
   `**缺口** 这一轮没接出一条站得住的链` —— **照实说，不许把空对象说成"想通了"**。
   `::thinkobj verify` 走的是**同一个函数**当场再复核一遍（不另写一份判据）。
4. **呈现**：`think_obj_print()` 只有一处（`::thinkobj` 与 `::delib` 的对象节共用）；
   `::delib` 在开关开着时多一节「—— 思考对象（`::thinkobj` 看的就是它）——」，
   打的是**对象**（结构化步骤 + 缺口数），不是上面那份文本痕迹。
5. **开关**：`::thinkobj on|off|verify`；默认关，`AIP_THINKOBJ=1`；
   关着时 `think_run` / `::delib` / `::cot` 一行都不走新路（下面有逐字节 A/B）。

- **一轮最多一个对象**（不是"一个目标一个对象"）：子目标的链只有在比主目标那条更好时才进对象，

- **对象不参与任何决策**：今天它纯粹是白箱呈现（`::delib`/`::thinkobj` 看），
  不改输出、不影响沉淀闸门 —— 要让它参与，那是 N3（回溯/在线修订）的事。
- **不跨重启**：只进内存（这正是 K1 的决定）。`::save` 里没有它，重载后对象不在 —— 看护钉着这一点。
- **`::cot` 没接**：它记的是**答复**那条流水线的链（`ai->cot`，agent.h 里一步步 push 的），
  与"思考对象"是两件事。K1 把呈现范围定在 `::delib`，所以 `::cot` 照旧；
  要把它也接到对象上，得动回答路径 —— 那要单独 A/B，排到 N3 之后。
- **"复核"是同一套 `der_verify`**（不是第二套独立实现）：独立指的是**独立重推每一步**
  （拿 `rel_direct`/`rel_solve` 重新验一遍），这与 ::der 那条路用的是同一个复核器 ——
  项目本来的立场就是"验证器只有一份"。
- 对象里的步骤**引用池里的 Token 指针**：只在本进程内有效（不存盘就没这个问题）；
  如果将来真要把对象存图/存盘，得先定"Token 引用怎么跨重启"（今天不做）。

### 6.62 K6：统一写入通道**补齐**（非观测直写也走同一套开关；默认关，**本轮做完**）

顶块第 6 条第二件（§6.54 的 K6 / §6.55 的 K6）。缺口原文：`microkernel.md` 一直记着
「**老写入者绕过安全内核**」——`ai_write_rel`（知识类）已经可路由，但 `ai_write_assoc`
（共现类）永远直写。处理决定：照 `ai_write_rel` 的 `route_writes` 模式给它**同一套**开关，
默认关 = 与今天逐字节相同；**感知共现（`ai_learn_pair`）保持直写**。

#### 一、做了什么

1. `ai.h` 的 `ai_write_assoc`：`route_writes` 打开时把这条写入提成 `MOD_ADD_ASSOC` 意图
   走受审通道（审查 → 预算 → 应用 → 记账 → 审计），source 记 `统一通道:<来源档>`
   （和 `ai_write_rel` 同一套有界拼接）。**返回口径两条路一致**：1=新加 / 0=已有 / −1=被拒。
   `route_writes` **关着时**这个函数与今天一字不差（早退到直写，连微内核状态都不碰）。
2. **一条静态例外（K6 的实测结论，不是拍脑袋）**：端点在**协议骨架**里的写入（`[时刻:…]` 这类
   "保留但不是内核命名空间"的名字）**不路由**。理由链：
   · 实测：打开路由后，时间链那条 `[时刻:N]→你好` 被安全内核拒了 ——
     **「不许改保留 Token」**（`SAFE_DENY_RESERVED`）；
   · 而那条规矩保护的是"**自修改**不许动骨架"；时间链/句界是**内核自己的记账**，不是自修改；
   · 于是判据取现成的 `micro_endpoint_reserved()`（**静态**：由 token 名字决定），
     不是"内核拒了就绕开" —— 内核会接的写入一条都逃不掉审查。
   结果：路由打开时**时间线不会丢**（`::stats` 时间点照涨，拒绝数 0）。
3. `::safe` 的报告改写清了口径：路由打开时**关系事实 + 非观测共现写入**都过内核，
   **两类刻意直写**（感知共现 / 骨架端点写入）各自写明理由，写入账照记。

#### 二、证据

- **默认跑法逐字节 A/B**：HEAD 的源码单独编 `build_old`，与新二进制跑同一份输入
  （5 轮对话含现场学两条新事实 + `::safe` + `::stats`）——
  **行为/答复/图完全一致**；唯一差别是 `::safe` 报告里描述"路由范围"的那几行**文字**
  （路由范围本来就变了，报告正是描述它的地方 —— 这一点照实记，不假装逐字节）。
- **路由打开时**：同一份输入，答复**一模一样**（`diff` 空），只有
  写入账 `受审 1→3`、审计多两条「打关系 雪→工具 / 猫→机器」、`意图=1(应用1→3)`。
  也就是"**机制在、行为不动**"。
- **C 级看护**（`tools/optest.c` ⑱ 节）：新增 9 项 —— 路由开时 `ai_write_assoc`
  返回口径（1/0）、边照样建出来、进审计（加边）、记账动了、**骨架端点走直写且内核没有拒它**
  （这一条可证伪：去掉例外就会看到"允许 0 拒绝 1"）。optest **252 项全过**（原 241 + 11）。
- **CLI 看护**（`tests/selfmod.sh` 新 §3.5，9 项）：默认关时走路人的写入不进内核（允许 0）；
  打开后**知识类写入真的过内核**（教一条模型里没有的事实 → 允许 ≥1 + 审计里「打关系」）；
  骨架写入**不被拒**（拒绝 0）且时间链照旧（时间点 ≥1）；`::safe` 报告里写明了例外。
  selfmod **67 项全过**。
- **整包**：默认跑法与 `AIP_ROUTE=1` 跑法各一遍，**32 套 + 冒烟全绿**（见 `_t/k6_ab.log`）。

#### 三、踩的坑

1. **`micro_endpoint_reserved` 不等于 `micro_reserved`**：`[时刻:…]` 是"保留但**不是**内核命名空间"
   ⇒ 内核拒绝它当端点。第一版直接路由，于是时间链在路由打开时**静默消失**
   （只有审计里一条"拒绝：不许改保留 Token"）—— 这就是"先量再定"的价值：
   如果只按计划写代码不跑 A/B，这条会当成"绿"发出去。
2. 测试里教现成知识（`猫 属于 动物`）**不会**触发写入：关系层只会答"我知道"（`known` 分支），
   所以那条断言一直是 允许 0。换成模型里没有的事实（`猫 属于 机器`）才真的写图。
3. 报告文字改了两处（`::safe` 的报告与 `::safe route` 的回应）—— 断言里不能再用老措辞；
   同时把"默认跑法逐字节相同"这句话**改成**"行为逐字节相同、报告文字随能力改写"。
4. **反向测量第一次就抓到两条假红**（这正是它是"规矩"而不是"形式"的原因）：
   `AIP_ROUTE=1` 跑整包时 `optest` 250/2、`selfmod` 66/1 ——
   · `optest`：新加的 K6 断言假设"路由关"，而 `AIP_ROUTE=1` 会让每个 `ai_new()` 出来就是开的
     ⇒ C 级测试**自己钉** `ai->route_writes`（与 delibtest ⑭ 同一个坑）；
   · `selfmod`：`路由=关（默认）` 那两条要按项目惯例 `if [ -z "${AIP_ROUTE:-}" ]` 跳过，
     反向跑法里改成断言"启动即开"。
   修完两个跑法都 32/32 全绿。

#### 四、局限（照实说）

- 路由**只覆盖两类写入口**（`ai_write_rel` 关系事实、`ai_write_assoc` 非观测共现）。
  图上还有别的写入者（感知共现 `ai_learn_pair`、睡眠/巩固 `token_consolidate`、
  抽象形成、衰减）still 直写 —— 它们要么是观测的丰富记录（转意图会丢 hits/pattern/topic），
  要么是**维护性**动作（排序/衰减/删），不是"AI 想写知识"。要全覆盖得先定"维护动作算不算自修改"。
- 骨架端点那条例外是**静态判据**：只要端点名字落在 `[原语:…]`/`[时刻:…]`/`[提醒:…]` 这类
  协议骨架里就不路由。它保护的是内核自己的记账；换一个骨架命名空间（新 `[xxx:`）要同步想一遍。
- 路由打开时，**A/B 只是"答复不变"**：预算/审计的数字会变（多了受审条目、`意图` 计数上涨），
  这是设计使然（多了一道审查）。真正"让内核看住写入"的收益（比如拦下不该写的边）
  要等有检测器/闸门配合才看得见 —— 今天只是**通道通了**。
- `AIP_ROUTE=1` 的整包全绿说明"打开不会改行为"；它**没有**证明"打开更安全"（那是另一件事，
  要有可证伪的拒绝场景才行）。
