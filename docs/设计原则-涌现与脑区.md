# 设计原则：**该涌现的涌现，该新写的才新写**

> **给三天后的人（一句话）**：哪些东西**不**硬编码（让它在语料里泡出来）、哪些必须写死（安全内核的底线），以及"脑区"式的分层理由。
> 想判断"这个功能该不该加、该加在哪一层"时先读它。


> 这条原则是用户给的（原话）：
>
> > 普通的、没有单独脑区管理的东西，应该在现有的架构里**涌现**；
> > 而有单独脑区的，应该**新写代码**；
> > 角色对现在的内核不重要的，可以**暂时放一下**。
>
> 它解决的是这个项目最怕的一类退化：**把本该从关联图里长出来的能力，
> 一条一条写成 if-else**。那样做出来的不是「类脑的关联机」，
> 而是「一个带很多特例的规则引擎」——而规则引擎正是这个项目一开始要绕开的东西。
> 反过来，也不该拿「涌现」当借口：**真实脑区干的活**（工作记忆、元认知监控、
> 安全底线）必须有专门的机制，不能指望它们从图里自己冒出来。
>
> 用户后来还补了一句方向与一条禁令（原话）：
>
> > **「越接近人思考的原理越好」** / **「但是不要把糟粕学来了」**
> >
> > 两句合起来是一个判据：**学人的机制，不学人的偏误** ——
> > 而且「原理」必须带**它的约束**（记忆强是因为惊讶 + 会遗忘；
> > 因果学习强是因为要协变 + 会被反例推翻）。只学前半句，学来的就是糟粕。
> > 采用的清单、**不采用（糟粕）的清单**、每条配的护栏与回归，见
> > `docs/人思考的原理-采用与不采用.md`。

## 一、判据：怎么区分这两类

问三个问题，按顺序：

| # | 问题 | 是 → 结论 |
|---|---|---|
| 1 | 这件事**人脑有专门区域**吗？（工作记忆、冲突监控、安全/价值底线、结构可塑性…） | 有 → **新写机制**（但不能写内容） |
| 2 | 它的**内容/知识**能不能从图、规则表、语料里读出来？ | 能 → **别写死内容**，让它被读出来 |
| 3 | 它对**当前内核**重要吗？ | 不重要 → **暂缓**，不要为它铺路 |

一句话版本：

> **机制可以新写，知识必须涌现；内容写进表，行为留给图。**

## 二、现有各层审计

按上面三条判据，逐层看一遍（✅ 合规 / ⚠️ 打折 / ❌ 越界）：

| 层 | 是什么 | 判定 | 依据 |
|---|---|---|---|
| `token.h` 图 + 边 | 白板/皮层回路 | ✅ 机制 | 它自己不产生任何「知识」，只提供结构 |
| `token_lang.h` 原语解释器 | 语言接口 | ✅ 机制 | 原语是操作，不是知识 |
| `ai.h` 学习/衰减/巩固 | 突触可塑性 | ✅ 机制 | 权重从 hits/时间算出来，不是写死的 |
| `ai.h` 抽象形成 | 概念形成 | ✅ 涌现 | 靠 Jaccard 相似度自己长类别，代码里没有「猫是动物」这种条目 |
| `ai.h` 元认知 | 内感受/知道感 | ✅ 机制 | 五信号合成 + 七档表达，信号权重是可调参数 |
| `frame.h` 结构化帧 | 句法骨架 | ⚠️ 半机制 | 骨架表是**手写知识**（`frames.txt`）。它现在外置成文件（可换、可读），但骨架本身没从图里长出来 —— 这是有意的权衡：没有它，输出只能是碎片 |
| `rel.h` 关系表 `AI_RELS` | 语义关系词汇 | ✅ 机制 + 表 | 关系类型是**声明**（表），推理靠规则；这一轮把「哪些关系有前提」也搬进表里（见第三节） |
| `rel.h` 推理规则 R1–R9 | 推理 | ✅ 机制 | 规则由表里的 `trans/inherit/sym/inv/excl/prereq` 决定，新增关系是改表 |
| `derive.h` 推导 + 验证器 | 工作记忆里的「链」 | ✅ 机制（真脑区） | 链是一等公民、可被独立复核；这是「能正确思考」的保证 |
| `micro.h` 意图队列 + 安全内核 | 结构可塑性 + 安全底线 | ✅ 机制（真脑区） | 修改必须受审、有预算、有审计；底线写死是对的（自修改系统不许改自己的底线） |
| `micro.h` 检测器 D1/D2/D3 | 自修改**策略** | ⚠️ 机制在、参数手写 | 判据是图内量出来的（邻居重叠、空缺感），但阈值/频率是人定的。等有数据再校准 |
| `think.h` 议程 + 痕迹 + 元认知 | 工作记忆 + 冲突监控 | ✅ 机制（真脑区） | 见第四节：这一轮把它里面**写死的策略表**拆掉了 |
| `think.h` 结论/未解问题 | 想出来的东西 | ✅ 涌现 | 全部来自求解器与图；思维**不把推出来的东西写进图** |
| 补丁层（`patch`） | 外设接口 | ✅ 启用一侧 | 机制在（热插拔、故障隔离、越界截断）+ **输出侧三个口子**（stage/emit/op）；内建 `自省`（感知侧）与 `记事本`（**输出侧**：可编辑答复 / 草稿区 / 何时发送，见 `docs/记事本与草稿区-输出补丁.md`）。仍然**不预置**视觉/听觉/3D —— 那些是硬件外设 |
| CPU 解耦（索引化/显式栈） | 换硬件 | ⏸ 暂缓 | 同上；只在 `docs/microkernel.md` 里记了做到哪一层 |

## 三、这一轮按原则做的两处改动

### ① 把「哪些关系有前提」从代码搬进表（`rel.h`）

之前求解器里写着：

```c
if (want_neg && rid == REL_CAN && rel_need_witness(ai, a, b, depth)) { ... }
```

`rid == REL_CAN` 是**知识**（只有「会」有前提这回事），却被写进了控制流。
现在它成了关系表的一列：

```c
    /* 名字    否定         id           传 继 对 逆          独占 前提 */
    { "会",   "不 会",     REL_CAN,      0, 1, 0, 0,          0, 1 },
```

求解器改读声明：`if (want_neg && rd && rd->prereq && rel_need_witness(...))`。
**后果**：以后哪条关系有前提，是改表；错误也只会犯在表里（一个地方）。

踩的坑记一下：字段顺序必须和表的列序一致（我把 `prereq` 插到了 `excl` 前面，
表里的值却按「…独占、前提」写 —— 不报错，只让值悄悄串位，
prerequisite.sh 当场变红）。

### ② 把思维层的「策略表」拆掉，改成从架构里长出来（`think.h`）

之前分解是写死的一串：试反方向 + 类比 + （`if rid == REL_CAN` 才问缺前提）。
现在子目标由**表和图的声明**生成：

| 子目标 | 谁决定它存在 |
|---|---|
| 换问法 | **机制**（规则 R7/R8/R9 只在问否定时开火），与具体关系无关 |
| 缺哪条前提 | 关系表：`rd->prereq` |
| 借最近邻 | **表示层在不在**（`emb` 有值才有这条路） |
| 经由某个中间词 | 关系表：`rd->trans`（同关系传递）/ `rd->inherit`（先走「属于」）+ **图给出的候选**（`rel_next_cands`，它会连假设覆盖层一起搜） |

实测的痕迹（`猫 会 唱歌 吗`）：

```
 5. 分解   ✓  够不着就拆
    够不着 → 拆出 4 个子目标压回议程（换问法 缺前提 借最近邻 经由动物 ）
 6. 推      ✓  交给求解器 + 验证器复核
    猫 -[会·缺前提]-> 唱歌
```

注意第 5 步末尾那个「经由动物」：**它不是代码里写的，是图给的**。

而且「经由中间词」不是把求解器重写一遍 —— 它补的是求解器**做不到**的那件事：
每一跳都是一次独立求解，所以串起来的深度不受单次调用的深度上限约束。
**新增能力来自机制的组合，不来自重复实现。**

---

### ③ 把「有哪些机制」也变成注册表（`think.h`）

上一轮改掉的是「分解写死策略表」，但**机制清单本身还是固定四种**（写在一排 `if` 里）——
那还是「新增手段要改循环」。这一轮把它变成注册表：

```c
{ "换问法",   TG_OPPOSITE, "关系在表里声明过",           applicable, NULL,        process },
{ "缺前提",   TG_NEED,     "关系表声明了 prereq",         applicable, NULL,        process },
{ "借最近邻", TG_ANALOGY,  "两端都有表示（emb）",          applicable, NULL,        process },
{ "经由中间词", TG_THROUGH, "关系表声明了 trans/inherit；中间词来自图", applicable, expand, process },
```

接口把三条边界钉住了：机制**怎么干活**写在回调里（新写代码，正当）；
机制**什么时候能用**写在 `applicable()` 里且**只读表/图/表示层**（知识必须涌现）；
**调度按注册表下标**，外部机制用 `TG_EXT`，不必抢内核的枚举值。

证据不是「我说它是可扩展的」，而是 `tools/delibtest.c` 里**运行时注册了一条内核没有的机制**
（`试上位类`：读父类指针 + 父类到宾语的边），循环/分解/调度一行没改，
它答出了核心答不了的问题（父子关系是**结构**，不是图里的边）。

顺带逮到一个真 bug：类比原来把**真值**当**回答**用，
所以问「猫 不 喜欢 鱼 吗」时答案会反过来（真值 → 回答的换算每条机制都要做）。
现在有专门的看护钉住它。

### ④ 让「谁赢」由证据的来源决定，而不是由代码顺序决定（`rel.h` + `token.h`）

冲突时谁说了算，以前隐含在代码顺序里（先查到的先说）。现在写成了**证据等级**：

```
观测到的直接事实  >  现场健全规则推导  >  推理缓存 / 非单调默认  >  假设  >  类比
```

两条落地：
* **具体优先于一般**：同一对词上有观测到的反面边时，**传递/继承不再外推**
  （例：`猫 属于 动物`、`动物 有 毛` 推出「猫有毛」；用户说「猫没有毛」之后，
  一般规则在这个具体例子上让路）。这是非单调推理（default with exceptions）的核心，
  它属于**推理机制**，所以写在求解器里；而「谁是观测、谁是缓存」是**数据**，
  由边上的 `role` 决定 —— 机制新写、判据来自数据，符合原则。
* **缓存不是依据**：推理沉淀下来的 `ASSOC_ROLE_DERIVED` 边，
  证据等级低于观测与现场推理；被推翻时允许撤销（观测到的关系边依旧不许删）。

这一条修掉的是「用户教的修正永远留不下来」（每轮都报自相矛盾）那个真问题。

### ⑤ 把「重复的表」合成一张、把「散在两个 switch 里的知识」搬进表

用户的第二条要求是「不要滥用硬编码」。按判据分两类处理：

| 东西 | 之前 | 现在 |
|---|---|---|
| 推导规则的名字与非单调性 | 散在**两个** switch 里（`derive.h` 的 `der_rule_name`、`think.h` 的 `think_evidence_class`），加一条规则要改两处 | 一张表 `REL_RULES[] = {id, name, ev}`；规则名与**证据强度**都是表的一列 |
| 疑问词表 | 在 `agent.h` 里**抄了三份**（学关系 / 检索门槛 / 拒答门槛），三份还不完全一样 | 一张 `AI_QUESTION_WORDS[]` + `ai_has_question_word()`，三处共用一个判据 |

第二处那种重复最危险：改一处忘一处，症状是「同一句话在一条路径上算问句、在另一条上不算」——
不是崩溃，是**行为分叉**。

### ⑥ 依据不存表，现算（`rel.h`）

「缓存的依据是什么」这件事，也可以选择另存一张依赖表；这里选了**现算**：
把缓存排除在外再推一遍，推得出来才算有依据。
好处是不多一份会和图不一致的状态，也不用动存档格式；
代价是每次复核要跑一次求解（缓存本来就少，实测可忽略）。
这条也是判据 2 的推论：**能从图里读出来的，就别再存一份**。

### ⑦ 命令表：**命令名只写一份**（`main.c`）

元命令当时 54 条（现在 55，`::revise` 是这一轮加的；条数以 `::help` 自报的为准），
原来写了两份清单：派发链五十个 `if (strcmp(cmd, "…"))` 一份，
`::help` 的文本又一份。两份会漂移，症状是「帮助里有的命令其实不认」——
不崩溃，是**文档骗人**。

现在：

```c
typedef struct {
    const char *name;
    const char *alias;      /* 别名，例如 help 的 ?、fingerprint 的 fp */
    CmdArgKind  arg;        /* NONE 不收参数 / OPT 可选 / REQ 必需 */
    const char *group;      /* 帮助里的分组标题 */
    const char *help;       /* 用法说明（%M 会换成默认模型文件名） */
    CmdId       id;
} CmdDef;
```

四条性质：

1. **派发里没有字符串**：先 `cmd_find(name)` 拿 id，再 `switch (cd->id)`；
2. **帮助由表生成**（连分组标题都是表的一列，`%M` 替换默认文件名）——
   命令名只在这一张表里出现；
3. **表里有而 switch 里漏了**的情况，`default` 分支当场报「命令表里有 X 但没有实现」——
   自检，而不是静默地当成用户输错；
4. **参数形状由表管**：不收参数的给了参数报用法、要参数的缺了报用法 ——
   以前这是每条命令各写一遍的样板代码。

证据（`tests/cmdtable.sh`，13 项）：把 `::help` 列出的每一条（现在 55 条）**逐条真的打一遍**，
断言不出现「未知命令」也不出现「没有实现」；再钉住别名（`::fp`）、
整词匹配（`::relx` 不认、`::rel` 与 `::relinfer` 不互相吃）、参数形状两个方向。

加一条新命令现在是：**表里加一行 + switch 里写它的行为**（行为是代码，进不了表）。

### ⑧ 再去三处重复：**先分类，再决定「去重」还是「合并」**

这一轮把剩下三处「同一份清单两处写」清了。它们教会的不是「重复就删」，而是**先分类**：

| 重复的形态 | 例子 | 正确做法 |
|---|---|---|
| **同一份清单被抄了两遍** | `main.c` 文件头的「用法」与 `cmd_help()` 打的用法段（**已经漂移**：`--batch --save` 只有一份有，`--interval`/`-h` 两份都没有）；`frame.h` 里 `已经`/`正在` 在同一张表里各写两遍 | **去重**：一张表 + 生成/查询。`USAGE[]`（6 行）由帮助打印；`FR_FUNC` 删掉重复项 |
| **两张表语义相交但不相等** | 「虚词表」（Gate B ①号门：填进槽位必成病句）与「词尾表」（以它收尾就是切词碎片） | **只把交集收成一张表**，不要整个合并：`过` 是虚词，但「经过」以它收尾是真词 —— 并进去就误伤真词。`FR_PARTICLES[]` 只放**两处都成立**的 8 个 |
| **同一族参数散在文件各处** | `ai.h` 的 `AI_MAX_*` / `COT_MAX_STEP` 上界跟着结构体定义走（51 行一个、241 行一个） | **集中**（不是消灭）：一个「参数区」块 + 注释，并注明其它层的参数区在哪。参数留常量是**有意的**，但「集中」是可检查的 |

两条判据：

1. **先看两份是不是一回事**：是一回事 → 去重；只是相交 → 只收交集，边界用测试钉住
   （`tools/dupcheck.c` 里那条「别把『经过』误伤」就是这条判据的看护）。
2. **清单重复的症状不是崩溃，是行为分叉 / 文档骗人**：同一句话在一条路径上算问句、
   在另一条上不算；帮助里写的开关其实不认。所以清理之后要配**自检**
   （`tools/dupcheck.c` 查所有表无重复项、`tests/cmdtable.sh` 查用法表与 `main()` 一致）。

### ⑨ 跨层要组合时：**注册进已有的机器，不新造一台**（`token_lang.h`）

用户在这里拍过一个取舍：「Token 栈还是临时 Token？」→ **临时 Token**。
但"要组合"的需求是真的（把一串图操作写成程序）。正确的做法不是给行为再配一台栈机，而是
**把行为注册进已经在跑的那台**（`Interp`，它已经跑原语、切分、语料）：

| 做法 | 结果 |
|---|---|
| 新造一台 Token 栈 | 多一台要维护的机器：栈生命周期、错误恢复、和 `Interp` 的关系、和 micro 队列的边界 —— 全是新的失败面；而且把「组合」从图搬进了语言层 |
| **注册进已有的 `Interp`**（采用） | `[原语:插词]` 这种写法天然可组合（用栈弹操作数）；语言层**仍然不碰图** —— 它把「行为编号 + 操作数」交给宿主，宿主（`main.c`）再走 `token_op_run` → 安全内核 |

顺手清掉的重复：原语名字以前写在**三**处（`prim_kind()` 的 if 链 + `pool_init_prims()` 的清单
+ `cmd_prims()`（`::prims`）手抄的第三份 —— 第三份还会漏列新原语），现在只有一张 `PRIMS[]`。
**判据同 ⑧：先看两份是不是一回事 —— 是一回事就去重。**
**教训：以为只有两份，往往还有第三份** —— 找重复要按"同一份清单"的**语义**找
（"所有原语名字"），不是按文件/函数找；清完还要配一条「表 N 条 / 列 N 条」的自检。
跨层契约（原语编号 ↔ `TOKEN_OPS[]` 下标）用测试钉住，不靠"约定俗成"。

## 四、这一层里还剩的「越界」与「打折」（照实说）

1. **机制可注册了，内建五条**（问前提 / 换问法 / 缺前提 / 借最近邻 / 经由中间词 ——
   顺序即优先级，「问前提」排第一是因为它最便宜而且解释失败原因）。注册表解决了「新增要改循环」，
   但 `applicable()` 谓词仍是手写的四个（它们只读表和图，这是接口要求）。
   彻底版是机制自己声明依赖、由内核去满足 —— 四条机制上还不值当。
2. **类比机制由 `emb` 在不在来把关**，但 `emb` 的质量本身撑不起细粒度分类
   （仓库既有结论）——所以这条路常常走不到。
3. **D1/D2/D3 的阈值是手写的**（Jaccard 0.30、每 100 轮、gap 0.65）。
   判据是图内量出来的，阈值不是。等有一批真实会话数据再校准。
4. **`frame.h` 的骨架仍是手写知识**（`frames.txt`）。这一条影响最大，
   也最难：要让句法从图里长出来，得有比现在大得多的语料和一套
   「结构相似 → 抽象」的机制。目前是有意的权衡，不是疏忽。
5. **`[自问:…]` / `[新概念:…]` 这两个命名空间是内核自有的**。
   它们不是「涌现」的，是机制需要的标记（工作记忆里的占位符）——
   按判据 1 属于「新写机制」，可以接受，但仅限于**标记**，不做知识。

## 四点五、**仍然是硬编码的**清单（照实说，附理由）

「不要滥用硬编码」不是「消灭所有常量」。把剩下的逐条列清楚，才知道哪些是该清的、哪些是先留着：

| 还是硬编码的 | 为什么先留着 |
|---|---|
| **参数**：D1 的 Jaccard/共同邻居阈值、D2 每 100 轮、D3 的 2000 tick、思维步数/停滞次数/未解问题 TTL、`REL_MAX_DEPTH`、各种 `AI_MAX_*` 上限 | 它们是**参数**不是知识，要靠**测量**调；搬进数据文件会把「调参」变成「改数据」，反而更难复现。要求是集中、有注释、能一条命令改（`::thinkbudget` 这类）。**这一轮已经把 ai.h 那一层收成一个「参数区」块**，并注明其它层的参数区在哪（`rel.h`/`derive.h`/`think.h`/`micro.h`/`frame.h`）——「集中」是可检查的，「留常量」不是借口 |
| `rel_shape_ok` 的句法形状（`<主语> [不] <谓语> <宾语> [吗]`） | 这是**语言层**的结构。让它自己从语料长出来要有大得多的语料和一套结构抽象机制 —— 已进暂缓清单，不是疏忽 |
| `AI_LEXICON`（分词词表） | 本来就是表，而且**语料构建与用户输入共用它**（不共用的话切法会不一致，文档里记了原因） |
| `AI_REFUSALS`（拒答说法池） | 表 ✓；内容可以更好，但形式对了（`tools/dupcheck.c` 钉住它没有重复项） |
| `frame.txt` / `relations.txt` | **知识出代码的正面例子**：改知识不用重编译 |
| ~~`main.c` 的元命令 if 链与 `::help` 的命令清单~~ | **已清（2026-10 这一轮）**：见下面 ⑦ —— 现在是一张 `CMDS[]` 表，派发按表的 id、帮助由表生成 |
| ~~`main.c` 文件头的「用法」与 `::help` 的用法段~~ | **已清（2026-10 这一轮）**：见下面 ⑧ —— 一张 `USAGE[]`（两份**已经漂移**：`--batch --save` 只有一份有、`--interval`/`-h` 两份都没有） |
| ~~`frame.h` 的功能词表与词尾表~~ | **已清（同一轮）**：见下面 ⑧ —— 一张 `FR_PARTICLES[]` 两处用；虚词表里的重复项（`已经`/`正在`）也删了 |
| `[原语:…]` / `[时刻:…]` / `[对话:结束]` | 内核**协议常量**，不是知识；正当 |
| `[自问:…]` / `[新概念:…]` / `[临:…]` / `[修正:…]` / `[前提]` / `[前提不]` | 内核**自有的图内命名空间**（工作记忆里的标记 / 草稿 / 留痕），机制需要它们 —— 但**内容仍然从图与表里读**：命名空间是「注册一行」（`micro_internal_ns` 一张表），新增一个只改那一处。`[临:` 还是**不存盘**的草稿纸；`[前提]`/`[前提不]` 是挂在边动作槽上的**行为 token**（条件标记，见 `docs/语境退役-前提token.md`） |
| `micro_reserved`（`[` 前缀 = 标记） | 约定，不是知识；正当。注意**两件事要分开**：`micro_token_reserved`（算不算内容 —— 统计/走边跳过标记）与 `micro_endpoint_reserved`（能不能当连线端点 —— 内核自有命名空间放行）；混成一个会让「草稿/留痕」要么污染统计、要么根本连不上边 |
| `TOKEN_OPS[]`（Token 的行为：加前提/前提接线/插词/回收） | **机制**，正当：行为是操作不是知识；展开成 `ModIntent` 走安全内核，新增一种行为 = 表里加一行 |
| ~~`AssocEntry.subs[]`/`subs_not[]`（「语境」）~~ | **已退役（这一轮）**：条件从**边上的字段**换成**图里的节点与边** —— `A —[前提]→ P → B`（P 是普通 token，`[前提]` 是行为 token）。字段只留作旧模型兼容（新数据恒 0），见 `docs/语境退役-前提token.md` |
| ~~原语名字的 `if` 链 + `pool_init_prims` 的手抄清单~~ | **已清（这一轮）**：见下面 ⑨ —— 合成一张 `PRIMS[]`（识别与 intern 同一张表） |

## 五、暂缓清单（角色对当前内核不重要的）

按用户的第三条：先不动，别为它们铺路。

| 暂缓项 | 为什么可以等 | 已经有的东西 |
|---|---|---|
| 视觉 / 3D / 听觉 / 运动补丁 | 它们对「关联 → 自修改 → 思维」这条主线不重要；现在连一个感官都没有，照样能跑 | 补丁接口 + 热插拔 + 故障隔离（`micro.h`），以及 `自省` 这一个不依赖外设的例子 |

| 逐条知识的可信度权重 | 现在用 5 档粗分级（事实/规则/默认/假设/类比）已经够避免误判矛盾 | `think_evidence_class` |

## 六、给自己（和下一个改这份代码的人）的检查表

新加一个能力之前，先回答：

- [ ] 这是**机制**还是**内容**？内容能不能从表/图/语料读出来？
- [ ] 它靠近**人的哪个思考原理**？那条原理**带什么约束**（不学约束就是学糟粕）？
      采用/不采用的清单在 `docs/人思考的原理-采用与不采用.md`，
      护栏要有能跑红的回归（`tools/biastest.c` / `tests/biases.sh` 是这类看护的家）。
- [ ] 如果是内容，我是不是应该**加一列/加一条语料**，而不是加一个 `if`？
- [ ] 这个能力人脑有专门区域吗？没有的话，它凭什么需要专门代码？
- [ ] 它现在对内核重要吗？不重要就写进暂缓清单，别铺路。
- [ ] 如果加了新能力，它是「注册一行」还是「改循环」？后者要说得出为什么。
- [ ] 我有没有**抄第二份表**？命令名、规则名、疑问词、虚词/词尾、命令行用法、默认值——
      同一份清单出现在两处就是行为分叉的种子（命令表、规则表、疑问词表、用法表、
      frame 词表都已经收拢过了；`tools/dupcheck.c` 会当场变红）。
- [ ] 我加的是**知识**还是**参数**？知识进表/进图/进语料，参数留常量但要集中、有注释、可一条命令改。
- [ ] 加完之后，**既有回归**（`sh tests/all.sh`，27 套）还全绿吗？
      动了默认值的话，跑过 `sh tests/thinkout_ab.sh` 了吗？
- [ ] 我加的是**清单**吗？如果是，它有没有**第二份**（正文、帮助、另一条路径）？
      先问「两份是不是一回事」：是一回事就去重，只是相交就**只收交集**并用测试钉住边界
      （`tools/dupcheck.c` 是这类自检的家）。
- [ ] 我把「为什么这么定」写进 docs 了吗（包括**没做**的部分）？
