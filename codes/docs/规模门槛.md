# 规模门槛（阶段二 WP0；§6.632）

> 目的：把"**图足够大**"从口号变成**能测的数**。阶段二后面每条能力（规则链、证明、论文、语言包、
> 复杂代码）的"撑不撑得住"都拿这张表当基准。
> **不扩图**：这张表只量"现有引擎在多大图上还撑得住"，不灌语料、不改结构。
> 合成图由 `tools/mkbig.c` 生成（固定种子、可复现、产物只放 `_t/` 或 `/tmp`，不进仓库）。

## 一、三档定义（M 档为**本轮实测确认可行**的档位；L 档未跑）

| 档 | 词数 | 事实（边） | 存档大小 | 规则条数（阶段二目标） | 状态 |
|---|---|---|---|---|---|
| **S**（现役真模型量级） | 1.2 k | 4.1 万 | 2.3 MB | 18（现有） | ✅ 已实测 |
| **M** | 5 万 | 200 万 | **113 MB** | 500 | ✅ 已实测（见下） |
| **L**（待压） | 50 万 | 2000 万 | ~1.1 GB（估） | 5000 | ⏳ 未跑（内存需求估 ~8 GB） |

> L 档只是**估算**：按 M 档线性外推（2 M 边 → 831 MB RSS），没实测，不算数。

## 二、M 档实测（本轮，同一台机器）

| 指标 | 数值 | 说明 |
|---|---|---|
| 造图（含写边+存盘） | **7.5 s** | 5 万词 + 200 万事实，写进 1,999,969 条 |
| **载入** | **9.4–11.2 s** | 113 MB 快照 + 重建 emb/槽类/idf/反查表 |
| **常驻内存（RSS）** | **812–831 MB** | 载入后 |
| `::rel <词>` 单次 | **≈0 ms**（<1 ms） | 走反查表，不受规模影响 |
| `::contradict` 单次 | **≈0 ms** | 合成图里没有独占关系 >2 值的词，扫得快 |
| `::revcheck` 单次 | **1.4 s** | 全表校验（2 M 边）——**这个是要盯的** |
| `::save` 单次 | **1.4 s** | 写 113 MB（含原子写） |

**结论（写死，后续引用）**：
1. **载入是 M 档的主要成本**（9–11 s / 812 MB），不是查询。所以阶段二的门槛必须**分两个数**：
   "载入 ≤ X 秒" 与 "单条查询 ≤ Y ms"。
2. **`::rel` / `::contradict` 在 M 档基本免费** —— 反查表 + 小候选集的功劳；这说明"大图上的问答"路线可行。
3. **`::revcheck` / `::save` 是线性成本**（每 100 万边 ≈0.7 s）。它们不是交互路径，但**启动自检**要谨慎：
   别在每次启动都跑全表校验。
4. **M 档不需要扩图**（113 MB 文件、812 MB 内存都在普通机器范围内）。

## 三、阶段二的规模门槛（建议值，等 M1 的 `prove` 落地后复核）

| 指标 | S | M | 判据 |
|---|---|---|---|
| 载入 | ≤ 0.3 s | **≤ 12 s** | 超了要么优化载入，要么降档 |
| 单条事实查询（`::rel`） | ≤ 1 ms | **≤ 5 ms** | 目标 |
| 单条规则证明（`prove` 深度 5，M1 后加） | ≤ 20 ms | **≤ 150 ms** | 目标（现在是 0，因为还没有 prove） |
| 全表矛盾扫描（`::contradict`） | ≤ 50 ms | **≤ 2 s** | 现在 ≈0（合成图无冲突），真语料会更高 |
| 存盘 | ≤ 0.1 s | **≤ 2 s** | 现在 1.4 s ✓ |

## 四、怎么复现

```sh
sh tests/scale.sh S            # 约 3 s
sh tests/scale.sh M            # 约 100 s（造图 7 s + 载入/5 次查询 + 两次 113 MB 写盘）
sh tests/scale.sh L            # 未验证，慎跑（预计 >8 GB 内存）
```

> ⚠ 本脚本**不进** `tests/all.sh`（太慢，M 档约 100 s）。需要时手动跑，或等阶段二后期
> 把它降成 S 档进套件（S 档只要 3 s）。

## 五、照实说

1. **合成图不是真图**：关系分布均匀、没有长尾、没有"少数枢纽词"，所以 `::rel` 的候选集偏小、
   `::contradict` 偏快。真语料上的数字会**更差**（尤其 `::contradict`）。
2. **L 档没跑**（内存估 8 GB），所以"50 万词 / 2000 万边"目前只是**假设**，不是证据。
3. 计时是**墙钟**、单次抽样（5 次平均），不是统计分布；换机器要用 `tests/scale.sh` 重测。
4. 载入的 9–11 s 是**现状**，没有做优化（不在本轮范围）；如果 M 档要进产品，载入必须优化
   （候选：emb 惰性构建、反查表按需、`::parts` 局部加载）。
