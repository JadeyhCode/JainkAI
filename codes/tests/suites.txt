# tests/suites.txt — 回归套件清单：**唯一一份**
#
# tests/all.sh 按这个清单跑（第 0 步「编译 + 探针」与最后一步「交互冒烟」写死在 all.sh 里）。
# 别在别处再列一遍套件名 —— 本项目的老毛病是「同一份清单两处写，改一处漏一处」。
#
# 格式：一行一套，`<名字>|<命令>`（`#` 开头与空行忽略）
#   名字：日志文件名（_t/par/<名字>.log）+ 只跑几套时的筛选键（SUITES="features tokenop"）
#   命令：在**该套件自己的沙箱目录**里执行（cwd = 沙箱，不是仓库根）。沙箱里
#         tests/ tools/ 是真副本，*.h *.c 与语料是软链，model.bin / frames.txt /
#         relations.txt 是真副本 —— 所以套件爱怎么改都不会串台。
#   $CORPUS：all.sh 传进来的语料文件（默认 _corpus.txt），由 all.sh export。
#
# 顺序 = 起跑顺序。**慢的排前面**：并行时它们先起跑、决定总时长。
# 每条后面的「本机实测 Xs」是 2026-10-07 串行整包量出来的（那一轮的对照表在
# docs/audit-vs-deepseek看这里.md 的 §6.42）；换机器/改套件后可以重新量再重排。
# 加一套：在这里加一行 + 写 tests/<名字>.sh；别忘 `codes/` 镜像同步要带上本文件。
#
# ⚠ **C 级套件的退出码必须真的传出来**（2026-10-10 量出来的洞）：原先那几条写的是
#   `./build_xxx | tail -3` —— 管道的退出码是 `tail` 的（永远 0），于是
#   **C 测试自己报的失败在整包汇总里是隐形的**（实测：`AIP_THINKOBJ=1` 跑整包时
#   delibtest 报了「125 项通过，5 项失败」，而整套照旧显示 [OK]）。
#   现在的写法是 `./build_xxx > ctest.log 2>&1; rc=$?; tail -N ctest.log; [ "$rc" -eq 0 ]`：
#   输出照样只留尾巴几行，但退出码**真的**决定这一套红不红。
